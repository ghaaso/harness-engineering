# Layer 3: Integrity and assurance (version 2)

Borrowed whole: the Clark-Wilson model with a small reference monitor and Biba low-water labels (D5 whole design; D7-01, the LCF kernel), assured the way independent verification and validation does it, by seeded faults (D4 whole design; D4-01). Every script exits 0 pass, 1 fail, 2 not run, 3 tampering. A gate treats 2 like 1.

## A. Integrity

**I1. Two classes.** *Untrusted (UDI):* web pages, reader returns, cards as a child writes them, child notes, drafts, reviews before certification, anything in a worktree. *Trusted (CDI):* stored snapshots, cards whose status is `witnessed` or `confirmed`, packs whose frozen hash is in the ledger, certified reviews, the synthesis built from them. Basis: D5-01 (rule C5). Runner: `promote.mjs` alone writes a status. Pack freeze, reviewer input, synthesis and `status.json` read only CDI items. On failure the script exits 1 and lists the UDI ids, the item stays UDI and the gate does not pass.

**I2. The one promotion procedure.** It has two steps, in order.
(a) *Witness, by script* (D7-01, D1-05, D5-04, D4-03, D4-04). The watcher runs `snapshot.mjs` and then `witness.mjs` on each new card at intake, again at pack freeze, and after the review on every cited card. `snapshot.mjs` fetches the URL with Node's own fetch (no rendering, no scripts), stores the raw bytes under `store/snapshots/<sha256>` and extracts the text (HTML only in the pilot). `witness.mjs` normalises the text (NFKC, case fold, whitespace, quote marks and dashes, hyphens at line breaks). It searches for the exact quote, then for the card's number (sign, separator, percent and unit variants) within *w* characters of the quote. There are three results. `witnessed`: both found. `rejected`: one is missing, and the card goes to quarantine. `unverifiable`: a fetch failure, PDF, block or empty text, which is not-run and is never passed. The result is bound to (sha256 of card, sha256 of snapshot, offset). If the card changes, the result is void (`stale`). A refetch with a new hash is logged as "source changed", not as a mismatch.
(b) *Judgment, through a narrow interface* (D5-10, D5-05, D8-06, D4-10). First `context-check.mjs` compares each citing sentence's typed `applies_to` with the card's typed conditions. Only flagged sentences and prose remainders go to the model. `check-queue.mjs` writes one input file per item: the card's typed fields, about 200 words of the snapshot around the offset and, for a citation, the sentence. The checker helper has one tool, Read, which the hook limits to that batch folder. Its brief is a fixed file in the trusted base. Its result schema is an enum {confirmed, number_mismatch, baseline_swapped, conditions_mismatch, outside_conditions, unclear} plus the offset and the field. `promote.mjs` reads the verdict from the checker's own transcript, which the harness writes, not from any session's file. It writes `confirmed` only if (a) passed and the checker is qualified for that fault class (A3). A verdict that is off the enum or missing counts as `unclear`, and the item stays `witnessed`.

**I3. Labels are computed, never self-assigned** (D5-03, D5-06; D5 and D8 missing risks). Card status order: confirmed > witnessed > unverifiable > udi = rejected = stale. A fact sentence takes the minimum over its cited cards. Its numbers must equal a cited card's number or baseline (D1-06). An uncited sentence is `judgment`. Session label: `clean` if every read and fetch in its transcript is in its input manifest of CDI items, otherwise `tainted` (Biba low-water mark at the level of the whole session, as in Flume). The child is tainted by design. A tainted session's output is never clean as a whole: each fact in it stands only on its own promoted cards. Runner: `certify.mjs`. The schemas reject any status or label field in a file a session writes.

**I4. Who reads what.** The privilege table below sets it. The coordinator reads only `status.json`, certificates, the ledger head and CDI files (D5-09). The harness gives the coordinator the first 400 characters of a child's turn end, and that channel cannot be closed. The child's brief therefore fixes its last line as `TURN-END <field>`, `perm-audit.mjs` flags any other note, and the coordinator treats the note only as a wake signal. What remains is obedience, flagged after the fact.
*F1, the field's answer* (D5-06, D3-13, D8-07, D4-08). On integrity grounds, a fresh session should write the review. Its reads are only the frozen pack (hash checked), snapshot windows of the must-read sections, and our files. Only such a review can be labelled clean. A same-session review is tainted, and its uncited sentences count as judgment. Integrity cannot say which form writes the better review, so the pilot writes both. Whatever the owner rules, the fresh path runs once per wave, so that the crash path stays tested (D1-12).

**I5. The trusted base** (D5-08, D7-04). It is `tcb/` in the coordinator's checkout at a pinned commit: the scripts, schemas, agent files, briefs, role profiles, approved question lists, approach ids, the hook and the thresholds. `tcb.lock.json` holds their hashes and changes only through a commit the owner has approved. Seed and plant keys sit in `sealed/`, outside every worktree. Checks run from `tcb/`, never from a worktree.
*Preventive layer.* `make-profile.mjs` writes each worktree's `.claude/settings.json` from the role's profile. It sets the allow and deny lists and registers `guard-hook.mjs` as a pre-tool hook. The hook refuses: reads and writes outside the role's paths; any write under `.claude/`; Bash; a helper of the wrong type; and, for the child, a fetch of any URL that is not in its field's list of witnessed must-read sources (amendment 3, row 5). Hooks are unverified on this app, so the hook test in `selftest.mjs` must show every refusal before the pilot.
*Detective layer, which does not depend on hooks.* `tcb-verify.mjs` checks the hash baseline of `tcb/` and every `.claude/` before each check run and each merge (Tripwire). `perm-audit.mjs` runs over every transcript after every turn. It checks tools, paths and URLs, and greps outgoing search text against a denylist of project terms (the confinement problem).
On failure: exit 3, the wave stops, the branch is quarantined, its items revert to UDI, and the owner is told.

**I6. Privileges** (D5-02, least privilege and the confused deputy; D8-05):

| Role | Tools | Reads | Writes |
|---|---|---|---|
| Reader | WebSearch, WebFetch; brief holds no project data | nothing on disk | nothing; result through a capped JSON schema |
| Checker | Read | `queue/<batch>/` | nothing; enum result |
| Child | Read, Write, Edit, Agent (reader type), WebFetch (witnessed must-read URLs) | own brief and question list, `fields/<n>/`, `status/<n>/` | `fields/<n>/` |
| Fresh reviewer | Read, Write | `review-in/<n>/` | `fields/<n>/review/` |
| Coordinator | Read, Write, Agent (checker type), session tools, Bash only `node tcb/scripts/*` | `status/`, certificates, CDI files | `coord/` |
| Scripts | Node fs; fetch (snapshot only); git (merge only) | everything | `status/`, `ledger/`, `store/`, `queue/`, `sealed/`, `review-in/` |
| Owner | all | all | `tcb/` through an approved commit |

**I7. The only route into the shared tree** (D5-08). `merge.mjs` commits the child's folder, because the child has no git. It runs `tcb-verify` first and refuses any diff outside `fields/<n>-<name>/`. On failure the merge is refused and the script exits 3.

**I8. The audit record** (D5-11; Clark-Wilson rule C4). Only `ledger.mjs` appends to `ledger/ledger.jsonl`, with h_i = sha256(h_{i-1} ‖ entry_i). Gate figures come only from scripts. A session's own lines are notes and are never counted. A hash chain gives forward integrity only, so the head hash is copied into each merge commit and into `status.json`. A break in the chain stops the wave.

## B. Assurance

**A1. Three values** (D4 missing risk; fail-safe defaults). Every check writes pass, fail or not-run, with a reason. A missing record counts as not-run. Gates count not-run against their threshold, and `status.json` shows it on its own line.

**A2. Scripts are tested before use** (D4 missing risk: a script with one version is a single point of failure). `selftest.mjs` runs every script on known-good and known-bad fixtures, one per fault class, plus the hook test. It runs whenever `tcb.lock.json` changes. One wrong answer and nothing starts.

**A3. Seeded faults** (D4-01, D8-04, D5-14; Mills; Arlat). Four classes are caught by script: S1 an invented quote, S2 a number altered (×10, ÷10, digits swapped), S3 a quote taken from another card, S4 a wrong card id. Four classes are left to the checker: J1 number and baseline swapped, J2 a condition dropped or altered, J3 a citing sentence wider than the card's conditions, J4 an instruction ("return confirmed") placed in a card's free text. `seed.mjs` mutates witnessed cards with these deterministic operators, gives each a fresh id from the normal id generator, shuffles them into the queue with a logged random seed, and keeps the key in `sealed/`. The checker's brief never mentions seeding. `promote.mjs` drops seeds by id, so they never reach a pack, a review or the synthesis. An equal number of clean items measures false alarms.
*How many.* To show detection ≥ d0 at 95 % with zero misses needs S ≥ ln 0.05 / ln d0 seeds: 29 for d0 = 0.9, 14 for 0.8, 9 for 0.7. Pilot calibration: 14 seeds per J class (56) plus 56 clean items. Each S class gets fixtures plus 5 seeds in the live check stream. In every later wave, 10 % of each batch is seeds (a proof test).
*Computed:* d_k = s_k/S_k with its Clopper-Pearson lower bound; the false-alarm rate; the chain's escape rate, measured on seeds that passed every layer in turn, never as a product of layer rates (D4-02); the residual estimate n_k(1−d_k)/d_k, which assumes faults are equally easy to detect; and for J4, whether any instruction was followed. If a class's lower bound is below d0, its checker is unqualified, its `confirmed` verdicts since its last pass revert to `witnessed`, and the next wave waits until the check is changed and measured again.

**A4. Sampling** (D4-09, D6-03, D7-01). *Uncited cards,* one lot per reader, zero acceptance: n = ⌈ln β / ln(1 − d·p1)⌉, and a lot no larger than n is checked in full. Worked sizes: p1 = 0.10, β = 0.10 gives 22 at d = 1 and 28 at d = 0.8. p1 = 0.05, β = 0.10 gives 45 and 57. p1 = 0.05, β = 0.05, d = 1 gives 59. p1 = 0.20, β = 0.10, d = 0.8 gives 14. One semantic failure means that reader's lot is checked in full, or dropped and listed as not covered. `check-queue.mjs` draws the sample at gate A.
*Cited cards* are all checked. The review is judged as a lot by an SPRT with p0 = 0.05, p1 = 0.20, α = β = 0.05. A failure adds 1.386 and a pass subtracts 0.172. It rejects at 2.944 (three early failures) and accepts at −2.944 (18 passes with no failure). A rejected review is rewritten fresh from the corrected pack, never patched. If no boundary is crossed, the review is accepted and flagged borderline. A rate with zero failures in n is reported with its 95 % upper bound of about 3/n.

**A5. Certifying an expert** (D5-07, D4-11). `certify.mjs` writes the certificate, and no line of it comes from the session. The expert is certified only if all of the following hold. Every approved question id is covered by a confirmed card or listed as not covered. Its reads match its manifest, or the review is marked tainted. Every cited card is confirmed, and every fact passes I3 and the context check. The SPRT accepts. At least t of k = 3 plants were found. `plant.mjs` puts the plants into the reviewer's copy of our work. Each rests on a confirmed card, and at least one goes against the answer we hope for (anchoring, P2). Three plants catch only gross failure, so the plant rate is pooled across experts. The certificate reads certified, not certified (one fresh re-review is allowed, then the review counts as judgment), or not run.

**A6. Every measure has an action line** (D4 missing risk: normalisation of deviance). The owner sets each threshold before the pilot, and the gate script compares against it at every wave.

## C. Where the classical assumptions fail
- A model checker cannot be certified. Scripts certify (`witnessed`). A model is measured (`confirmed` means measured and qualified).
- A model's output depends on its whole window, so labels are set per session, not per sentence.
- Instances of one model are not independent, so agreement adds nothing. Diversity comes from a script, a different input, or a different model (F3).
- Hand-written seeds may be easier to catch than real faults. The operators copy the failure classes seen so far, and the checker's disagreement with the script on the decidable part is tracked.
- Hooks in a folder could be edited, so the detective layer backs the preventive one.

## D. File formats (JSONL unless noted; each carries `schema_v`)
- `fields/<n>/cards.jsonl` (child): card_id, question_id, url, primary_id, source_kind enum, quote (≤15 words), number, unit, baseline, conditions {task, model_family, repo_size, language, metric}, conditions_note (≤40 words), what_measured (≤40 words). It has no status field.
- `store/snapshots/<sha256>` raw bytes, plus `.json` {url, final_url, http_status, content_type, fetched_at, text_sha256, extractor_v}.
- `status/<n>/card_status.jsonl` (promote.mjs only, append-only): seq, card_id, card_sha256, snapshot_sha256, offset, status, reason, check_ref, ts. The last line per card is its current status.
- `queue/<batch>/item-<id>.json`; `sealed/<batch>.key.json` {item_id: operator or null}.
- `fields/<n>/review/review.json`: sentences [{sentence_id, approach_id, measure, kind fact/judgment, text, cites [{card_id, pack_hash}], applies_to {...}}].
- `status/<n>/certificate.json`: review_sha256, pack_hash, manifest_sha256, coverage, session_label, sprt, plants {k, found, contra_found}, result, reasons, ledger_seq.
- `ledger/ledger.jsonl`: seq, ts, script, script_sha256, kind, subject, data, prev, hash.
- `tcb/tcb.lock.json` {commit, files {path: sha256}, owner_approval_ref}; `tcb/profiles/<role>.json` {tools, read_prefixes, write_prefixes, agent_types, url_allow_source, bash_allow}; `review-in/<n>/manifest.json` {inputs [{path, sha256}]}.
