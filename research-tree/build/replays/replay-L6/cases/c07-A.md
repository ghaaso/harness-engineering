# S06 races, lock-removal experiments and fault injection

Date: 4 November 2026, on this machine with the worktree's PostgreSQL 17 database (Compose, port 55439). This is timing and outcome evidence from local runs only. It says nothing about production load or about interleavings the tests did not try.

## Races (`src/clinic/finance/tests/test_supplier_races.py`)

Each race commits on two connections through the S02 harness (`committed_db`). The first call holds its transaction open. While the second call waits, a third connection reads which row it is queued for (the S03 root-gate pattern). The two calls are always of different document types, so a shared number counter cannot be what serializes them (D02-32).

| Race | Commands | Lock named | Asserted outcome |
| --- | --- | --- | --- |
| 1 | Supplier payment SPY (500 to an invoice of 600) against credit application CAP (200 to the same invoice) | The invoice's obligation row, FOR UPDATE in `ledger.lock_allocation_plan` and `ledger.allocate` | The payment posts; the application gets ALLOCATION_EXCEEDS_DUE; 100 remains due; no application row; the second waited on `clinic_finance_obligation` |
| 2 | Credit application CAP (200 of a credit of 300) against supplier refund SRF (200 of the same credit) | The credit's settlement row, FOR UPDATE in `ledger.lock_allocation_plan` | The application posts; the refund gets ALLOCATION_EXCEEDS_DUE; 100 stays unapplied; no refund row; waited on `clinic_finance_settlement` |
| 3 | Credit SCR linking 2 returned units as it posts, against settlement link RSL of another credit for the same 2 units | The supplier row, FOR UPDATE in `post_credit`, `link_settlement` and the link trigger | One link; nothing pending; the second gets INVALID_VALUE; waited on `clinic_purchasing_supplier` |
| 4 | Generic reversal REV of a credit, against settlement link RSL of that credit | The credit's posted document, FOR UPDATE in the reversal and FOR SHARE in `add_link` and the link trigger (review R1) | The reversal posts; the link gets INVALID_VALUE; no link; 2 still pending; waited on `clinic_operations_posteddocument` |

## Lock-removal experiments

Each experiment removed the named lock in a working copy and ran its race. The files were then restored byte for byte, checked by MD5 before and after; the script is outside the repository. Output, abridged:

| Experiment | Lock removed | Result |
| --- | --- | --- |
| E1 | Obligation FOR UPDATE in `lock_allocation_plan` and `allocate` (S02 ledger) | Race 1 fails. The second was not refused by the service. The S02 deferred trigger `clinic_allocation_deferred` refused it at commit: "obligation … would be allocated 700 of 600". So the row lock gives the documented answer, and the database backstop still prevents over-allocation without it |
| E2 | Settlement FOR UPDATE in `lock_allocation_plan` and `allocate` | Race 2 fails the same way. `clinic_allocation_deferred` refused at commit: "settlement … would allocate 400 of 300" |
| E3a | Supplier FOR UPDATE in `link_settlement` and `post_credit` only | Race 3 fails. The link trigger, which takes the supplier row itself, refused the second: "settlement links exceed the returned quantity". The service lock gives the documented answer; the trigger is the backstop |
| E3b | E3a, plus the supplier lock in the link trigger (finance 0016) | Race 3 fails. Both links committed and the return was over-settled; the second was not blocked. The supplier row is what decides |
| E4 | FOR SHARE on the documents in `add_link`, and in the link trigger (finance 0018) | Race 4 fails. The link committed on the reversed credit: the second was blocked on the dependency insert and then succeeded. This reproduces review R1 and shows the share lock fixes it |

## Fault injection and closed periods (`src/clinic/finance/tests/test_supplier_faults.py`)

The ten commands covered are:
- supplier invoice;
- opening;
- credit (with an allocation and a return link);
- payment (an allocation plus an advance);
- advance application;
- credit application;
- refund;
- return dispatch;
- return settlement link;
- generic reversal of a supplier payment.

The checkpoints of each command come from one recording run inside a rolled-back transaction, so the list cannot drift from the code. Then:
- A fault at each checkpoint leaves every counted table unchanged. The counted tables are the documents, journals and lines, obligations, settlements, allocations, payments, invoice matches, cost revisions, credits, applications, refunds, returns and their lines, links, stock movements, layers and layer allocations, operation records, number counters, posted invoices and openings, and successful audit events.
- The key stays free, and the same command then posts once.
- With today closed (closed from tomorrow's clock), every one of the ten commands is refused with PERIOD_CLOSED and nothing is written.

20 tests, all passing; see the check summary for the run.
