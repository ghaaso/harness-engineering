**Review findings and handling:**
- **Fixed, high:** a correction could be posted on top of a version that a concurrent reversal had just undone. The correction now locks that version's document and refuses (VERSION_CONFLICT), and migration `0008` refuses the same in the database. Race tests cover both orders.
- **Fixed, high:** anyone with the reversal permission could reverse a document of their own pay. A check now refuses it through a new hook in `operations/reversal.py`. Migration `0009` adds a trigger on reversal rows of `clinic_operations_posteddocument`, plus a database check against preparing your own pay record.
- **Fixed, medium:** single payment rows (number, date, amount) are now shown only to `cash.full` holders. A `payroll.read` holder still sees each accrual's paid total.
- **Fixed, low:** a malformed number in a form gave a 500 error. The new test also found that any refused "remove line" gave a 500; both now come back as an ordinary refused form.
- **Recorded, not fixed:** a reversed accrual cannot be accrued again for the same period. Some links between pay rows and the ledger are not checked in the database. A payment and a reversal can deadlock; the losing command is retried.
