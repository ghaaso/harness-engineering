Checked against the learning material

After the graph was drawn I read both learning files again in full, with the graph beside them, and checked every option against the exact words of the entry it names. All twelve choices stand. The check changed these things:

  • Two references were only analogies and are replaced by entries that say it directly (why not the most popular repositories; why collect everything).
  • One reference was indirect (code structure) and is replaced by the entries on reach and on adding links to a graph that lacks them.
  • Two reasons are now marked as extensions of an entry, not as its words (a subset of files chosen by kind; a file drawn once per change).
  • One requirement was added to the tests: when one right file is scored, the other right files of the same change are never counted against it. The material ranks a true link only against links that are not real.
  • The graph the models read now also rests on the entries that say the graph is an input built from the repository alone and that identities cannot carry over.

How an option is ruled out

Not by weighing arguments against each other. One entry of the learning files that says "this cannot" is enough to rule an option out, and it is named on the option. A chosen option has to rest on entries; where the material is silent the option says "assumption".

What going through every entry added

The first draft was written in one pass. Checking every data-side entry of the learning files against every decision, including entries the draft never used, added four things.

  • A new decision, D12. A commit is how work was recorded, not the work itself. Where a host records pull requests, the files of the whole pull request are kept as a second answer set.
  • How the sample is drawn (D4). Random draws need a stated list to draw from, and every list leaves something out. Crawling outward from known repositories is ruled out: it over-samples the well connected.
  • Files the parser cannot read (D5). They are flagged and kept, never dropped. Dropping incomplete rows shrinks the data fast, and what is missing is not missing at random: it depends on the language.
  • Keeping every kind of file (D3). Keeping only code files is a sample of the file graph, and such a sample biases every count.
