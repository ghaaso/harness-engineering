# W7 departures (FX-W7; branch u/W7)

Design places: `model/as-built/FIX-wake.md` FX-W7 (FW:362-387), `FIX-JOIN.md` points 11 and 2c,
`build/branches.md` (RL-no, L1, LR-4 (b)). Tests named are on u/W7 (lane label W7-lib-watch).

1. **The dropped copy keeps its `intake` record.** FW:371-372 drops the whole copy on a busy tick.
   An intake the copy spawned (evaluate step i) is a running process; dropping its record would
   spawn another intake at every busy tick while the run lock stays busy. Not tested (the watch tests
   run with `--no-intake`).
2. **`--once` on a busy run lock exits 75 `lock-busy`** (after the busy tick is counted). FW:373
   names exit 75 only for a lost watcher.lock, which is about the loop; `--once` has no next tick.
   Test W7b.
3. **A dropped start evaluation is made again, still uncounted** (R6: a new watcher's first kept
   evaluation counts no tick). Test W7b (`ticks_total` 0 after busy ticks).
4. **`breakStep(c, doBreak)`** replaces the skeleton's `breakStep(name, doBreak)` (FX-W7's own
   step): it needs the root, the judged bytes and the caller's lock options. `watcher.json` is read
   right before the holder is judged. A `watcher.json` changed under the run lock returns `progress`:
   the verdict is dropped and the sightings start again, so the waiter neither spins nor breaks. The
   run lock inside the break uses the caller's `retries`/`retryMs`; busy ends in `lock-busy` 75. No
   ledger line for a watcher.lock break (CONTRACT 4.4 keeps `lock-break` for run.lock). Test W7a.
5. **Quarantine (step 3) as built here.** Revision 2's text is not in the record (FW:375 points to
   it; REFUTE-wake A7.5 says only "counters restart, spends re-parse from byte 0"). Built: an
   unparseable `watcher.json` is renamed as found to `watcher.json.<pid>.<nonce8>.corrupt`, named in
   `result.quarantined`; no ledger line. The existing test T17's first half (exit 67) now expects
   the quarantine; its `tasks.json` half is unchanged. Test T17.
6. **Busy count.** Read from `run/watcher-busy.json` when a watcher starts and continued across
   watchers and ce (the run lock is per root); unreadable counts 0; a held tick writes 0 only when
   the count is not 0.
7. **The short try** is `ceil(watcher_lock_try_ms / 100)` retries of the library's 100 ms (+-50 %)
   wait (S0.5 departure 5). At 5000 that is 50 retries, so a dead run-lock holder is still judged
   (LOCK_JUDGE_AFTER 50) and broken inside the try, and an unreadable run.lock meets LR-4's 50-retry
   budget after about 5 s instead of about 30 s (the rule counts retries; kept, branches.md row 12).
8. **Test data:** `tcb/fixtures/watch/_testdata.json` gains `watcher_lock_try_ms` (5000), which the
   watcher reads strictly (`param-missing` otherwise), placed after `lock_retries`.
9. **Kept, per branches.md:** L1 (a holder of unknown liveness is never broken; no
   `watcher_lease_ticks`), RL-no (no `run_lock_lease_ms`), LR-4 (b) (the unreadable-lock break does
   not pass `breakStep` and takes no run lock: thin item 4).
