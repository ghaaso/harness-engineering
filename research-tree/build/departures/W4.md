# W4 (FX-W4, the dead-man): departures from the design

Branch `u/W4`, final commit 439a50c6. Tests named are in `research-tree/tcb/test/status.test.mjs`.

1. **`deadman-nowake` by effect, not by reading the task's settings.** FIX-wake FX-W4 step 1 says the status view
   flags an install without wake-to-run. Reading the install needs a Task Scheduler query, which nobody here may
   make (tests included). The status view judges the effect instead: no record (`no-run`), an unreadable one, one
   older than 3 periods (`stale`), or a gap of more than 2 periods between two runs of one boot (`gap`). The same
   effect also covers wake timers switched off in the power plan, and a missing task (B4.3: `no-run`, `stale`).
   Cost: an install without wake shows at its first sleep, not at install. Test: "FX-W4 status view".
2. **"The list answers" read as "the verdict is known".** A run whose records are all absent, of another ce,
   corrupt or marked counts as `none` (+1) even with the list down. An `unknown` verdict leaves the count as it
   was: a reset would let a flapping list hide a dead alarm. Tests: "FX-W4 dead-man, the list answering" (the list
   down: counts unchanged), "FX-W4 dead-man, the list down".
3. **`unarmed-records` counts only records of the current `turn_seq`.** FIX-wake step 3 says "two unarmed records
   share a turn_seq". Taken literally, it never clears after a recovery, and the alert repeats forever. Records of
   another ce do not count either. Test: "FX-W4 dead-man, the list down" (turn_seq 8, one record of ce 1 and one
   of ce 2: no alert).
4. **`runs_no_alarm` and `runs_no_watcher` restart at a new ce.** They count from the successor's first run.
   `list_hist`, `alerted`, `stuck` and `busy_ticks` carry over. Test: "FX-W4 dead-man, the list answering" (ce 2:
   1 and 1, no alert).
5. **Error exits are not paced.** Exits 2, 66, 67 and 70 are toasted at every run. A broken dead-man is loud.
   Exit 70 covers node not starting. Test: the task file's command (`if ($x -ne 0)`, `$null` to 70), "FX-W4
   status view".
6. **The `run/deadman.json` format extends S0.5's.** S0.5 had `{runs_no_alarm, runs_no_watcher, list_hist[5],
   alerted:{cause, runs}}`. The built format is `{schema_version, ce, runs, at, boot, runs_no_alarm,
   runs_no_watcher, list_hist, alerted: {cause: runs since its last alert}, gap}` (CONTRACT §3.9 [deadman];
   `lib.RUNTIME_FILES` entry updated, its own FX-W4 line). `stuck` is one cause, not one per ident. Rev 5 N1's
   re-alert replaces the join's "once per onset" (R6-d, J point 1.4): every `realert_runs` runs (P1: 6), and a
   cause absent for one run is dropped. Tests: "FX-W4 dead-man re-alert (rev 5 N1, P1)" and S2.1's test, adapted.
7. **Residue: the coordinator may run the dead-man.** The hook's `EXEC_FORMS.status` (W1) admits `status --deadman
   --root` for the coordinator. A coordinator run counts toward the pace, and its alert reaches no owner. The
   coordinator brief 0c says never run it. The hook is unchanged.
8. **A shared line: CONTRACT §2.1's first sentence** ("Every write below `run/` ... happens under `run/run.lock`")
   now names two exceptions, each rewritten without the lock by its one writer: `run/deadman.json` (FX-W4) and W7's
   `run/watcher-busy.json` (§3.10 already said so). The sentence was false for W7's file before. A row for
   `run/deadman.json` is added to the table. There is still no row for `watcher-busy.json`: that row is W7's.
9. **The parameters.** `realert_runs` and `busy_alert_ticks` are read from `thresholds.json`, with the design's 6
   and 10 when a key is missing or invalid. The other values are constants in `status.mjs` `DM` (2 runs, a window
   of 5 with 3 failures, 3 unarmed turns, 2 records, the 5-min period, the 30 s list). The status test fixture
   gained both keys. Tests: "FX-W4 dead-man, the list down" (`busy_alert_ticks` 5) and the re-alert test
   (`realert_runs` 2).
10. **The task file is unverified on a real install.** `tcb/settings/deadman-task.xml` is never registered (B1-4).
    Not checked: the import, whether the toast reaches the owner, and whether a console flashes at each run. The
    test only checks the settings as text and that the command parses as PowerShell, without running it.
