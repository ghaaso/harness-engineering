# W1 (FX-W1): departures from the design

Branch `u/W1`, final commit 9089fa97 (entries 1-11 written at 2aff1708, 12-13 at e9f6482b). Design: `model/as-built/FIX-wake.md` FX-W1 (rev 4), FIX-JOIN point 6 and
part 3 R6-b, R29; branches L1 and U3-F8 (a) (`build/branches.md`). Each entry: what, why, which test shows it.

1. **Shared stubs line.** `tcb/test/lib.test.mjs:3090`, the skeleton test's shared `const stubs` line, drops
   `liveness: 3` (liveness is built, so it no longer throws `not-built`). Why: the S0.5 skeleton test asserts the
   stubs still throw. Test: lib.test.mjs "S0.5 round-3 skeleton" and "FX-W1 liveness" (both pass after the merge
   of `build` at 8269b551, which kept this removal; no conflict).
2. **Watch alarm form admits a bare `--alarm` and `--intake`.** `EXEC_FORMS.watch` allows `--alarm --root --ce`
   (the as-built M2 call, `spec/watch.mjs.md:13`) beside `--alarm --ensure --nonce`, until FX-W2 makes `--ensure`
   required; and `--intake --root --ce` (spec line 19: the coordinator starts every mode). FIX-wake step 5 lists
   only the default watcher and the ensure form. Why: without them today's coordinator could not start its alarm
   or intake. Test: guard-hook.test.mjs T16 ("FX-W1 allow list", production cases).
3. **Ten refused seams, not eight.** `TEST_SEAM_FLAGS` adds `--rng-seed` and `--transcripts-root` to the eight of
   step 5, because the specs label them test seams too. Test: T16 (every seam, every script, both spellings).
4. **CONTRACT §1.2 gets the test-seam sentence only.** Branch L1 leaves §1.2 without the lease sentence (R5
   unchanged); BUILD-PLAN's "CONTRACT 1.2" for W1 is read as the one sentence that the coordinator's hook refuses
   the seams (FX-W1 step 5). No test (text).
5. **U3-F8 (a) lines in CGATE's files.** `tcb/profiles/coordinator.json` `agent_types: ["checker"]`,
   `tcb/settings/coordinator.json` drops `Agent(mapper)`, `spec/guard-hook.mjs.md` coordinator row, and
   guard-hook.test.mjs (the "coordinator Agent mapper" case expects `agent-type`; COORD `agent_types:
   ['checker']`, near :500 and :964). Why: the root assigned U3-F8 to W1; CGATE's hunks in both JSON files are 2+
   lines away (checked). R55 in the protocol is not changed: no slice-1 unit writes the protocol. Test:
   guard-hook.test.mjs T6, T14 (21 tests: 18 pass, 3 skipped, run from `hx-W1` at a78deee2).
6. **`armAtStart` changed (D1 at S:596)** though FX-W2 removes it later: an unknown alarm (list unavailable)
   asks nothing; only a dead one gives `alarm-missing`. Why: step 3's rule that unknown is never dead holds for
   every reader until FX-W2 lands. Test: status.test.mjs "FX-W1 reconcile with the list unavailable".
7. **`unarmed-*` records of an older ce are not removed** by the prune (FIX-JOIN point 6 says they "may go").
   Why: FX-W4 reads them and owns their life; removing them is optional. Test: status.test.mjs "FX-W1 reconcile
   prunes" (`unarmed-*` stays).
8. **Status reads the wake records before the process list.** In the build the records are read (`readWake`)
   before `gatherFacts` takes the list and judged after it (`judgeWake`); in endturn the list query moved below
   the record reads. Why: a record written after the list was taken would name a live process the list does not
   show, i.e. a false dead (the "record written after r1" case). Inside the hold the verdict counts only while
   the record's bytes are unchanged (changed bytes: unknown). Tests: status.test.mjs FX-W1 (4 tests), T4, T10,
   T11, M2.
9. **CONTRACT §1.4's 67 row amended** (a shared line, outside the round-3 row): status reads `watcher.json` and
   `alarm.json` loosely, a corrupt one is the anomaly `state-corrupt` and a dead source, not 67 (FX-W1 step 4).
   Why: otherwise the row contradicts the built behaviour. The round-3 row itself was left as S0.5 wrote it.
   Test: status.test.mjs "FX-W1 a corrupt watcher.json or alarm.json".
10. **R6-b placed under decision 41** (whose heading names FX-W2, FX-W3, FX-W4) as its own FX-W1 paragraph, as
    the root's list asked; the sentence is FIX-JOIN line 382 nearly verbatim, with "status --endturn" named.
    No test (text).
11. **The exit marker uses `lib.createExclusive` non-strict** (it makes `run/arm/`), and a failed create is one
    stderr line, never a changed exit code. FIX-wake says "exclusively creates"; strictness is not stated. Why:
    the alarm's exit code is the wake; a marker failure must not change it. Test: watch.test.mjs "FX-W1 alarm".
12. **Place 0a of the coordinator brief is in the builder's words** (`tcb/briefs/coordinator.md`, e9f6482b).
    FX-W1 step 2 and FIX-JOIN 2b row 0 give the facts, not the brief's text. The wording names the error exits
    as 67 and 70 where step 2 says "any error exit after registration"; names the prune as reconcile's (FIX-JOIN
    point 6) without step 2's condition that no slot record names the marker (the coordinator never prunes);
    and adds two instructions the design implies but does not state for the brief: never write, move or delete
    under `run/arm/` (the marker is the alarm's own exclusive create), and on unknown start nothing (FIX-JOIN
    2b row 9 starts a source only on endturn exit 1). Why: the brief tells the coordinator what it sees and may
    do. Place 4 is left to W3. No test (text); watch.test.mjs "FX-W1 alarm" covers markers on 30, 0, 64 and 67,
    not 70.
13. **The e2e stands in for the hook's bind step** (`e2e/run-e2e.mjs`, e9f6482b). Before `handover bind --nonce
    <X>` the script itself writes `run/coord-session-2.json` {session_id: COORD2_SID}, the file FIX-fence part 3
    step 2 (FX-CGATE `stepBind`) has the coordinator's PreToolUse hook strict-create. Why: the e2e runs the
    scripts with no app and so no hook, and `handover bind` takes the session from that file (it refuses
    `--session`, 66). The stand-in is a plain write, not the hook's strict create, so the e2e does not exercise
    `bound-elsewhere` or the earlier-ce rule (guard-hook G1 does). The nonce is read from the raise's brief line
    (`--nonce <32 hex>`), as the successor would. Test: the e2e step "handover bind (successor session)"
    (coord.json names COORD2_SID, `successor_nonce` cleared); not run by W1's helpers (the root runs the e2e).
