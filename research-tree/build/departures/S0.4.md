# S0.4 (0b): departures and choices the design left open

Design: `model/as-built/FIX-fence.md` section 0b; `notes/r3-changes.md` lines 91-92, 125, 154, 221, 265.

1. Exit codes the design does not give: `no-parent` 2 (`not-run`: a precondition is absent), `budget-spent` 2,
   `bad-budget` 70 (a budget that is not a number). `no-hardlink` 3 as the design says. Test: lib T22b, T22c.
2. The budget also covers the temp create, the byte compare after EEXIST (`readBytes`) and a check before the
   link: a create whose budget is spent before its link makes nothing. The temp's removal is tried once even then.
   Test: lib T22b (budget 0, budget 150 with EPERM), guard-hook T15.
3. "Measured from the hook's start": as a process, `performance.now()` (time since the process began) against
   `hook_deadline_ms`; in-process (tests) a call counts from its own start to 5000. The fallback timer is unchanged
   (still set when main() has read the threshold). Test: guard-hook T15 (in-process only; no step writes yet).
4. The hook's write is `hookCreate(io, file, data)` (exported as `hookWrite` for tests); `io` gains `create` and
   `budgetMs`. An existing name with other bytes is the result `different`, not a deny (the slot callers read the
   winner). No step calls it yet: FX-OUT, FX-CLAIM, FX-CGATE add the calls (B4).
5. selftest's check is its own probe (write, link, `nlink` 2 on both names, same `dev` and `ino`, bytes read
   back), as fact F-P12 measured, not a call of the strict create; it runs only in a full run (a dry run writes
   nothing, `--only` certifies nothing), makes no folder, and fails closed on any error. Test: selftest T1, T11
   (preloaded `fs.linkSync` failing EXDEV in `wt/`, ENOTSUP in `run/`; a missing `wt/`), T12, T13.
6. CONTRACT: besides decision 20, section 1.1 (the `--ce` exception) and section 4.3 (`createExclusive` options,
   `fsRetry` budget) were amended so the contract states the new signature.
7. Not done here: R13's sentence in the protocol document (S17:525) lies outside this unit's files.
