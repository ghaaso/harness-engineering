1. **"Continue" on the age cap is the coordinator's acknowledgement.** The design says the coordinator
   "lets the attempt continue (which re-arms the cap for another `attempt_max_ticks`) or stops it.
   FX-W5 raises it again, and its `stuck` path reaches the owner." No script gives the coordinator a
   "continue" act; the only answer the watcher can see is endturn's acknowledgement. So an age-cap
   event line at or below `acked_seq` re-arms the cap (`age_base = age_ticks`) and the condition clears.
   Consequence: FX-W5's re-raise and `stuck` path never reach an acknowledged age cap, so the owner hears
   of an imitating child only through the coordinator, once per `attempt_max_ticks`. Making both
   sentences hold needs a continue act (a new mechanism, not built). Test: "FX-W6 age cap".
2. **The count restarts on any new conversation record of the attempt, not only on a new call.** A
   per-operation deadline starts when its operation starts: without this, a tool result arriving after
   a long tool would put the following model call past `model_ticks` at once (a false hang). "Moved" =
   the transcript's `tail.n` grew, or it was re-parsed. The kind (and so the deadline) is the main
   transcript's; helpers only restart the count, as calls did. Test: "FX-W6 per-kind deadline".
