3. **Shards plus a rest run.** A file in `shards.cmds` runs as its shards and one more run with every shard pattern as
   `--test-skip-pattern`, so a test no shard names (one S0.4 or a later unit adds to selftest) still runs. The rest
   run's time is left out of T for the group call (unknown until it ran). L6.
4. **Section 13 row 6 for every failure in the call.** A file or shard that fails, or gets no result, in the group
   call runs once more by itself (its own lane call), also when the call held one file: pass then = flaky (`flaky` in

   fault. L2, L5, L7.
5. **Exit 75 retried by a wait budget**, not a fixed count: tries = max(2, ceil(300 / W)). W is 5 s when T is 140, so a
   fixed few tries would give up long before a slot held to the 150 s rule frees. `--wait-budget-s` sets it. L7.
6. **No result undoes the merge.** Lane 124, or 75 after the tries, is not a result; not a pass, so the merge is undone,
   the line says not-run, exit 5. A re-check with no result undoes nothing and writes an exit-5 line, which does not
   count as recording the merge, so the next landing checks it again. L7.
7. **A pass needs exit 0 and a TAP summary.** Found in the first test run: under an outer `node --test`,
   `NODE_TEST_CONTEXT` made the nested runs report nothing and exit 0, so every file "passed". land.mjs now removes
   that variable for its runs (L1, L2, L4-L7 depend on it), and exit 0 with no TAP summary counts as not-run (a guard;
   no test reaches it).
8. **The merge message carries the file list**: `Land-Unit` and `Land-Files` trailers. The re-check of a merge with no
   line runs those files, or the files given when it is the landed unit's own merge. A merge with no line and no
   `Land-Files` (one made by hand) is reported, exit 3, nothing changed; `node land.mjs <its unit> <its files>` checks
   it. A failing re-check is undone only when it is the tip, else left for `git revert -m 1` (exit 4). L4 (tip case).
9. **What records a merge**: a line whose `merge` (or `commit`) is the merge's hash or a prefix of at least 7 hex
   characters, with exit other than 5. The root's hand line for S0.6 must carry the merge hash under `merge`.
