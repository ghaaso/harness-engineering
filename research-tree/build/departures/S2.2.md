# Departures of S2.2 (the model as built): what of the code is not modelled, and why

S2.2, task r57-0507 slice 2, branch `u/S2.2`, 2026-11-20. The model is `research-tree/model/as-built/model-build.mjs`;
`MAP-build.md` maps every flag to its code lines and says where an oracle stays. This file lists what of the code on
`build` the model leaves out, and why. Each item names the test or run that shows the modelled part.

1. **FX-W3 and FX-W7 are in no model** (branches.md:82). The model has no unarmed-turn records, no `turn.json`
   counts, no run-lock busy count and no tick state kept only on a successful hold. On `build` they reach the owner
   only through the dead-man's causes `unarmed-turns`, `unarmed-records` and `run-lock-busy` (status.mjs:986-998).
   The model's dead-man counts no-alarm and list failures only (FX-W4, the step "status --deadman run" of model-build.mjs). So a
   liveness verdict of the wake group that needs those causes is not checked.
2. **The owner is a premise, not code.** Three owner steps stand for a person. He types to the coordinator when a
   start is due (PROC.OT, strongly fair; `--weak-owner` is the ablation, model-build.test.mjs "the owner typing is
   strongly fair"). He answers a close-missing with `closed`, and the coordinator's relay is merged with his act (fault
   w breaks the relay: IDGAP-W). In AGE-STUCK he answers the dead-man's `stuck` alert by ending the imitating session.
   His other answers (drop, resume, ruling) are not modelled.
3. **The lease act under reading (ii) is bounded.** FX_LEASE_NOBOUND at one field fills its memory before the state
   space ends (RUN-BUILD section 4). A "holds" there is "not refuted (bounded)". Two fields are not covered.
4. **Unrecorded facts are run both ways, never assumed.** Whether a refused start leaves `start.json`
   (BQ5_REFUSED_SJ: BQ5-SJ and BQ5-NOSJ). Whether `stop_session` only interrupts and `archive_session` waits for an
   approval (BLD_STOP_INTERRUPT_ONLY and BLD_ARCHIVE_APPROVAL: the `-B` runs and CLOSE-APPROVAL*). The pilot settles
   which value holds.
5. **W6 item 6 is modelled in its smallest form** (MAP-build section 3). The 240 counted ticks of `attempt_max_ticks`
   are one tick, and the re-arm is the next tick. Only an imitating child reaches the cap: the premise is that the cap
   is above any healthy attempt. idle-child is not modelled, and neither is a coordinator that answers the cap with an
   act (its brief has no line for it). FX-W5's intervals are untimed. The design leg (BLD_AGE_STUCK, AGE_STUCK = 2
   raises in place of the code's 6) is not code. It is the ablation that shows AgeCapReachesOwner can hold
   (model-build.test.mjs "W6 item 6").
6. **REDO is modelled at the reconcile's `started` line only.** The start death through the seam is left out
   (`replace start` writes the row and its admit line in one hold, replace.mjs:994-1007). So are the `admit` and
   `stop-request` lines, fsck and render. A status run that dies (fault g) leaves the turn nothing to act on, and the
   turn goes to endturn, as the built brief says for any failed call (coordinator.md:158-166), whatever
   FIX_ENDTURN_ALWAYS says (model-build.test.mjs "REDO").
7. **FXW-4R-B keeps the R57 id's flags without N2.** FN-N2-B is that configuration with N2, as built (branches row 11).
   The model's turn-start path without FX-W2 still ends the turn on a 75, which is FIX-JOIN 2b row 8's reading, not the
   brief's. No configuration with N2 takes that path (MAP-build section 4).
8. **Sizes.** No configuration was run at full size here: each call stayed under 150 s. RUN-BUILD names what each
   reduced size leaves uncovered: the k=2 mixed parts of FN-OUT-CLOSE-K2-B that end BOUNDED, the lease at two fields,
   three faults with m, and g with the close group's cd, z and t at three faults.
