The answer

  1. The harness works for sessions started at the repo root. All four pieces (tier hook, record guard, start hook, commit check) cover them; the start text and a refused edit of archived evidence were seen live.
  2. What does not reach the build yet, and the one step for each. (a) Builders work in worktrees, and the record guard, start hook and commit check are uncommitted and do not reach a worktree: fix the guard and the pre-commit hook (P0), then commit them on your word. (b) The withdrawn "never above 3 children" still sits in 13 living files: the build's own units remove it (FX-CLAIM, S0.5). (c) The start documents (START-HERE, RULINGS, CLAUDE.md rule 5, memory lines) are stale: the top session updates them before the root starts. (d) Nested helpers run in the foreground, so no batch orchestrator: the root runs every batch; one probe before B1-1 can bring one back.
  3. The tree. One Fable root session that alone talks to you; below it only helpers (Opus builders and refuters, Sonnet readers and runners, Haiku extractors); B1-1 runs 3 builders at once.
  4. Cost. About 416 M tokens, 10.4 weekly points (6.7 to 16.6) through the model check, computed; wall time about 9 to 13 hours plus your turns estimate. It fits this week (16 points free after 20 protected), so nothing is paced.
  5. What you are asked. approve: commit the hook files, P0's fixes and the plan files (ORCHESTRATION.md, BUILD-PLAN.md); approve: the build's start with the nesting probe (an experiment, about 0.5 M tokens); cap: 15 weekly points for the build.
