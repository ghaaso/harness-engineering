## hang.mjs as built (S3's COORDINATOR.md reads these words)
One line, appended to `run/hang.log`: `hang <UTC>: <unit> <min>, <unit> <min>[; SILENT <unit> <min>][; RETURNED <unit>][; PAUSE <min>]`
("none running" when none). Exit 1 on SILENT or RETURNED, 0 otherwise (PAUSE alone 0), 2 on an unreadable config.

## Choices (where the item left a gap; the reading that keeps the run working unattended)
1. hang.mjs `<min>` = minutes since the newer of the unit's latest START slot and its last transcript write; SILENT iff
   that is over D (equivalent to "started more than D ago and none written for D").
2. hang.mjs PAUSE: with no line in `run/hang.log` yet (the first wake), `run/STATE.md`'s time stands in for the last
   line, so a suspend before the first timer wake gives no false SILENT (a false SILENT restarts a live unit).
3. hang.mjs RETURNED skips a done file whose first line says `FAILED by the coordinator` (the coordinator's own "given
   up" RETURN.md, COORDINATOR s8): else a given-up unit could be read as a return and restarted.
4. hang.mjs falls back to D = 20 if `hang_silent_min` is missing (detection kept working); the gate, by contrast, holds
   on a missing `starts_max` (as on every config number), so the restart guard cannot be silently lost.
5. Limit noted, not changed (WIDEN's rule as given): a missed notice is seen only until the coordinator next rewrites
   `run/STATE.md` for another event; after that the done file is older than STATE.md and RETURNED no longer fires.

Choices in item 1 (beyond S1's design above):
- PARTS.md is published whole: written to `work/.PARTS.md.<pid>.tmp` and hard-linked to the name (the link fails with
  EEXIST if PARTS.md exists: the repeat path); the exclusive flag `wx` where a link fails. A killed call can leave no
  half-written PARTS.md (an empty one would read as "no parts" to the coordinator's grep and end the field's parts).
  The temporary file sits in `work/`, which the map's commits leave out.
- A row of KEYS.md's exact form (6 cells, a rank, a key, an owner) after a blank line inside the table still counts
  (else its keys would be lost without a word); other tables below the table are not read.
- Header case and backticks ignored; owner case ignored (`F2` = `f2`); a repeated key adds `; repeated keys dropped <d>`
  to the line (so keys = parts + not covered + dropped).
- A missing or wrong `split` in run/config.json: `REFUSED f<n>m: run/config.json has no split...` (no built-in values:
  the gate holds on a broken config anyway). A missing folder `fields/<n>m-*`: `REFUSED f<n>m: no folder ...`.
