## Small items (not breaking; for the end list)

1. **Exit 1 can mean two things.**
   - A killed or crashed node process exits 1 on Windows (PC). That is also land.mjs's code for "tests failed, merge
     undone", yet in that case the merge stays in place unchecked and without a line.
   - The next landing heals this (PC). But a root that reads only the exit code would send the unit back for nothing.
   - Fix: read the line, or give a test failure a code that Node never uses.
2. **After exit 4 below the tip, nothing stops the next landing (PD).**
   - The exit-4 line counts as recording the merge (`recordedBy` accepts any exit other than 5).
   - BUILD-PLAN 3.5 leaves the revert to the root. Until the root reverts, landings stack on a merge known to fail,
     and only the next suite finds it again.
   - Fix: treat a line with exit 4 and `undone: false` as no record until a revert of that merge is on the branch.
3. **M23: only the order of two statements protects the crash window of a fail.**
   - If the line came before the undo, a crash between them would leave a failing merge that its own exit-1 line
     marks as recorded, so it would never be re-checked.
   - The order in the code is right. It needs a test, for example a kill between the two steps through an
     environment hook.
4. **Gaps to close first:**
   - M20, a skip only after a pass;
   - M06 and M07, a re-check with no result;
   - M23;
   - M29, a stale lock;
   - M15 and M16, T + W at most 145. A test can read T and W from the call spec that land.mjs writes in its logs
     folder.
   - The rest: M03, M10, M17, M27, M31, M33, M35, M36.
5. **The stale-lock break can let two breakers in.** It uses `rmSync` and then `mkdir`, as the lane does (P0-GATE item
   10). The design has one lander, so this is remote.
6. **What the key covers.**
   - It covers `research-tree/tcb`, `research-tree/tools` and the test file's own top folder at the commit.
   - Today's test files read only `tcb/` and `research-tree/tmp/` (grep of `tcb/test` and `tools`), so the key is
     complete for them.
   - Untracked files in the build worktree are not in the key, and the cleanliness check ignores them.
7. **Group size.** The group runs every member at once with no cap, and T is 1.5 x the slowest member's time alone.
   - If a large group (S0.5) times out, each unfinished member runs alone in its own lane call. The result stays
     right; it just takes longer.
   - The full-suite measurement (12 processes at once, shards about 70-80 s) suggests T = 106 is enough.
