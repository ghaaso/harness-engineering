## Why PASS

The code does what FX-W7 and the settled branches say, read line by line: the break of watcher.lock runs under
run.lock with both files compared to the judgement; unknown is never broken (L1); every append and the
`watcher.json` write sit in one hold after `assertHeld`; a busy hold drops the copy, writes neither file, counts a
busy tick and keeps the loop up; only watch.mjs takes watcher.lock and never inside a run-lock hold, so the new
lock order (watcher.lock, then run.lock) has no inverse; `watcher-busy.json` is `{ce, busy_ticks}` as in
`RUNTIME_FILES`, which FX-W4 reads; no `watcher_lease_ticks` (L1), no `run_lock_lease_ms` (RL-no), LR-4 (b) kept.
The surviving mutations are gaps in the tests, not wrong behaviour, so none is breaking.

## Findings (test gaps)

1. **M9: W7b's "not counted" checks no counted tick.** Its busy evaluations are the uncounted start evaluation, and
   `--once` exits after its busy tick, so `ticks_total` 0 holds whether or not a busy counted tick is adopted. This
   is schedule 18's own property (the hang count must not advance on a busy tick). A test that would catch it: a
   default-mode watcher with an active row has one held counted tick, then the run lock is held for several ticks
   and released. `ticks_total` and `hang_ticks` must not have moved by the busy ticks.
2. **M13, M14: no test loses watcher.lock while a watcher runs.** The holder's half of SingleWatcher (an
   `assertHeld` failure ends the tick, inside the hold before any append, or on a busy tick) is untested; only the
   breaker's half (W7a) is. A test: replace watcher.lock's record while the watcher is running and a class is
   present. Expected: exit 75, no event line from the old watcher, no `watcher-busy.json` write from it.
3. **M17: the short wait is untested.** No test holds the run lock for less than `watcher_lock_try_ms` and checks
   that the tick is kept, not dropped.
4. **M5: the re-judgement after `progress` is untested.** W7a's case 2 ends at its first `progress` (5 retries).
   With the mutation, a holder that wrote between the snapshot and the break and then died is never broken by that
   waiter (lock-busy 75, liveness only; the next start works).
