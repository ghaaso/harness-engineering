# C. What this PC and the app can carry (task r57-0517, part C)

Measured 2026-11-19 about 11:39 UTC (16:39 local). Marks: **measured** = I ran it now; **read** = from a file; **estimate** = with a range.

## Answer in 5 lines
1. The PC is not the limit: 24 threads, 31.1 GB, 14.3 GB free now with the coordinator's two suite runs and 13 sessions going; nothing in the build uses the GPU (grep found no file).
2. The width that binds is the lane: 2 slots (capacity.txt), hard maximum 4. Processor would allow about 20 single-threaded runs and memory about 20 (0.5 GB each above a 4 GB floor).
3. A session costs about 0.23 GB working set (13 session processes: 3.0 GB, range 0.16-0.60 GB); helpers live inside the session process and cannot be counted separately.
4. The lane's numbers misfit the work: default timeout 540 s is below the 596 s suite; the slot break at 20 min is below the 25 min timeout cap; waiters are not ordered; a command over 25 min cannot run in it.
5. The app limits that bind are not memory: a task-started session cannot start sessions, a foreground call over about 180 s is backgrounded, a program start can block for 25-63 min, the PC sleeps after 15 idle minutes.
