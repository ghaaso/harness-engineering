MECHANISMS:
- Fix-round contract (bounded, with rollback): 1. Each finding gets a reproduction test that fails on the pre-fix commit and passes after; the existing section 0 rule, applied to every P1/P2. 2. The full gate runs before the fix commit (all steps, mypy included; A3-13). If any previously passing test fails, revert the fix commit and retry once; never patch on patch. 3. The re-review is a FRESH refute reviewer, not the root. It is briefed with the fix diff since the verdict SHA, the prior findings list and the blast radius, and labels each finding old, fix-induced or independent. 4. At most two fix rounds. A third, or any fix that touches lines an earlier fix round changed (the pseudo-cycle sign), escalates: revert that fix family and redesign it with an Opus design note, or the owner carries it as a named risk. 5. Stop rule: an independent re-review of the whole fix diff finds no P1/P2 that was not already on the list, and every reproduction test is green. Each merge records 'final head reviewed by: X' (A2-08).
  COST: Brief and template text, about an hour. One full check per round (274-840 s on this PC, plus queue waits) and one fresh Opus reviewer per round, much as today. Rounds should fall.
  PROOF: Over the next five gated branches: fix-induced P1/P2 divided by P1/P2 fixed, against the baseline of at least 15/110 (at least 5/19 for P1). Also rounds per branch, and how many branches end root-only. Adopt if the fix-induced P1 count is zero and the overall rate falls below half the baseline.
- State-exit table for fixes that add a hold, lock, marker or status: Before re-review, any fix that adds state lists every way the state can end: post, abandon, reverse, owner or preparer absent, crash mid-write, rollback. Each exit gets one test. Recovery scripts get the full table of record state x marker x serving, with a drill per cell (A2-02, A2-03 transfer).
  COST: 30-60 minutes per such fix. Applies only to a minority of fixes.
  PROOF: Retrospective: apply the table to the cutoff-guards and S11 histories and check whether it demands the tests GD-01, RS-1, GV-01 and GV-02 needed (target 4 of 4). Forward: zero 'state never ends or is lost' findings in later rounds.
- Blast-radius report attached to every fix diff: A deterministic list made by script: functions and classes changed, their callers and importers (AST or grep), files co-changed with them in git log, and the test ids that touch them. The reviewer must clear each line. Run those tests first, then the full suite.
  COST: A script of about 100-200 lines, no install. It runs in seconds.
  PROOF: For each fix-induced finding in the trial: was its file in the report? Target at least 80% coverage. Compare the regression rate against the trial branches without the report.
THOUGHT STRUCTURES (narrow): Only best-of-N with an executable selector has coding evidence (Agentless, CodeMonkeys; B1 C6/C8). Its use on review-fix rounds is unmeasured (B1 C10), and it multiplies checks on a PC that already queues (B07) and tokens toward limits. At most, trial 2-3 candidate fixes chosen by the reproduction test plus the full suite, only for P1 fixes in stateful code. ToT, FoT and LLM-judge trees: no. Repeated LLM review invents defects (B3 C4).
GRAPH RECALL (narrow): Code-structure neighbourhood (callers, importers, co-change) is the blast-radius report. TDAD measured a 70% cut in regressions from it, on small models (B3 C3; B2 C6/C10). A plain script gives it; no graph store is needed. Temporal facts matter only through the knowledge store's 'do not apply' entries.
GAIN: Fewer P1s found late, and an honest stop. Baseline: at least 5 fix-induced P1s and at least 10 fix-induced P2s, 9 of 11 gates closing on a root-only read, and a build stopped by fiat. Expect most branches to pass in two rounds with an independent final read, and stateful fixes to stop producing 'never ends' or 'lost after rollback' P1s. The trial count decides it.
