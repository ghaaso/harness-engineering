BUILD RECS:
  - Q1 'what could break if I change this': directed reverse reachability (dependents) with an explicit depth cap, shown in tiers by hop, ranked by personalised PageRank seeded on the changed files. Do not return the undirected closure (measured: a quarter of the repo by hop 6, versus about 2 % for directed dependents). Keep a separate 'edited together before' list from co-change rather than mixing it into the dependency tier. Hop limit 2 with a visible count of what lies beyond; sweep 1 to 4.
  - Q1 edge types in expected order of value: import (test files as importers), test-to-source, route-to-client-call and same-named slice (the cross-runtime edges are the only way to see the 15 % of co-changed pairs that imports cannot reach), co-change, migration-to-model; docs-citing-file as a separate list because a stale doc is worse than none. Output per item: path, kind, hop, one-line signature of the linking symbol; path only for the long tail.
  - Q1 tests: select at file/class level with the project's own import and mock links; avoid method-level call-graph selection (less safe, less precise, slower than running everything in the measured study). For a hub changed file such as backend/app/core/db.py, report that it selects everything and fall back to the slice's tests. Learned weighting by failure and change history is the strongest published feature but needs test-outcome history.
  - Q2 'what do I need to read to do this task': lexical or symbol anchors from the task text, aligned to graph nodes, then personalised PageRank (restart 0.15 to 0.30) from the anchors over imports + calls + co-change edges, packed into the token budget by binary search on entry count (Aider design). Default expansion 1 hop; let the agent ask for a second expansion rather than widening the radius. Output: ranked paths, signature lines for the top few, path only for the rest, full source only for files the agent opens. No natural-language summaries of code.
  - Q3 'where is the thing that does X': symbol and lexical index first (the largest ablation effect in the literature is the search component), graph only to expand and rerank at 1 hop. Return fully qualified ids (path plus symbol) plus signature in the exact form the agent will use next; id form alone explained about half the structured gain in one study. Edges: defined-in, import, same-named slice, route string to handler.
  - Co-change edges: build from non-merge commits on main, drop change sets over 30 code files, track renames (git log --follow or -M) because the HEAD file set lost over half the co-change coverage, weight recent commits more, rebuild on each merge. Treat minimum support (1, 2, 3) and the tangled-commit filter as parameters.
  - Do not spend effort on hub damping, transitive reduction, dominators or community detection first: hub damping showed no gain here, no empirical study of reduction/dominators for impact sets was found, and the 12 slices are already declared. Leiden is worth a later test only where it disagrees with the declared slices.
  - Freshness: rebuild the file-level graph on demand (about 0.4 to 0.5 s here). Store a content hash per node only to validate a cached symbol-level layer, which is the part that will cost more.
TEST RECS:
  - Score both stores on the same ground truth and report value per token, not store size: (a) files co-changed in historical commits with a time split and a leak-free graph rebuilt at the split commit (the HEAD graph leaks the test commits' own new imports and overstated hop-1 precision 0.435 vs 0.315), (b) tests that fail on historical or injected changes, (c) files an agent actually opens and edits in real tasks.
  - Report precision and recall at fixed list sizes (5, 10, 20) and at fixed token budgets, with 95 % intervals that resample commits (queries inside a commit share truth). With 45 test commits the differences between PPR, co-change and the hybrid were inside the noise; use more history, or all-refs, or several time splits (rolling origin) before claiming a winner.
  - Include cheap non-graph baselines in every comparison: same directory, same slice name, grep plus names, most-imported files, random. In this repo same-directory (P 0.22 as a set) is not far behind a 1-hop import set (P 0.315).
  - Sweep these parameters: hop radius 1 to 4 and uncapped directed closure; direction (undirected, dependents-only, dependencies-only); ranking (BFS, PPR restart 0.10/0.15/0.30, degree-normalised, Aider-style multipliers); edge set (imports, +tests, +route-to-client, +co-change weight 0.5/1/3, +same-slice, +docs); history window (last 50, 100, all), recency decay, min support 1/2/3, change-set cap 15/30, rename tracking on/off, tangled filter on/off; token budget 500/1,000/2,000/4,000; output form (paths, path+signature, snippet, summary); Leiden prior on/off; rebuild vs hash-validated reuse.

Expect Python call recall around 70 % (PyCG).
