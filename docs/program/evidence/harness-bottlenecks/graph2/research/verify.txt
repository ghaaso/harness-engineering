  - Schema lane, '0 ambiguous URL matches': this is a code artifact. join.js matchUrl slices the candidates to one whenever preferServer is set, and it is always set.   - Schema lane demos (screen to tables, impact, tests reaching) use a graph built at HEAD. Used in a test, that leaks future structure. The protocol's build-at-parent rule fixes this only if it is enforced for the graph build too.
  - Schema lane test-node filter: join.js isTest = /test|\.test\.|conftest/ on node ids. Any production symbol whose id contains 'test' (for example 'latest') is silently dropped as a test. This is not quantified.
  - Scoring lane is mostly neutral and reproducible: every pool number and baseline came out the same in an independent re-implementation. Its ground truth leans toward co-change and against the graph. The labels are changed files only, the seed is a changed file rather than an issue text, and CO is trained on the same signal as the label.
  - Against plain search and hybrid: T1 has no textual query (the commit message is excluded), so BM25 and grep have nothing to search but the seed file's own content. A hybrid arm cannot show the text-search value the lane itself cites from LocAgent (-18 points without SearchEntity). DIR is a stand-in for 'browse nearby', not a real grep or BM25 baseline. A fair plain-search arm would use seed identifiers or route strings as queries.
  - Against the graph on hops: the proposed tune sweep is hops 1-5. Cross-runtime questions measured at 7-9 hops (screen to tables), or 8 (service to mobile screen), fall outside that range unless metapath budgets per edge type are swept. Under a 10-file or 8k budget, unranked BFS floods: the median neighbourhood is 77 files at 3 hops. So the graph's result depends on ranking (PPR, degree normalisation, co-change weight), and the protocol must tune that as hard as the CO table.
  - Against the relational store: the scoring lane's tuning-parity rule is sound (same facts, same number of configurations, idiomatic indexes). The risk is the reverse: algorithms such as PPR or metapath search may be implemented natively in the graph arm, while the SQL arm gets a literal recursive-CTE port without equivalent effort. Arm-(d) output equivalence on the tune split guards against this and should be mandatory.
  - Statistical power cuts both ways: with 75 held-out commits and SD about 0.29, the MDE is about 0.094. An 'inconclusive' verdict is likely, and it should not be reported as 'graph does not help'.
