BUILD RECS:
  - Build the graph deterministically with parsers (tree-sitter for Python, JS/JSX, TS; Python ast or Jedi-class resolution and the TypeScript compiler API already in technician-app/node_modules/typescript for call resolution). Evidence: parser graphs beat LLM graphs on cost and coverage; all positive localisation systems except CoSIL use AST extraction.
  - Use few typed edges with a confidence value on each: contains, imports, calls, inherits, tests, documents (doc cites file or symbol), plus repo-specific HTTP edges (client URL literal -> route decorator) and a same-name-slice link across runtimes. Typed and confidence-weighted edges and source-to-test/doc edges have ablation support (LARGER); cross-runtime edges have no measured support, only shipped tools (Codebase-Memory HTTP_CALLS), so build them as a separately switchable edge class.
  - Make the entry point lexical: BM25/FTS over symbol names, paths, docstrings and doc text picks seeds. LocAgent ablation: removing SearchEntity costs 19 points file Acc@5, removing TraverseGraph about 2. Add exact-name resolution (find_entity style) as the first tool.
  - Expand 1 hop by default, up to 2 only through a ranked, capped result; rank the neighbourhood with personalised PageRank or random walk with restart (Aider, 2611.07286); cap output in tokens (Aider 1,024 up to 8x; ARISE 8,000; small-agent tool 50 edges); return paths, signatures, line ranges and relation lines, not source bodies; favour precision over recall (Cognition).
  - Expose it as a few on-demand tools beside grep and read, not as a standing prompt overview (2611.07286 mounts tools beside native ones; AGENTS.md study: overviews gave no success gain and over 20 % more cost).
  - Update incrementally by per-file hash or mtime (Aider, Codebase-Memory about 1.2 s). At 477 code files a full rebuild is seconds, so caching is about freshness.
  - Store in the simplest in-process form (SQLite + recursive CTE, or an in-memory graph library). The literature gives no support for a graph database server at this size, and none against either; keep the engine swappable so the test can vary it.
  - Target localisation and impact analysis (which files, tests, callers), not the edit step (SeeRepo repair -5.0, validation -3.4 pts).
  - Do NOT use: LLM-written Cypher, LLM-extracted graphs, raw 2-hop dumps, statement-level data-flow graphs, image-rendered graphs, trained graph models (CGM, GNN).
TEST RECS:
  - Separate the engine from the structure: store identical edges and run the identical ranking and hop logic in a relational table (recursive CTEs) and in a graph structure; then vary content, ranking, hops, cap and return format independently. No paper does this.
  - Score the answer and its value, not the store size: gold-location recall@k and precision against files a fix commit actually changed (Loc-Bench-style, from the repo's own history: 72 fix commits, 368 on main), tokens returned, steps to first correct file, and downstream task success; report per-hop-distance strata (small-agent study method) because averages hide the hop-0/1 vs hop-2+ split.
  - Baselines: grep+read only; BM25 symbol search; an Aider-style ranked map at 1k and 8k tokens; graph with 0, 1, 2, 3 hops each with and without ranking and with and without a token cap; add HTTP/test/doc edge classes one at a time.
  - Hold model and agent harness constant across arms (LARGER and Augment comparisons change backbones; those are not usable as a pattern). Use the model the owner actually runs.
  - Repeat each condition several times; treat differences under about 3 to 5 points as noise at 100-300 task scale (small-agent study; Augment states 1.1 pts is run variance; most 2026 papers use one run).
  - Include task types where localisation is not the bottleneck (editing, test writing) to see the null or negative cases (2611.07286 SWT-bench tokens up; SeeRepo repair -5.0).
  - Count build, update and tool-description tokens in the cost (2611.07286 omits map-construction cost; Codebase-Memory excludes indexing).
OPEN:
  - Does a cross-runtime HTTP edge (client URL literal to route decorator, about 73 literals vs 77 routes here) reduce steps or raise localisation on tasks that span web/mobile and backend? Tools ship it; no paper measures it.
  - At roughly 500 code files, where is the break-even between grep-plus-read and any index? Only Cursor gives a size-stratified signal (+0.3 % overall, +2.6 % at 1,000+ files).
  - Is the engine (graph database vs relational) ever the variable that matters once content, ranking and output format are fixed? No source tests it.
  - Does ranked 2-3 hop closure computed by the tool beat leaving chaining to the model? The small-agent paper suggests it but did not test it; no hop sweep beyond 2 with ranking exists.
  - Do tool-returned graph results help frontier models on accuracy at all, or only on tokens? Existing frontier-model evidence (2611.07286, SeeRepo, Augment) shows tokens down and success about flat.
  - How much does steering (a hook forcing one map query, a short skill file) contribute versus the graph itself? 2611.07286 and TDAD (107 to 20 line skill file moved resolution 12 to 50 % on 10 tasks) both confound them.

FINDINGS:
  * [neither/high] Aider's repo map: file-level graph, personalised PageRank, token-budgeted output; no published ablation of the map :: Nodes = files; edge referencer->definer per identifier that is both defined and referenced (multigraph, self-edge 0.1 for unreferenced defs). Tree-sitter tags cached per file by mtime. Edge weight = multiplier*sqrt(ref count); multipliers: identifier mentioned in chat x10, long snake/camel/kebab name (8+ chars) x10, leading underscore x0.1, more than 5 definers x0.1, referencing file in chat x50. Personalisation on chat files and files whose names match mentioned identifiers. Output = paths + ranked definition lines (signatures), binary-searched to a token budget (default 1,024; up to 8x when no files in chat, capped by context window minus 4,096). No hop limit (global PageRank). The 2023 bl (aider.chat/2023/10/22/repomap.html; raw aider/repomap.py (main); aider.chat/2024/05/22/swe-bench-lite.html)
