FINDINGS:
  * [graph/high] Client-to-route HTTP edges extract exactly. All 75 production URL literal sites (mobile and web) match a backend or ops-server route by method and path. All 380 backend test HTTP calls match too. :: Done with the TypeScript 5.3.3 compiler API from technician-app plus the Python ast module. A ${...} placeholder after a slash becomes {}; other placeholders and ?... are treated as the query and dropped. The HTTP method comes from the options {method} or the apiSend second argument. When two routes match, the one with more literal segments wins. Result: 0 ambiguous matches and 4 non-literal wrapper calls; the wrapper's inner literal is still captured. 53 of 77 backend routes have a client; 24 have none (ledger, advances, shop settings, webhooks, health, ops). 73 routes are exercised over HTTP by pytest. These edges are invisible to an import graph and to plain grep. (measured: ts_extract.js, py_extract.py, join.js in the lane folder)
  * [graph/high] Python function-level calls resolve at about 98.5% recall for in-repo targets using stdlib ast and lightweight type rules. Precision was 25 of 25 in a sample. :: 8,335 call sites. 2,377 resolve to in-repo definitions (2,085 distinct edges), 3,786 are external, 2,034 name no repo definition. Only 36 sites whose name matches a repo definition stay unresolved: callbacks (dead_letter, handler, on_orphan), module singletons (metrics_registry), chained constructors and local closures. Typing rules that made the difference:
- imports and re-exports
- self methods, including base classes
- __init__ attribute types
- Annotated[...] dependency aliases followed across modules
- pytest fixture return types, including tuple[JobService, MagicMock] unpacking: fixed 256 test calls (680 unresolved before)
- closure scope: fixed build_dispatch_handler.handle -> JobSer (measured: py_extract.py, py_stats.txt, precision_sample.txt)
  * [graph/high] TypeScript and JavaScript calls resolve through the compiler's type checker with 20 of 20 precision in a sample. The remaining dynamic calls are React context and prop callbacks. :: 2,358 resolved in-repo call sites; 1,259 are production code, giving 946 distinct production pairs (mobile 814 sites, web 445). Unresolved production calls are mostly built-ins on untyped JS values (web 231). Unresolved test calls are jest globals (2,229), because @types/jest is not in the program.
