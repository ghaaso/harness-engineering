# Protocol addendum 1: the environment (2026-11-12, after the owner's instruction to run Linux rather than accept a handicap)

This does not change what is tested or how it is scored. It fixes where the arms run.

- **One environment for every arm.** All arms (search, relational, in-memory reference, both graph engines) are run, and all engine measures are taken, inside one Linux image, `graphtest:1`, built from `engines-linux/Dockerfile` on Docker Desktop (WSL2 kernel, 24 CPUs and 16 GB given to Docker on this PC). Results produced on Windows while the arms were being developed are development output only and are not reported.
- **Why.** On Windows, LadybugDB 0.22.3 from npm runs its core (typed multi-hop paths, shortest paths) but its algorithm extension does not load: it needs arrow.dll, networkit_state.dll and two OpenSSL libraries that the download does not ship. Computing ranking outside the engine for one arm only would have handicapped the graph side.
- **What the image holds.** Debian 12, Node 24; `@ladybugdb/core` 0.22.3 with its `algo` extension loaded; `@duckdb/node-api` 2.0.0-r.1 (DuckDB v2.0.0) with the DuckPGQ community extension; SQLite through `node:sqlite`. The algo extension links against icebug 13.5, the Ladybug developers' fork of NetworKit (prebuilt release from github.com/Ladybug-Memory/icebug, named in the extension's own build script), Arrow 26 (libarrow.so.2600, taken from the pyarrow 26 wheel), OpenMP (libgomp1), OpenSSL 3 and CA certificates. Both extensions are installed at build time, and the image was verified to run with the network off.
- **Verified in the image.** Ladybug: typed variable-length paths with an edge filter, PageRank, Louvain, weakly and strongly connected components, k-core. DuckDB with DuckPGQ: property graph, bounded variable-length paths, PageRank, connected components. On the same 2,000-node sample both engines return the same 3-hop reach (56 nodes) and the same top three nodes by PageRank.
- **Known engine limits to design around.** DuckPGQ does not accept an edge-property filter inside a quantified path: use one edge table per kind as labels. DuckPGQ needs `SET active_grammar_extensions=['duckpgq']` after `LOAD duckpgq`. Louvain in Ladybug gives different communities from run to run: any use of communities must fix a seed or report the spread.
- **Facts are still built on Windows** (the extractor needs the repo's TypeScript compiler and a Python interpreter there) and are loaded by every arm as the same files, so the environment does not touch answer content.
