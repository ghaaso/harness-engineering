# Verifier (a): the design-deciding claims of the construction, modelling and storage lanes, checked at the source

Date: 2026-11-13. Scope: the claims behind each lane's "do", "adopt" or "trial" recommendations, plus their surprising numbers. For every claim I opened the primary source: the paper's PDF text (extracted locally with pypdf), the arXiv HTML, the official documentation or the source file. I also re-counted the local numbers from the frozen-commit facts in the build folder. Verdicts: **confirmed**, **partly** (with the corrected statement), **not supported**. Where I could not open a source I say so and default to partly.

Method notes. I extracted PDF text with the bundled Python (`pypdf`) into my scratchpad folder `va/txt/`, then searched it for the quoted numbers. My local re-count script is `va/chk.js` in the scratchpad. It reads `build/facts/cache/a31924a…/{nodes,edges,commits}.jsonl` read-only. Nothing was installed. No project detail went into any search or URL.

## 4. Recommendations to drop or weaken

1. **Construction "dynamic test-run edges", from "do after measurement" to "trial against a file-level static baseline".** Legunsen (C4) found class/file-level static selection unsafe in only 0.2% of revisions against dynamic Ekstazi. That paper also says suites under about 5 s should simply run everything. v1 already has 441 test-to-route records, not 39 (C14). Coverage contexts record lines, not calls, and coverage.py is an install (C10). The marginal value over file-level static links may be close to zero; the tuning test must include that baseline.
2. **Construction "three-tier field-level contract edges", from "do" to "trial", tier 3 last.** Tiers 1–2 rest on strong mechanisms: the OpenAPI export and the TypeScript checker. Tier 3, a home-made def-use pass over untyped JavaScript, rests only on ARISE's abstract (one backbone, no tokens, weak). Its kill test against "co-change only" is the right gate.
3. **Modelling R3 (hyperedge change sets, w/|e|), keep but cut the expected effect to "meaning, not ranking".** The mathematics is confirmed (M2). The 30-entity cap is a CVS-merge filter, not evidence about sweep noise (M3). v1's own test already showed a plain co-change list ties the graph outside the mobile app. Expect the commit message and PR to help with "and why", and expect no recall gain.
4. **Modelling R4 identity ladder, keep, but start the body-similarity threshold at 0.70–0.75**, as HistoryFinder uses (M4). The tool numbers are Java-only and self-evaluated, so they cannot set an expected accuracy here; measure locally as the lane proposes.
5. **Modelling R2 (metapath discovery from example pairs), weaken to "only if R1 leaves a gap".** Its sources (Lao and Cohen 2010; Meng et al. 2015) were read as summaries only, its evidence is biology and bibliographic networks, and fitting path weights to 65 tuning commits risks overfitting, as the lane itself says.
6. **Modelling R6 (calibrated confidence), keep the split as hygiene and drop any expected ranking gain.** Knowledge Vault's calibration (M6) was done at 1.6B triples. Here, parser-exact kinds are already about 1.0.
7. **Storage "typed arrays in process", optional, justified by simplicity only.** Per-query cost is milliseconds against a model step of seconds; no agent-visible gain is claimed or expected.
8. **Storage "containment-aware answer format", keep as a trial but drop the 4.8–61.8% citation as support** (S8: synthetic reasoning tasks). The token saving is a character estimate until a real tokenizer counts it.
9. **Any graph tool interface, carry CodexGraph's cost as the default expectation** (M5): 7–15x the tokens of BM25 for equal or slightly better results. Every arm must beat a plain search baseline on tokens, not only on recall.
10. **Confirmed rejections, keep as rejections:** Jelly (no React or React Native evaluation, C3), CodeQL (licence, C7), and reachability indexes, reordering and compression (S1, S2, S4, S5; GRAIL's own "small" datasets are this size).

## 5. Feasibility problems

- **FastAPI internals are moving, and the version is not pinned.** `APIRoute` attributes are now set through `_populate_api_route_state`, and the backend allows `fastapi>=0.115,<1.0`. Walking `app.routes` must pin the exact FastAPI version of the Docker image, or use only the public `app.openapi()`.
- **Importing the app** works without a database in principle: `Settings()` has defaults and `create_async_engine` does not connect at import. It still needs the backend's full dependency set (asyncpg and so on), so run it in the project's image. I did not check other import side effects, for example Sentry init.
- **scip-typescript** needs Node ≥ 22.23.4 and bundles TypeScript 6.x, while the mobile app uses TypeScript 5.3.3. Disagreements may come from the compiler version, not from v1. The web app needs `--infer-tsconfig`.
- **scip-python** needs an `--environment` JSON to avoid calling pip offline. It is 20.3 MB unpacked before dependencies, and Python 3.10+ only.
- **coverage.py is not a backend dependency.** Per-test contexts need it, or pytest-cov, installed (owner decision). The alternative, a hand-written `sys.monitoring` collector, has no documented overhead figure. Integration tests need Postgres, which the Docker gate provides.
- **mypy `build.build` is an internal API**, and `dmypy inspect --show definition` is experimental. mypy is also unpinned (`>=1.13,<3.0`).
- **DuckPGQ downloads from the community repository** at install time, so it is not offline without vendoring. This only matters if the engine verdict is ever reopened.
- **No offline tokenizer**: every token figure in the storage lane is a character estimate (3–4 characters per token).
- **Count drift across documents**: 36 edge kinds, not 37. 18,875 edge records, 17,410 distinct typed edges, against 16,462 / 16,500 / 17,370 / 18,900 elsewhere. Test-to-route edges number 441, not 39.
