# Verifier (b): primary-source re-check of the three graph-v2 lanes (ranking, selection and interface, time and incremental)

Date: 2026-11-13. Read-only. I searched only for public papers and tools by their own names and put no project detail into any request.
Method: I opened each primary source (arXiv HTML or ar5iv, the authors' PDF run through pdftotext, the official GitHub or PyPI page, or the vendor's own post) and compared it with the lane's sentence.
Verdicts:
- confirmed: the source says it, with the numbers quoted.
- partly: the source says something close, but the statement needs a correction or a caveat, which I give.
- not supported: the source does not say it.
I count a source I could not open as "partly" and say so.

I also re-ran the ranking pilot's headline contrasts, read-only, from the cached feature files it left in the temp folder (`pilot_rows.pkl`, `pilot_store.pkl`). I sent the script through stdin and wrote no files.

## 4. Recommendations to drop or weaken

1. **Ranking R2 (rebuild co-change).** Keep the cheap sweep, but weaken its theory line:
   - The 8-file transaction cap and the 25,000-commit figure are unverified today (Moonen PDFs blocked).
   - NBI's gain was measured on random-split user-item data.
   - HistoRank found plain confidence ranking worst and static file proximity best on 6 of 10 systems. The arm list should therefore include file or directory proximity as a co-change competitor, not only co-change variants.
2. **Ranking R1 is sound, but write its claim as small and coverage-limited.**
   - The reproduction holds: +0.027 to +0.030 P@10, robust to the RRF constant and the ridge penalty. Tie noise is about 0.004.
   - The EdgeBank support is weaker than written: EdgeBank_tw wins under historical negatives only on UN Trade.
   - The recurrency baseline is 9th to 10th on the ICEWS sets.
   - Do not cite "EdgeBank is best under hard negatives on three sets".
3. **Ranking R7 (embedding arm): keep as deferred.** Pujara's evidence is four translational models from 2013 to 2016. It does not test ComplEx-N3 or RotatE, so "embeddings fall below simple baselines on sparse graphs" is a medium-strength inference for modern models, not a measurement.
4. **Ranking R8 (break ranker): restate the Legunsen figures.**
   - 0.2 % and 10.6 % are revisions with any safety violation relative to dynamic selection, not tests missed.
   - The setting is Java class or method dependencies.
   - The Python and TS transfer is untested.
5. **Selection: weaken "value-density selection with a cost-based stop" from adopt to trial.**
   - The derivation is the lane's own.
   - The one published gap-based stop (Adaptive-k) scored 73.33 vs 76.33 to 78.00 for fixed budgets on GPT-4o factoid QA, against the paper's own "matches or exceeds" claim.
   - The stop also needs calibrated probabilities, and at P@10 of about 0.23 those are noisy with 65 commits.
6. **Selection: the 'entry point worth 19 points, traversal about 2' argument for the three-tool surface rests on a fine-tuned 7B localiser** with an unnamed dataset. Do not carry the ratio over to a frontier agent; treat it as direction only.
7. **Selection: the tree-format default is evidenced on 37 samples, where tree vs JSON is about one sample.** Adopt it for its token saving, which the lane measured itself, not for accuracy.
8. **Selection: the cost argument against LLM-driven traversal (11.6 calls / 7,069 tokens vs 2 / 231 to 521) is an uncontrolled cross-paper comparison** with different readers and copied baselines. Keep the conclusion, which also rests on CypherBench and SWE-agent, but stop quoting the ratio as a measured saving.
9. **Selection: "community detection swap (Leiden)" and "redundancy MMR term" stay low priority.** The packer's single positive was 1 of 14 contrasts at a 3B reader, and it reversed at 14B.
10. **Time T-b: rewrite "early cutoff on prose is unsound"** as "early cutoff cannot be applied to prose; only premise query results are compared". The source supports the design but not that wording.
11. **Time R6 (no Datalog engine): keep the reject, and strengthen it.** DDlog is archived (13 July 2026); FlowLog is a demo-track prototype with no licence stated in the paper. Motik et al. show maintenance loses to rematerialisation for large updates, and recompute here is in microseconds.

## 5. Feasibility problems

1. **AnyBURL (R6).** Real, BSD-3, 23-1x release with a bug fix on 12.11.2025. It needs a Java runtime, version unstated ("Java version conflicts may occur"), and the jar size is not stated. That is one more runtime in the container (a JRE is roughly 50 to 200 MB; my estimate, not checked).
2. **PyKEEN 1.11.1 (R7).** Released 24 April 2025, about 19 months without a release. Python 3.10 to 3.12 classifiers; a 730 kB universal wheel. It is fine for Python 3.12 in a Linux container, but the torch CPU wheel size was not checked, and a stale release line is a maintenance risk if the container moves to Python 3.13.
3. **pcst_fast (Steiner trial).** Version 1.0.10 (29 January 2024), one maintainer, releases years apart. It has manylinux and musllinux wheels for CPython 3.12 on x86 only, **no aarch64 Linux wheel**, so on an ARM container it needs a C++ build. The lane's plan to write exact Dreyfus-Wagner in JavaScript avoids this.
4. **leidenalg (Leiden trial).** Version 0.12.0 (24 May 2026), abi3 wheels (2.5 to 4.1 MB) that cover Python 3.12 on x86-64 and ARM64. It needs python-igraph at runtime, which is not declared in Requires, so it must be installed explicitly.
5. **Feldera (only if revisited).** Docker image available; a source build needs about 13 GB plus JDK 19+, Rust, Node 20, Bun and Python 3.10. Image pull only.
6. **Souffle (only if revisited).** UPL-1.0 with distro packages; no release date was visible on the page, and it has no incremental mode. One-shot plus provenance only.
7. **DDlog: do not use** (archived, read-only). **FlowLog: do not depend on it** (2026 demo, licence not stated in the paper).
8. **Moonen et al. PDFs** (the source behind R2's size cap and the history-length argument) are behind a bot check for WebFetch and curl. Whoever cites them next needs another copy (Springer DOI 10.1007/s10664-017-9588-z) before any number is quoted as verified.
9. **The ranking pilot's cached inputs** live in the user temp folder outside the evidence tree (`pilot_rows.pkl`, `pilot_store.pkl`, `pilot_svd.pkl`, `gl2.txt`). They are not in the repository or the evidence directory, so the pilot is not reproducible from the evidence tree alone. They should be copied into the evidence folder when the owner allows writes.

## 6. Earlier rounds, in my area

- Both earlier rounds and the ranking lane leaned on EdgeBank as "best under historical negatives on three sets". The tables show one. The temporal-baseline literature supports "a recurrence baseline is a required comparison", not "a recurrence baseline wins".
- The ranking lane and earlier rounds cite HistoRank (via the time lane) without drawing its sharpest consequence: file proximity is as good as any history ranking in that study. The pilot has `same_dir` and `same_slice` flags, and the floor model C measures this. R1's "+0.02 over the floor" is the comparison that matters, and it is above zero in the pilot (the lane's number; I did not re-run C).
