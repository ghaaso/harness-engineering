THE TEN STEPS OF THE DESIGN.
1. A task arrives for the cheap model. What is in its window?
2. Trigger: does anything cause a lookup, and when?
3. Query: what is asked, in what words or signals?

const findPrompt = (l) => `${SYSTEM}

YOUR JOB: FIND REAL CASES. FACTS ONLY. A later agent will walk each case through the ten steps. You do not judge the design.

PATHWAY FAMILY: ${l.family}
WHERE TO LOOK: ${l.look}

Return three or four real cases, the more different from each other the better. For each: what happened (under 150 words), when, which model or session did it if the record shows it, the exact evidence (error text, commit subject and hash, finding text, transcript file), the sources, and the "later moment": the later situation in which knowledge from this case was needed again, or would have been, with its own source. If the record holds no later moment, say so. Do not invent cases; if you find fewer than three, return what you found and say what you searched.

OUTPUT. Write the case file as markdown to ${OUT}/${l.id}-cases.md (Write tool), then return the structured result.`

const walkPrompt = (l, found) => `${SYSTEM}

YOUR JOB: WALK REAL CASES THROUGH THE DESIGN AND REPORT WHERE IT WORKS AND WHERE IT BREAKS.

PATHWAY FAMILY: ${l.family}

THE CASES (collected by a reader; open the sources and check them before relying on a detail; add a case of your own if these are thin):
${found && found.cases && found.cases.length ? JSON.stringify(found.cases, null, 1) : 'The reader returned no cases. Find three real ones yourself. Where to look: ' + l.look}

HOW TO WALK A CASE. Replay it as if the library had existed from the start of the project. Be concrete. Write the entry as the solver could have written it at the time, in under 120 words, using only what was known then. State exactly what the later moment looked like to the model in that session: what was in its window, what it was doing. Say what a lookup keyed on which signal would have returned. Then give every one of the ten steps a status: works, strains, breaks, not_specified (the design does not say what happens here), or not_reached. A step breaks when it cannot produce what the next step needs, produces something wrong, costs more than it saves, or would do damage. Keep each note under 60 words.

NO FIXES. The owner wants the limitations found and discussed before any solution is attempted. Do not propose solutions, mitigations or redesigns, not even in passing. If the existing design documents already contain a mechanism that handles a step, say so and count the step as working: ${KS} (972 lines, many several KB long: Grep a heading and read around it) and its summary ${F1}.

NOT ALLOWED. Arguments that the work may not repeat often enough, or any base rate from a short history. The question is how the mechanism behaves on a case, not how often such cases come.

ALSO REPORT WHAT WORKS. Where the design would have helped in a real case, say so plainly and say what it would have saved (calls, a session, a failed build, an outage).

${KNOWN}
For every break you find, set seen_before to true if it is on the known list and false if it is new. Report only what your cases show: do not list an item because it is on the list. If your cases show a listed item did NOT happen, or matters less than the list implies, put it under did_not_break with the reason.

OUTPUT. At most twelve breaks, the ones your cases show most clearly first; "description" under 70 words, "evidence" under 50, "cases_hit" is how many of your cases showed it. Write your full walk as markdown to ${OUT}/${l.id}-walk.md (Write tool), then return the structured result. "summary" under 150 words.`

const stage1 = (l) =>
  agent(findPrompt(l), { label: 'find:' + l.id, phase: 'Find cases', schema: CASES_SCHEMA, model: 'sonnet', effort: 'medium', agentType: 'general-purpose' })

const stage2 = (found, l) =>
  agent(walkPrompt(l, found), { label: 'walk:' + l.id, phase: 'Walk cases', schema: WALK_SCHEMA, model: 'opus', effort: 'xhigh', agentType: 'general-purpose' })
    .then(r => r ? ({ id: l.id, cases_found: found && found.cases ? found.cases.length : 0, ...r }) : null)

const out = []
for (const group of [LANES.slice(0, 5), LANES.slice(5)]) {
  const res = await pipeline(group, stage1, stage2)
  out.push(...res)
  log(`group done: ${res.filter(Boolean).length}/${group.length} walks returned`)
}
const ok = out.filter(Boolean)
const missing = LANES.map(l => l.id).filter(id => !ok.some(r => r.id === id))
if (missing.length) log(`missing: ${missing.join(', ')}`)
return { dir: OUT, lanes: ok, missing }
