# Knowledge-store design (PR #183, KNOWLEDGE-STORE-DESIGN-2026-11.md, v1.3.1): extract for harness v2

Source: `origin/claude/knowledge-store-research-9c609c:docs/program/KNOWLEDGE-STORE-DESIGN-2026-11.md` (972 lines). Sections cited as §n. The design is a **diagnosis store** (hard solved problems, traps, do-not-apply facts), not a general library. Nothing is built; only KS-0 (audit) is asked for.

## 1. Entry, journal, truth vs index (§3.1, §3.2)
- **Truth = journal**: "append-only, immutable event records: one canonical-JSON file per event (keys sorted, integers only, UTF-8, LF), named by the sha256 of its bytes, fanned out as `events/<aa>/<sha256>.json`". Lives in a private git repo at `C:\Users\User\.fixflow-ks\store` (never AppData/OneDrive/work tree), pushed over SSH to a bare repo on the owner's VPS, never GitHub.
- **Index = projection**: one SQLite file per host, keyed by schema, recipe, runner and scrub versions; "a broken or outdated index is deleted, never migrated", rebuilt by `ks rebuild`. Lookup and gate-run events are host-local (`store/local/`), never journaled; `ks close` journals rollup counts.
- **Entry** = immutable id `ks-<slug>-<6 hex>` plus an event stream; state is a fold. Field groups: Identity (`kind` in defect, trap, do_not_apply, open_defect, rule_without_case; `root_cause_id`); Symptom (`title`, `symptom_meaning`, `misleading`); Diagnosis (`cause`, `manifestation_conditions`, ordered `diagnosis_path`); Fix (`fix`, `fix_kind`, `fix_commit` 40-hex, `pending_anchor`); Negative results (approach, why_failed, failure_class, scope, proof, optional executable refuting check); Validity (`applies_while`, facets); Links (`refs`: mainline shas, blob OIDs, PR numbers, doc anchors); Status (provisional, verified, suspect, conflict, refuted, superseded, withdrawn, fixed_off_main; counters); Cost (raw tokens, model, tier, wall time; NULL = unknown, never 0); Provenance on every event.
- **Handles** (§3.3): eight fuzzy keys: `tmpl` (canonical error template, with an ambiguity flag), `sig`, `frames`, `ctx`, `prose` paraphrases, `ident` (files, symbols, env names, error codes), `doc_ref`, `action` (verb-object intent), plus `not_when`.
- Event kinds (§3.6) include recorded, revised, confirmed, refuted, invalidated, reaffirmed, controls_broken, anchored, lookup, gate_run, outcome, claim, attempt.

## 2. SQLite side and CLI (§3.1, §4.5, §6, §7.1)
- Engine: `node:sqlite` (inside Node 24), WAL, `BEGIN IMMEDIATE`, FTS5 (BM25 column weights, trigram table, `fts5vocab` for IDF). SQLite >= 3.51.3 required. Ports: `Journal`, `Index`, plus `Canonicaliser`, `Scrubber`, `CodeState`, `Gate`.
- Tables are described, not enumerated: entries, handles, FTS5 tables, `footprint_item`, traces, lookups, gate runs, outcomes, claims, `entry_link` (recursive CTE for supersession). Named **views**: `v_retrieval`, `v_false_leads`, `v_rule_of_three`, `v_missed_existing`, `v_concurrent_misses`, `v_store_unavailable`, `v_lock_wait`, `v_stale`, `v_cost`, `v_gate_wrong`.
- CLI `tools/ks/` (zero-dep): `lookup` (any tier), `verify`, `show` (<=6,000 chars/section, fix withheld until `applies`), `outcome`, `claim/attempt/release`, Opus-only `record/capture/control/approve/reject/revise/supersede/withdraw/accept-handle`, admin `close/status/stats/history/rebuild/fsck/doctor/eval/rescrub`. Lookup exit codes: 0 answered, **3 store unavailable, 4 busy, 5 check could not run**; first output line `KS miss|candidate|lead <lookup-id>`; whole output capped at 2,000 chars (~860 tokens).
- Lineage queries are joins plus one recursive CTE (§3.7); Cypher/Datalog "documentation of intent only".

## 3. Lookup protocol (§4.1, §7.2)
- **Callers/triggers** (pull-only): before escalating a defect or failing gate to a higher tier (`ks lookup --log <captured error file>`), before retrying a failed build/deploy, before applying a fix a prose register prescribes (`--prescription`), and four times per code phase via `ks lookup --diff <base> --action "<phase Goal>"` (first commit, PR-ready, Opus review, inside `ks close`).
- Pipeline: canonicalise and scrub, deterministic prefilter, FTS5 rank (order: exact handle, IDF coverage, BM25, entry_id), abstain on score-free features. **Lead** needs strong exact hit, coverage >= 0.5, margin >= 0.2, validated status, no unmet precondition. **Candidate** is weaker. Else miss. Max one lead and one candidate card.
- **Gate**: "nothing is acted on until `ks verify <id> --lookup <lid>` returns `applies`". Checks are data, not scripts: declarative probes (json_predicate, regex_in_span, duplicate_values, dep_version...) over git blobs, or pytest/jest/vitest ids in Docker, or db_probe. Each runnable check has a **control pair** (`fails_at` reads PRESENT, `passes_at` reads ABSENT), refactor mutants, an inject-control re-run on the current tree, and typed `valid_when` preconditions. A text probe may return `applies` only where the matched value is itself the root cause (config value); code-behaviour entries are candidate-only without an executable check.
- Cheap agent: runs lookup, then verify; on `applies` applies the fix outside Opus-reserved areas (outbox, migrations, auth, money, lifecycle); on a miss it claims and escalates passing **only the lookup id** in the brief. For solved entries, exit 3/4/5 or `inconclusive` = proceed as today; for do-not-apply routes they are "diff check not run", never "no warnings".

## 4. Validity and staleness (§5)
- Entry tied to code by a **footprint**: typed items (`file_blob` git blob OID, `symbol_span` from KS-6b, `config_key` value hash, `dep_version`, `env`, `tool_resolution`, `doc_anchor`, `precondition`), each with a provenance tier; the **trace** is the digest when the controls last flipped. Fix tied to `fix_commit` via `git merge-base --is-ancestor`, patch-id fallback.
- Drift: "(1) a footprint item's digest at the target differs from the trace ... No TTL, no review dates, no scheduled sweep." Invalidation by events only (§5.1, 11 triggers). Lazy recompute at lookup/verify marks the entry **suspect for this caller only**, capped at candidate, no event written. **Early cutoff**: if controls still flip and preconditions hold, a `reaffirmed` event re-stamps the trace. `ks close` scans blobs at `origin/main`, appends `invalidated`, re-runs every validated declarative probe ("fix not on main" vs "regression"). "An unchanged footprint is necessary, never sufficient."
- For do-not-apply/open-defect/trap entries, change in a PR diff is a **warning**, not staleness.

## 5. Evolution (§4.3, §7.3, §7.4, §4.5)
- Write-through at solve time: the solving Opus agent runs `ks record` (fixed schema; no LLM transcript extraction) before PR-ready, only if the case needed an escalation, 2+ failed approaches, or a burned build. Lands `provisional`/`pending_anchor`; the PR's Opus reviewer (never the author) refutes and `ks approve`s. Write gate: scrub, Jaccard near-duplicate check, negative-corpus precision check, self-match refusal, control pair.
- Feedback: applies+resolved -> `confirmed`; not_applies -> `gate_absent` plus proposed `not_when`; applies+not_resolved -> `refuted` scoped to the footprint digest.
- **Misses**: `ks record --lookup <id>` rules each prior lookup's candidates `same` / `related` / `new`; `same` writes `outcome(missed_existing)` with CLI-computed cause class (handle_gap, typo, vocabulary, threshold) feeding `v_missed_existing`; reviewer re-rules blind. Mechanical writer for rephrase-then-hit. `missed_dna` for forbidden changes that merged unwarned.
- **Promotion to a check**: D17 only: a validated trap probe becomes a repository CI check (ex7 empty-env, ex8 plugin, a caller-pin pytest for `verify_pin`/`create_access_token`). Manual, owner-ruled, not automatic.
- Retirement: by status (superseded, withdrawn, refuted at footprint), never delete. Teardown KS-T.
- Metrics: confirmed hits, refuted hits (`gate_absent` vs `gate_wrong`), misses that later matched (§4.6).

## 6. Token cost (§0, §7.7, §10)
- No measured saving anywhere. Break-even model: net = h*(S - L_hit) - (1-h)*L_miss - W/E; S (top-tier solve cost avoided) "unknown until KS-9", no historical prior. Per-call cost dominated by the caller's context re-read as cache reads, not output; ~0.4 tokens/char; quiet phase = three `--diff` turns plus one reviewer call (170-220 ms each).
- **KS-0 audit** (Sonnet + Opus refuter, no code): counts only repeats a store could have served (lookup-able symptom, not findable by `git log --grep`/CLAUDE.md, non-trivial). Prior: 3-5 same-cause repeats among 48 fix commits. D1 yes; **D1b default no** (build only after audit).
- **KS-5 pilot** (stop point): >=20 blind positives, >=40 hard-negative/stale probes, two incumbent arms, diff replay of every first-parent commit plus planted forbidden diffs. **D8 go**: recall at shown >= 60 %, zero acted false positives, beats both incumbents at equal precision, all planted diffs caught, warning rate <= 1 in 10 commits. go-minimal or stop. **KS-9** checkpoint at 20 encounters or 8 weeks; kill on <3 verified hits, any acted false positive merged, or incumbent matches. **D16** embeddings: k>=3 vocabulary misses among n>=10, 95% lower bound >= 5 %; not expected to fire. Thresholds frozen at KS-4, never changed in KS-5.

## 7. Graph and explicit non-builds (§1.4, §4.4, §6, §7.1, §9)
- Relations are plain tables: `root_cause_id` (shared cause = equality join), `entry_link` (supersedes), `refs` to commits/PRs/doc anchors, footprint-to-changed-path join. No graph engine ("E-08 not needed"; Neo4j/Memgraph/AGE rejected).
- Not built: embeddings v1 (lexical only; reserve sqlite-vec behind D16, dense hit may reach candidate never lead); LLM-extracted memory/graph; code index (graphify "evaluated and skipped"); any hook or push into context ("pull-only"; edit-time hook held off as D21); TTL expiry; MCP wrapper (D15); LLM re-ranker; second engine (Postgres, DuckDB, Meilisearch only on triggers); `scripted` checks (D18).

## 8. Gaps for a harness-wide library
- **Work state**: no slice status, gate verdicts, open findings (open defects explicitly stay in G2/the plan; "Not the defect register", "Not session memory").
- **Code neighbourhood**: no callers/importers/co-change; one-hop callers named an undetectable hole (§5.5), `guarded_refs` optional and off (D22); D17 pushes it to CI.
- **Plan-time data**: only `--action` matching on phase Goal text; no file footprints for planned slices (only 6 of 45 phases name a file).
- **Per-lookup token accounting**: raw tokens logged per lookup/cost field, but no baseline, no saved-tokens estimate; S unmeasured.
- Also: lookup is triggered by error/escalation/diff, not by "before exploring"; write is gated on hardness, so routine knowledge is not captured; promotion to checks is manual; no automatic retirement; self-reported compliance.
