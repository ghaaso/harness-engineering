## Summary
Access: a Bash-called project CLI needs no configuration. Subagents inherit Bash by default, and background subagents keep Bash and every MCP tool. A project .mcp.json asks for approval in interactive sessions and loads without asking in non-interactive runs. MCP tool schemas are deferred by default, so their context cost is low. Output is bounded: MCP warns at 10k tokens and caps at 25k; Bash defaults to 30k characters. Local check: Node 24.22.1 ships node:sqlite with SQLite 3.53.4 and working FTS5, so a zero-install CLI over SQLite is possible. The node:sqlite docs rate it Stability 1.2 (release candidate).

MCP landscape: the reference sqlite, postgres and redis servers were archived on 2025-05-29 into modelcontextprotocol/servers-archived with no security guarantees. Replacements are community or vendor servers. Meilisearch and Weaviate are moving MCP into the engine itself, and Meilisearch's route is read-only. Kuzu was archived 2025-10-10.

Egress: Meilisearch, Qdrant, Weaviate, Neo4j, Memgraph and ClickHouse (crash reports) send data by default, and each has a documented off switch. Meilisearch, Qdrant and Weaviate state that stored content is not sent. SQLite and Postgres have no documented telemetry. DuckDB sends no telemetry but auto-downloads extensions. Not established: whether Chroma's Rust-side telemetry is live, Milvus phone-home, Typesense telemetry, and FastMCP's update-check call site. Whatever an agent reads from the store also goes to the model provider, so engine-level egress control does not cover that path.

## Design implications
- (strong) Make a project CLI the primary agent interface and put the lookup, verify and record procedure in a skill. Bash is the only access path guaranteed in every subagent with no config or approval prompt, and it also works for the cheap-tier agents the store is meant to serve. Add an MCP wrapper only if CLI usage proves error-prone. [F16, F19, F15]
- (strong) The CLI must cap its own output: a few ranked hits, each a short card (symptom handles, validity conditions, verification command, outcome counts), with full diagnosis paths fetched by id. Stay well under Bash's 30k-character default read-back and MCP's 10k-token warning. [F18]
- (strong) Do not build on the archived reference MCP servers for sqlite, postgres or redis, nor on the deprecated standalone Weaviate server or the Meilisearch Python MCP. Engines that provide MCP now ship it in-process (Meilisearch read-only, Weaviate preview), so a read/write store needs the CLI anyway. [F2, F7, F9]
- (strong) SQLite via node:sqlite with FTS5 is feasible with zero installs, zero network code and a single file. Treat the release-candidate status as the one risk and keep the storage layer behind an interface (the brief requires one) so Postgres can replace it. Multi-worktree write concurrency (WAL, busy timeout, one DB location outside worktrees) is untested here and needs a test. [F20, F30]
- (strong) Egress classification for any engine adopted later: telemetry (counts, versions, hardware, IPs) is on by default in Meilisearch, Qdrant, Weaviate, Neo4j, Memgraph and ClickHouse (crash reports). Each has a documented off switch, so disable it at launch and add a container-level egress block as a backstop. Never enable remote embedders, S3/remote snapshots or crash upload. [F21, F22, F23, F25, F26, F27, F32]
- (moderate) DuckDB and SQLite have no telemetry setting, but DuckDB auto-installs extensions over the network by default. If used for analytics, set autoinstall_known_extensions=false, pre-install what is needed and lock configuration. [F29, F30]
- (moderate) The owner's no-egress rule cannot be met by engine choice alone, because stored defect text read by an agent becomes model context. The design should state which scope the rule covers (store and services versus also the LLM provider) and, if the latter, decide what cards may contain. This needs an owner decision. [F31]
- (moderate) Agents can reach read-heavy lookups cheaply because tool search defers MCP schemas; a skill description costs at most 1,536 characters of standing context. The standing context cost is therefore small for either path, and the choice should rest on reliability and constraint-enforcement, not tokens. [F17, F19]
- (moderate) Enforce read-only access for cheap agents at the access layer: a read-only CLI verb set, with writes (record/refute/retain) behind a separate verb gated by a PreToolUse hook or a permissions.deny rule, rather than relying on MCP servers' own read-only flags, which vary (Qdrant, ClickHouse and Neo4j have them; Chroma and Redis do not). [F16, F10, F11, F12]

## Rejected paths
- Using the archived modelcontextprotocol sqlite/postgres/redis reference MCP servers — Archived 2025-05-29 with no security guarantees; npm postgres package deprecated.
- Relying on Meilisearch's built-in MCP for the store — It is read-only (list, describe, search, facet search), experimental and HTTP bearer-only, so it cannot record outcomes or entries.
- Weaviate or Chroma as the primary store — Weaviate telemetry defaults on with account IDs and possible third-party sharing; Chroma's MCP has no read-only mode and bundles remote embedders; both are heavy for hundreds of entries.
- Treating 'no telemetry mentioned in the README' as proof an MCP server sends none — The MCP READMEs I read are silent, and FastMCP, used by several of them, has a PyPI version-check utility whose call site I could not verify.
