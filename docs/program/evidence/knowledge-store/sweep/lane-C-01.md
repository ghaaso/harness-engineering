## Design implications
- (strong) No component that sends code, defect text or transcripts to a third party may be in the production path; every hosted memory service the owner evaluated (MemTree, claude-mem's observer and Haiku compression, hosted Virtual Context presets, Graphify's LLM doc pass) is to be cited for design only. LLM calls over entry text must go through an owner-controlled model route or be excluded. [F01, F02, F03, F04, F11, F16]
- (strong) The store must be declared the single owner of one new kind of state (diagnosed defects and build traps, with negative results) and must link to, not restate, the owners of everything else (plan, PR body, git, register). Any generated view (index, digest, owner page) is a rebuildable projection that carries its source identity and has a defined refresh trigger. The FixFlow harness review ruled FixFlow already has one owner per kind of state, so adding this owner needs an explicit ruling by the main session or owner. [F39, F40, F48, F15]
- (strong) Invalidation should be event-driven on a dependency set recorded per entry (repo-relative path, symbol or region, dependency version, platform) and evaluated against git objects at a named commit, not against working-tree bytes (RT-04) and not by wall-clock age. A whole-file hash change is a coarse suspect trigger that routes the entry to the verification gate, not proof of invalidity; an unchanged hash is not proof the entry still applies. Immutable, sequence-numbered records bound to events are the owner's accepted alternative to expiry. [F42, F44, F27, F46, F47]
- (strong) The verification gate must return an explicit tri-state per check (passed, failed, not-run/skipped/exempt) and must fail when zero checks were collected, an integration check was skipped, a referenced test id or file no longer exists, or the only passing result is an exemption. Gate counts or exit codes alone must never be accepted (RT-01); the parent recomputes the verdict from structured per-check outcomes with per-launch identity. [F24, F34, F33, F47]
- (strong) Gate scripts must use if/raise (never bare assert) and be safe under python -O/-OO/PYTHONOPTIMIZE (RT-02); each discriminating check needs a negative control that runs in a fresh fixture with a declared, cleaned environment (including Windows variables such as SystemRoot) and asserts the intended diagnostic rather than any nonzero exit (RT-05), proving the check really reproduces the root cause on current code. [F25, F28, F33]
- (strong) Outcome history (confirmed, refuted, invalidated, revised) must be append-only and bind each verdict to entry version, code commit SHA, gate version and environment (RT-03). A confirmed row may never coexist with a failed check on the same revision; a refuted-then-repaired entry is a new attempt with the earlier outcome retained; supersession is reserved for erroneous or duplicate records of the same attempt. The reviewer verdict on a reuse is bound to the head SHA it read. [F26, F47, F33]
- (strong) Analytics on hit/refute/miss rates and cost saved must store unknown as NULL with an explicit status (complete, partial, estimated, unavailable, not applicable), never default 0, keep denominators explicit, and never sum overlapping parallel-agent intervals (RT-06). The owner's own trials recorded provider tokens, all-worker cost and human minutes as null, so 'cost saved' is not measurable unless the store captures its own usage fields; claim only what is captured. [F29, F18, F19, F21]
- (moderate) Retrieval must not rely on keyword or heading matching of single wording (the 'Spending' matched 'pending' failure). Use several declared handle types, exact-reference results (path+line or entry id), precision-first thresholds with a relevance floor, model-requested pull rather than push, and never surface an entry whose cause is already in the current context. At a few hundred entries a linear scan is adequate: the owner's regex recall scanned 115 MB in about 1 s. [F43, F06, F17, F04, F12]
- (moderate) Do not use wall-clock expiry to invalidate entries; time may be shown for humans. If an explicit time-boxed exemption is ever needed it must be a reviewed, source-hash-bound field (as in the RT-01 plan), not a heuristic. This tension between the context-admission rejection and the RT-01 exemption field should be settled by an explicit ruling. [F44, F34]
- (strong) Writers need explicit identity (agent, session, worktree, commit) recorded on every write; do not infer it from the session id because subagent hooks fire with the main session id, and do not keep any project-wide mutable 'current' pointer. Parallel worktrees have different working-tree bytes, so per-commit evaluation is required. [F45, F27, F49]
- (moderate) Store writes must be atomic and idempotent and resumable by checking what already exists, because the owner's agents were interrupted six times by usage limits and a failed first workflow call must not be resumed. [F45]
- (moderate) Keep the agent-facing surface pull-based and the write ritual attached to an existing routine (the phase-close message and the PR-body 'Decisions / ruled out' journal) rather than new per-edit forms or always-on injection. Evidence that always-on context costs more and does not reliably help is secondary and mixed; the owner's own small synthetic trials showed no measurable gain from added projections. [F18, F19, F22, F36, F47, F52]
- (strong) Do not re-adopt skipped machinery: no docs/tasks-style state-owner tree with context.md and evidence JSON, no Python checkpoint hashing or resume, no pre-commit hook as the gate (CI and explicit gate runs instead), no context-system install, no measurement pipeline or evaluation-run schema, no Compact Instructions, no Graphify. Conventions that were adopted (Plan @ sha, in-PR decisions journal, SHA-bound reviews, skip-aware gates, six-question closing message) are the integration points. [F48, F47, F21]
- (moderate) Model-tier routing: entry writes, confirmations and any change to what a gate treats as passing touch verification invariants and belong to Opus under a refute-by-default brief; cheap-tier agents (Haiku/Sonnet) should be limited to symptom lookup and running an already-defined gate, then reporting outcomes. Respect the one-Docker-gate-phase-at-a-time and the two-week package age rules for any engine choice. [F49, F47]
- (moderate) Windows 11 dev constraints: store repo-relative POSIX paths in entries (dead absolute roots caused RT-07), distinguish missing from path-limit or access errors when resolving dependencies (RT-09), use NUL-framed or JSON IO instead of text-mode stdin, do not place the store under %LOCALAPPDATA% or %APPDATA% (Store-app redirection), and do not depend on a Bash-only hook. [F30, F32, F50, F05]
- (moderate) The seed corpus can start from existing artifacts that already carry symptom, reproduction, rejected alternatives and closure: the RT-01..RT-09 register and follow-up corrections, the harness-review rulings table, and CLAUDE.md build traps. The owner's task format (Decisions, Ruled out, Open questions, Invalidation triggers, Retired issues) is the existing vocabulary for negative results. [F51, F33, F47]
- (moderate) A planted-fact canary (a fact must be recoverable using only what the lookup advertises) is a cheap recoverability check borrowed from cch-eval; quality claims for the store need outcomes against a fixed baseline, not retrieval counts or compaction success. Do not treat a vendor or one-off benchmark as evidence of equivalence. [F07, F23, F52, F38]

## Rejected paths
- Adopt a hosted memory or context service (MemTree, claude-mem hosted observer, hosted Virtual Context presets) — Owner requirement and decision: hosted third-party memory does not satisfy the requirement; conversation content leaves the machine.
- Keyword or heading-name matching to pick which stored sections apply — Matched 'Spending' as 'pending' and ranked user clarifications last; replaced by declared exact sections or markers.
- Time-based expiry of stored snapshots or entries — Refused valid snapshots and made the fallback note untrue; replaced by immutable sequence-numbered records bound to events.
- A project-wide mutable pointer or focus file shared by all sessions — Leaked one session's task into another; state must be per session and writers explicitly identified.
- Private vendor auto-memory as the durable authority for corrections and policy — Cannot supply cross-client or team authority and may carry stale next steps; allowed only as a pointer.
- A second competing summary or projection tree (docs/tasks-style task.md, context.md, evidence JSON, preservation manifests) — Harness review skipped it: FixFlow already has one owner per kind of state; projections drift.
- Whole-file sha256 of working-tree bytes (coding_workflow.py checkpoints) as the sole invalidation test, and a pre-commit hook as the gate — Over- and under-invalidates, checks bytes that may differ from what is committed (RT-04), hook skipped by the harness review.
- Verification gates that accept exit codes, test counts, skip-as-pass or bare assert — RT-01 and RT-02: green without testing anything.
- Installing the owner's context-system (PreCompact/SessionStart hooks) or any compaction hook as the knowledge store — Never run live, Python, undocumented hook behaviour, owner keeps it in its own repo; it solves window size not diagnosed-defect reuse.
- Bash-only hook tools (context-mode, RTK, squeez) on the owner's PowerShell sessions — They do not fire on the PowerShell tool.
- The M00-M06 measurement pipeline and evaluation-run schema as the way to measure the store — Skipped: a month of research established no gain; owner priority low.
- Graphify or another LLM-doc graph indexer — Stale under cherry-pick branches, hooks nudge every parallel agent, LLM doc pass egress, version too new.
