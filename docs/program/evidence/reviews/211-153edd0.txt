B. THE LANE'S CHOICE

"Sign-off absent and backend not running" is NOT exactly "not live" on this stack. It is a test of one moment, and it looks only at containers named `backend` in project `fixflow` that are in state `running`.
- What it misses: a paused or restarting backend (shown above); any writer under another name or project (shown above); and writes made between 6.6 (b)'s copy and 6.7 by a backend that has since stopped (route 2b).
- What `max(job_event.seq)` would catch that this misses: past writes in that window (route 2b), and a writer under any name, but only when the write touches `job_event`.
- What this catches that `max(seq)` misses: writes to every other table (punches, pings, travel, the staff ledger, settings, customers, PINs, telemetry); a backend that is running at the DROP but has not written yet; and a first restore, which has no `job_event`.
The lane's choice is the better primary test. One line to add: put the same live test in front of 6.6 (b)'s three marker lines, and drop `--status running`, so that no marker can exist for a live database and a paused or restarting backend counts as live.
