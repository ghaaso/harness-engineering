3. THE NEW 6.6 (b) LINES AS SHELL

- `DX` on the dump line (l.1480):
  - When the live test refuses: `DX=refused`, the line prints `STOP: no copy taken (<the reason that fired>)` and `dump exit=refused`, and the redirect never runs, so no file is created.
  - When `pg_dump` fails: the brace group returns the status of `DX=$?`, which is 0, so no STOP line prints; `DX` is the real code (`dump exit=1`) and the marker line refuses with `pg_dump exit 1`.
  - On success: `DX=0`.
  - `DX=refused` is set before `${P:?}`, so a stale `DX=0` from an earlier pass cannot survive a run of this line.
  - Nothing can take `refused` for success: both marker lines test `[ "$DX" = 0 ]`, and `DX` is assigned nowhere else in the runbook.
- Every `WHY` printed was the reason that actually stopped the line, in every trial. After a `pg_dump` failure the leftover `WHY` is never printed.
- A failing `ffc ps` refuses on every new line (both forms tested).
- Skipping the copy by pasting in parts: NOT CLOSED (MINOR-A). The marker line checks that `L`, `P`, the receipt and `DX=0` are consistent with EACH OTHER, not that they belong to this attempt. Shell variables outlive 6.9 and 6.1, so pasting the marker line alone vouches for an older copy.
