FINDINGS

E1 MAJOR, fix before merge. A slot version that appears only in an after-report is never judged.
- Code. `apply_after_reports` 2335-2339 marks the manifest row `superseded` from any later document. The newer version found in an after-report is not a row: `rows = merge_rows(parsed)` (3068) takes manifests only. So nothing checks whether that version ever landed.
- Contract. Point 10 says "The newer version is judged on its own."
- Phone path. `enqueue` replaces by id (`outbox.ts:162-168`). For example: a re-negotiation after the last manifest, or a completion redone after its queued copy parked. `completionPrefill` blocks only a queued completion, not a failed one.
- Got. Whether the newer version is pending, refused (`app_detail`) or given up on (`gave_up_5xx`), the result is exit 0, "ALL ACCOUNTED FOR", with nothing for manual entry. The `superseded` note does not say the newer version is still on the phone. That breaks C54's "never exit 0 for a row no server judged", and a refused completion's content is lost silently.
- Smallest fix. When `found` comes from an after-report:
  - if the newest usable report still lists that version, judge the row with `_judge_listed(res, newer, ...)` (so `in_progress`, `still_parked`, `retry_pending`), keeping the "replaced in its slot" note;
  - if it is not listed, keep `superseded` only when `_later_write` or a discard accounts for it;
  - otherwise `missing`, naming the version.
- Pin. The reviewer's probe `test_e1_newer_version_only_in_after_report_is_never_judged` in the coordinator's scratchpad, `rv203probe/test_scratch_rv203_phone3.py`, turned into an assertion.

- The discard entry carries no amount, so the sum cannot be stated, but the count can.
- Fix: add "N payment discard(s) in no manifest, amount unknown" to the verdict (`AuditReport.verdict` 2740-2773).
