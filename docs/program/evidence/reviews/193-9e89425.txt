**Your attack list (item 3)**

- **Reload with the request in flight:** the entry is stored before the send, so the reloaded page resumes the same key and shows "sent moments ago". Discard is blocked for 30 s.
- **Two tabs, same payment:** the second tab finds the key in storage and resends it. If the server sees both at once, its IntegrityError recovery (`service.py:1468-1477`) keeps one row.
- **Discard in one tab while the other is sending:** the sending tab restamps the send time in storage before it sends. The other tab picks up the later time on its next read (`paymentAttempts.js:170`), so its discard is refused.
- **`storage` event late or never:** nothing depends on it except refreshing the notice. Every submit, discard and render re-reads storage.
- **Clock backwards or a future-dated entry:** that entry can't be discarded or expired, but a retry restamps it to the current time (`:223`). That retry either lands or collapses onto the earlier payment, and either way the key is retired. So it never blocks a legitimate payment for good.
- **24 h expiry:** applies on the client only (the server's key constraint never expires). After 24 h a retry would mint a new key, but by then the ledger shows whether it landed. Low.
- **Storage full, disabled or holding the wrong shape:** wrong-shape data is filtered by `isEntry` and repaired by the next write. Storage that throws or is full falls back to memory, and an unsaved entry in memory is never pruned (`:175` prunes only entries that were saved). Covered by tests.
- **Editing the figure after an unanswered attempt:** the edit gets a new key, so 500 and 600 can both land. The 500 stays listed in the notice. This is inherent: only server truth could fix it.
- **Request the server received before the 25 s abort:** the key is kept, so a retry collapses onto it. A server commit after 30 s plus a discard is the manager's call (finding 1).
- **Anything beyond the five fields in `localStorage`:** no. `writeStored` writes only key, job id, amount, method and time (`:141-147`); test "stores only key, job, amount, method and time".
- **`init` changing other `apiSend` callers:** it can't. `...init` is spread first and `method`, `headers` and `body` override it (`api.js:68-72`). No other caller of the 15 passes a fourth argument; test "leaves other callers' requests without a signal".
