FINDINGS, BY SEVERITY

F1 BLOCKER: on a shared phone, another technician's write counts as the queued row's evidence, and the report shows nothing.
- Code: a row "by state" is matched against `phone_techs`, the manifest's owners plus its uploader (`drain_audit.py:470`). The check is `_by_phone` at `:1162`, used by `_take` (transition fallback, completion, negotiate, customer pin) and by the note count at `:1280`. The row's own owner is never checked.
- Phone side: an owned outbox row can only be sent under its owner's session: `if (item.techId !== null && item.techId !== me) continue;` (c5eadbd `lib/outboxSync.ts:206`).
- Scenario: technicians a1 and b1 share a phone and b1 uploads the manifest; a1 has a queued note, or `completion:J`, that never sends because a1 does not sign in on that phone again; after the receipt b1 adds a note to job J, or completes J from b1's own phone; a1's row becomes `landed_by_state` and the run exits 0.
- Why nobody is told: `landed_by_state` rows with no notes are not printed in ATTENTION (`drain_audit_report.py:166`). The completion form on a1's phone cannot catch this either, because it blocks on any technician's queued completion (c5eadbd `completionPrefill.ts:86`), which pushes b1 onto another phone.
- Proof: VERIFIED-BY-COMMAND, scratch tests `test_shared_phone_another_technicians_note_accounts_for_an_unsent_note` and `..._completion_...` pass.
- Fix: for outbox rows with an owner, require `actor == row.owner`. Keep `phone_techs` only for owner-less rows (legacy v1) and for media.

F2 MAJOR: a write still waiting on one phone is called `superseded` because another phone listed a newer version.
- Code: `_superseded` (`:698`) requires only "the two phones share a technician" and "newer device time". The manifest carries no phone identity: `uploadProps` (c5eadbd `drainGate.ts:524-533`) has none.
- Scenario: phone P1 (owners t1 and u1) holds `completion:J` version A, never sent; phone P2 (owner t1) holds a newer version B, which lands; version A becomes SUPERSEDED with the note "replaced on the phone...", and the run exits 0. Version A is still queued on P1. If t1 ever signs in there, it sends, and it can rewrite the bill if the bill is not frozen.
- Proof: VERIFIED-BY-COMMAND, `test_a_second_phone_of_the_same_technician_marks_an_unsent_version_superseded`.
- Fix: require a strictly higher `version_code` (a later build on the same phone) for a supersede. Better, P2b-1 uploads a phone id: `fleet.drain.firstSeenAt` is already stored once per phone.

F3 MAJOR: one discard trace accounts for every row with that id, on any phone.
- Code: traces are keyed on `(queue, record_id)` only, the first trace wins (`:1069`), and they are looked up at `:1517` with no owner check and no use-once rule.
- Why it matters: outbox and media ids are mostly shared per job: `ready:<job>`, `negotiate:<job>`, `completion:<job>`, `arrival:<job>:<slot>`.
- Scenario: technician x1 discards his own `ready:J` on phone P2. Technician t1's unsent `ready:J` on phone P1 becomes DISCARDED, attributed to x1, with no shared-phone flag because `owner_tech == discarded_by`.
- Proof: VERIFIED-BY-COMMAND, `test_one_discard_trace_accounts_for_every_phones_row_with_that_stable_id`.
- Fix: match a trace only when `owner_tech == row.owner` (or, for an owner-less row, when `discarded_by` is in `row.phone_techs`), and use each trace once.

F4 MAJOR (a mismatch nothing can clear): a ping or crossing captured just before the snapshot fails the audit.
- Phone side, two causes: the snapshot stamps `takenAt` after reading every key (c5eadbd `drainGate.ts:360-361`); pings and travel stamp `captured_at` from `fix.timestamp` (`pingTracker.ts:296`, `travelTracker.ts:268`), the location's time, not the moment the row is queued.
- Effect: such a row is written after the snapshot (writes wait for it), lands, and its device time is earlier than the floor. `find_extras` (`:1711-1712`) then calls it UNEXPECTED, and the run exits 3.
- When it happens: P4a step 4 sets up exactly this case (the technician is clocked in and the ping task stays registered across `adb install -r`). A phone clock that runs fast, compared with location times, does the same between the snapshot and the receipt (INFERRED: Android location time is not guaranteed to be the system clock).
- Proof: VERIFIED-BY-COMMAND, `test_a_fix_that_predates_the_snapshot_but_was_queued_after_it_fails_the_audit`.
- Fix: audit: judge UNEXPECTED only for punches and crossings; list pings and breadcrumbs from before the floor in a category that does not fail. P2b-1: stamp `takenAt` before `readAllRaw`.

F5 MAJOR (a mismatch nothing can clear): a row the server refuses during the drain stays `missing` for ever.
- Cases: a pending row that our server refuses during the drain while its job exists (a negotiate refused with "no bill yet", a pin refused 403, a close refused because the restore lost its closing clip); a row whose discard trace was dropped (telemetry is a droppable queue with a 1000-row cap).
- No way out today: retry cannot land a definitive refusal; discard is forbidden by the release notice; a manager re-entering cash writes a new `client_id`, so the row stays missing (VERIFIED-BY-COMMAND, `test_a_payment_parked_during_the_drain_stays_missing_after_the_manager_reenters_it`).
- Why it matters: O-10 E5 and E7 accept leftovers parked with an app reason. P4a turns any exit 3 into a fleet halt and a rerun on the next phone.
- Fix (the reviewer: needs an owner decision): either P2b-1 uploads an AFTER event (the record ids now parked, with their reason class, from `readLiveManifest`), or the audit takes an owner-signed acceptance file. In both cases the report should say what clears each kind.

Rows re-parked with app reasons then read MISSING instead of `still_parked`. Fix: ignore `unpark_applied` when its `at` is earlier than `taken_at`.
- M6. Exit 4 can be permanent, with no way out written down: with `unreadable_parts`, with saved corrupt copies (these persist into every later build's manifest), and with the drain manifest's own `.corrupt` copy, which holds no rows but is counted as "unknown rows"; also when a non-owner, non-uploader technician's punches land, where the way out (a scoped run) is not stated.

- Location +-10 s with a wrong phone clock: the stored `device_time` and the manifest's `created_at` are taken in the same tap (`TravelScreen.tsx:167`, `outbox.ts:170`), so clock error cancels out.
- Negotiate in whole rupees: the phone holds one negotiate per job, and each piece of evidence is used once. Apart from F1, no money loss found.
- Gate claim: a live send queues while the gate is shut (c5eadbd `outboxSync.ts:299`, `:201`). Nothing sends before the receipt.
- Settled states and event texts match the drain tree.
- 401 pause during the drain: the row reads missing until the technician signs in, then lands and clears.
- Completion replayed against a frozen bill: an unfrozen lost edit stays missing.
- Personal data: no path prints props, typed text, server reason text, coordinates or names. Only ids, slugs, generated notes and integers are printed.
