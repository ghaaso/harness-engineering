Findings

1. MAJOR (evidence gap). Nobody had shown a native compile of this head. It adds technician-app/app.config.js (it sets android.versionCode from fleet-version.js) and switches eas.json cli.appVersionSource to a local source. Both change what a prebuild reads; expo export proves nothing native. What does not change: package, plugins and permissions are still app.json's own (keys checked; app.json has no versionCode today). Dev builds get versionCode 1 while the constant is 0. Fix: require that compile's green result before the merge counts as "fleet v1 ready".
2. MINOR. A Discard whose trace fails to write still deletes the row. src/lib/telemetry.ts:117 swallows every storage error, so recordQueueDiscard never throws, and discardItem, discardPunch, discardPresence and discardPendingMedia go on to remove the row; telemetry.test "never throws when storage throws" pins this. On a nearly full phone a cash row can be discarded with no queue_discard trace; the audit then sees a manifest row that never landed, with nothing to explain it. O-06 item 6 only makes the network leg droppable. Fix: a variant that rethrows when the local write fails; abort the discard on that error.
3. MINOR. A corrupt manifest part makes the app take a second snapshot over the phone's archive, even after the receipt. In src/features/drain/drainGate.ts takeOrLoad (around 287-303) a SyntaxError in the head or in any part copies only the head to .corrupt, overwriting any earlier .corrupt, then retakes the snapshot into the same keys, without checking whether a receipt already exists. On a later launch the payload archive the manager enters parked cash from (O-10 E7) is replaced by the post-drain state, with a new manifest_id. The server copy is unaffected. Fix: once a receipt exists for this versionCode, never retake; only report the part as unreadable.
4. MINOR (test gap). Two sync paths can lose their gate check with no test failing: removing syncGateOpen() from presenceSync.ts and from travelSync.ts left all 186 tests of the 11 suites green. Presence is a never-delete queue. Fix: add both queues to the "no queue sends before the receipt" case.
5. MINOR. The fleet versionCode check does not insist on the fleet maximum: scripts/check-fleet-values.js:59 checks --fleet-max only when it is passed, and the docs/HANDOFF.md build line runs the script without it. A positive versionCode below the fleet maximum passes; the install is then refused as a downgrade (safe under R5, but it costs a fleet build). Fix: make --fleet-max mandatory whenever the versionCode is set.
6. MINOR. The 336 h "too old" prompt is shown on job writes and media, payments included (src/features/jobs/JobDetailScreen.tsx:223, src/features/drain/NeedsAttentionScreen.tsx:76). No such ceiling exists for job writes, so a technician may tap Keep on a payment for no reason. Nothing is lost. Fix: limit the prompt to punches and crossings.
7. MINOR. The manifest does not count arrival drafts. The field app (a31924a) writes jobs.arrivalDraft.v1:<jobId> (bill materials in paisa, capture URIs, per-capture upload states) and jobs.arrivalAnchor.v1:*; STORE_KEYS in src/features/drain/constants.ts lacks both, so their bytes appear only in total_bytes. jobs.outbox.v1.corrupt (possibly cash) appears only as bytes in preserved_corrupt. Fix: a per-job draft count and a count of failed uploads inside drafts.
8. MINOR. The receipt is not tied to its manifest: isGateOpen checks only that a receipt exists for the versionCode, not its manifest_id, and stops waiting for the un-park once a receipt is cached. Breaks B10 and B11 changed no test result. The impact today is nil, because the upload already requires the un-park and the snapshot.
