C. POINT 15 PER SLOT KIND

- "Received" timestamp: the server's. `job_event.created_at` has `server_default now()` (`app/features/jobs/models.py:275-277`), `job_media.created_at` likewise (`media/models.py:95-97`), and no app writer sets either (grep). Because `now()` is the transaction start, a write that began before the receipt reads as earlier, which leaves the row `missing` (safe side).
- Same owner from another install: yes, it stands in (P1).
- Void: not counted.
- Manager correction: not counted (`_by_owner`, 2201).
- Replayed identical completion: an unfrozen identical resubmit writes a `complete` event, so it counts. A frozen one writes nothing.
- Job closed in between: closed before the receipt -> `residue` (1948-1955; customer_pin is not in that list). Closed after -> a parked listing (`still_parked`), or not listed -> `missing`. A close event never stands for completion, negotiate or pin, and `"closed" != "ready"`.
