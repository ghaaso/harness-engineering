Notes

1. The orphan removal trusts that this run holds every slot, which is true only by configuration (ops/lab/android-compile.sh:184, :205-212). The acquire passes on whatever FF_POOL, FF_SLOT_SH, FF_LOCK_DIR or FF_SLOTS the caller's shell has set. Today ff-gates.sh:119 sets FF_POOL for its own command only, so the default is the heavy pool and the precondition holds. But if someone runs with FF_POOL=light, the build takes the light pool exclusively, and the removal would then kill another lane's legitimate Android build running in the heavy pool. Smallest hardening: call the acquire with FF_POOL=heavy explicitly, and skip any container whose fixflow.holder label ends in a PID that kill -0 finds alive. On name-alikes: a container named fixflow-*-android is removed only if it carries the fixflow.holder label or runs the fixflow-android-build image (:207-208); none of the containers running now matches.
