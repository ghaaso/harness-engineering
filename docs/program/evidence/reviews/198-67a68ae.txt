**Tried and could not break**
- **Re-read loop:** none. At most two attempts, then the job is left as the payment call set it.
- **Two payments in flight, or a failure before sending:** these only move the counter, which causes an extra read and nothing else.
- **Job switch:** answers are applied by `mapped.id`, so an answer for job A never lands on job B.
- **Newer answer wrongly rejected:** only possible if a held row disappears, which the server never does.
- **Older answer wrongly accepted:** an answer that holds every held row, with the same voids, is not older on the ledger. Its other fields (status, timeline) can be briefly older, as the author notes.
- **Late list:** it keeps detail fields only for jobs whose detail already loaded, and list fields still apply. Detail fields are refreshed on the next load. The old behaviour (an emptied completion) was worse.
- **Money logic:** unchanged. `paymentAttempts.js` and `logPayment` in `jobsApi.js` are not in this diff; only `fetchJob` changed.
