Findings

1. MAJOR: a killed run leaves a 6 GB container running after its slots are freed. ops/lab/android-compile.sh:221 starts the container. docs/program/lab/ff-slot.sh:61 frees the slots once the script's PID is gone. An agent's task-stop or taskkill /F acts like SIGKILL: the container then runs for up to 110 minutes outside the lock, and the next exclusive build adds another 6 GB in a 15.5 GB VM where other lanes' database containers live. The README documents this; nothing prevents it. Smallest fix, in this PR's own file: after the slots are acquired, remove any running container labelled fixflow.holder whose name matches fixflow-*-android. That is safe because, while this run holds every slot, no other Android build can be legitimately running.
2. MINOR: some untracked secret files are copied into the build. android-compile.sh:192 copies untracked files that are not ignored. git check-ignore: technician-app/.env.production, .env.development, credentials.json and *.keystore are NOT ignored. If a .env.production exists, Expo loads it for the release bundle, so the real API URL and DSN get baked in. The redaction never covers .env values. That would make README:18-20 ("cannot reach a real server") false. Fix: exit 3 when the copy list contains technician-app/.env* (except .env.example), credentials.json, *.keystore or *.jks.
3. MINOR: "compile evidence only" is enforced by nothing. android-compile-inner.sh:195 writes app-release.apk with the production package name com.fixflow.technician. Fix: name it COMPILE-ONLY-debugkey-<variant>.apk, or keep only the facts unless an opt-in variable asks for the APK.
4. MINOR: README:93-97 says the secret-bearing material lives only in the container. But the Gradle build cache in the fixflow-gradle-cache volume stores task outputs, which include the processed google-services resources and the merged manifest, unredacted (inferred from how the Gradle cache works; the volume was not opened). Fix: say so in the README.
5. MINOR: with Docker stopped, the run still queues for the exclusive slots. The docker inspect at line 154 fails silently, the run waits for all slots, then reports "image build failed" with exit 5 (lines 199-204). Fix: docker info >/dev/null || die before acquiring.
6. MINOR: supply chain gaps. Dockerfile.android:47: yes | sdkmanager --licenses accepts the SDK licences silently, and the README never says so. apt packages (line 34) and platform-tools (line 49) are unpinned. The prebuild template is fetched by the moving dist-tag sdk-52 (inner:61; the log resolved it to 52.0.79). The Gradle distribution download (cold build.log:87) shows no checksum check. Fix: pin the template with --template expo-template-bare-minimum@52.0.79 and document the licence acceptance.
7. MINOR: memory knobs and the out-of-memory note. FF_ANDROID_XMX "at most 4g" is not enforced (outer:121). An out-of-memory kill of a Gradle child process exits 1, which maps to 10 "build failed", not 12 (outer:236-247); only container_oom_kills shows the real cause. The spike peaked at exactly the 6g cap, and a cold build at 6g is still unmeasured.
