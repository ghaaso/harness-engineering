**Tried and could not break**

- **Other places showing a paid amount or balance:** `amountPaid`, `balance` and `revenueEntries` are used only on `JobDetail` and the dashboard tile (note 1). I found no list page, receipt or "paid in full" display.
- **Void without loaded payments:** the void controls belong to ledger entries, and a list row has none.
- **Negotiate:** it uses bill fields, which list rows do carry, not payment figures.
- **Deep link or switching job:** the form's `open` is held closed until that job's payments load. I found no keyboard shortcut.
- **Where `hasDetail` comes from:** only `replaceFromDetail`. All 14 callers pass an answer from an endpoint that returns the full job detail. The only endpoints that return list-shaped rows are list and create, and neither goes through `replaceFromDetail`. A late list keeps `hasDetail`, because it is in `DETAIL_ONLY_FIELDS`.
- **Retry and the re-read counter:** Retry goes through `loadJobDetail`, so it keeps the counter. If both reads are overtaken, the promise resolves without applying anything. `hasDetail` then stays false and the card shows "not loaded" with Retry, never a zero. The Retry button is hidden while a retry is loading, so clicks don't stack in practice.
- **A job with no payments:** once its detail has loaded, `hasDetail` is true and the grid renders Rs 0 received.
- **Unconfirmed-payment notice:** it lives in the payment form, which opens once the payments have loaded.
- **Money logic:** unchanged. `paymentAttempts.js` and `jobsApi.js` are not in this diff; under `src/features/jobs/data` and `src/app/providers` only `AppContext.jsx` changed.
