A shift open across midnight shows as "not clocked in". `backend/app/features/attendance/service.py:726` reads only the board day's events (`events = bucket.get(tech_id, {}).get(day, [])`), and `:739` derives `clocked_in_at` from them. That is not "healthy", so the rule "a dead tracker never shows as healthy" still holds, but the tracker's state is hidden. When the only ping came from an earlier session that day (in, out, in again), the server correctly says `silent`, but the label counts minutes from that old ping. The manager sees "No pings for 300 min" instead of "since clock-in". The tone is still danger. Fix: for `silent`, always say "since clock-in".

**Tried and could not break**
- **Boundaries:** d+a == r is inside; d−a == r is unknown. Accuracy null, 0, negative, NaN or ±inf gives unknown. Accuracy exactly 100 is judged; 100.5 is unknown. The ceiling never caps a value.
- **The two float vectors:** they come out the same under IEEE ties-to-even in JS and in Python. 2^-53 is written in a form that round-trips exactly.
- **Fixture shape:** vectors are given as distances. The coordinate vectors sit far from any boundary, and the 1112 m north vector's 0.5 m tolerance would catch an ellipsoid port. The fixture is versioned, and its header (version and constants) is pinned to the module by `test_contract_header_matches_the_module`.
- **Job punches** use the same module (`jobs/service.py` imports `fence_verdict`), not a copy.
- **Wi-Fi promotion:** it cannot turn an outside into an inside, cannot promote a mock fix, a ping or a job punch, and does nothing while the fence has no BSSIDs. The redacted BSSID with surrounding spaces or upper-case is stored as null.
- **Ping query:** the window function is evaluated before DISTINCT ON, so counts are per tech. One range query uses `ix_attendance_ping_shop_time (shop_id, captured_at)`.
- **Sampler states:** a late batch for an old gap leaves `last_captured_at` old. Past days get a null state. "ok" requires a ping since the clock-in within 3× the cadence, and the web demotes an aged "ok".
- **Discard props:** missing or malformed props are never counted and never attributed to the uploader.
- **Installed app compatibility:** punch, presence and ping request schemas are unchanged, so nothing the installed app sends is newly refused.
- **Rebase onto P1:** 240 h is intact in both places (`config.py:98`, `service.py:136`). No `models.py` change; `alembic check` passed.
- **Web confinement:** web changes stay inside `src/features/attendance/`, with no `dangerouslySetInnerHTML`.
