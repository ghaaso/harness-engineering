**Findings**

1. **MINOR. A corrupt manifest head after the receipt adds one storage copy per relaunch and per retry, up to 50.**
   - Where: `preserveCorrupt` in `src/features/drain/drainGate.ts` (around line 238) writes the head's bytes under the first free `.corrupt[.N]` name. It never checks whether an earlier copy already holds the same bytes.
   - After a receipt, `takeOrLoad` calls it (around line 347) and then throws, so the snapshot fails. Every retry repeats this: each relaunch, every queue write, and the Drain Report poll every 30 s.
   - I showed it with a probe test in my checkout: six relaunches with a broken head left six `.corrupt*` keys.
   - Failure: on a phone that is already in a bad state, up to 50 copies of the head pile up in AsyncStorage's 6 MB. That can push a nearly full phone into failing the technician's taps. Drained records are not touched.
   - Smallest fix: return early when any existing copy equals the bytes, as `lib/queueStore.ts` `preserveCorrupt` already does.
