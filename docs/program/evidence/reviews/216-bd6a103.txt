B. THE BILL RULES AGAINST THE NEW WRITER
Every bill write takes the job row lock first (`try_lock_unclosed` or `lock_job_status`). `_write_bill` then reads the latest revision under that lock and adds the revision, then the chain entry (which takes the chain lock), all in one transaction. A refused call raises before `_write_bill`; the router commits only on success (`router.py:333`) and `get_session` closes, which rolls back.
- First completion: writes revision 1, kind `completion` (`:1911-1924`, `:1985`).
- Resubmit by a technician: frozen means 409, as before (`:1893-1894`). A free resubmit writes a `completion` revision only if something in the bill changed.
- Correction by a manager: an `override` revision with the reason (`:1899-1909`). The closed check still comes first (`:1823` and `:1835`). The revision before it keeps the lines the customer was shown (the integration test asserts this).
- Identical replay: on a frozen bill it returns at `:1891-1892`, no revision and no event, for both roles. On an unfrozen bill there is no revision, but a second `complete` event is written; base does the same, and the messaging test pins that the customer gets one bill message.
- Negotiate: the replay check runs before and after the lock (`:2125`, `:2134`), then a `negotiate` revision. The two-session test against a close (`test_money_close_race_integration.py:145`) is unchanged and green.
- Send: for both the manual endpoint (`customer_messaging/router.py:98`, `:153`) and the automated dispatcher (`customer_messaging/service.py:479`), a `send` revision is written on the first send only (`:2236-2240`). The dispatcher still calls `log_customer_message`, and `test_messaging_integration.py` now asserts `["completion","send"]` and that `bill_sent_at` is stamped.
- Scripts: none write `job.bill_*` (grep at the head).
Findings:
- B1 MINOR: a lowered bill can refuse a technician's small discount. `repository.py:344-357` takes the earliest revision with an original, whatever its kind; `service.py:2148` uses the larger of that and the current original. Example in paisa: completion 450000, bill sent, manager override to 135000 ("compressor not fitted"), cap 50000. The technician then negotiates 130000 (a Rs 50 discount). `capped = 450000 - 130000 = 320000 > 50000`, so the answer is 403; base answered 200. The phone parks a definitive 403. It only happens when a shop sets the cap; the default is 0 (`tenancy/specs.py:170`). Smallest fix: measure from the first original at or after the latest `override` revision. The ruling's own wording gives the same result, so this is a call for the coordinator.
- B2 NIT: a required reason can be thrown away. A manager who changes only the remarks, fault code or action code of a frozen completion must give a reason (`:1891-1904`). The money is unchanged, so `_write_bill` writes nothing (`:1742-1749`) and the reason is not stored anywhere; the event text never carries it. CLAUDE.md says the reason is "kept on its revision". Fix: require the reason only when the bill would change, or put it in the event text.
- B3 MINOR: a change to the material lines alone is not pinned by any test (break O2). Real changes to the bill are recorded correctly at this head. The gap: if the material lines, labour and fuel are dropped from the "nothing changed" comparison (`:1747`), the full suite still passes 1484 of 1484; a swap of parts at the same total would then write no revision and nothing would notice. Fix: one integration test that resubmits different lines at the same total and expects two revisions.
- B4 NIT: a manager's identical frozen resubmit no longer re-prices fuel. It is now a replay. The PR body discloses this.
- B5 MINOR: the larger-of-two rule in C13 is not pinned by any test (break O3). Measuring against the first original alone still passes 1484 of 1484. Fix: a test where an override raises the bill.

F. C13 ARITHMETIC
All integer paisa: `capped = max(original, first) - amount`, and the request is refused only when `cap > 0 and capped > cap`. With cap 50000 and reference 450000, an amount of 400000 is allowed and 399999 is refused. A figure above the reference is never capped. Managers are never capped. It affects technicians negotiating on the phone, and only with a cap set. The message rounds down to whole rupees (base did the same).
