Findings

1. MAJOR. The stub writes its own 400 when a request has no Host header (breaks standing rule 5). ops/hang-stub/server.mjs:297 builds the server without requireHostHeader: false. Node (default true on the image's Node 22, checked with node:22-alpine) writes "HTTP/1.1 400 Bad Request" itself for a Host-less HTTP/1.1 request; that reply skips clientError and the request handler. Reproduced on a raw socket in both hang and proxy mode. No test covers it. The README claim at line 33 ("all intercepted") is false. Reach: Railway's edge always sets Host, so phones probably cannot trigger it; it is still the one place the stub answers by itself, and phones park a bare 4xx. Fix: requireHostHeader: false, plus a raw-socket test "no Host gets no 400".
2. MAJOR. The restore gate misses YAML-style lines, so backend.env can beat a forced key. docker-compose.prod.yml:93 only matches "key=". Compose's env_file parser also accepts "key: value". With lowercase fixflow_environment and fixflow_enable_dispatcher lines in that form, docker compose config passed both lowercase keys into the backend environment, and a copy of the gate logic printed OPEN. In a test container both spellings were present, ordered by Docker rather than sorted; a lower-casing loader that keeps the last value would read the hostile one (that pydantic-settings keeps the last duplicate is inferred, not run). Result: the backend can boot as dev (rule 3) or with the dispatcher on (rule 4): exactly what the gate exists to stop. Fix: match [=:], or better refuse any line whose key equals a forced name ignoring case but is not the exact NAME= form; add the colon case to smoke S4b.
3. MAJOR. Runbook 10.6's STOP remedy creates the failure it guards against. docs/RUNBOOK-SELFHOST.md:1941 says to remove the deployment's public route before doing anything else. Once the route is gone, Railway's edge answers every phone with its own markerless 404; the field APK parks queued records on that bare 4xx, fleet-wide. Line 10.9 of the same runbook admits removal gives a 404, and 10.0 forbids a 404 page. Fix: on STOP, set STUB_MODE=hang and roll back to the previous good deployment, keeping the fleet offline; never detach the domain while any roster phone lacks a row.
4. MAJOR. R3 reuses section 6, which drops the live schema before the dump is proven or the live data saved. docs/RUNBOOK-SELFHOST.md:1319 (6.6 DROP SCHEMA public CASCADE) runs before 6.7's pg_restore -l and list checks. Section 6 has no step that dumps the current database first, yet R3 (lines 2384 and 2414) sends a live host there, including after T_open; manager-side writes made since the dump are in no phone manifest, so they are lost. 6.2's provenance check (line 1277) cannot be met for a later R2 dump, and R3 gives no way to fetch one (only R7.2 does). Fix: move the TOC, list and TABLE DATA count checks before 6.6; add "if public has tables: pg_dump --format=custom the live database, then put it to archive/pre-restore/"; in R3 point to R7.2 for the fetch and use the hourly or nightly receipt's sha256.

"No published port", the restore gate and the forced env keys are checked only by the local smoke; CI never renders docker-compose.prod.yml (a port-publish break showed up only in docker compose config).
