4. C88: CAN A DOCUMENT CARRY AN ENTRY NOT MADE ON THAT PHONE? YES, AFTER AN ANDROID BACKUP RESTORE
- How: `technician-app/app.json` at dbc95a2 has no backup key (key names only were checked). Expo's default is to allow Android Auto Backup (INFERRED by the reviewer; the coordinator confirmed it in the installed `@expo/config-plugins`: `config.android?.allowBackup ?? true`). A reinstall, or a replacement phone restored from Google backup, gets back AsyncStorage as of the backup: `fleet.drain.installId.v1`, the discard list, the manifest head and its receipt. Its documents then go out under the old install id, with entries made on the other device or earlier.
- Effect: as far as traced, only the safe side. The restored list is a subset of what any later manifest of that lineage holds, so a manifest made after the backup refuses those entries. An older restored report can only drop rows or entries, which gives `missing` or `in_progress`.
- For contract point 9: an install id is not proof of one device while backup is on. Turning backup off is an app.json decision for the coordinator and P2b-1.
- NIT: the C88 note (`:2304`) is added for any trace under another install id, including another phone's real discard of the same slot (two phones holding `negotiate:J`); the probe printed "... under another install id (i2): not counted (ruling C88)" for exactly that. Nothing counts it, so it is safe. Smallest fix: cite C88 only when no document in the run carries that install id.
