## method

Checker's overall view: The measured part holds up. Context is input + cache-write + cache-read (replay.js.txt:176), which matches the definition in 1.1. Each message id is counted once across files, with the original or longer copy kept (lines 166-174). Agent, inline and workflow windows are kept apart from session windows (lines 97, 261). Compactions come from compact_boundary preTokens (line 54), and the growth at a compaction call is rebuilt from pre (line 179). The 1,000,000 window is supported only at the strength the document already gives it (A4; 1.2 deals with the Opus 400k setting). Eighteen of the 33 non-Opus compactions came well below the default trigger, and nothing explains them (F9). The simulation is where the headline is decided. In the code a split abandons the old window, starts each child at F+B+rho*0.26*size*share, and deals every later recorded call, with its recorded growth, to one leaf by weight. The leaves form a binary tree with no merges, and the parent is charged nothing. Under that model any method that restarts a window and lets it grow back to the line averages about (start+line)/2. So the ratio to the earlier compaction window is set almost entirely by how a child's start compares with the measured 105k restart, not by the division. I ran a scratch copy of the replay stage (private subfolder wp12-check/method; baseline reproduces 1.055/1.050/1.060): - A roll-over that starts at the compaction restart: exactly 1.000. - Two children, no hand-over costs: only 1.10/1.10/1.14. - rho = 0: 1.14/1.12/1.13. rho = 1: 0.98/0.98/0.97. - drain = 0: 1.12/1.09/1.12. - Child start at the measured session median of 79k: 1.02/1.03/1.04. - Child start at the agent median of 64k: 1.08/1.07/1.07. - Brief 2k: 1.07/1.06/1.06. Brief 8k: 1.04/1.04/1.05. Brief 20k: 1.00/1.02/1.02. - Four-way split: 1.19/1.19/1.28. - The table's own favourable even case: 1.24/1.20/1.22. So "1.05 to 1.06" is the middle case's guessed re-learning and drain. A single guessed parameter moves it across the 1.10 test. The alternative is not fully like with like: - The cap fires before the crossing call, while the rule serves that call and six drain calls at full size. - Re-learning is a guess charged to the rule. The cap's restart is measured, and it is not swept. - The low and middle child starts are agent figures, though a child is a session. - The method check exercises only the reader and the compaction arithmetic, and it uses a restart fitted on the same compactions. - N3 compares session-window calls with a calls-per-prompt figure that counts all calls, agent calls included. What stands within what the replay can show: the measured exposure in sections A to C, and "in the middle case the rule's token net is close to the cap's". It cannot support "on tokens the rule is the cap" as a general finding.
