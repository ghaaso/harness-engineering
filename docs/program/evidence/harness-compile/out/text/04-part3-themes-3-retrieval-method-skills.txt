Find the right code fast
5 in use · 11 tested · 5 built · 3 designed · 5 ideas · 1 parked Work packages: WP7WP8WP10a
Before an agent can change code it has to find what the change touches. On 75 held-out FixFlow commits, a typed store of code facts put 0.700 of the touched files and definitions in front of the reader within an 8,000-token answer M, ahead of a scripted search at 0.625 M. The gain sits in the mobile app; outside it the two are still too close to call.
The three engines we tried, one relational and two graph, gave identical answers, so the engine can be chosen on speed, size and effort. The test was a fixed script with no agent in it. Next comes a zero-token index replay; the wider test I asked for, with an agent in the loop, knowledge graphs, time and caching, follows under a written budget once I settle GT-1.

How we orchestrate
17 in use · 1 tested · 3 built · 20 designed · 17 ideas · 9 parked Work packages: WP3WP4WP6bWP10a
Our method is written down in the orchestration design of 31 October: a main session that plans and judges, cheaper models that discover with citations, and fresh-context reviewers that try to refute what was found. This document was made that way.
The ideas here are how we brief agents, shape workflows, choose a model for each job and recover when an agent fails or returns nothing. Many are in use every day; the rest are refinements we have designed and can now test.
