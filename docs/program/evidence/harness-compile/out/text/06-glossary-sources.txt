General software terms
Allow-list A list of permitted forms (citation styles, tools) so legitimate items are not flagged or refused.General security and configuration practice.
Amdahl-style bound The ceiling on speed-up when only part of the work can be removed: if a share X of the time is removed, the best speed-up is 1/(1-X).Amdahl's law, from computer architecture.
Atomic rename Replacing a file by writing the new version beside it and renaming it over the old one in a single step, so anything reading the file sees either the whole old version or the whole new one, never half of each.Standard file-system practice; FixFlow’s gate scripts land changes this way so a running lane never reads a half-written script.
B+ tree A balanced search tree used by databases. Inner nodes hold only keys that route a search and all data sits in the leaves; a node that outgrows its size splits in two, and small neighbours merge.Database systems, 1970s; in the database lectures on our list (MTH-67).
Backend gate tools (Alembic, ruff, mypy, lint-imports, pytest, pip-audit) Migrations, lint and format, type check, import-boundary check, tests, and an advisory dependency vulnerability scan.Outside open-source Python tools.
BM25 / IDF / IDF-weighted coverage BM25 is a word-matching formula whose scores only order results within one query. IDF weights rare words. IDF-weighted coverage is the share of a query's rare-word weight an entry matches.Information-retrieval field; BM25 is built into SQLite FTS5.
Branch A named line of commits that a slice or lane works on, kept apart from the main line until the work is reviewed and merged.Git; each lane and slice gets its own branch and worktree.
Call graph / blast radius / touch list A call graph maps which functions call which. Blast radius, or touch list, is the set of functions, callers, importers, co-changing files and tests a fix could affect, attached to a reviewer brief.General software practice; the script is proposed in HARNESS-BOTTLENECKS section 6.
chars/4 A rule-of-thumb token estimate (characters divided by 4) that undercounts by about 25-35 percent E in this repository.A common rule of thumb.
CI Continuous integration: the automated checks that run on the repository (GitHub Actions, pinned to Node 22).General software practice.
Co-change How often two files change in the same commit, used as a hint that they belong together. In the graph test it reached precision 0.26 M in a list of ten.Software-evolution research; measured in our graph test.
Commit One saved, named change to the code in git. Reviews bind to a specific commit, and a finding closes on a commit.Git; our verdicts name the head commit they were made on.
Community prior / Louvain A stored grouping of related nodes, found by Louvain community detection, added to the ranking as a prior.General graph-algorithm field.
Connected components / k-core Two graph measures. Connected components are groups of nodes linked to one another; the k-core is the part of a graph where every node has at least k links, its densely connected centre.Standard graph algorithms.
Content-hash id / canonical JSON A file named by the sha256 of its own sorted-key JSON bytes, so replaying an event is harmless. SHA-256 is the fingerprint used to pin versions.General content-addressing practice.
Context window Everything the model sees on one call: system prompt, tools, earlier messages and results. With our compaction setting the practical ceiling is near 367k tokens M.General language-model field.
Covering index A database index that holds every column a query needs, so the query is answered from the index without reading the table.Standard database practice.
Cypher The query language of graph databases such as Neo4j and LadybugDB: a query describes a pattern of nodes and links to find.Created for Neo4j; now the openCypher standard.
Egress Data leaving the machine to an outside service, here the model provider.General security term.
Escape hatch An allowed value such as UNVERIFIABLE or unknown that lets an agent say the input does not fit, instead of inventing an answer.General prompt-engineering practice.
Fail open / fail closed What a check does when it breaks. Fail open lets the action through; fail closed refuses it. Our edit hook fails open so a broken hook never blocks work; the privacy scrubber fails closed so nothing unscrubbed is written.Standard reliability and security terms.
Fail-before / pass-after A fix is evidenced by a test that fails (by assertion) on the base commit and passes on the head commit.General testing practice; our stricter form comes from Horthy's material.
Git bundle A single file holding a repository's history, usable as an off-machine backup.A git feature.
Graph engine Software that stores nodes and edges and answers multi-hop queries natively, such as LadybugDB or DuckDB with graph support. Under test against SQLite.Graph-test research; engine choice is my pending install decision.
Head SHA / base SHA The git commit id at the tip of a branch (head) or where it branched (base). A reviewer's verdict is bound to the head SHA it read.Git.
Hop One link step in a graph; three hops reaches things three links away from the starting point.Graph theory.
Hub / metapath Hub: a file many others depend on. Metapath: a typed route through the graph, such as calls, client URL, route, handler, then table write.General graph field.
Jest / Vitest Test runners for the mobile code (Jest) and the web code (Vitest).Open-source JavaScript tools.
JSON Schema (additionalProperties:false) A typed shape for agent output. The additionalProperties:false setting forbids extra fields, and a description keyword attaches plain-language meaning to a property.Outside standard (JSON Schema).
Knowledge graph / temporal knowledge graph (TKG) A graph where a model reads text and code and writes meaning into it. A TKG also records when each fact became true and was superseded. Our parser-built graph was neither.General AI field; outside systems such as Graphiti and Zep implement it.
Lock-removal experiment / race test Removing one lock to prove the named test then fails. A race test runs two concurrent actions to prove a lock stops the conflict.Used in the clinic gate; general concurrency testing.
Locust / query count (N+1) / fsync=off Locust is an open-source load tester. N+1 is a page issuing many small database queries. fsync=off is a Postgres setting that skips disk flushes, safe only for disposable test databases.Outside open-source projects and database practice.
Main line (main) The branch holding the accepted state of the code. Work merges into it only after the check and a review; a deploy is cut from it.Git convention; FixFlow's default branch is main.
Merge Bringing a reviewed branch into the main line. In harness v2 a script does it, through the merge queue, after one check.Git; harness v2 mechanism that removes root edits at merge.
node:sqlite / WAL / BEGIN IMMEDIATE / busy_timeout Node's built-in SQLite module (release candidate) and the settings that let many readers and one writer share a file safely and wait briefly when it is busy.Node.js and SQLite.
Output tokens Tokens the model writes, including thinking. In the token study, 45 % M of them were thinking.General language-model field.
P0, P1, P2, P3 (severity) Finding severity from most to least serious. In the testbed, late P1 fixes sometimes created new defects, and many P3 ids were carried without a status.Common triage convention; the scheme is used in the G2 gate and clinic reviews.
PageRank / personalised PageRank A ranking that scores a node higher when well-linked nodes point to it. The personalised version restarts from a seed file so scores favour its neighbourhood. Aider's repo-map uses it.Google's web-search ranking algorithm; used in the Aider tool.
pg_stat_activity A built-in Postgres view that lists the open sessions and what each one is waiting on.PostgreSQL.
Playwright A browser automation tool that can drive a web app and take screenshots.Outside open-source project (Microsoft).
Property graph / symbol-level graph A graph whose nodes and links each carry a kind and evidence (file and line). Symbol-level means nodes are functions, classes and components rather than whole files.General graph-database and code-analysis field.
Pull request (PR) A proposal on GitHub to merge a branch into main, with its changes, discussion and checks. Several of our design documents live as numbered PRs.GitHub; see PR #182 to #186.
Red-team Deliberate adversarial testing of a mechanism to find how it fails; eight M red-team defects were still open.Security field practice.
RPO / RTO Recovery point objective (how much data may be lost) and recovery time objective (how long recovery may take).Disaster-recovery field.
Serial pass / pytest-xdist pytest-xdist runs tests in parallel workers. The serial pass is a second run for tests that cannot run in parallel, such as race tests.pytest-xdist is an open-source pytest plugin; the serial pass is our usage.
SQLite / FTS5 / recursive query SQLite is a small file-based database. FTS5 is its built-in full-text search with BM25 ranking. A recursive query follows links over several steps.Open-source SQLite project.
Squash merge / cherry-pick / patch-id Squash merge lands a PR as one commit; cherry-pick copies a commit onto another branch; patch-id hashes a change so it still matches after squashing.Git and GitHub features.
Stampede / single-flight / claim / fencing token / Lamport counter Stampede: several sessions repeating costly work. Claim: the first proceeds. Fencing token (claim_seq): marks a stale holder. tmux A terminal tool that runs several shell sessions in one window. One program can read or type into another’s session, which is how one Claude session can watch another.Outside open-source tool.
Token The unit of text a model reads or writes. Usage, cost and window size are all counted in tokens.General language-model field.
Tracing (test start-up) Recording where a program spends its time, step by step, so the slow part can be found and cut. Trees (event and fault trees) A view listing every route from start to outcome, with its chance and cost on each branch.Reliability engineering; proposed by me for the pathway map.
uv A fast Python package and environment manager. A throwaway uv environment is made for one job and deleted afterwards, so nothing is installed on the system.Outside open-source tool (Astral).

Measurement and statistics
95 % interval The range expected to hold the true value in 95 of 100 repeats of a test. A difference smaller than the interval cannot be told from noise.Statistics; used with the bootstrap in the held-out graph test.
Cluster bootstrap / sign-flip test A 95 % S interval from 10,000 S resamples by commit, and a permutation test for paired differences between arms.General statistics.
Leave-one-handle-out A calibration that removes one lookup key from an entry and checks the entry can still be found.Information-retrieval evaluation style; named in knowledge-store research lane T-03.
Monte Carlo runs (ensemble) Running a model many times with each unknown drawn from its range, to see the spread of outcomes and which unknowns matter most, instead of one answer.General statistics; I proposed it for the library pathway map.
MRR / nDCG@10 / AUC Rank-quality scores: mean reciprocal rank, normalised discounted cumulative gain at ten, and area under the recall-against-tokens curve.Information-retrieval field.
P@1 / recall at shown / acted false positive P@1: precision of the top result. Recall at shown: how many true entries appear in what is displayed. Acted false positive: a wrong lead someone acted on.Information-retrieval metrics; applied in the knowledge-store design.
p50 / p95 (percentiles) Response-time percentiles. p50 is the median: half of the requests are faster. p95 is the time that 95 % of requests beat, so it shows the slow tail.Standard performance-testing statistics.
Positive control A case that must be detected, proving the check can find something. Every check that reports nothing found needs one.Scientific method (laboratory and statistical practice).
Recall / precision / recall@8k Recall: share of true items found. Precision: share of returned items that are true. recall@8k: share of reference items inside an 8,000-token S answer, the graph test's main score.Information-retrieval field.
Rolling-origin test Repeating a held-out test at several split dates: each time, tune on the commits before the date and score on the commits after it, to see whether a result holds over time rather than for one split.Time-series forecasting practice (rolling-origin evaluation).
Rule of three / Clopper-Pearson bound Bounds on a rate from few trials: zero failures in n trials puts the true rate under about 3/n, so 0 in 40 gives 7.5 % S. Clopper-Pearson gives the exact one-sided bound.Statistics field.
Spearman rank correlation A statistic showing how steadily one number rises or falls as another rises across runs; used to rank which unknowns move a result most.General statistics, named for Charles Spearman.
TUNE / HELD-OUT split The 65 S June commits used to choose settings (tune) and the 75 S July-August commits scored once for the verdict (held-out).General machine-learning practice; split defined in graph2/protocol.md.
System dynamics
Knee The lane or worker count where the lowest limit is reached. Beyond it, more lanes or workers add queues and tokens but no speed. In the testbed the check’s knee was between 6 and 12 workers M, and about three lanes M were worth running.Capacity-planning and queueing practice.
Loops R1-R4, B1-B5 Reinforcing (R) and balancing (B) feedback loops. R1 fix spiral, R2 context growth, R3 library compounds, R4 pile-up. B1 check capacity, B2 serial gate, B3 limit stop, B4 staleness, B5 lanes at knee.System dynamics method; the loops are named by us in the harness v2 design.
Stocks and flows Model quantities (stocks, such as slices waiting) and the rates that move them between states (flows).System dynamics.
System dynamics A way of modelling a system as stocks (things that pile up, such as waiting work), flows (rates in and out) and feedback loops, then running the model over time to see where queues form and what a change would do. We use it for the harness and the library, with loops R1 to R4 and B1 to B5.A modelling method begun by Jay Forrester at MIT in the 1950s. Harness v2 and the library pathway map use it, because I asked to see the system as stocks, flows and loops with a runnable model.

How this compile was made
I followed our orchestration design. Sonnet agents first extracted every idea, bottleneck and term from the sources without judging them, each record with a citation in the form path:line — quote. I merged duplicates and sorted the records into themes and work packages. Fresh-context Opus agents then checked all 469 M condensed idea records, and every number in the narrative, against the sources; they split out 10 M more where one record had swallowed a second idea, and I set aside one record about FixFlow’s own product features, which gives the 478 M ideas in Part 3. 268 M idea records and 11 M narrative claims were corrected or tightened, and the corrected text is what is printed here. Last, nine fresh-context readers read the draft as a newcomer would and raised 317 M points on clarity, numbers and tone; I applied nearly all of them. Where the record does not know something, this compile says so. Throughout, “I” is me and “we” is the team. What changed on 14 November. I changed the lens to the seven metrics and asked for the ideas that lived only in chat. Agents read all 376 M messages I typed in 59 M saved sessions and matched 113 M ideas, observations and requests against the records: 5 M were missing and are now recorded, and one measurement that no record held (MSR-50) joins them: six new ideas, 484 M in all. Eight classifier agents sorted all 606 M earlier records by metric and cause, and a blind second reading agreed on the main metric for 80 of 101 M. Idea records otherwise describe where things stood on 13 November, except those of the split idea (PAR-22, TOK-44, TOK-02, TK-FILL, TK-SUMMARIES, PR-HALLU and package WP12), which carry what WP12 finished on 14 November: the rule, its replay and the set-up of the trial I approved.
