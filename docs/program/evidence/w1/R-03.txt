SUMMARY: 

[F1] (web, fetched=true) Publishing an app via Cloudflare Tunnel requires a domain already added to Cloudflare; the server must reach Cloudflare on port 7844 (outbound).
    - https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/get-started/create-remote-tunnel/
[F2] {Outbound-only implies it works behind CGNAT/dynamic IP; not stated on the page} (web, fetched=true) cloudflared initiates an outbound connection from origin to Cloudflare; all inbound traffic can be blocked at the firewall. (Page did not mention CGNAT explicitly.)
    - https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/
[F3] (web, fetched=true) Zero Trust account limits page: 1,000 cloudflared tunnels per account, 25 active replicas per tunnel, 500 Access applications default; Free accounts 50 custom Application Library apps. No free-plan seat figure on that page.
    - https://developers.cloudflare.com/cloudflare-one/account-limits/
[F4] {Free tier = 50 seats; verify on cloudflare.com/plans/zero-trust-services before relying} (web, fetched=false) Free Zero Trust plan seat limit: search snippets say Cloudflare's pages state 'up to 50 users' on the Free plan (Access page: 'Try it forever for up to 50 users'). Official pages fetched directly did not state the number; only search-result snippets.
    - https://www.cloudflare.com/en-gb/sase/products/access/
[F5] (web, fetched=true) Caddy automatic HTTPS: needs A/AAAA DNS pointing to server and ports 80/443 reachable for HTTP/TLS-ALPN challenges; DNS challenge needs no open ports but needs DNS provider credentials; data dir must be persistent.
    - https://caddyserver.com/docs/automatic-https
[F6] (web, fetched=true) Cloudflare Origin CA certs only encrypt Cloudflare-to-origin traffic, are not browser-trusted, work with Full (strict) mode, and Cloudflare sends no expiry notifications; validity chosen at creation.
    - https://developers.cloudflare.com/ssl/origin-configuration/origin-ca/
[F7] (web, fetched=true) pg_dump can dump servers back to 9.2 but refuses a server newer than itself; dump output is expected to load into newer versions; loading into an older server is not guaranteed and may need manual editing.
    - https://www.postgresql.org/docs/17/app-pgdump.html
[F8] (web, fetched=true) pg_dump is a logical backup and cannot be used for continuous archiving/PITR; base backup + WAL archiving gives PITR, whole-cluster only; docs say continuous archiving is preferred where high reliability is needed; test archiving before first base backup and inspect data after recovery; unmonitored archive_command failure can fill pg_wal; config files are not captured.
    - https://www.postgresql.org/docs/17/continuous-archiving.html
[F9] (web, fetched=true) pgBackRest supports full/differential/incremental backups, parallel async WAL push/get, retention policies, and ten PostgreSQL versions (five current plus last five EOL).
    - https://pgbackrest.org/
[F10] (web, fetched=true) R2 free tier (Standard storage): 10 GB-month storage, 1 million Class A ops/month, 10 million Class B ops/month, egress free; not applicable to Infrequent Access.
    - https://developers.cloudflare.com/r2/pricing/
[F11] (web, fetched=true) github.com/minio/minio is AGPLv3 and its README says 'THIS REPOSITORY IS NO LONGER MAINTAINED'; archived 2026-04-25; community edition source-only, no new binaries; alternatives named are AIStor Free and AIStor Enterprise. Docs URL 301-redirects to docs.min.io/enterprise/aistor-object-store. MinIO resource needs not retrieved.
    - https://github.com/minio/minio
[F12] (web, fetched=true) GlitchTip: needs PostgreSQL 14+, a GlitchTip service (all-in-one or web+worker), optional Valkey/Redis 7+; recommended 512 MB RAM, minimum 256 MB all-in-one; ~30 GB disk per ~1M events/month; sample compose.yml provided.
    - https://glitchtip.com/documentation/install
[F13] (web, fetched=true) Uptime Kuma ships compose.yaml in repo; image louislam/uptime-kuma:2 on port 3001; can bind to 127.0.0.1; NFS storage unsupported; no RAM requirement listed on page.
    - https://github.com/louislam/uptime-kuma
[F14] (web, fetched=true) Docker restart policies: no (default), on-failure[:n], always, unless-stopped; unless-stopped keeps manually stopped containers stopped across daemon restart/reboot; policy applies only after container has run 10 seconds.
    - https://docs.docker.com/engine/containers/start-containers-automatically/
[F15] (web, fetched=true) PostgreSQL docs: fsync=off can cause unrecoverable corruption after power failure; full_page_writes=off risks corruption; synchronous_commit=off loses recent commits but not consistency (up to 3x wal_writer_delay window).
    - https://www.postgresql.org/docs/17/runtime-config-wal.html
[F16] (web, fetched=true) Docker published ports are diverted in the nat table before ufw rules apply, so ufw is effectively bypassed for published container ports.
    - https://docs.docker.com/engine/network/packet-filtering-firewalls/
[F17] (web, fetched=true) Docker daemon runs as root unless rootless; only trusted users should control it; containers can mount host / without restriction. Page does not literally say 'socket access equals root'.
    - https://docs.docker.com/engine/security/#docker-daemon-attack-surface
[F18] {Needs direct ISP confirmation or a home-line test (compare router WAN IP with public IP)} (web, fetched=true) Q7 (Pakistani ISPs): search found no authoritative source on CGNAT or static-IP policy for PTCL, Nayatel, StormFiber or Transworld, and no upload-bandwidth figures. Only anecdotes: a forum user says Nayatel gives a static IP on request; another says PTCL changes public IP daily. Both unverified.
    - https://en.wikipedia.org/wiki/Nayatel
