# R-01 — R-01 Android OEM background / geofencing platform and vendor behaviour

SUMMARY: 

[H1] (web, fetched=true) Android 8+: background apps receive location updates only a few times each hour; no exact number given. A foreground service, or a foreground app, lifts the limit. Geofencing average responsiveness is 'every couple of minutes or so'.
    - https://developer.android.com/about/versions/oreo/background-location-limits
[H1] (web, fetched=true) Location docs restate: Android 8.0+ background apps get location 'only a few times each hour'. On Android 11+, a foreground service started while the app is in the background cannot access location unless ACCESS_BACKGROUND_LOCATION is granted.
    - https://developer.android.com/develop/sensors-and-location/location/background
[H2] (web, fetched=true) Android 12+ background FGS-start exemptions include: app receives a geofencing or activity-recognition transition event; ACTION_BOOT_COMPLETED / LOCKED_BOOT_COMPLETED / MY_PACKAGE_REPLACED in a receiver; user turns off battery optimizations for the app; high-priority FCM; SYSTEM_ALERT_WINDOW.
    - https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start
[H2] {Whether the 'location' type is on the Android 14 boot-receiver blocked list was not verified in this run; needs a direct fetch of the full page section.} (web, fetched=true) Caveat on the same page: for apps targeting Android 14+, there are restrictions on launching certain foreground service types from a BOOT_COMPLETED receiver (the fetch summary did not enumerate which types; location not confirmed either way).
    - https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start
[H3] (web, fetched=true) From Android 14 (API 34) every foreground service must declare a type. Location type needs android:foregroundServiceType="location", FOREGROUND_SERVICE and FOREGROUND_SERVICE_LOCATION permissions, location services enabled, and at least one of COARSE/FINE granted. The page says (per fetch summary) a location FGS cannot be created while the app is in the background unless ACCESS_BACKGROUND_LOCATION is granted.
    - https://developer.android.com/develop/background-work/services/fgs/service-types
[H3] {Missing-type exception name is inferred, not documented on the fetched page.} (web, fetched=true) The service-types page did not name the exception thrown for a missing type; the fetch summary only suggested MissingForegroundServiceTypeException from general knowledge. ForegroundServiceTypeNotAllowedException is documented for declaring an ineligible type. The same page suggests the geofence API as the alternative when only location-triggered work is needed.
    - https://developer.android.com/develop/background-work/services/fgs/service-types
[H8] (web, fetched=true) Geofencing guidance: minimum radius 100-150 m; Wi-Fi accuracy 20-50 m, assume about 50 m indoors; rural/no-Wi-Fi accuracy can degrade to hundreds of m to km. Alerts usually under 2 minutes, average 2-3 minutes under background limits, up to about 6 minutes when stationary a long time.
    - https://developer.android.com/develop/sensors-and-location/location/geofencing
[H8] (web, fetched=true) GEOFENCE_NOT_AVAILABLE 'typically happens after NLP (Android's Network Location Provider) is disabled'; the app must re-register geofences. The page does not mention 'Google Location Accuracy' by name and does not cover location-mode-off directly. Geofencing depends on network location; without Wi-Fi/data connectivity alerts may not arrive.
    - https://developer.android.com/develop/sensors-and-location/location/geofencing
[H9] {Force-stop behaviour is undocumented here; likely clears registrations but unverified in this run.} (web, fetched=true) Geofences are not recovered after reboot (app must re-register on boot-complete), nor after uninstall/reinstall, app data clear, or Google Play services data clear. They are restored after Play services upgrade/restart or location-process crash. Force-stop is not addressed on the page.
    - https://developer.android.com/develop/sensors-and-location/location/geofencing
[H10] (web, fetched=true) App hibernation (Android 11+ targets; Android 12+ extra effects): runtime permissions reset as if user chose Deny; app cannot run background jobs or alarms; cannot receive push including high-priority FCM; cache files removed. Trigger is 'a few months' of no user interaction (no exact figure). Scheduled jobs, implicit broadcasts and alarms do not count as use.
    - https://developer.android.com/topic/performance/app-hibernation
[H10] (web, fetched=true) Opt-out is user-mediated: check getUnusedAppRestrictionsStatus(), then launch IntentCompat.createManageUnusedAppRestrictionsIntent() via startActivityForResult; toggle named e.g. 'Pause app activity if unused' on Android 13+. Legacy isAutoRevokeWhitelisted() covers Android 11+ only. System-exempt: device policy controllers, carrier-privileged apps, work-profile apps, apps with no launcher shortcut.
    - https://developer.android.com/topic/performance/app-hibernation
[H10] (web, fetched=true) Permissions guide: for apps targeting Android 11+ unused 'for a few months', sensitive runtime permissions are auto-reset; apps should re-check a permission before each use rather than assume it persists.
    - https://developer.android.com/training/permissions/requesting
[H11] (web, fetched=true) Xiaomi/MIUI (dontkillmyapp): default settings break background processing. Lock: drag app down in recents tray, or long-press padlock. Autostart (MIUI 14): Settings > Apps > app > App permissions > Background autostart; older: Security > Permissions > Auto-start. Battery: Security > Battery > App Battery Saver > app > No restriction. Also 'Keep running after screen off', and hidden MIUI Optimizations toggle in Developer options may break background tasks. Page covers MIUI only, not HyperOS.
    - https://dontkillmyapp.com/xiaomi
[H11] (web, fetched=true) Oppo/ColorOS (dontkillmyapp, data for Oppo F1S only): background services killed every time the screen turns off. Fix needs four steps: enable auto-start in app info (ColorOS 6) / startup manager and floating app list; disable battery optimization; App info > Battery usage > Run in background and Power Saver mode allow background; pin app in recents.
    - https://dontkillmyapp.com/oppo
[H11] (web, fetched=true) Vivo (dontkillmyapp): restrictions 'not fully uncovered'. Autostart: Settings > More settings > Applications > Autostart (FuntouchOS 2.6 and lower: i Manager > App manager > Autostart manager). Settings > Battery > High background power consumption: enable app. Battery optimization must be 'Not optimized'. Lock via recents sub-menu 'Lockdown' or swipe icon down to padlock. No OriginOS-specific content.
    - https://dontkillmyapp.com/vivo
[H11] (web, fetched=true) Realme UI (dontkillmyapp): Power saving may terminate background processes; Super power saving allows at most 6 apps; Smart Performance Mode may break background processes; App quick freeze stops background running and notifications for listed apps. Settings > Battery > Power saving settings > App battery management > app: Allow auto-launch, Allow background activity, Allow foreground activity. Lock-in-recents not covered.
    - https://dontkillmyapp.com/realme
