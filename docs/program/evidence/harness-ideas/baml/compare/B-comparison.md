## 3. Where BAML's structure is better for a sub-step

1. **Typed skeptic input.** Static: the prompt builder cannot carry other fields. Same property today: a pure `skepticInput(finding)` returning `{claim, evidence, failing_condition}` plus a replay test that the rendered prompt omits `impact`, `fix_sketch`, `confidence`, `severity`. Cost: ~10 lines; runtime, not compile-time.
2. **Exhaustive `match` over verdicts.** Same property today: one table `{CONFIRMED:'verified', PARTIALLY:'verified', UNVERIFIABLE:'open', REFUTED:'refuted'}` from which the schema enum is generated (`Object.keys`), so schema and buckets cannot diverge; citation status folded in the same way. Cost: ~15 lines. The check is at test time, not compile time, which matters because the bucket step runs after the spend.
3. **Typed failures instead of `null`.** The one property not available without changing the Workflow tool: the script sees only `null` (P:44-50), and a schema-failure `null` would count as a "fresh null" toward the session-limit breaker (D:205), UNKNOWN whether that happens. Partial remedy today: have `run()` return a tagged result (`null` versus caught error message, D:228). On Route A BAML's types are coarse anyway.
4. **Test runner for pure steps.** Same property today: run the script body under `node` with stub `agent`/`parallel`/`log`/`phase` (the skeleton uses top-level `await` and `return`, D:241, 251, so it is a function body; INFERRED, untried). Scripted nulls exercise HALT, `not_started`, retry labels, cap overflow, bucket totality, with no model spend. Cost: ~40 lines.
5. **Reads derived from events** (Route B's `ToolRequested`, A§2). Today's equivalent exists only if subagent transcripts are readable (UNKNOWN).

Nothing else I found: SAP, `schema_attempts`, `Fallback`, and the agent loop add nothing P lacks on the subscription route.

## 4. The decisive differences

1. **The route fork collapses BAML's structure.** P needs three things together: the owner's subscription (P:51-53), an agent that reads a live repo, and per-step effort (D:88, 97). Route A has the first two and loses effort (no `--effort`, verified) and observability (one model call, verified); Route B has neither subscription nor Claude Code's tools. On Route A BAML becomes a second orchestrator around the same `claude -p` loop Workflow already drives, with a second schema pass (`--json-schema`, then SAP) on top. Evidence for BAML: typed signatures and offline tests are real. Evidence against: the part P cannot use is the part that is distinctive.
2. **Resume.** Workflow has journaled cached-prefix resume designed around a recorded mid-run loss (D:586-587, P:61-64); the BAML runner has none (verified for `runner.baml`). Building it is feasible (INFERRED) but is exactly the bookkeeping that already produced three defects.
3. **Silent omission versus whole-object validation.** Today a malformed `findings[]` element fails the call; in BAML v1 a refused list element is dropped with exit 0 (verified for the tested case). Counter-evidence: on Route A `--json-schema` may pre-empt this (UNKNOWN), and a declared-count field is a known mitigation (A§5.4, INFERRED). Today has its own gap: D:219 and D:487 still say findings are "sliced to 12" with a logged count, against D:292 and D:792 (no truncation).
4. **Pure-step testing.** BAML's strongest structural advantage for P, because the recorded defects were in control flow. Weakening fact: the same property is reachable with a stub harness (§3.4), so it argues for a harness, not for BAML.
5. **Maturity and footprint.** Pre-1.0 canary line, client unreleased in docs (A§4), Windows UNKNOWN, a second local store of repo excerpts. Today: zero install. Lowest rank because the first four already decide it.

## 5. What the current structure could borrow structurally

1. **Tagged `run()` results** (null, caught error, value) so the breaker counts only suspected-limit nulls. Cost ~10 lines. Measure: a stubbed run injecting one schema error and two nulls halts only on the nulls.
2. **One constants table** generating schema enums and bucket mapping. Cost ~15 lines. Measure: adding a verdict to the table without a bucket fails the stub test.
3. **Stub harness for the script body.** Cost ~40 lines, zero spend. Measure: re-introduce each of the three recorded bookkeeping defects (`not_started` on HALT, swallowed catch, cached null re-served; P:61-64); the harness must fail on all three.
4. **A pure prompt-input boundary** for the skeptic with a replay test (§3.1). Cost ~10 lines. Measure: the test fails when a forbidden field is added.
5. **Transcript-derived read audit**, if subagent transcripts are readable. Cost: UNKNOWN until checked. Measure: mismatch rate between self-listed extra reads (D:533-535) and the transcript on one analyst.
