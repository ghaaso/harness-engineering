# A5 option 2: causal replay into exact traces
Lens: graph first; this option departs from it. Time is collapsed before the network sees anything.

**Mechanism.** One pass over each repository's main line, in the order commits reached it (D6), keeps for every pair of files (s, c) and relation kind r exponential traces on the commit clock:

T_{s,c,r,k}(t) = T_{s,c,r,k}(t') * exp(-(t - t')/tau_k) + sum of g(n_e) over new events e linking s and c by r

with g(n) in {1, 1/n}, a fixed bank of tau_k, plus the time since the last joint event and since the candidate's last change. At each asking time the state is read off. The state at t_q is a function only of events replayed before t_q: what was known is guaranteed by the order of the pass, not by a mask. The network reads, per candidate, log(1 + T) per k and r, relative to the starting file's trace with all files, and learns a readout. Decay fixed; readout learned. This is the flat table D14 derives.

**Needs from other parts.** A1: event sizes. A3: per-pair traces in place of event nodes. A4: relation kinds. A6: candidates with no trace get zeros and are ranked by content and structure. A9: the pass computed once on processors (N 14.4).

**Can.** M2 by construction: the decayed one-over-size count is one trace, exactly, with nothing to learn. M4 by construction and auditable: the D13 test "inputs cut at the asking time equal inputs from the whole store" is the pass stopped at t_q. M3 by construction: commit clock, relative traces. M7 by construction: K numbers per co-occurring pair; network cost independent of history length.

**Cannot.** Anything not a sum of per-event decayed contributions. Counterexample: ten joint changes inside one pull request and ten in separate pull requests give equal traces if commits are counted alike; an old event's content cannot change its weight; a time constant outside the bank cannot be learned. This is the lossy projection of D 9.2 and D 4.3. Nearest veto W2: not met, sums keep counts. W4: not met, no window. W7: traces carry the graph one hop only, so A6 must supply structure.

**Rests on.** N 14.4, N 9.5, N 13.9; D 6.2, D 9.2, D 9.4, D 4.3; record: `research-tree/build/improve/units/T3/report.md` (tree ranker over count and age features leads; the graph part added nothing over count features); assumption: on the change question history's value lies mostly in decayed per-pair counts, as that record suggests; count first: pairs with traces per repository, for memory.

**Refuted if.** Option 1, reading event nodes with content and size, beats this on held-out repositories by more than the spread between repositories, among right files with earlier joint change.
