# A5 option 1: as-of kernel bank, ranker mixes
Lens: exact relational computation first; what can be computed exactly from the store relative to the question is computed, and a learned ranker reads it.

**Mechanism.** Every fact carries the time it became visible (D6: main-line arrival). For a question asked at t_q the feature code has one access path: the view V(t_q) of facts visible before t_q. Ages use two clocks in the repository's own scale: a_ord(e), main-line units between e and t_q; a_wall(e) = (t_q - v_e) / g_R, g_R the median gap between units of R before t_q. For starting file s, candidate c and a fixed geometric bank tau_1 < ... < tau_K:

C_k(s,c) = sum over e in V(t_q), s and c in F_e, of w(n_e) exp(-a(e)/tau_k), with w = 1 and w = 1/n_e as separate columns.

Also exact: the candidate's own decayed activity M_k(c), so coupling is not confused with churn; ages of the last joint change, of the candidate's last change and of its creation; directed order L_k(s->c), the decayed count of units with c shortly after a unit with s, and the reverse. Exponential kernels update lazily and exactly (store value and time, scale by exp(-shift/tau_k) when read), so one pass in time serves every asking time. The ranker reads the columns relative to the repository's distribution at t_q. Decay is both: shapes fixed, mixture learned. A non-negative mix represents any curve that is a mixture of exponentials within the bank's range (assumption, from Bernstein's theorem on completely monotone functions).

**Needs from other parts.** A3: combining over the starting set. A1: relative scaling. A7/A8: a ranker reading columns. A9: the one pass keeping pair states.

**Can.** M2 by construction: the decayed, size-weighted joint count is C_k with w = 1/n_e, exactly. M4 by construction: one filtered access path; D13's test (cut store equals whole store) applies directly. M3 by construction for time: ages relative to the repository's pace, no identity. M1 in part: relative to the starting files, not the question's text.

**Cannot.** Represent a decay that is not monotone. Counterexample: two files changed together at every release, every six months; their coupling peaks at one cycle's lag, and no mix of decaying exponentials weights six months above one week. Order patterns longer than one step (A, B, then A) are absent. One mixture serves all repositories unless the ranker conditions on pace. Nearest veto W4: no window; every visible event enters. W10: amounts relative, never raw.

**Rests on.** D 9.1, D 9.4, D 6.2, D 6.4, D 4.4, D 7.5, D 8.1; N 9.5, N 13.9; record: `research-tree/build/improve/units/T3/report.md` items 2, 4, 8 (window, churn); FACTS: one-over-size and decay carried counting. count first: the spread of g_R across repositories; the share of joint changes older than the longest tau.

**Refuted if.** On validation repositories, an empirical lag curve per repository (option 3) or a learned time function (option 2) on the same events raises per-repository ranks beyond the resampling intervals; or a leak test finds a fact dated at or after t_q.
