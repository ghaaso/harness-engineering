# A7 option 1: exact denominator, listwise loss, baseline offset
Lens: exact relational computation first; what can be computed exactly from the store relative to the question is computed, and a learned ranker reads it.

**Mechanism.** Output: one real score per candidate, s(q,c) = b_k(q,c) + f_θ(x(q,c)). x is the exact pair vector. f_θ: any ranker trained by a gradient per row. b_k is a fixed offset, the D12 baseline of question kind k in log form: log(ε + decayed one-over-size joint count) for a change; log(ε + BM25), plus a constant for named files, for task words; trace depth for an error.
- *Candidates* U(q): every file alive at t, plus one slot per folder ("a new file belongs here"). A slot's x: decayed count of earlier units adding a file there with a starting file; sum and maximum of its files' x; BM25 of its path. An added file labels its folder's slot.
- *Negatives.* R(q) holds candidates with any non-zero relational feature; R(q) \ P(q) is taken whole. The rest: a Poisson sample, each c drawn alone with known π_c = min(1, κ[λ/|rest| + (1-λ) softmax(BM25/T)_c]) > 0. Right files P(q) are never negatives.
- *Loss.* Each right file against the wrong files only:
  L(q) = -(1/|P|) Σ_p log[ e^{s_p} / (e^{s_p} + Z) ],  Z = Σ_{R\P} e^{s_c} + Σ_{sampled} e^{s_c}/π_c,
  Z a Horvitz-Thompson estimate of the total over all wrong files.
- *Weights.* w_q = min(1/n_R, β): equal total per repository, bounded per example (D11). Steps of one pull request share one weight; bulk-flagged questions weigh zero. β, κ, λ, T set on validation repositories.

**Needs from other parts.** A1.c.1, A2.a.2: x with relative amounts. A3.c.1, A4.c.1, A5.c.1: exact kernels and path counts at the cut, which define R(q). A8: the family of f_θ. A9: x computed once.

**Can.** M7 by construction: every right file ranked against every wrong file, negatives never right files of q, weights and π by design. M2 by construction: the offset is the exact count. M1 by construction through x. M8 in part: f_θ = 0 is the baseline on the same examples. M6 in part: far files enter Z; new files get slots. M3 by construction.

**Cannot.**
- Aim at the top ten: moving a right file from rank 500 to 50 can lower L more than from 12 to 3.
- Be unbiased: log of an unbiased Z is biased low (Jensen).
- Tell unlabelled right files from wrong: a file fixed in the next pull request is a negative. Nearest W9; not under it, as it is no right file of q (D8); it is label noise.
- Name a new file, or place one in a folder not yet made.

**Rests on.** D 3.2, N 13.6, D 6.2, D 7.2, D 8.1, N 9.5. Record: `research-tree/build/improve/units/T3/report.md` items 1, 7 (historical negatives, 0.141 to 0.007). Assumption: that fall came from negatives that over-weight earlier partners; R(q) whole keeps the real mix. Count first: |R(q)|; share of e^s outside R(q).

**Refuted if.** Per validation repository, uniform uncorrected negatives of equal number score the same; or f_θ adds nothing over b_k on unseen repositories.
