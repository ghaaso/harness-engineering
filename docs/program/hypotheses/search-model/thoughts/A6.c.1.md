# A6 option 1: exact reach columns for every file
Lens: exact relational computation first; what can be computed exactly from the store relative to the question is computed, and a learned ranker reads it.

**Mechanism.** On the store cut at the asking time, for every file alive:
- *Seeds* sigma_k: the starting files of kind k. For task words, also the files defining a name in the text (D5) and BM25 scores, normalised.
- *Reach by any path.* For fixed relation groups g (code links, both directions; joint change weighted 1/n_e exp(-a_e/tau) as in A3.c.1; folder tree; all) and a fixed bank of restart rates alpha: pi_{k,g,alpha} = alpha sum_m (1-alpha)^m sigma_k P_g^m, by repeated sparse products (N 2.3). Beside it: pi over c's stationary mass (the walk's degree bias removed, D 2.9), and the hop distance from c to the seed set (the question's files as anchor set, N 10.5).
- *Echo of past work:* E(c) = sum over past units u of BM25(q, text_u) [c in u] / n_u: question, similar earlier unit, file.
- *Content:* BM25; matched names and path strings; maximum cosine against every chunk of c under A1's frozen encoder.
A learned ranker reads these columns beside A1.c.1 and A4.c.1 features and scores every file alive plus one "new file here" entry per folder. The reader of A2 rescores its top K; the rest keep this order, so every file alive has a rank.

**Needs from other parts.** A1.c.1 (BM25, names, frozen encoder, relative amounts); A3.c.1 (event weights); A4.c.1 (typed adjacency, two-hop counts); A5.c.1 (the cut view); A2.b.1 (the reader of the top K); A7 (loss over all files, the "new file" entry).

**Can.** M6 by construction for a file joined to a seed by a path of any length, or by a word, a name or a similar past unit. M1 by construction: every column depends on the question. M2: P_g is linear in edge weights, so counts pass; the exact count stays A3's column. M3 by construction: no learned coefficient per hop, no identity. M7 by construction: O(E) per product.

**Cannot.** Keep the order of kinds along a route: test, import, import gets the same mass in "all" as any route of equal weight. Reach a file with no link, word, name or echo: a config key built by joining strings, where only folder proximity remains. Nearest veto W1: a file reached only by cosine is scored from two vectors computed apart; the joint reader repairs that only inside the top K. Not W5: reach is computed, not learned.

**Rests on.** N 2.3, N 9.5, N 10.5, N 11.3, N 14.2, N 14.4; D 2.8, D 2.9, D 9.4; FACTS (30, 66, 21 % without joint history). count first: per repository, the share of right files at zero in every reach column.

**Refuted if.** On validation repositories, among right files with no joint history and no two-hop path, adding the reach and echo columns does not raise their rank over BM25 and cosine alone.
