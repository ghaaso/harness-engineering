# A4 option 2: question-marked relational message passing
Lens: exact relational computation first. This option departs from it: compositions are learned, not enumerated.
**Mechanism.** On the question's neighbourhood (store cut at the asking time) the start files carry a one-hot of their kind in Q = {in change, named in text, in trace}; other files carry zeros (marking the root, N 9.10). Three layers of relational message passing, sum aggregation, no degree normalisation:
h_v' = sigma( W_0 h_v + sum over r, u in N_r(v) of (sum_b a_rb V_b) h_u * phi(e_uv) ),
R the 12 directed kinds of option 1 (a kind and its reverse separate), V_b B shared basis matrices, a_rb per-kind mixing weights (N 13.2), phi(e_uv) the edge's amounts (event size, age). Log degree per kind is an input, so hub size stays visible. The score is read from h_c. Parameters: B matrices plus 12B weights; a new kind costs B numbers.
**Needs from other parts.** A1: content encoding, relative amounts. A3/A5: phi. A6: the retrieved set, hub sampling. A7: loss, negatives. A9: memory for three hops.
**Can.** Learn compositions of kinds up to three steps and join a kind with content: "imports the start file and names the symbol the diff edits" is a function of the marked graph that option 1 cannot express. M1 by construction (the marks make vectors relative to the question). M5 by construction at bounded parameters; it is not a knowledge-graph score, so N 13.8's limits do not bind. M3 by construction. M2 open on a test: sums can carry the decayed count; whether training reproduces it is read off the vectors on held-out questions. M6 in part, three hops.
**Cannot.** Keep exact counts when a hub is sampled: a 2,000-file folder under neighbour sampling gives a count with variance, under subgraphs a bias (D 2.10, N 14.2, N 14.3). Avoid over-squashing through hubs (N 11.1). Separate mirror-placed candidates with equal content (N 9.6). Transfer as depth and width grow (N 8.4). Nearest veto: W5; not under it, as depth stays three and far reach is A6's. W1 is avoided by the marks.
**Rests on.** N 9.5, N 9.10, N 13.2, N 13.3, N 13.9 ("learnable version of hand-crafted features"; "information which is hard to pre-compute"), N 11.1, N 14.2; D 2.10; record: `research-tree/build/improve/units/T3/report.md` item 3 (an unmarked, mean-aggregated graph model fell below counting without count features; this differs in both). assumption: the material forces the departure: option 1's two-hop limit and blindness to content in a link are what N 13.9 says a learned aggregation adds.
**Refuted if.** Without count features it does not reach counting on the change question; or its vectors do not reproduce the decayed joint count on held-out questions; or it adds nothing over option 1 on right files at three hops.
