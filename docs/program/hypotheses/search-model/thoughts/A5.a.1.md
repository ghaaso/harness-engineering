# A5 option 1: decay bank on edges to the question
Lens: graph first. The model computes on the typed neighbourhood handed over by the data, with the question as a node of it.

**Mechanism.** No absolute date enters the model. Every event node e (unit of work, commit) carries its age relative to the question node q on two clocks: commit age c_e, the number of main-line commits between e and q; and wall age t_q - t_e divided by the repository's median gap between main-line commits before t_q. Both are in the repository's own pace. A message of relation r from an event to a file it touches is

m_e = phi_r(h_e, enc(c_e)) * w_r(c_e),   w_r(c) = sum_k softplus(alpha_{r,k}) * exp(-c / tau_k)

with a fixed bank of time constants tau_k (geometric, a few commits to the whole history), learned non-negative mixing weights per relation kind, and enc a learned age encoding (the message times an embedding of the fact's time, S12 slide 62). Messages are summed. Decay is both: shapes fixed, mix learned. Order comes from ages; in a pull request asked step by step, a later commit is absent until revealed.
Known at the asking time, three locks: the loader serves only facts dated before t_q (D6, D 9.4); the model drops any event with age <= 0; every scale statistic is computed from history before t_q. The model keeps no state across questions (no memory module).

**Needs from other parts.** A1: each event's size as an input (1/n exact). A3: sum over all linking events, no window. A4: relation kinds. A9: per-pair traces kept per tau_k.

**Can.** M2 by construction: the decayed one-over-size count is phi = 1/n_e with alpha one-hot on the counting baseline's tau, if the bank holds it. M4 by construction for the model's part. M3 by construction: ages on the repository's clock carry across paces. M7 open on a count: exponential sums update recursively, S(t) = S(t') e^{-(t-t')/tau} + new, so all history fits in K numbers per pair. M5 in part: K weights per kind.

**Cannot.** A non-negative mix of exponentials is monotone: relevance peaking at middle age (a release cycle) is outside it. enc bends the shape only within ages seen in training and cannot extrapolate past them (D 8.1). Nearest veto W4: avoided, traces cover the whole history. W2: avoided by summing.

**Rests on.** N 9.5, N 13.9, N 14.2; D 6.2, D 9.1, D 9.4, D 2.10; record: `research-tree/build/improve/units/T3/report.md` (memory form scored change frequency; a 20 to 32 event window lost counts); assumption: a joint change matters less with age on the repository's clock, as the decayed counting baseline shows; count first: the best counting form's decay constant, and events per linked pair.

**Refuted if.** Equal weight on all events, ages removed, scores the same on held-out repositories; or the wall clock alone equals the commit clock on repositories whose pace differs most from training.
