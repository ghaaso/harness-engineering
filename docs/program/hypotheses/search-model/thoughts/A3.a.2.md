# A3 option 2: fixed history statistics computed once
Lens: graph first; this option departs from it. History does not pass through the network; the loader computes it.

**Mechanism.** For each pair (starting file s, candidate c), from the store cut at the asking time, the loader computes a fixed bank of statistics and hands them to the scorer as numbers:
- C[p, tau] = sum over joint events e of n_e^(-p) * exp(-a_e / tau), with p in {0, 1/2, 1} and tau spaced by factors of four from a day to several years.
- The same sums over c's own events and over s's own events (activity), giving the rates C / A_s and C / A_c in both directions.
- The age of the last joint event, the number of distinct units of work shared, and the share of them flagged bulk.
- Each amount divided by the repository's scale of the same statistic (D14).

Over the starting set: the sum and the max of each. A decay kernel that is a mix of exponentials in the grid's range is a linear function of the bank.

Why depart: N 14.4 (a diffusion without nonlinearity is computed once and fed to any model); D 7.5 (rolling statistics make time patterns available to plain models); the record (the count features carried the whole score; the graph part added nothing).

**Needs from other parts.** A1: the scale per statistic. A5: the asking time and the cut. A7: a scorer, network or tree ranker, taking this vector beside A2's description.

**Can.**
- M2: exact on the grid; between grid points a small relative error (neighbouring decays differ by four). Open on a named test: the best single decay found on validation lies inside the grid.
- M3 by construction: relative amounts, no identities.
- M4 by construction, and checkable statistic by statistic with the D13 test (cut store equals whole store).
- M7: the cheapest form; computed once on ordinary processors, no neighbour sampling in training.

**Cannot.**
- Learn an event weighting outside the bank. Counterexample: joint changes in a reviewed pull request may count more than in a direct push; unless that split was foreseen as a statistic, no scorer recovers it, because what was aggregated away is lost (D 9.2, D 4.3).
- Let the question weigh past events.
- Reach files with no joint history.
- Nearest vetoes: W12, not under it, since the grid is set by argument (hours to years at a fixed ratio), not by a sweep; W10, avoided by relative amounts.

**Rests on.** N 14.4, N 9.5, D 7.5, D 9.2 (its limit), D 6.2, D 9.4. record: research-tree/build/improve/units/T3/report.md items 1, 3; FACTS-MODELS-SO-FAR.md (the one-over-size weight carries much of counting). count first: the spread of ages of joint events per repository, to place the grid's ends.

**Refuted if.** Option 1, or any learned event weighting, beats this bank on pairs with earlier joint change, on the same examples, by more than the interval between repositories.
