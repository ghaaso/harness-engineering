# A6 option 3: descent through the folder tree
Lens: graph first. The route to a far file is the repository's own hierarchy (N 12.4), not a retrieved list.

**Mechanism.** The folder tree at asking time t is a given hierarchy. For each node a, a cheap question-relative score g(q,a) is read from sums over the files under a:
- sums of its files' channels: BM25, symbol matches with q, A3's exact kernels to the starting files, A4's path counts. These are sums, so counts pass (N 9.5);
- the best question-chunk cosine below a (A1's frozen vectors);
- a's path and the names its files define, read jointly with q by the scorer of A2 at the top levels only;
- a's size as a percentile within the repository.
Every file v alive gets a probability, with no candidate cut:
log P(v | Q) = sum over the ancestors a of v, v included, of log softmax over a's siblings of g(q,a).
It is exact over all files, at cost linear in the number of nodes, because g is cheap. A file with no signal of its own inherits its folder's mass: the unimported cache config sits under a folder whose files answer q.
*Candidates.* The joint scorer (A2) re-reads the files with the highest P(v|Q), up to a budget set on validation. Every other file keeps its rank by P.

**Needs from other parts.** A1.a.1 chunk vectors; A2.a.1 or A2.b.1 inside the budget; A3.c.1 kernels; A4.c.1 path counts; A5.c.1 as-of view; A7 a loss over the factorised probability, with sibling negatives drawn with known probabilities; A9 per-folder sums once per question.

**Can.** M6 by construction for files whose folder carries the signal: reach is O(depth) steps, never L stacked hops (N 11.3, N 12.4). Every file is ranked by one score; no fallback for the tail. M1 by construction: g is relative to q. M2: the sums keep exact counts. M3: no identities; folders are read by content, not by name. M4: tree and sums cut at t.

**Cannot.** Help a flat repository: one folder of 3,000 files is one softmax, and the descent adds nothing. Follow a module that is spread across folders. Counterexample: a feature in `api/`, `ui/` and `db/`, each folder diluted by unrelated siblings. Recover from a wrong turn high up: a low score near the root lowers every file below it. The partition (N 12.4) is the repository's, maybe not its modules. Nearest veto W2: the softmax runs over sibling scores, never over history, which enters as sums. W5: no stacked local steps.

**Rests on.** N 9.5, N 11.2, N 11.3, N 12.4, N 5.4; D 9.4. FACTS: 30, 66 and 21 % of right files have no joint change. assumption: right files cluster in folders that the question's words reach. count first: per repository, the depth and fan-out of the tree, and the share of right files whose folder holds another file with a content or history signal.

**Refuted if.** On validation, among far right files, P(v|Q) places no more of them in the top budget than option 1's f0. Or a flat softmax over the same file channels ranks them as well.
