# A1 option 3: words as nodes, no pretrained encoder
Lens: graph first. The model computes on the typed neighbourhood handed over by the data, with the question as a node of it.

**Mechanism.** Text enters as structure.
- Subwords are split from the facts of D5 (defined names, used names, imports as written, comments, strings) and from the question text, by camelCase, snake_case, dots and spaces. Each distinct subword in the repository at t is a `term` node.
- Edges: question to term (contains). File to term, with separate kinds for defines, uses, path and comment. Each edge carries its term frequency. Each term carries the repository-relative inverse document frequency log(N_t/df_t), counted over files alive at t.
- Each term also carries a trained embedding over a hashed subword vocabulary, shared by all repositories.
- Question to term to file is a path of two hops. Sum aggregation with the tf and idf weights can reproduce a BM25-like lexical score exactly. It can also learn which kinds of term edge count, and closeness between different words.
- Terms above a fixed share of files are features of the question with no edges, because hubs explode the computation graph (N 14.2).
- Events, amounts, typed links, structure features and the repository node are as in option 1. There is no pretrained part, so no encoder cut-off limits the test date (D7).

**Needs from other parts.** A4: term edges as kinds, aggregated by sum. A6: question to term to file treated as a reach path. A9: the term graph built once per tree, keyed by content hash.

**Can.** M6 in part, by construction: a file with no history and no code link to the starting files is two hops from the question through shared words. M3 by construction: no file or repository identity, and idf is relative. M4 by construction: terms and counts come from the tree at t. M1 in part: the terms a question holds change which files it reaches.

**Cannot.** It cannot relate meaning that no shared subword carries. "Users cannot log in after the update" against `session_store.rs` shares nothing. A vocabulary trained on 400 to 1,500 repositories may not learn that closeness, where a pretrained encoder might. Word order is lost: "remove X from Y" equals "remove Y from X". Nearest veto: W3. It is not struck, because the vectors belong to words shared across repositories, not to files or repositories.

**Rests on.** N 6, N 9.5, N 13.3, N 13.9 (aggregation as a learnable hand-made feature), N 14.2; D 9.3. Record: `docs/program/hypotheses/search-model/FACTS-MODELS-SO-FAR.md` (retrievers as they come swing +23 and -14 against text search by repository). Count first: the share of task-words right files that share no non-hub subword with the question.

**Refuted if.** On unseen repositories this arm scores no better than BM25 alone on task words, in the segment with no joint change. Or: adding frozen pretrained chunks (option 1) gains mainly on right files that share no subword with the question.
