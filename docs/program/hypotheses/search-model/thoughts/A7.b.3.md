# A7 option 3: calibrated per-file probability, weighted negatives
Lens: language model first.

**Mechanism.** The output is a probability per candidate, not a logit that means something only within one list:
p(c|q) = sigma(s(q,c) + beta·log|F_t|).
- s is A2.b.1's score.
- The term in log|F_t| lets the base rate fall with the size of the repository; it is an input, not an identity.
- The negatives are drawn as in option 1 (a fixed set D, m draws with known pi, P and R_u excluded).
- The loss is binary cross-entropy. Each negative term is weighted by one over its inclusion probability, which gives an unbiased estimate of the loss over every file alive (D 3.2):
  L_q = -sum_{p in P} log p(p|q) - sum_{d in D} log(1 - p(d|q)) - (1/m) sum_j log(1 - p(n_j|q))/pi(n_j).
- The expected number of right files, N^ = sum_{c in F_t} p(c|q), is estimated the same way. The cut is then the shortest top list whose expected recall, (sum of p in the list)/N^, reaches a set share.
- New files: folder slots carry their own p.
- Weights: as option 1 (D11).

**Needs from other parts.** A2.b.1 and A1.b.1 (score and amounts); A3.c.1 (exact x_qc); A5.b.1 (cut-off mark). A6: pi over every file alive. A10: a calibration reading per repository beside D12's ranks.

**Can.**
- Tell the harness how many files to read. With 1 right file or with 8, the probabilities keep their absolute meaning; a softmax over one list (option 1) cannot, being shift-invariant.
- Order right files as option 1 does, to the extent that a calibrated score orders them.
- M7: by construction for the loss, negatives and weights.
- M1, M2: through A2.b.1.
- M3: in part. The base rate follows the repository's size by the log|F_t| input; it does not follow the repository's habits.

**Cannot.**
- Be cheap in variance. In a repository of 50,000 files, uniform draws carry 1/pi in the thousands, so a few draws swing the loss (N 14.2). Hard draws through r reduce this.
- Rank as sharply as a listwise loss. Cross-entropy spends capacity on the tail: separating ranks 4,000 and 9,000 lowers the loss and moves no measure of D12.
- Stay calibrated where the share of right files moves with something not among the inputs. Counterexample: a repository that squashes many tasks into one change has more right files per question at the same size.
- Nearest veto: W9. It is avoided because P and R_u are excluded and nothing is fitted on test.

**Rests on.** N 13.6, N 14.2; D 2.9, D 3.2, D 7.3; D11, D12 (DATA-CHOICES.md); FACTS: hits in the top ten over ten cannot exceed about a quarter on the old data. count first: the spread of |P| per question by repository.

**Refuted if.** On validation repositories, N^ misses |P| no better than option 1's softmax with one temperature fitted on validation. Or the cut at a set recall reads no fewer files than a fixed top ten at the same recall.
