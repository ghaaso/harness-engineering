# A2 option 1: question-marked propagation from the question node
Lens: graph first; the model computes on the typed neighbourhood handed over by the data, with the question as a node of it.

**Mechanism.** The question Q is a node (D14). Its starting files S_k(Q) are tied to it by edges of kind k: "in the change", "named in the text", "in the trace" (with frame depth as an edge feature). Each candidate v also gets an edge Q->v with a pair reading phi(q, x_v): the question text read together with v's content at the asking time, plus exact name and path matches. The propagation starts from the question:
h_v^0 = sum_k [v in S_k(Q)] a_k + phi(q, x_v) + g(x_v)
h_v^{l+1} = sigma( W_0 h_v^l + sum_r sum_{u in N_r(v)} W_r psi(e_uv) h_u^l )
The aggregation is a sum with no division by degree (N 9.5). Event nodes carry size and age in psi. The score is a fixed, shallow read-out of the candidate's own vector: s(Q, v) = w . h_v^L (N 5.4). The marks a_k are the "marked root" of N 9.10, with a set of starting files in place of one node, and the start set acts as an anchor set drawn afresh by each question (N 10.5).
Per question: change: q is the diff and S the files in the change. Task words: S is often empty, so the question enters through phi and Q's node. Error: S is the trace's files, by depth.

**Needs from other parts.** A1: the encoders behind phi and g. A3: event messages that sum. A4: the relation basis and direction. A5: a neighbourhood cut at the asking time. A6: the candidate set, with Q->v edges for far files.

**Can.** M1 by construction: every vector depends on Q through h^0. Two candidates with the same surroundings but different paths to S(Q), or a different phi, get different scores. One file scores differently under two questions. Node vectors computed alone cannot do this (N 9.8). M3 by construction: the marks are relative identities, with no table of files (N 9.10). M2 by construction, given A3's sum. M6 in part: Q->v is a direct one-hop path for every candidate in the set (N 11.3).

**Cannot.** Separate two candidates at the same typed path from S(Q) with the same content reading. Two sibling tests of a changed file with identical counts tie (the price of N 5.2). Where S is empty and the text is weak, the score rests on phi alone. Right files with no earlier joint change run from 21 to 66 % by repository (FACTS). For those files, a phi made of two texts encoded apart would be W1, so phi must read them together. No node vector can be shared across questions: one propagation per question. Nearest veto W1: avoided through h^0.

**Rests on.** N 9.4, N 9.8, N 9.10, N 10.5, N 9.5, N 5.4, N 11.3, N 13.2; D14 (DATA-CHOICES.md); record: `research-tree/build/improve/units/T3/report.md` items 3 and 8 (vectors from neighbours with a pair head; the memory form ranked by how often a file changes); count first: the size of the per-question neighbourhood.

**Refuted if.** On validation, candidate rankings barely move across questions asked at the same moment (rank correlation near 1, like the memory form's 0.96 to 0.99), or zeroing every a_k costs nothing measurable.
