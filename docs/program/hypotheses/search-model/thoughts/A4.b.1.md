# A4 option 1: relations written as directed path statements
Lens: language model first.

**Mechanism.** For a question q and a candidate c, enumerate the typed, directed paths of at most two links from q to c:
q -[in the change | named in the text | in the trace]-> s, then s-[k]-c in either direction, or s-[k]-m-[k']-c. Each
link kind k is a fixed phrase. Direction is word order: "s imports c" and "c imports s" are different statements.
Symmetric kinds (folder, changed together) get a symmetric phrase. Paths are grouped by signature, the ordered list of
(kind, direction). Each group becomes one line: the signature in words, a few intermediate paths, and their flags
(named in the text, in the trace). A pretrained model of text and code reads [q] [c path and content] [signature lines]
as one sequence, a cross-encoder, and gives one score. The size of a group, relative to the repository, enters through
one shared numeric adapter, not as digits: e_g <- e_g + W·phi(n_g / n_repo). Parameters per kind: none. A new kind is a
new phrase.

**Needs from other parts.** A1: the trained encoder and phi. A3: the amount carried by "changed together". A6: a
retrieved candidate set, because there is one forward pass per pair. A7: the loss over that set.

**Can.** M5 by construction: kinds are told apart, direction is kept, and parameters do not grow with the kinds.
Pretrained meaning carries over to rare kinds, such as unresolved names. N 13.8 patterns: the score is not an algebraic
rule over entity vectors. Asymmetry holds by construction (word order), and so does one-to-many (each candidate is read
on its own). Composition holds in part, up to two links, because paths are given, not inferred. M1 by construction:
q and c are read jointly. M3 by construction: no row is learned per file.

**Cannot.** See paths longer than the enumeration. Counterexample: a right file three imports away gets no line (W5 is
nearest; reach is left to A6, not to stacked steps). It cannot tell which member of a group mattered beyond those
written out. Counterexample: twelve shared importers, where only the eleventh matters. It cannot score all files alive
(W6 is nearest; it reads pairs from a retrieved set, never all pairs). Its context grows with the signatures, up to
(2K)^2 for K kinds. N 9.5 does not bite here: a group is one line and its count is kept.

**Rests on.** N 12.7 (edge features enter the score), N 13.1 (kinds as given features), N 13.8, N 9.4 and N 9.8 (joint
reading avoids W1), N 13.7 (no lookup rows), N 12.5. Assumption: a model trained on code reads direction from word
order, since in code, order carries meaning. Count first: signature groups per (q, c) pair.

**Refuted if.** Reversing the direction of every statement at test leaves the ranks unchanged. Or one neutral phrase
for every kind gives the same validation score.
