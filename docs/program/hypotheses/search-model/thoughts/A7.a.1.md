# A7 option 1: per-positive softmax, corrected sampled negatives
Lens: graph first. The model computes on the typed neighbourhood, with the question as a node.

**Mechanism.** *Output.* One real score per candidate, read from its last-layer vector plus the exact channels:
s(Q,v) = w^T h_v^L + sum_k beta_k log(1 + C_k(Q,v)), beta_k >= 0,
with C_k the exact decayed, size-weighted counts. An added file has no node at the asking time. So each folder in the neighbourhood gets a virtual slot node nu_f ("a new file here"). It is linked by a folder edge, has no content, and is scored like a file (N 13.5: add virtual nodes). A deleted file is an ordinary candidate whose label kind is stored.
*Loss.* For question Q with right set P: every candidate in the neighbourhood set C(Q) that is not in P is scored in the same pass (N_in). Far files get m draws from the alive files outside C(Q) and P, with known probabilities pi_n: a stated mix of uniform and A6's retrieval score. A draw that lands in P is rejected. Each positive is set against negatives only:
L(Q) = (1/|P|) sum_{p in P} [ -s_p + log( e^{s_p} + sum_{n in N_in} e^{s_n} + sum_{j=1..m} e^{s_{n_j} - log(m pi_{n_j})} ) ].
The correction makes the far term an unbiased estimate of the full sum over far files (Horvitz-Thompson, D 3.2).
*Weights.* omega_Q follows D11: every repository the same total, a cap per example set on validation. The 1/|P| above keeps a 40-file change from counting forty times. When a unit is asked step by step (D8), its prefixes share one unit's weight. Bulk-flagged units are left out of the main term (assumption: D11 says "read apart").

**Needs from other parts.** A1.a.1 (inputs), A2.a.1 (h_v^L depends on Q through the marks and phi), A3.a.3 or A4.a.1 (summed channels C_k; the gate at neutral gives the count), A5.c.1 (the bank and the cut at t). A6: C(Q) and pi. A8: the mix of questions. A9: one pass per question.

**Can.** M7 by construction: negatives have known probabilities and are never right files; weights are set by design. M2 at the output: with w = 0, the ranking is exactly decayed counting, so the class contains the baseline (N 9.5). M3: a softmax per question ignores a shift per question, so a repository's score scale does not matter. M1: inherited from A2.a.1. Several right files: no right file appears in another's denominator, so none is pushed down for being right. New file: in part (slots).

**Cannot.** Say how many files are right: the mass is shared, so a one-file and a five-file change can give the same top score (option 3). The log of an unbiased sum is biased low (Jensen); the bias shrinks with m and does not vanish. A new file in a folder that does not yet exist has no slot. Tied rooted subtrees tie (N 9.4). Nearest veto W9: the rejection step keeps P out, and no "historical negative" labels an earlier real pair false. In the record that labelling took 0.141 to 0.007.

**Rests on.** N 13.6, N 13.5, N 5.4, N 9.5; D 3.2, D11, D8, D12; record: `research-tree/build/improve/units/T3/report.md` item 7. Count first: the share of right files outside C(Q); the share of added files whose folder exists at t.

**Refuted if.** On small validation repositories, where the full set of alive files fits, training with the exact denominator orders right files differently per repository beyond the intervals. Or a pointwise logistic loss on the same model and negatives ranks right files as well.
