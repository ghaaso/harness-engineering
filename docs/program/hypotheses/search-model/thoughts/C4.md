# C4: Question-rooted graph over a tuned code reader
Starting pairing: A1.b.1 (tuned code model reads text, numbers bypass it) with A2.a.1 (question-marked propagation from the question node).
Parents: A1.b.1, A2.a.1, A3.a.3, A4.a.1, A5.b.1, A6.b.1, A7.c.1, A8.c.1

## The design, part by part

**A1, taken from A1.b.1.** One pretrained decoder of code and text, tuned with low-rank adapters on training repositories and times only (D 6.2). Text and code (question, diff, error, file as path plus chunks of B tokens, repository description as a cached prefix) are read by it. Amounts enter as a = [log(1+x), q_{R,t}(x)], q the quantile in repository R before t (N 7.1, D 6.4), and raw (x, 1/n, age) on a bypass, never as digits. Question-free structure per file, as quantiles within R: degree per kind and direction, closed walks diag(A^k), k = 2..6, on the import-and-use graph (N 9.10), return probabilities (N 10.4), folder depth, age, decayed change rate; no eigenvectors (N 10.3, N 10.6); missing values flagged (D 5.3). A frozen pass stores one vector per chunk per content hash, once (D3).
**Changed to fit.** (1) The link soft tokens E_kind[k] + E_dir[d] + E_res[r] + MLP(a) do not enter attention; they become the edge feature psi(e_uv) of the propagation, because A4.a.1 carries kinds as relation maps. (2) The tuned pass reads a pair (q, v) only for v in the shortlist C of A6.b.1, with v's two chunks of highest stage-1 dense similarity (added: the chunk choice; reason: A1.b.1 cannot read a long file whole, and A6.b.1 already scores chunks). (3) The same frozen pass encodes each event's message and diff (v_e) and the question (q_0), because A3.a.3's gate needs both in one space.

**A2, taken from A2.a.1.** The question Q is a node; its starting files S_k(Q) carry marks a_k; each v in C gets an edge Q->v with a joint reading phi(q, x_v):
h_v^0 = sum_k [v in S_k(Q)] a_k + [v in C] P phi(q, x_v) + g(x_v)
h_v^{l+1} = sigma( W_0 h_v^l + sum_r sum_{u in N_r(v,t)} g_r(e_uv) W_r h_u^l ),  L = 2,
a sum with no division by degree (N 9.5). phi is the tuned decoder's last state at a read token after [prefix][question][soft tokens][path, chunks]: question and file read together, so not W1 (N 9.4, N 9.8). The marks are the marked root (N 9.10); the start set is an anchor set drawn by each question (N 10.5).
**Changed to fit.** phi exists only on C (one decoder pass per pair; A6.b.1 gives C). Neighbourhood files outside C enter with g(x_v) and a flag. The fixed read-out w . h_v^L becomes A8.c.1's head. New-file slots (A7.c.1) are nodes joined to their folder; a slot's phi reads q with the folder path and the names its files define.

**A3, taken from A3.a.3.** Per start file s and candidate c:
h_{c|s}[k] = sum_{e in E(s,c,t)} n_e^(-p_k) exp(-a_e/tau_k) sigma_k(q_0, v_e),  sigma_k = 2 sigmoid(b_k + q_0^T W_k v_e), W_k low rank.
Per event, bounded, unnormalised (N 9.3, N 12.6); at W_k = 0, b_k = 0 it is the exact decayed, size-weighted count. Pooled over start files by sum, maximum and number above zero.
**Changed to fit.** (1) A3.a.3 trains p_k and tau_k; A5.b.1 fixes the bank and learns a non-negative mixture. Resolved by N 14.4 and D 7.5: with fixed shapes, p_k in {0, 1/2, 1} and tau_k geometric on both clocks, the ungated columns are computed once, exactly, outside training, and a non-negative mix still covers any completely monotone decay within the bank's range. (2) Ungated columns (sigma = 1) are kept beside the gated ones, so M2 does not rest on the gate learning neutrality. (3) The same bank is the gate of file-event edges: g_event(e) = sum_k m_k n_e^(-p_k) exp(-a_e/tau_k) sigma_k(q_0, v_e), m_k >= 0, the form A4.a.1 asks of g.

**A4, taken from A4.a.1.** About 11 kinds, each forward and reverse, R = 22; W_r = sum_{b=1..B} a_rb V_b (N 13.2); sums within and across relations (N 13.3); question and start files marked by kind.
**Changed to fit.** g_r for file-event edges is the gate above; for code links g_r = softplus(MLP(psi(e))) of A1's link features (resolved or not, test rule). Events touching a start file are kept up to a cap K_e and sampled beyond it with weight 1/pi (D 2.9, D 3.2), as A4.a.1 asks of A9; the exact columns of A3 always sum every event.

**A5, taken from A5.b.1.** The asking time t is the zero of every clock; no date enters. Two ages: wall (t - t_e)/g_R, g_R the median gap between units before t; event age in units landed since e. The exact bank enters the decoder as one soft token (learned projection of C_1..C_K) beside the candidate. Order as text: the candidate's latest events (message, size, both ages), newest first. The decoder's cut-off must precede the validation stretch; every example is marked by whether t falls before it.
**Changed to fit.** The event list is cut to E_max events after the chunks (count first: tokens per pair); the bank carries all history, so this is not W4. C_k is pooled over S as in A3.

**A6, taken from A6.b.1.** Stage 1 scores every file alive: s1(q,f) = u^T z(q,f), z relative to the repository, channels: dense (best and top-3 mean similarity of q to f's frozen chunk vectors, question side with its own adapter), BM25 with idf from files alive at t, names in q and names the decoder generates after reading q and S, resolved against the symbol table at t (unresolved dropped), exact (A3's bank and typed path counts to two hops, zero with a flag). C = top N by s1, plus files named in q or the trace, plus the top M by joint kernel. Final order: C by the stage-2 score, then every other file by s1.
**Changed to fit.** A2.b.1's joint reader named by A6.b.1 is replaced by A2.a.1's propagation with phi (the fixed pairing). Added: training shortlists come from a stage 1 fitted on the other half of the training clusters (D 6.4: a shortlist built in-sample is easier than at test, so stage 2 would train on the wrong mix).

**A7, taken from A7.c.1.** s = b_k + f_theta; b_k fixed: log(eps + decayed one-over-size count) for a change, log(eps + BM25) plus a constant for named files for task words, trace depth for an error. Candidates: every file alive plus one slot per folder. Negatives: R(q) \ P(q) whole; the rest a Poisson sample with known pi_c > 0; right files never negatives (N 13.6). Loss L(q) = -(1/|P|) sum_p log[e^{s_p}/(e^{s_p} + Z)], Z a Horvitz-Thompson total (D 3.2). Weights w_q = min(1/n_R, beta); bulk questions weigh zero.
**Changed to fit.** Two terms: L1 on the stage-1 score over all files alive, as written; L2 on the full score over C, where Z = sum over C \ P exactly (pi = 1). R(q) is defined by the non-zero exact columns of A3 and the two-hop counts of A6.b.1.

**A8, taken from A8.c.1.** For question kind j:
s_j(q,c) = b_j(q,c) + (a_0 + d_j)^T z_qc + [c in C] (w_0 + D_j)^T h_c^L,
d_j, D_j and a low-rank adapter per kind, penalised lambda_j ||.||^2, lambda_j on validation repositories. One run, every batch holds all kinds, each repository weighs the same inside a kind (D11), each kind's loss divided by its total weight. Errors train on D10's tier (e) and the real tiers' training repositories; trace files enter as S.
**Changed to fit.** z_qc is A6.b.1's channel vector. The run has two phases: phase 1 fits the linear term and question-side adapter with L1 and builds the cross-fitted shortlists; phase 2 trains the reader adapters, the propagation, the gate and the heads with L2, linear term frozen. Reason: C is a function of the linear term, and A4.a.1's sampled neighbourhoods are built from C before phase 2.

## One question, end to end
Common: the loader cuts the store at t and asserts nothing at or after t is served (D6, D 9.4). Exact, on a processor: the ungated bank, two-hop path counts, BM25, name matches, quantiles, structure features. Frozen and cached by hash: chunk vectors, v_e, q_0. Learned: adapters, u, d_j, the gate (W_k, b_k, m_k), the propagation (W_0, V_b, a_rb, P, g, g_r), the heads.

**A change.** q is the first commit's diff (D8); S its files, kind "in the change". Stage 1 (A6.b.1, A8.c.1 linear term, A7.c.1 offset) ranks every file and slot. C is formed. The neighbourhood: Q, S marked (A2.a.1), C with phi (the decoder reads the diff with each candidate's chunks, its bank token and latest events: A1.b.1, A5.b.1), events touching S with the gate weighing earlier changes like this diff above others (A3.a.3), one hop of code links of S and C under 22 relations (A4.a.1). Two layers; head D_chg. C is ordered by s_chg, the rest by s1.

**Task words.** q is the issue as first written (D9); S the files the text names, often empty. Then the marks are absent and the bank is zero with a flag; b_txt is BM25. Stage 1 rests on dense, BM25 and names, generated ones included. In stage 2 the question enters through phi and the Q->v edges; the propagation lets shortlisted files pass evidence along code links and shared events (two candidates that changed together raise each other). Head D_txt.

**An error.** q is the error text; S the trace's files, kind "in the trace", frame depth as an edge feature; b_err is trace depth. The bank counts from the trace files as from a change. Head D_err, with the shared backbone taught mostly by changes (N 5.2).

## What is trained and what it costs
Trained: low-rank adapters of one decoder (size class 0.5 to 1.5 billion parameters; the count below decides); a question-side adapter on the same decoder; the linear term (hundreds of numbers); the gate (K low-rank maps); the propagation at d = 256, L = 2, B = 8 bases, about B d^2 L, near one million numbers; the heads. The decoder must be trained on code and natural-language text, its cut-off before the validation stretch (A5.b.1), stricter than D7. No product is named.
Computed once: frozen vectors per content hash (chunks, event messages and diffs, questions); exact columns per question; structure features per repository and asking time.
Memory: a 1.5-billion decoder in 16-bit is about 3 GB; with checkpointed activations, tens of pairs of about 1,200 tokens fit in 96 GB (assumption). A neighbourhood of hundreds to thousands of nodes is small. Time, not memory, binds.
Time: one tuned pair costs about 6 P T operations, 1.1e13 at P = 1.5e9, T = 1.2e3. The frozen pass costs 2 P per token over D_tok distinct tokens. Three cards for eight hours are 86,400 card-seconds. At a sustained F = 2e14 per card (assumption, count first), a frozen pass of D_tok = 5e9 at P = 1.5e9 takes about 21 card-hours of 24, too much; at P = 0.5e9 about 7, leaving about 4e6 pair passes at that size, which at N = 32 is about 1e5 question passes. So P is set by P <= (share of budget) / (2 D_tok) once D_tok is counted.
Count first: D_tok over contents alive at the sampled asking times; recall at N of C per repository, by segment; neighbourhood size per question; joint events per start file; sustained throughput of the card; share of files over B tokens.
Smaller form: the same graph, gate and heads with the decoder at its smallest size class quantised for inference, chunk vectors computed once per repository on the PC and updated by content hash. A question then costs one stage-1 pass over stored vectors and N short decoder passes.

## Against the sheet
**M1 by construction inside C, in part outside.** Inside C, phi reads q and v together and the marks root the subgraph (N 9.8, N 9.10, A2.a.1); the gate makes history depend on the question (A3.a.3). Outside C the dense channel is two vectors; names, counts and BM25 are pair-specific.
**M2 by construction.** The ungated column with p = 1 is the decayed one-over-size count; it sits in z and in b_chg and never passes a mean or a softmax (N 9.5, A3.a.3, A7.c.1).
**M3 by construction for what is trained; open on a test for the decoder.** No identities, amounts relative, structure codes that transfer (N 9.10, N 10.4), two layers (N 8.4). A path is a near-identity to a pretrained model: open on D12's reading of repositories created after the cut-off.
**M4 by construction for the store; open on a count for the decoder.** Loader cut at t (D 9.4), relative clocks (A5.b.1); the decoder's memory is open on the count of training repositories and validation questions after its cut-off.
**M5 by construction, in part for rare kinds.** 22 directed relations at B d^2 + R B numbers (N 13.2); antisymmetry, symmetry through shared nodes, composition and one-to-many as A4.a.1 argues (N 13.8). The thin trace relation rests on the basis span.
**M6 in part.** Direct Q->v edges and stage-1 reach by content, names and two-hop counts (N 11.3, A6.b.1). A file sharing nothing with the question is not reached.
**M7 open on the counts above.** Every right file ranked against the wrong ones with a Horvitz-Thompson total (A7.c.1, D 3.2); negatives never right files; weights by D11; hub sampling with known probabilities (D 2.9).
**M8** is not this part's; the design gives arms that differ in one decision each: b only, stage 1 only, the gate held neutral, phi frozen.

Nearest vetoes. W1: outside C the dense channel is two vectors, but s1 also reads pair-specific counts and names, and inside C the reading is joint. W2: every aggregation is a sum; the gate is per event, unnormalised. W3: nothing is learned per file or repository; recall by the decoder is a risk, tested by D12. W4: the event text list is short, the bank covers all history. W5: two layers, reach by Q->v edges and stage 1. W6: attention spans one pair. W9: negatives exclude P; lambda_j, beta, N, M set on validation; shortlists cross-fitted. W10: no tree. W11: no eigenvectors. W12: every choice follows an entry. W13: the owner's two repositories meet only the small form on his PC.

## Cannot
- Read a long file whole: a relevant function past the two chosen chunks is seen only through chunk vectors (A1.b.1).
- Forget pretraining: a public repository's joint changes may be recalled from paths (A1.b.1); generated names may be recalled, not reasoned (A6.b.1).
- Rescue a file stage 1 ranks below N and that no rule adds to C (A6.b.1). Counterexample: a build setting a new feature needs, sharing no word, name or two-hop path with the question.
- Separate two candidates with the same typed paths from S and the same reading: two sibling tests of a changed file tie (A2.a.1, A4.a.1; N 9.4).
- See past two hops inside the graph (N 5.5); a right file three imports away depends on stage 1 alone.
- Help where messages say nothing: the gate stays neutral (A3.a.3); weigh the order across separate events beyond the short text list; keep the gate from learning one repository's message habits (bounded, not removed).
- Represent a decay that is not monotone: files that change together every release peak at one cycle's lag (A5.b.1's bank); model calendar drift (no absolute time).
- Give the rare trace relation a direction outside the shared bases (A4.a.1); keep sums through a hub of 2,000 importers on a transferable scale except by sampling and relative inputs.
- Aim at the top ten: moving a right file from rank 500 to 50 can lower L more than from 12 to 3; log of the estimated Z is biased low; a file fixed in the next pull request is a negative (A7.c.1).
- Name a new file, or place one in a folder not yet made (A7.c.1).
- Restore in a head what the backbone never computes; with S empty, a backbone taught mostly by history leaves task words to phi (A8.c.1).
- Score across the stage boundary: a file in C always ranks above one outside it, however weak its stage-2 score (from A6.b.1's order).

## Refuted if
- A1.b.1, the tuned reader: on repositories created after the cut-off, the design with phi from frozen chunk vectors scores the same.
- A2.a.1, rooting: rankings barely move across questions asked at the same moment, or zeroing every a_k costs nothing.
- A3.a.3, the gate: it stays near neutral on validation repositories, or it gains on training repositories and not on held-out ones.
- A4.a.1, kinds: the same network with kinds merged and a one-hot kind feature scores within this one's interval.
- A5.b.1, time: shuffling ages in the event list changes nothing, or the lead over decayed counting is larger before the decoder's cut-off than after.
- A6.b.1, reach: removing the dense and generated-name channels leaves recall at N of right files with no joint change within its interval.
- A7.c.1, the loss: uniform uncorrected negatives of equal number score the same, or f_theta adds nothing over b_k on unseen repositories.
- A8.c.1, sharing: a backbone trained on one kind alone matches the shared one on task words and errors.
- The combination: on unseen repositories, inside C, the head term (w_0 + D_j)^T h^L adds nothing over stage 1 read per repository; then the graph with the reader does not earn its cost.
