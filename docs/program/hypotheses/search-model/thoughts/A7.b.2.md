# A7 option 2: measure-weighted ranker, cross-fitted language score
Lens: language model first. This option departs from it, following the material. A ranker over exact pair columns leads in the record, and language models cannot count (N 13.9), so the language model becomes one column.

**Mechanism.** The training repositories are split in two halves, H1 and H2, by cluster.
- On H1, the cross-encoder of A2.b.1 is tuned with option 1's loss.
- On H2, its score l(q,c) becomes one column beside the exact pair columns: the record of A2.a.2, the kernel bank of A3.c.1, the paths of A4.c.1, and the as-of columns of A5.c.1 and A5.c.3.
- A boosted tree ranker is trained on H2. The swap of a right file p and a wrong file n is weighted by the change in D12's measure M (hits in the top ten over the smaller of ten and |P|):
  lambda_pn = |Delta M_pn| · sigma(-(s_p - s_n)).
- Ranks are estimated among all files alive, from the same draws as option 1 (a fixed set D, m draws with known pi):
  r^_p = 1 + sum_{d in D} 1[s_d > s_p] + (1/m) sum_j 1[s_{n_j} > s_p]/pi(n_j).
- A new file is handled by folder slots with folder-level columns, in a list of their own.
- Example weights are those of option 1 (D11). All amounts are relative to the repository.

**Needs from other parts.** A2.a.2, A3.c.1, A4.c.1, A5.c.1, A5.c.3 (exact columns); A2.b.1 and A1.b.1 (the language column); A5.b.1 (cut-off mark). A6: a cheap score giving pi. A8: the split of training repositories into H1 and H2.

**Can.**
- Spend its effort where the measure is decided.
- Keep the column honest. The ranker learns how far to trust l on repositories l never saw, which is the test condition. Scored in-sample, l looks overconfident and the ranker would lean on it (D 6.4).
- M2 by construction, through the exact columns. M7 by construction for the loss, negatives and weights; tree training runs on processors. M1 in part: text meets counts only through splits on l.

**Cannot.**
- Learn a text representation from the counts' errors. No gradient reaches the encoder.
- Use all training repositories for both stages: each sees half. count first: whether half the repositories of D2 still reach the pilot's computed number.
- Avoid noise in r^ at small m, which flips Delta M near rank ten.
- Rank beyond the columns' range: trees plateau (D 8.1).
- Nearest veto: W10. It is avoided because every amount is relative to the repository.

**Rests on.** N 13.9, N 1.1; D 3.2, D 6.4, D 7.5, D 8.1, D 9.2; D11, D12 (DATA-CHOICES.md); record: `research-tree/build/improve/units/T3/report.md` item 1; `research-tree/build/improve/units/U3/report.md` (the tree ranker leads on task words too).

**Refuted if.** Per validation repository, setting every |Delta M| to 1 changes no rank beyond the intervals. Or l trained on all repositories and scored in-sample gives the same held-out ranks as the cross-fitted l. Or option 1 alone matches this on right files that have exact columns.
