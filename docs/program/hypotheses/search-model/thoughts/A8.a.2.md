# A8 option 2: shared parts, residual ranker per question
Lens: one shared model. Departs from it: in the record a ranker over exact pair features led on both measured questions, and a learned trunk added nothing over its count features. So the exact computation and one reader are shared; the decision is per question, stacked on a shared base.

**Mechanism.** Four linked parts.
1. *Exact features, untrained, shared.* One code path builds the pair record R(Q, v) for every kind: kernel bank, typed path counts, as-of columns. Only the start kind differs (change, text, trace).
2. *One joint reader, shared.* One cross-encoder c(q, x_v) trained on pairs of all three kinds together, the kind as a first token. Text is where the questions are most alike, and the reader needs the most data.
3. *Rankers.* A base f_0 is trained on change and task-word examples pooled, kind as a feature. Each kind gets a residual: s_k(Q, v) = f_0(R, c) + f_k(R, c). f_k is fitted on kind k alone, boosting continued from f_0's output, with strong shrinkage. With few error examples f_error stays near zero, so errors fall back to the pooled base, not to a model fitted on a handful (D 7.4).
4. *Retrieval, a separate untrained stage.* Candidates are the union of non-zero path counts, text-search hits, frozen-chunk neighbours and, for errors, trace files. Its recall per kind is counted on validation before any ranker is trained.
*Mix.* Each repository has equal weight (D11); losses reweighted by one over known draw probabilities (D 3.2).

**Needs from other parts.** A1.c.1 (exact typed path sums, relative amounts); A2.a.2 (pair record) and A2.b.1 (joint reader); A3.c.1 (kernel bank); A4.c.1 (path counts by kind); A5.c.1 (as-of bank), A5.c.3 optional. A6 the union's reach; A7 a ranking loss.

**Can.** M1 by construction: R and c depend on (Q, v), and f_k lets one pair score differently by kind. M2, M3, M4 by construction, as the parts it builds on. M7 by construction: features once on processors; only the reader uses the cards. M8 in part: f_0 against f_0 + f_k is a one-decision comparison per kind. Errors get the pooled base, and the residual adds only what their examples support.

**Cannot.** Learn an aggregate the record lacks (D 9.2). Counterexample: a three-hop path that matters for errors only is zero in R for every kind. Share learned structure across kinds: a regularity found in changes reaches errors only through f_0's splits, not as a representation. Recover a right file the union misses. Nearest veto W10; avoided, amounts are relative to the repository. W1 avoided by the joint reader.

**Rests on.** D 9.2, D 7.4, D 8.1, D 3.2, D10, D11; N 13.9, N 1.1; record: `research-tree/build/improve/units/T3/report.md` items 1, 3; record: `research-tree/build/improve/units/U3/report.md` (tree ranker leads on task words). Count first: the union's recall per kind and repository.

**Refuted if.** Per validation repository, f_k moves no rank beyond the intervals for any kind; or option 1 beats it on errors, at equal candidates, on unseen repositories.
