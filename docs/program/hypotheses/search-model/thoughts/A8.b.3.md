# A8 option 3: residual cascade over a counted baseline
Lens: linked specialists: a pipeline of parts, each trained for its own job. A stage's job: correct the stages before it.

**Mechanism.** The score is a sum of stages, each trained with the earlier ones frozen as an offset:
s(q,c) = s_0(q,c) + s_1(q,c) + s_2(q,c).
- *s_0, untrained:* the D12 baseline of the question kind: decayed one-over-size joint count from S (change; error, with S the trace's files), BM25 plus named files (task words).
- *s_1:* a ranker on exact pair features, trained with listwise loss over the candidate set on logits s_0 + s_1, s_0 fixed.
- *s_2:* a cross-encoder of question text and candidate chunk, trained on logits s_0 + s_1 + s_2 with s_0 + s_1 frozen, over the top M by s_0 + s_1 united with the text channels' top K. Its gradient falls where cheaper stages misrank: far files, ties.
- The offsets s_1 on which s_2 trains are out-of-fold (two halves of the training clusters), so s_2 learns no fix for s_1's in-sample overfit.
- *Questions:* s_1 and s_2 are shared, with the start kind as input. *Error:* s_0 is the trace baseline; the learned stages add corrections learned mostly on other kinds.
- *Mixing:* equal weight per repository (D11); every stage sees all kinds.

**Needs from other parts.** A1.c.1 (exact, relative features); A2.a.2 (pair record for s_1) and A2.b.1 (joint reading for s_2); A3.c.1 (kernel bank); A4.c.1 (path counts); A5.c.1 (as-of bank). A6 the channels, M and K; A7 the listwise loss; A9 the order of training.

**Can.** M1 by construction (s_2 joint; s_0, s_1 relative to S). M2 by construction: the exact count is s_0 itself, never lost later. M3, M5 by construction (inherited). M4 given the loader. M6 in part: s_2 reads far files the channels retrieve. M7: s_2 reads only M plus K pairs per question; open on that count. M8 by construction: each stage's added gain is read per segment.

**Cannot.** Undo truncation: a right file below M by s_0 + s_1 and outside the text channels never reaches s_2. Retrain one stage alone: a change to s_1 shifts what s_2 was trained to correct. Bind evidence beyond addition: s_2 sees text, not the count, so the conjunction of option 1's counterexample is missed here too. A strong, confident s_0 wrong on a repository (bulk changes) needs large negative corrections the later stages may not have learned. Nearest vetoes: W9, avoided by out-of-fold offsets; W10, amounts relative.

**Rests on.** N 5.4, N 9.5, N 13.9; D 3.2, D 6.4, D 7.2, D 9.2; record: `research-tree/build/improve/units/T3/report.md` item 1; FACTS (one-over-size counting). Count first: per repository, the share of right files below M by s_0 + s_1 and outside the text channels.

**Refuted if.** On validation repositories, option 1's independently trained text reader, stacked, matches s_2 on right files with no earlier joint change; or s_2's added gain is within the intervals in that segment.
