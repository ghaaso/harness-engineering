# A8 option 1: shared backbone, per-question residual heads
Lens: one backbone with a small part per question.

**Mechanism.** Each question takes one form: text q (diff, issue, error), start set S with link kind k (in the change, named in the text, in the trace with frame depth), asking time t. One backbone B is shared by all three: exact pair features x_qc (kernel bank, typed path counts) for every file alive; the rooted relational sum with root mark a_k; the joint text reader on a retrieved top K. For question kind j:

s_j(q,c) = (a_0 + d_j)^T x_qc + [c in top_K] (w_0 + D_j)^T h_B(q,c).

The per-question part is d_j, D_j and a low-rank adapter on the reader, each penalised by lambda_j ||.||^2 toward zero, so a kind with little data falls back on the shared head; lambda_j is set on validation repositories. Stages are one model: the linear term ranks every file (stage 1), the backbone re-ranks the top K, placed above the rest.

One training run; every batch holds all kinds; inside a kind each repository weighs the same (D11); each kind's ranking loss is divided by its total weight, so change questions do not take the shared gradient. Errors train on D10's training-only tier (e) and the real tiers' training repositories; trace files enter as S, as a change's files do.

**Needs from other parts.** A2.a.1 (root marks), A2.b.1 (joint reader, linear term), A3.c.1 (exact bank), A4.a.1 (shared bases), A5.c.1 (as-of cut), A1.a.1 or A1.b.1 (encoders). A6: top K. A7: per-kind loss. A9: one run.

**Can.** The three questions are one function class with different inputs: given q and S, rank partners. By N 5.2 this multiplies the data: change questions teach what serves an error's trace files. M1 by construction (A2; per kind through D_j). M2 by construction: the exact count is in x_qc. M3 by construction: the per-question part is per kind, never per file or repository. M6 in part: stage 1 ranks all files. M7 by construction: one backbone, one run, encoder passes shared. M8: option 2 differs in one decision.

**Cannot.** A head cannot restore what the backbone never computes. Counterexample: an error's right file is the caller two frames up, by a link kind the shared bases spread thin (A4.a.1); no linear D_j finds it. Shared training can pull a kind down: with S empty (task words), a backbone tuned mostly on history leaves the score to the reader. Nearest veto W12: one argued decision, not a sweep. W9: lambda_j set on validation only.

**Rests on.** N 5.2, N 8.4 (nothing grows per kind), N 9.10, N 13.2; D 6.4; D10, D11 (DATA-CHOICES.md); FACTS: no error data or model yet. assumption: the questions differ mainly in input, not in scoring function. count first: examples per kind and tier.

**Refuted if.** On unseen repositories, a backbone trained on one kind alone matches the shared one on task words and on errors; or the error D_j move no per-repository rank beyond the intervals.
