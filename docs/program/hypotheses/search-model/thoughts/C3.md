# C3: exact pair record, tree ranker, joint-reading residual
Starting pairing: A1.c.1 (what the model reads) with A2.a.2 (how the question enters).
Parents: A1.c.1, A2.a.2, A3.c.1, A4.c.1, A5.c.3, A6.c.1, A7.c.1, A8.b.3

## The design, part by part

**A1, taken from A1.c.1.** The store cut at the asking time t, read as a typed directed graph: question q, starting files S_k (k in {in the change, named in the text, in the trace}), events e with size n_e and ages, files, D5 links. Per candidate c, a vector of exact quantities: history sums, link counts, symbol matches (names in q that c defines; paths in q that resolve to c), BM25 of q against c's path and content (idf over files alive at t), cosine of q against c's chunks under a frozen code-and-text encoder (max, top-3 mean). Question-free features of c: degree per kind and direction, decayed change rate, age, size, test flag, folder depth, language. Every amount enters as log(1+x), its percentile among this question's candidates, and x over the largest among them; missing is a flag, never zero. A few relative numbers describe the repository.
**Changed to fit.** (1) A1.c.1's history weight 1/(|e|-1) is replaced by A3.c.1's n_e^(-p) bank, with p = 1 as the canonical column, since the counting baseline that carries the record uses one over the number of files (record: FACTS-MODELS-SO-FAR.md). (2) Its length-two pattern list P is not a separate list: it is A2.a.2's full grammar, computed as A4.c.1's path types.

**A2, taken from A2.a.2.** The question enters only through the pair record R(q,c): block 1, for every typed path (k, r_1, ..., r_m), m <= 2, the number of paths and, through events, the sum of f(n_e) d(a_e); block 2, a joint reading c(q, x_c), one encoder reading question text and candidate content as one input; block 3, flags (c named in q, c in S, c a new file in a folder S touches). Change: k = in the change, q = the diff. Task words: k = named in the text; S empty gives block 1 zeros with a flag. Error: k = in the trace, frame depth an extra path index.
**Changed to fit.** (1) Block 2 is computed only for a shortlist (A6.c.1 asks for a reader on its top K; A8.b.3 for a reader on M plus K), and is trained, as the s_2 stage of A8. Reason: a tree cannot pass a gradient into an encoder (A7.a.2's Cannot, a fact of the mechanism), and D 6.2 allows tuning on training repositories and times. (2) Contradiction: A2.a.2 has one scorer read the whole record including c; A8.b.3 adds the reader as a separate stage that "sees text, not the count". Resolved by N 9.4, N 9.8 and D 9.2: a sum of separately computed scores cannot form a conjunction, which is A8.b.3's own counterexample. So the s_2 head reads [h_joint(q,c); R_ex(q,c)], a small network over the reader's vector and the exact record, which A2.a.2 itself allows ("a tree ranker or a small network reads it"). Not added.

**A3, taken from A3.c.1.** For starting file s, candidate c, events E(s,c,t) that reached the main line before t:
f_{p,j}(s,c) = sum_{e in E(s,c,t)} n_e^(-p) exp(-age_e / tau_j), p in {0, 1/2, 1, [n_e <= k]}, tau_j geometric on two clocks (days; main-line commits since e, in quantiles of the repository's own gaps). Beside each: f/F_s and f/F_c (conditional rates both ways), the sums restricted to "c after s" and "c before s". Over several starting files: sum, maximum, number with f > 0. Two-hop sums by one sparse product per kernel. The ranker mixes the bank.
**Changed to fit.** None. f with p = 1 is the A2.a.2 path (k, joint) and the A4.c.1 joint-change edge weight; one definition serves all three.

**A4, taken from A4.c.1.** File-to-file kinds, each directed one taken twice: import resolved, name matched unresolved, use, test by import, test by name; folder sibling and joint change symmetric: |R| = 12. For p = (k, r1) or (k, r1, r2): raw count x_p(c) = sum_{s in S_k} (A_r1 A_r2)[s,c]; the count with each middle file m weighted 1/deg_r2(m); the number of distinct starting files reaching c. At most 3(12 + 144) = 468 types; a type with no support in training repositories is dropped there. A kind is a feature position, never a parameter per kind of its own.
**Changed to fit.** None; this is A2.a.2 block 1 made exact.

**A5, taken from A5.c.3.** The decay curve is counted per repository before t: for every unit u before t, file s in u, partner c that changed with s before u, b the lag bucket (units) since their last joint change,
h_R(b) = (N_R(b) + alpha h_0(b)) / (D_R(b) + alpha), also by size of the earlier joint unit, h_R(b, n).
Columns: H(s,c) = sum over joint units e of h_R(lag(e), n_e), and h_R at the lag of the last joint change. h_0 and alpha set on training repositories and times only. One pass in time.
**Changed to fit.** (1) A5.c.3 relies on an as-of view and on option 1's columns. The view is the loader's cut (D6, D 9.4), which every part already reads; the monotone bank is A3.c.1's, which A5.c.3 names as the companion. (2) Churn: A5.c.3 says the candidate's own rate must sit beside H; A3.c.1's f/F_c and A1.c.1's decayed change rate are that column. Nothing added.

**A6, taken from A6.c.1.** For every file alive: seeds sigma_k (starting files of kind k; for task words also files defining a name in q, and normalised BM25). Reach by any path: pi_{k,g,alpha} = alpha sum_m (1 - alpha)^m sigma_k P_g^m by repeated sparse products, relation groups g in {code links both ways, joint change weighted as f_{1,j}, folder tree, all}, a fixed bank of restart rates; pi over c's stationary mass (degree bias removed, D 2.9); hop distance to the seed set. Echo: E(c) = sum_u BM25(q, text_u)[c in u] / n_u over past units. Every file alive plus one "new file here" slot per folder is ranked.
**Changed to fit.** The reader that rescores the top K is A2.a.2's joint reading trained as A8.b.3's s_2, in place of A2.b.1's (not a parent). The shortlist is A8.b.3's: top M by s_0 + s_1, united with the top K of the text channels (BM25, cosine, names, echo).

**A7, taken from A7.c.1.** s = b_k + f, b_k fixed: log(eps + f_{1,j*}) summed over S for a change; log(eps + BM25) plus a constant for named files for task words; trace depth for an error. Candidates U(q): all files alive plus folder slots (slot features: decayed count of units adding a file there with a starting file; sum and max of its files' record; BM25 of its path). Negatives: R(q) \ P(q) whole (any non-zero relational feature); the rest a Poisson sample with pi_c = min(1, kappa[lambda/|rest| + (1 - lambda) softmax(BM25/T)_c]). Right files never negatives. Loss:
L(q) = -(1/|P|) sum_p log[ e^{s_p} / (e^{s_p} + Z) ], Z = sum_{R\P} e^{s_c} + sum_{sampled} e^{s_c}/pi_c.
Weights w_q = min(1/n_R, beta); steps of one pull request share one weight; bulk-flagged questions weigh zero. beta, kappa, lambda, T on validation repositories.
**Changed to fit.** Contradiction on the error offset: A8.b.3 takes the joint count from the trace files, A7.c.1 the trace depth. D12 names the files in the trace as the error baseline, so b_err is trace depth (A7.c.1); the counts from trace files enter R through k = in the trace.

**A8, taken from A8.b.3.** s(q,c) = s_0 + s_1 + s_2. s_0 = b_k. s_1 = gradient-boosted trees over the exact record R_ex (A1 to A6 without block 2), trained with A7.c.1's loss on logits s_0 + s_1. s_2 = the trained joint reader over the shortlist, on logits s_0 + s_1 + s_2, with s_0 + s_1 frozen and out of fold (two halves of the training clusters). s_1 and s_2 are shared by the three questions, with the start kind k as input. Outside the shortlist s_2 = 0, so one score ranks every file.
**Changed to fit.** (1) s_2 also reads R_ex (A2, change 2). (2) The s_2 loss is A7.c.1's over all of U(q), with s_2 = 0 outside the shortlist, so its terms there are constants in Z; this keeps one loss for both stages, as A8.b.3 asks of A7.

## One question, end to end

Common to all three: the loader cuts the store at t and asserts nothing served is dated at or after it (D6, D13). On a processor, for every file alive and every folder slot: A1 text and structure columns, A2/A4 path counts, A3 bank, A5 hazard, A6 reach and echo. All exact. Then s_0 (exact), s_1 (learned trees), shortlist, s_2 (learned reader), sort.

- **A change.** q = the first commit's diff; S = its files, kind "in the change". s_0 = log of the decayed one-over-size joint count, which is the D12 baseline itself (A7.c.1). The trees learn mixtures of the bank (A3), the per-repository lag curve (A5), typed two-step paths (A4: the test of an import), and reach beyond two hops (A6). The reader reads the diff against each shortlisted file's best chunk together with that pair's record (A2, A8).
- **Task words.** q = issue title and body; S = files named in the text, often empty. Block 1 is zeros with a flag; seeds become name-defining files and BM25 (A6). s_0 = BM25 plus named files. The echo E(c) carries files of similar past units. The reader does most of the work inside the shortlist; outside it, BM25, names, echo and cosine rank.
- **An error.** q = the error text; S = the trace's files with frame depth as a path index. s_0 = trace depth. Joint counts, paths and reach from trace files are columns of R, as for a change; s_1 and s_2 carry corrections learned mostly on the other two kinds.

## What is trained and what it costs

Trained: s_1, a gradient-boosted tree ensemble over about 800 to 1,000 columns (count first: the exact number after dropping unsupported path types); s_2, a pretrained code-and-text encoder of a few hundred million parameters with a small head, tuned on training repositories and times only (D 6.2). Its pretraining cut-off is no later than the test cut-off (D7); it needs to have read code and natural language; no product is named. The frozen cosine encoder may be the same model before tuning. Fitted numbers: h_0, alpha (A5); beta, kappa, lambda, T (A7); M, K.

Computed once, on processors and outside card time: the record for every (question, candidate) row kept for training, in one time-ordered pass per repository (A3, A5 update lazily; A6 by sparse products, O(E) each); chunk vectors per content hash.

Memory, argued: s_1 rows are R(q) whole plus the Poisson sample. With 8-bit binned features, one 96 GB card holds about 10^8 rows of 800 columns; three cards, data-parallel, about 3 x 10^8. That is about 300,000 questions at 1,000 rows each, so questions are drawn per repository with known probability (D 3.2), weighted as D11. Time, argued: s_1 needs three fits (two halves for out-of-fold offsets, one on all), assumption about an hour together. s_2 at 512 tokens costs about 6 x 3 x 10^8 x 512 = 10^12 operations per pair for a step; at an assumed 1.5 x 10^14 effective per card, about 150 pairs per second per card, so 5 hours on three cards is about 8 x 10^6 pairs, about 50,000 questions at 150 shortlisted pairs. One hour remains for validation scoring.

Count first: |R(q)| and rows per question by repository; processor hours for the record on the rented machine; joint units per hub file (A5's partner lists); share of files beyond one chunk budget; per repository, the share of right files below M and outside the text channels' top K.

Smaller form for a 12 GB card: s_0 and s_1 run on a processor with no card. The reader's weights in half precision take under 1 GB, so it runs inference on the shortlist on the card as it is, or a smaller encoder is tuned to match it.

## Against the sheet

- **M1: by construction for change and error; for task words by construction inside the shortlist and in part outside.** Every column is a function of (q, c): paths from S_k, kernels, BM25, names, echo (A1.c.1, A2.a.2; N 9.4, N 9.8). The reader is a joint pair computation. Outside the shortlist the cosine channel alone is two vectors computed apart.
- **M2: by construction.** The decayed one-over-size count is f_{1,j} exactly and is s_0 for a change; every aggregate is a sum over all events; sampling is of candidates, never of events (N 9.5; A3.c.1, A7.c.1).
- **M3: by construction; open on two tests.** No identity; coefficients are trees and encoder weights; amounts are per-question percentiles and repository clocks; h_R is recomputed at every t (N 9.10, N 13.7; D 8.1). Open on the repository clock against days, and on D12's repositories created after the encoder's cut-off (a path read as text is a near-identity in pretraining).
- **M4: by construction for the record; open on the encoder's cut-off.** One cut view; D13's cut-against-whole test applies to R directly (D 9.4, D 6.2). Encoder: D7.
- **M5: by construction.** Twelve directed kinds as feature positions; every pattern of N 13.8, since nothing is embedded by an algebraic rule (A4.c.1). Columns grow with kinds squared, bounded at 468 types.
- **M6: in part.** Reach of any length (A6.c.1, N 2.3), words, names, echo, and the joint reader in the shortlist; a file with none of these is not reached.
- **M7: open on the counts above.** Loss ranks every right file against an unbiased estimate of all wrong files; negatives never right files; weights and pi by design (A7.c.1; D 3.2, N 13.6).

Vetoes nearest: W1 (the cosine channel; never the only score, BM25, names and paths are pair computations). W10 (trees on amounts; every amount is relative). W9 (negatives exclude P; h_0, alpha, beta, kappa on training or validation; s_2 trains on out-of-fold offsets). W4 (no window; every visible event). W6 (attention spans one pair). W7 (the graph enters as typed path counts and reach). W12 (the path grammar is enumerated in full; the bank is fixed and geometric). W2, W3, W5, W8, W11 not approached.

## Cannot

- See the order of kinds along a route longer than two: test, import, import gets the same reach mass in "all" as any route of equal weight (A6.c.1, A1.c.1). Counterexample: the three-hop co-change through an importer of a starting file is seen only untyped.
- Reach a file with no link, word, name or echo: a config key built by joining strings (A6.c.1).
- Weigh an event by what it is: a mass rename and a feature of six files at equal age weigh the same (A3.c.1). Bulk-flagged questions are dropped, not bulk events.
- Form an aggregate outside the bank and grammar (D 9.2); the record is a projection (A2.a.2).
- Represent order of events beyond one step (A2.a.2, A5.c.3); say anything about a pair's first joint change (A5.c.3); estimate h_R on a short history, where it is h_0.
- Tell which symbol a link carries outside the shortlist (A4.c.1): two users of the starting file, one through the edited function, tie.
- Bind text with counts outside the shortlist: only addition there (A8.b.3).
- Undo truncation: a right file below M and outside the text channels' top K never reaches the reader (A8.b.3). Retrain one stage alone (A8.b.3).
- Correct a confident, wrong s_0 on a repository of bulk changes unless the later stages learned large negative corrections (A8.b.3).
- Aim the loss at the top ten (A7.c.1): rank 500 to 50 can lower it more than 12 to 3. log Z is biased low. A right file fixed in the next pull request is a negative. A new file can be placed only in a folder that exists, never named.
- Extrapolate an amount beyond the relative range seen (D 8.1).
- Learn error-specific scoring from data: there is none yet (FACTS); errors ride on what the change and task-words questions taught.

## Refuted if

- **The exact record (A1, A2, A4):** a learned relational model on the same neighbourhoods beats the record per validation repository among right files with a path of two or less; or merging all kinds into one untyped count loses nothing in any segment.
- **The bank (A3):** the trees over the bank do no better per validation repository than the best single kernel.
- **The counted lag curve (A5):** h_R curves differ from h_0 no more than their resampling spread, or adding H moves no per-repository rank beyond the intervals.
- **Reach (A6):** among right files with no joint history and no two-hop path, the reach and echo columns do not raise their rank over BM25 and cosine alone.
- **The loss (A7):** uniform uncorrected negatives of equal number score the same; or s_1 adds nothing over b_k on unseen repositories.
- **The cascade (A8):** s_2's added gain on right files with no earlier joint change lies within the intervals; or s_2 with the record removed from its head matches s_2 with it on the segment where trace depth and message string must combine (tests change 2 of A2).
- **Sharing across questions:** an s_1 and s_2 trained on one kind alone match the shared ones on task words and errors on unseen repositories.
- **Pretraining memory:** the lead over the baselines is larger on repositories created before the encoder's cut-off than after.
