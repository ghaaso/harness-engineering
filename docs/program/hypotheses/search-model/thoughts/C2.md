# C2: Counted cascade under a tuned joint code reader
Starting pairing: A1.b.1 (code model reads text, numbers bypass it) with A2.b.1 (joint reading with relation tokens).
Parents: A1.b.1, A2.b.1, A3.c.1, A4.c.1, A5.b.1, A6.b.1, A7.c.1, A8.b.3

## The design, part by part

**A1, taken from A1.b.1.** One pretrained decoder of code and text, tuned with low-rank adapters on training repositories and times only (D 6.2). It reads text and code. Every amount x enters as a = [log(1+x), q_R,t(x)], where q is x's quantile in repository R before the asking time t, with a missing flag (N 7.1, D 5.3). The raw (x, 1/n, age) values go past the model. Events and links enter as soft tokens, E_kind + E_dir + E_res + MLP(a), with no identity of a file or a repository (N 9.10, N 13.7). Structure that does not depend on the question is computed per file at t, as quantiles: degree per kind and direction, closed walks diag(A^k) for k = 2..6, and return probabilities (N 9.10, N 10.4). No eigenvectors (W11). Chunk vectors are frozen, one per chunk per content hash, and computed once.
**Changed to fit.** The candidate's structure features become one soft token in the reader and columns in z (below). Reason: A2.b.1 gives them no place.

**A2, taken from A2.b.1.** The question and the candidate form one sequence: the question segment (diff with its files marked, issue text, or error text with trace files marked), then the relation tokens, then the candidate's path and chunk. Relation token: g = E_k + E_r + (Σ_b α_{(k,r),b} V_b) φ(x_{k,r}), with the basis V_b shared by all kinds (N 13.2). The reader's score is s2 = v^T h(q, c, g, events).
**Changed to fit.**
- A1.b.1 names a decoder; A2.b.1 names an encoder in which every layer attends across both segments. They contradict. Resolved by N 12.6: attention is message passing, and a causal mask is message passing on a directed complete graph. With the question first, every candidate token reads the question at every layer, and the last token reads all of them. So h is the last token's state, and the computation is still joint (N 9.4, N 9.8). The decoder is kept because A6.b.1 needs generation. A side gain: the question's cached keys and values are shared by every candidate of one question.
- There is one token per pair (start kind k, first relation r) that has any non-zero path, not one per kind. φ reads all of that pair's amounts: for joint change, the A3 bank; for code links, the one-hop count, the two-hop counts by second relation and the number of distinct start files (A4.c.1). Reason: A2.b.1 sees structure only one link out, "unless A3 or A4 put it in x_qc".
- A2.b.1's linear term a^T x_qc moves into stage 1, as the linear skip of f_θ. Reason: A8.b.3's cascade already carries the exact amounts past the reader, as offsets.
- Up to m chunks per candidate are read jointly, chosen by the stage-1 dense channel, and the maximum is kept (added bound; reason: A2.b.1 reads every chunk, and the pair budget needs a cap). count first: the share of files over m·B tokens.

**A3, taken from A3.c.1.** f_{p,j}(s,c) = Σ_{e∈E(s,c,t)} n_e^{-p} exp(-age_e/τ_j), with p ∈ {0, 1/2, 1, [n_e ≤ k]}. The τ_j are set on both clocks in the repository's units. Beside each sum: f/F_s and f/F_c, the sums restricted to "c after s" and "c before s", and over the starting files the sum, the maximum and the number with f > 0. Two-hop sums come from one sparse product per kernel. All of it is computed once per asking time, on a processor.
**Changed to fit.** None.

**A4, taken from A4.c.1.** Q = {in the change, named in the text, in the trace}. R holds 12 directed kinds. For path types (k, r1) and (k, r1, r2): the raw count x_p(c) = Σ_{s∈S_k} (A_{r1}A_{r2})[s,c]; the count with each middle file weighted 1/deg_{r2}(m); and the number of distinct start files. That is at most 468 types, and a type with no support in the training repositories is dropped. Joint change carries A3's weights. Nothing is embedded, so every pattern of N 13.8 can be represented.
**Changed to fit.** The counts serve two readers: the columns of z, and φ inside the relation tokens of A2. A4.c.1's "learned ranker" becomes stage 1 and the joint reader (A8).

**A5, taken from A5.b.1.** The asking time is the zero of every clock, and no date reaches the model. Wall age is (t - t_e)/g_R, with g_R the median gap before t. Event age is the number of units landed since e. The exact bank of A3 enters as a soft token, and its decay is a non-negative mix of fixed kernels. Order enters as text: the candidate's latest L events, newest first, each with its message. The decoder's training cut-off must come before the validation stretch, and every example is marked by whether t falls after it.
**Changed to fit.**
- A5.b.1 writes the event ages "as numbers" in the text, while A1.b.1 says "never as digits in a prompt". Resolved by N 13.9 (language models read digits badly) and N 12.6: each listed event's size and ages enter as its soft token, and only its message is text.
- The event token carries a flag "also touched a starting file" (added; reason: without it the list shows churn and coupling alike, a fault A5.c.1 names).
- The τ bank of A5 and A3 is one bank. L is set by the pair token budget, not chosen.
- The non-negative mix is imposed on f_θ's weights for the kernel columns.

**A6, taken from A6.b.1.** Stage 1 scores every file alive from channels: dense (best and top-3 mean of chunk similarity; adapters on the question side only); BM25 over path and content with the idf of the files alive at t; names from the question and names the decoder generates after reading q and S, resolved against the symbol table at t (an unresolved name is dropped); A3's bank; A4's counts. The shortlist is C = top N by s0+s1 ∪ files named in q or the trace ∪ top M by joint-change kernel. Final order: C by its full score, then every other file by s0+s1. Every file gets a rank.
**Changed to fit.**
- A6.b.1's s1 = u^T z becomes f_θ(z) with a linear skip (from A7.c.1, "any ranker trained by a gradient per row"). Reason: a linear u cannot form the interactions among counts (count by recency) that the tree ranker of the record shows matter (record: `research-tree/build/improve/units/T3/report.md` item 1). Trees are excluded, because the dense channel's question adapters need a gradient.
- Names are generated with the adapters switched off. Reason: the adapters are trained only for the score head (A2), so their effect on generation is untrained.
- A1.b.1's structure columns join z.

**A7, taken from A7.c.1.** The offset b_k is log(ε + decayed one-over-size count) for a change and log(ε + BM25) plus a constant for named files for task words. Candidates: every file alive plus one slot per folder. Negatives: R(q)\P whole, plus a Poisson sample with known π_c. The loss is L(q) = -(1/|P|) Σ_p log[e^{s_p}/(e^{s_p}+Z)], with Z a Horvitz-Thompson total. Weights: w_q = min(1/n_R, β), bulk questions at zero. Right files are never negatives.
**Changed to fit.**
- For an error, A8.b.3 takes the joint count from the trace's files as the baseline, and A7.c.1 takes trace depth. Resolved by D 7.2 (benchmark against the naive forecast) with D12, which names "the files in the trace" as this question's naive baseline. So b_err is the trace-depth term, and the joint count from trace files enters through z.
- The same loss is used twice. Stage 1 runs over U(q) on the logits b_k + s1. Stage 2 runs over C on the logits (s0+s1, frozen) + s2, with negatives in C drawn by a Poisson sample with π proportional to softmax of the offset (known, HT-corrected). That replaces BM25 in A7.c.1's sampler, because C is already ranked by the offset.
- A slot enters C as its folder path plus the names of its files, read jointly (added; reason: A6.b.1 places C above all else, so a slot left outside C could never rank above a file).

**A8, taken from A8.b.3.** s(q,c) = s0 + s1 + [c∈C] s2. Each stage is trained with the earlier ones frozen as an offset. The s1 that s2 trains on is out-of-fold (two halves of the training clusters). s1 and s2 are shared by the three questions, with the start kind as input. Every stage sees all kinds, each repository at equal weight (D11).
**Changed to fit.**
- A8.b.3's s2 "sees text, not the count". Here it reads the relation tokens and the history token, so this Cannot is removed.
- A8.b.3's mapping onto A2.b.1's score: a^T x_qc is s1, and v^T h is s2.

## One question, end to end

Common to all three. The loader cuts the store at t (D 9.4). On a processor, it computes A3's bank, A4's path counts and A1's structure quantiles for every file alive. Stage 1: s0 = b_k (exact), plus s1 = f_θ(z) (learned), for every file and slot. C is formed (A6). For each c in C, the decoder reads: the question prefix (cached once), the relation tokens with non-zero support, the history token, the structure token, the latest L events (message text and soft token), the path, and m chunks. The output s2 is learned. Files in C are ordered by s0+s1+s2, and every other file follows by s0+s1.

- **Change.** q is the first commit's diff, and S is the files in it (kind "in the change"). b is the decayed one-over-size count. A3 and A4 come into full use. The reader sees the edited lines against a candidate's call sites.
- **Task words.** q is the issue text. S is the files named in the text, often empty. b is BM25 plus named files. When S is empty the relation tokens are absent, stage 1 rests on dense, BM25 and generated names, and s2 carries the score.
- **Error.** q is the error text with trace files marked. S is the trace files, with frame depth as an extra index of the path type. b is the trace depth. The joint count from S, the path counts from S and the generated names enter through z and the tokens. The learned stages come mostly from change and task questions, plus D10's training-only tier (e) and the training repositories of the real tiers.

## What is trained and what it costs

Trained: f_θ (a small MLP with a linear skip; thousands of parameters); the dense channel's question-side adapters; the decoder's low-rank adapters, v, the basis V_b, α, φ and the token embeddings (millions). Computed once: chunk vectors per content hash, the bank, path counts, structure quantiles (processor, linear in events and edges touched, N 14.4).

**Memory is not what binds.** A decoder of a few billion parameters in 16-bit takes 2 bytes per parameter, so 3 to 14 GB, and the adapter states are small. Activations for one question with about 16 pairs fit within 96 GB under checkpointing.

**Time binds.** Tuning costs about 6P floating-point operations per token (assumption: forward 2P, backward through frozen weights about 4P).
- With prefix sharing, one training question is about B_q + 16 × 0.7k ≈ 12k tokens: right files plus about 15 sampled negatives from C.
- Assume about 6 of the 8 hours for stage 2 and sustained throughput τ per card. The tokens processed are 3 × τ × 21,600 s / 6P.
- At P = 1.5 × 10^9 and an assumed τ = 1.5 × 10^14 per second, that is about 1.1 × 10^9 tokens, about 90,000 questions. That covers 400 to 1,500 repositories at tens of questions each. At P = 7 × 10^9 it is about 19,000.
- So the size class is computed from the counted throughput: about 1 to 3 billion parameters unless the count allows more.
- Stage 1 and its two out-of-fold fits take the remaining time on one card.

count first:
- sustained throughput per card;
- distinct content hashes alive at the asking times of the drawn questions, times chunks (the frozen pass could otherwise rival the training budget);
- tokens per pair;
- recall of right files in C at N.

12 GB form: the trained decoder at 1 to 3 billion parameters fits in 16-bit with the adapters merged, and stage 1 runs on the processor. Only the size of C shrinks, to what the time per question allows, and every file still gets a rank from s0+s1.

## Against the sheet

- **M1, by construction.**
  - Inside C, the candidate tokens read the question at every layer (N 9.4, N 9.8).
  - Outside C, s1 reads features of the pair: BM25, names, paths from S_k, kernels from S.
  - Nearest weakness: a file outside C with only the cosine channel.
- **M2, by construction.**
  - The decayed one-over-size count is s0 itself and a column of z (A3, N 9.5).
  - The reader's attention never carries counts alone, since the cascade adds them outside it.
- **M3, open on a named test.**
  - Nothing trained depends on a file or a repository, and amounts are quantiles in R (N 7.1, N 8.1, N 9.10).
  - The test: whether the decoder recalls public repositories. A path is a near-identity. Read D12's segment of repositories created after the cut-off.
- **M4.**
  - By construction for the store: one cut at t, D13's tests.
  - Open on a count for the decoder's memory: training repositories and validation questions after its cut-off (A5.b.1).
- **M5, by construction.**
  - A4's path types are kept apart, both directions and two-step composition (N 13.8, nothing embedded).
  - The tokens grow by the B mixing weights per kind (N 13.2).
- **M6, in part.**
  - Reached: every file joined by a word, name, path, generated name, kernel or two-hop path (N 11.3, no stacked steps).
  - Not reached: a file with none of these, or a file below N.
  - count first: recall at N of right files with no joint change.
- **M7, open on counts.**
  - Negatives by a known design with HT totals, never right files (N 13.6, D 3.2). Weights by D11.
  - Time is argued above, and is open on throughput and hash counts.
- **M8, in part.** The stages give baseline, then +s1, then +s2 on the same examples, read per segment. The arms are A10's.

**Vetoes it comes nearest to.**
- **W1.** Outside C the dense channel is two vectors, but s1 also reads names and counts that belong to the pair, and inside C the reading is joint.
- **W2.** Attention normalises inside the reader, but counts pass through s0 and s1 and the tokens.
- **W3.** No learned row per file. Pretrained recall is the open M3 test.
- **W4.** The event list is the latest L, but the bank covers all history.
- **W6.** Attention spans one pair.
- **W7.** The graph enters through relation tokens and path counts.
- **W9.** s1 for stage 2 is out-of-fold. The decoder's cut-off comes before validation. β, κ and N are set on validation repositories.
- **W10.** f_θ is a network on relative amounts.
- **W11.** No eigenvectors.
- **W13.** The owner's two repositories never train it. The pretrained decoder is named with its source and size to the owner before any download.

## Cannot

- **See past two hops.** A right file three imports away gets no path feature (A4.c.1, A2.b.1). It is found only by content or names.
- **Find a file that shares no word, name, path or history.** A build setting a feature needs, or a config key built by joining strings (A6.b.1, A2.b.1).
- **Rescue a file below N.** Ranked by s0+s1 under N, and not named, it never reaches s2 (A6.b.1, A8.b.3).
- **Read a long file whole.** A function past the m chosen chunks is seen only through vectors computed apart from the question (A1.b.1).
- **Forget pretraining.** A generated name or a score may be recalled, not reasoned (A1.b.1, A6.b.1).
- **Weigh an old event by what it was.** Two six-file commits of equal age weigh the same in the bank. Only the latest L events show their messages (A3.c.1, part removed by A5.b.1).
- **Form an aggregate outside the bank,** or recover a conjunction lost when paths are summed (A3.c.1, A4.c.1, D 9.2).
- **Tell which symbol a link carries** outside C. Inside C the reader sees it only if the chosen chunk holds it (A4.c.1, part removed by A2.b.1).
- **Represent a decay that is not monotone.** A pair that changes together at every half-year release is weighted below last week (A5.b.1). Calendar drift is not modelled.
- **Aim at the top ten.** Moving a file from 500 to 50 can lower the loss more than moving one from 12 to 3. Log Z is biased low. A file fixed in the next pull request counts as a negative (A7.c.1).
- **Name a new file,** or place one in a folder not yet made (A7.c.1).
- **Retrain one stage alone,** or correct a confident s0 that is wrong on a repository, such as one full of bulk changes (A8.b.3).
- **Learn error-specific scoring** where it differs from changes and task words. The error questions only shift shared stages.

## Refuted if

- **Tuned joint reader (A1.b.1, A2.b.1).** On repositories created after the decoder's cut-off, s2 adds nothing beyond its interval on right files with no joint change. Or shuffling question segments across questions scores the same.
- **Decoder memory (A5.b.1, A6.b.1).** The lead over counting is larger for repositories created before the cut-off than after it.
- **Counts inside the reader (A2 change).** Removing the relation tokens and the history token from s2 leaves per-repository ranks within their intervals. Then the cascade's addition is enough, and the tokens are cost only.
- **Typed path counts (A4.c.1).** Merging all kinds into one untyped count loses nothing in any segment.
- **Order as text (A5.b.1).** Shuffling the ages among the listed events, with the bank kept, leaves validation scores unchanged.
- **Reach channels (A6.b.1).** Without the dense and generated-name channels, recall at N of right files with no joint change and no two-hop path stays within its interval.
- **Negatives and denominator (A7.c.1).** Uniform uncorrected negatives of equal number score the same per validation repository.
- **Cascade (A8.b.3).** The gain of s2 over s0+s1 lies within the intervals on right files with no joint change. Or a separately trained reader, stacked, matches it.
- **Shared stages for errors (A8.b.3).** On real error tiers, s0+s1+s2 does no better than the trace baseline.
- **f_θ in place of a linear u (A6 change).** A linear s1 matches it per repository.
