# A8 option 1: evidence specialists, cross-fitted combiner
Lens: linked specialists: a pipeline of parts, each trained for its own job.

**Mechanism.** Specialists are cut by kind of evidence, not by question. Each serves all three questions, with the kind of starting link (in the change, named in the text, in the trace) as an input, and has its own ranking loss.
- *Retrieve:* candidates = union of the top K of separate channels (exact history kernels from S, typed path counts, BM25, frozen-encoder vector search, files named in text or trace). Other files keep a fallback rank.
- *H* scores the kernel bank of (S, c); *P* the typed path counts; *T* is one cross-encoder of question text and candidate chunk, trained on the texts of all three questions (error tier (e) of D10 included).
- *Combiner per question k:* s_k(q,c) = G_k(z_H, z_P, z_T, x_exact), x_exact passing the decayed one-over-size count and the named flag past the specialists. G_k is fitted on out-of-fold scores: each specialist is fitted twice, on halves of the training clusters, and scores the other half; at test the two are averaged.
- *Error:* G_err = G_chg + delta, delta fitted on error-tier training repositories with an L2 penalty toward zero; with no error data, delta = 0 and the trace is the start set.
- *Mixing:* equal weight per repository (D11), bounded share per question kind.

**Needs from other parts.** A1.c.1 (exact, relative features) and A1.b.1 (T's encoder); A2.b.1 (T's joint reading) and A2.a.2 (pair record); A3.c.1 (H's bank); A4.c.1 (P's counts); A5.c.1 and A5.c.3 (as-of bank, lag hazard). A6 the channels and K; A7 each loss; A9 the folds.

**Can.** M3, M5 by construction (inherited). M1 by construction (T joint; H, P relative to S). M2 by construction: the exact count reaches G_k unchanged. M4 by construction given the loader; folds cut by cluster. M6 in part: T reads only what a channel retrieved. M7 open on a count of T's pairs; H, P, G train on processors. M8 by construction: each specialist is a removable arm. Only delta needs error data.

**Cannot.** Bind evidence below the combiner. Counterexample: the right file is the partner whose co-changed function is the one the diff edits; T sees the name, H the count, G two scalars (D 9.2, D 4.3). A file no channel retrieves is lost to all later stages. H learned on change start sets may not hold for trace frames through framework hubs (assumption). Nearest vetoes: W1, but vector search only selects; W9, but G never sees in-fold scores.

**Rests on.** N 5.2, N 9.4, N 9.5, N 13.9; D 6.1, D 6.4, D 9.2, D 3.2; record: `research-tree/build/improve/units/T3/report.md` items 1, 3; record: `research-tree/build/improve/units/U3/report.md`. Count first: recall at K per channel, question kind and repository; history coverage of trace files.

**Refuted if.** On validation repositories, option 2 ranks right files needing both text and history higher beyond the intervals; or G_k fitted on in-fold scores matches the cross-fitted one.
