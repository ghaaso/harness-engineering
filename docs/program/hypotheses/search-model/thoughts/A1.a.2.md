# A1 option 2: pair record and joint text
Lens: graph first. This option departs from it: the graph enters only through exact aggregates computed beforehand.

**Mechanism.** The model reads a pair (question q, candidate f), not nodes.
- A fixed program computes aggregates at loading over the typed neighbourhood at t (D14 (b)). For each starting file s, link kind k, direction and τ in a fixed bank: C_k,τ(s,f) = Σ_{e ∋ s,f; time(e) < t} (1/n_e)·exp(-(t-time(e))/τ), the raw count, and the age of the last joint event. Beside them: the shortest typed path length from the starting set in the import, use, test and folder graph (capped); whether f is named in the text or trace; folder distance; f's change frequency. Sum and max over starting files.
- Each amount enters as log(1+x), as its quantile over the repository's own past before t, and as a missing flag.
- The text is one sequence: [question text ; path of f ; best-matching chunk of f]. A pretrained encoder reads it, fine-tuned on training repositories and training times only (D6), with a cut-off no later than the test cut-off. Tokens of the question and the file attend to each other from the first layer.
- Repository description and scale amounts join every pair.

**Needs from other parts.** A6 supplies a retrieved candidate set, since there is one encoder pass per pair. A7 supplies a ranking loss over pairs. A9 computes the aggregates once per question.

**Can.** By construction: M1 for text, since two files with the same surroundings differ by what the question attends to; M2 for every aggregate in the bank; M3, with no identities and relative scale; M4, since everything is cut at t at loading (D 9.4). M6 only in part: content is read for retrieved candidates only.

**Cannot.** A pattern outside the bank is lost before learning (D 9.2, N 13.9). Counterexample: "files changed with s in commits that also touched a test of f, by one person, within a week". Joint encoding of every live file is too costly, so far files depend on retrieval. Nearest veto: W7. It is not struck, because path lengths and typed counts are computed from adjacency.

**Rests on.** Record: `research-tree/build/improve/units/T3/report.md` items 1, 3 and 6. There, the tree ranker on pair features was best, and the count features without the graph scored as the whole did. Record: `research-tree/build/improve/units/T2/report.md` (the change text added 0.010). N 9.5, N 12.6, N 13.9; D 6.2, D 8.1, D 9.2, D 9.4. Assumption: the patterns that matter are few and nameable. Count first: the share of right files linked to the starting set only by a path of two or more hops through mixed kinds.

**Refuted if.** On unseen repositories, adding learned sum message passing over the same neighbourhood to these inputs raises hits beyond the resampling interval. Look most at right files with no joint change but a path of two or more hops: that is what the fixed bank lost.
