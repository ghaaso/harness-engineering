# A3 option 2: learned sum over event nodes
Lens: exact relational computation first. Departs from it: a fixed bank loses what it did not foresee (D 9.2, N 13.9), so the aggregate is learned, with the exact count kept as a guaranteed channel.

**Mechanism.** Joint events E(s,c,t) are nodes (D14). Each has a vector x_e: size, ages on both clocks, bulk and bot flags, whether s and c were added, deleted or edited, lines changed at each, an encoding of its message (A1). The pair's history:

h(s,c) = rho( sum over e of [ k(n_e, age_e) ; phi(x_e) ] )

k a fixed channel holding exact kernels (at least n_e^-1 exp(-age_e/tau)); phi a learned network with a time embedding entering multiplicatively (N 13.9). A sum, never a mean or softmax; MLPs before and after make it injective on multisets (N 9.5). Several starting files: a second sum of the same form. For a pair with more than K joint events, phi is summed over a sample of K drawn with known probability, each term weighted by one over it (D 3.2), so the learned sum is unbiased; k is always summed over all events.

**Needs from other parts.** A1 message encoder, relative amounts; A5 the cut, clocks; A6 a bounded candidate set; A7 the loss; A9 event sampling and memory.

**Can.** M2 by construction: the exact count is a channel, learned channels are sums. Weigh an event by what it is: the rename and the feature of option 1's counterexample get different phi. M4 by construction given loading at t (D 9.4). M3 by construction: phi reads event features, no identities. M5 in part: kind of edit per end and order in x_e. M7 open on a count of joint events per pair. M1 in part, as option 1.

**Cannot.** Cover many candidates cheaply: cost grows with each scored pair's joint events, so A6 must narrow first. Be exact on hubs: the sampled part is unbiased, with variance (N 14.2). Carry the message channel to a repository whose messages say nothing; counterexample: every message "update", phi learns nothing there and only k carries it. Reach a file with no joint event. Nearest veto W4: hub sampling covers all history with known probabilities, not a recent window. Not W2: a sum.

**Rests on.** N 9.5; N 13.9; D 9.2, D 9.3 (events as nodes, nothing aggregated in advance); D 3.2; N 14.2; D14; record: research-tree/build/improve/units/T3/report.md items 3, 5 (the mean-aggregating graph added nothing beyond count features; this is a sum over events, not a mean over files). count first: joint events per candidate pair by repository; share of messages that say nothing.

**Refuted if.** Per validation repository, the learned channels add nothing over k alone with the same ranker, or their gain vanishes on repositories unseen in training.
