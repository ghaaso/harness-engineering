# A2 option 2: question-marked graph, sum over paths
Lens: language model first; departed from, because N 9.10 and N 10.5 give a question-relative description without a
joint reading. The graph does the main work; a language model supplies one number per file.
**Mechanism.** The question marks its starting files, a relative identity in place of a stored one (N 9.10, marking
the root; N 10.5, the starting set as anchor set). Initial state of file v for question q:
h_v^0 = [ m_k(v) per start kind k ; t(q,v) ; structure features of v ],
m_k(v) = 1 if v is a start of kind k (in the change; named in the text; in the trace, with frame depth), else 0;
t(q,v) = text relevance from a frozen pretrained encoder (cut-off before the test cut-off, D7). For task words naming
no file, the top files by t are soft starts, m = their normalised t. Then K layers of typed, directed sums over the
graph cut at the asking time, events as nodes:
h_v^(l+1) = U h_v^l + sum_r sum_(u in N_r(v)) w_uv W_r h_u^l,
w_uv = decay(age)/size on an event edge, else 1; W_r a mix of shared bases (N 13.2). Score of c: f(h_c^K).
**Needs from other parts.** A1: t and structure features. A3: w and decay. A4: kinds, direction. A5: the time-cut
graph. A6: candidates beyond K hops. A7: loss.
**Can.** M1 by construction: two files with identical surroundings but different distance to the marked starts, or
one file under two questions with different starts, get different states; this answers the position failure of
N 9.7 that a node vector computed once cannot. M2 by construction: at K = 2, start to event to candidate, the sum is
exactly the decayed, one-over-size count; a mean is not (N 9.5). M3 by construction: marks are relative, nothing
stored per file. M5 by construction. Every file alive gets a rank at the cost of K sparse passes (N 12.2).
**Cannot.** Read the question against content beyond the scalar t: two candidates at equal distance with equal t
tie. Reach past K hops except through t; a far file unlike the question is
lost. For task words naming no file, the marks are only as good as retrieval, and retrievers swing by repository.
Nearest veto W1: t is two independent vectors, but the score does not come only from them. W5: reach rests also on
t, not on stacked steps alone.
**Rests on.** N 9.5, N 9.7, N 9.10, N 10.5, N 12.2, N 13.2, N 13.9; D 9.4; record:
research-tree/build/improve/units/T3/report.md (a pair head over node vectors added nothing beyond counts); record:
research-tree/build/improve/units/U3/report.md (retriever swing);
count first: share of right files within K hops of the marked starts,
per question kind, on the time-cut graph.
**Refuted if.** Zeroing all marks leaves the validation ranking unchanged, or at K = 2 the model fails to order
pairs as the exact decayed count does on the change question.
