# A5 option 1: relative clocks, exact decay bank, horizon-checked LM
Lens: language model first.
**Mechanism.** The asking time t is the zero of every clock; no calendar date reaches the model. The loader builds each example from the store cut at t. Each event e gets two ages in the repository's own scale: wall age (t - t_e)/g, g the median gap between units of work before t; event age, the units of work landed since e. Time enters the LM twice.
1. Exact history as a soft token: C_k(c) = sum over events e touching c and the start set of w(|e|) exp(-age_e/tau_k), for a fixed bank of tau_k (geometric, both clocks), computed exactly first. A learned projection makes (C_1..C_K) one input token beside the candidate. The decay used is a learned non-negative mixture of fixed kernels: both fixed and learned.
2. Order as text: the candidate's latest events (message, size, both ages as numbers), newest first, after the question and the candidate's content at t.
The LM's own memory is a second leak: its training cut-off must precede the validation stretch, not only the test cut-off, and every example is marked by whether t falls before it.
**Needs from other parts.** A1: an LM taking soft tokens. A3: the size weight w and the combination of counts. A7: the score head. A10: readings split by the cut-off mark. D7: stretches placed for the stricter cut-off.
**Can.** M4 by construction for the store (D 9.4, D 6.2); open on a count for the LM's memory. M2 by construction for any decay in the bank's span: each C_k is an exact sum (N 9.5), the mixture linear in them. M3 by construction: ages follow the repository's pace, and no input depends on a date that lies outside the training range at test (D 7.1, D 8.1). M1 in part: ages are relative to this question.
**Cannot.** Model calendar drift (D 7.4): that needs absolute time, out of range at test. Count from the text list: attention normalises and context is limited (N 12.6; N 13.9, S12 slide 21). Nearest vetoes W2 and W4; it falls under neither, because exact counts over the whole history enter by the soft token and the text list is extra. A decay far from every mixture of the bank, such as a step at one age, is only approximated.
**Rests on.** N 13.9; N 9.5; N 12.6; D 6.1, D 6.2, D 7.1, D 7.4, D 8.1, D 9.1, D 9.4. record: `research-tree/build/improve/units/T3/report.md` (recent-window models, decayed counting). assumption: relevance of a joint change falls monotonically with age, so a mixture of exponentials covers it. count first: training repositories and validation questions after the LM's cut-off.
**Refuted if.** Shuffling ages among the listed events, soft token kept, leaves validation scores unchanged (the text path carries no time). Or the model's lead over decayed counting on test is larger for repositories created before the LM's cut-off than after it (memory, not mechanism, does the work).
