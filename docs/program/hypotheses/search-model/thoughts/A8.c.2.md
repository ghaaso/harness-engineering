# A8 option 2: separate specialists, error by composition
Lens: one backbone with a small part per question. Departs from it: nothing learned is shared; each question with data has its own ranker, and errors are served by composing them.

**Mechanism.** Shared, but not learned: the store cut at t, the frozen encoder, the exact pair features x_qc (kernel bank, typed path counts). Per question, a separate ranker over its own retrieved set, trained only on its own questions, each repository weighing the same (D11):
- change: R_chg(q, S, c), a ranker over x_qc and the joint reading;
- task words: R_txt(q, c), a joint reader of text and content, plus x_qc where the text names files.

Errors reuse both, with no error-trained backbone:
s_err(q,c) = b_0 + b_1 R_chg(S = trace files, c) + b_2 R_txt(q = error text, c) + b^T z_qc,
z_qc a few exact trace features (c in the trace, its deepest frame's depth, c defines a name in the error text). Only b is fitted on error data. Base scores are cross-fitted: for an error example they come from a fit that left out its repository cluster. Stages: A6 retrieves per question, the ranker re-ranks; other files keep the retrieval score, below.

**Needs from other parts.** A1.c.1 and A2.a.2 (pair record), A2.b.1 (joint reader), A3.c.1 and A5.c.1 (exact bank, as-of cut), A4.c.1 (typed path counts). A6: a retrieved set per question. A7: per-question losses. A9: two fits plus cross-fitting.

**Can.** No kind pulls another down. The change ranker may be a tree over relative features, the form that leads on both questions with data (record); the task-words ranker may be a cross-encoder; neither is held to the other's form. Errors need only |b| numbers fitted, so a few hundred real examples suffice (assumption: under ten weights fit stably from hundreds of examples). M1 by construction, through each ranker's pair reading. M2 and M4 by construction, through the exact features. M3 by construction. M7 by construction: fits run apart, one card each. M8: the "separate" arm against option 1.

**Cannot.** Pool what the questions share: both read text against code, and the task-words reader learns from far fewer questions alone. Learn an interaction across the two scores. Counterexample: the right file is the trace's deepest frame and contains the message string; that conjunction was never seen by either ranker, and a linear stacker sees two numbers. A file neither specialist ranks (a config file the trace never names, sharing no word with the error) is lost. Nearest veto W1: no; each base score is a joint pair computation. W9: cross-fitting by cluster.

**Rests on.** N 1.1, N 9.4, N 9.8; D 3.2, D 6.2, D 6.4; D10, D11 (DATA-CHOICES.md); record: `research-tree/build/improve/units/T3/report.md` item 1, `research-tree/build/improve/units/U3/report.md`. count first: real error examples per tier and cluster.

**Refuted if.** On unseen repositories, option 1's shared backbone beats both specialists on their own questions beyond the intervals; or on errors the stacker does no better than the trace-files baseline.
