# A1 option 3: exact facts written into cross-encoder
Lens: exact relational computation first. The exact facts are computed as in option 1; the ranker that reads them is a language model reading question and candidate together.

**Mechanism.** For each pair (q, c) one input sequence: the question text, diff or error text; c's path; the parts of c's content at t chosen by exact rules (the definitions of names the question uses, the lines that resolve a path or import named in it, else the head of the file); and a short written block of option 1's exact relational facts, amounts written relative to the candidates of this question ("joint changes with starting files: 3, newest 4 days; percentile 97; imports a starting file: yes"). A pretrained encoder (cut-off before the test cut-off) reads the sequence and outputs one score; it is trained on training repositories and training times only. No repository or file identity appears.

**Needs from other parts.** A6: a short list, since every pair is read in full (the top few hundred). A7: the loss. A9: the cost of reading pairs. A8: whether option 1's ranker makes the short list.

**Can.** Match text to code token by token: a diff that changes a function's signature is matched against the call in c, which option 1 sees only as a count of names. M1 by construction (one joint pass per pair; the graph enters through the tokens, N 12.7). M2 in part: the exact count is given, but the network reads it as written tokens, so its effect is learned and need not be monotone. M3 by construction. M6 in part, inside the short list.

**Cannot.** See the graph beyond what was written: the facts are option 1's table, with its lost patterns (D 9.2). Read numbers as precisely as a ranker on numbers: two counts that differ in the third digit are two token strings. Rank every file: the cost per pair limits it to a short list (N 12.1). Read a long file whole: context is limited (N 13.9, "context size is limited"), so a large c is cut. Nearest veto W7: the graph enters only as written facts; it does not fall under it because those facts carry the adjacency of the pair. W1: avoided, the pair is read jointly.

**Rests on.** N 12.6, N 12.7, N 13.9 (the reasons a language model does not replace relational learning), D 9.2; record: `research-tree/build/improve/units/T2/report.md` (the change's text names a right file in 37 % of tasks); count first: the share of right files inside a short list of a few hundred from option 1.

**Refuted if.** Inside the same short list it does no better than option 1's ranker, or it does worse on repositories created after the encoder's cut-off.
