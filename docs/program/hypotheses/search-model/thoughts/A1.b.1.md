# A1 option 1: code model reads text, numbers bypass it
Lens: language model first.

**Mechanism.** Three paths.
- *Text and code* (question, diff, error, file, repository description): one pretrained decoder of code and text, cut-off no later than the test cut-off (D7), tuned with low-rank adapters on training repositories and times only (D6). A diff enters as unified text with line markers; trace paths also become "in the trace" links. A file is its path plus content in chunks of B tokens; a frozen pass stores one vector per chunk per content hash, once (D3). The tuned pass reads question and file together where A2 asks. The repository description: a cached prefix.
- *Events and links* enter as soft tokens: t = E_kind[k] + E_dir[d] + E_res[r] + MLP(a) (closed set of kinds, D5, D14; direction; resolved or not; amounts a below). No file or repository identity (N 9.10, N 13.7).
- *Amounts* (size of a unit of work, age, counts) enter twice. As features a = [log(1+x), q_R,t(x)], q being x's quantile in repository R before asking time t (N 7.1, D 6.4). And raw (x, 1/n, age) on a path that bypasses the model, so A3 computes sums of exp(-age/tau)/n exactly. Never as digits in a prompt.
- *Structure independent of the question*, per file at t, as quantiles within R: degree per kind and direction; closed-walk counts diag(A^k), k = 2..6, on the import-and-use graph (N 9.10); random-walk return probabilities (N 10.4); folder depth; age; decayed change rate. No eigenvectors (N 10.3, N 10.6). Missing values flagged (D 5.3).

**Needs from other parts.** A2: where question and file are read together. A3: aggregation of the raw numbers. A4: how link tokens enter attention. A6: which candidates get the tuned pass.

**Can.** A right file with no history or code link is still read by a model that knows code (M6, in part; up to 66 % of right files had no earlier joint change, record: FACTS). M3 by construction. M4 by construction for amounts and structure; for the weights, open on D12's repositories created after the cut-off. M2: exact inputs reach A3 by construction. M5: in part.

**Cannot.** Read a long file whole: a 5,000-line file whose relevant function lies past the budget is seen only through question-independent chunk vectors; a score from those alone is W1, so they serve reach only. Count from text (hence the bypass; nearest W2). Forget pretraining: a path is a near-identity, and the model may recall joint changes of public repositories it read (nearest W3; nothing is learned per file, and post-cut-off repositories expose it).

**Rests on.** N 12.5, N 12.7, N 13.3, N 13.1, N 9.10, N 10.4, N 7.1; D 6.2, D 6.4, D 9.4; record: `research-tree/build/improve/units/T3/report.md` item 1; assumption: a model with a fitting cut-off exists; count first: share of files over B tokens.

**Refuted if.** On repositories created after the cut-off, the tuned reader gains nothing over the same design with frozen chunk vectors only.
