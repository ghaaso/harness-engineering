# A3 option 2: learned event messages, summed exactly
Lens: language model first; this option departs from it. Aggregation is a small trained network over events, as in
relational deep learning (N 13.9).
**Mechanism.** Every event before the asking time containing c and a starting file sends a message; messages are
summed, never averaged:
h(S,c) = sum_{e: c in e, e cap S nonempty} |e cap S| * rho(n_e, a_e) (elementwise) psi(x_e),
x_e = [log size relative to the repository's median, age in the repository's clock, kind (commit, pull request,
merge, flagged bulk or bot), lines added and removed relative to the repository, u_e], u_e a frozen encoding of the
message. rho_j = n_e^(-alpha_j) exp(-a_e / tau_j), learned per output dimension. psi is an MLP whose first output is
fixed to 1, so h_1 with alpha = 1 and the baseline's decay is the counting baseline exactly. The same sum over c's own
events gives an activity vector g(c). The scorer sees [h, g(c), g(S)]. Nothing is sampled.
**Needs from other parts.** A5: age unit, decay fixed or learned. A4: which links make an event. A1: encoder for u_e.
A2, A7: a scorer combining h with the question. A9: per-pair event lists computed once.
**Can.** M2 by construction (constant output, sum aggregation; N 9.5). M4 by construction: events cut at the asking
time (D 9.4). M3 by construction: relative inputs, nothing per file. Beyond option 1: learns which events count by
more than size and age (a revert, bulk rename or bot commit weighted down; size and age interacting). Linear in joint
events; runs on every pair with history, no retrieved set needed.
**Cannot.** See order: the sum ignores it, so "s then c in the next commit" counts only if A4 makes a follow-up an
event. Reach a candidate with no joint event: h is zero (30, 66 and 21 % of right files, facts sheet); that is A6.
Relate events to the question: h ignores it, so two questions with the same starting files get the same h (M1 rests
on A2). Transfer across habits: counterexample, a repository squashing every pull request into one large commit; if
training saw few, psi may down-weight its normal events; relative size softens this, no more. Nearest veto W2: not
met, no mean or normalised attention. W3: u_e is content, not an index.
**Rests on.** N 13.9 (learned aggregates; message times time embedding); N 9.5; N 13.2; D 3.2; D 9.2 (fixed aggregates
lose information); D 9.4; record: `research-tree/build/improve/units/T3/report.md` item 5 (1/size edge weights under
mean aggregation changed nothing, as a mean predicts). assumption: event kind and size carry signal beyond the kernel
family. count first: share of joint events that are bulk, bot or revert, per repository.
**Refuted if.** With the same scorer, h scores no better than option 1's fixed channels on unseen repositories, or
loses to them in the stratum of repositories that squash.
