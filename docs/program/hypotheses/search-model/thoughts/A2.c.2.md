# A2 option 2: question-marked relational message passing
Lens: exact relational computation first; this option departs from it, because a fixed bank of paths cannot learn a relation it does not list (D 9.2).
**Mechanism.** The question is a node Q holding its encoded text (A1), linked to its starts by typed links "in the change", "named in the text", "in the trace" (D14). Per question a subgraph is cut from the store at t_q: S_q, the candidates retrieved for q (A6), and the events and files on typed paths between them. Initial states carry the question: h_v^0 = x_v + [v in S_q] u_kind(v) + [v in S_q] P(Q), x_v being content features. Then L layers of relational sum aggregation along direction, per-relation weights as mixes of shared bases (N 13.2): h_v^{l+1} = phi(h_v^l, sum_r sum_{u in N_r(v)} sum_b a_rb B_b h_u^l). The exact decayed, size-weighted joint count (A3) is an edge feature on start-candidate pairs, never relearned. The score reads h_c^L with h_Q^L (A7). Because states start from the marks and Q, h_c describes c relative to this question.
**Needs from other parts.** A1 encoder; A3 exact aggregate as edge feature; A4 kinds and bases; A5 time cut in loading and sampling; A6 retrieved candidates; A7 score and loss; A9 one subgraph per question, its sampling recorded.
**Can.** M1 by construction: marks and Q make one candidate's state differ between questions; nodes symmetric in the graph are told apart by their relation to the marked starts (N 9.10; the position problem of N 9.7 answered relative to S_q). M2 by construction: sum aggregation plus the exact edge feature. M3 by construction: coefficients only. M4 by construction if loading is cut. M5 by construction, bounded by the bases. M6 in part: a retrieved candidate gets a direct path, not a long chain. Learns multi-hop patterns the bank of option 1 does not list.
**Cannot.** See past L hops (N 5.5); over-squash where one event joins many files (N 11.1); a 500-file commit must be sampled (N 14.2), so its exact count rests on the edge feature. One subgraph per question; nothing shared between questions. Beyond the marks, still bounded by 1-WL (N 9.1). Nearest veto W5: reach is not left to stacked steps alone, since retrieval and Q give direct paths. W2: aggregation is a sum.
**Rests on.** N 9.4, N 9.5, N 9.7, N 9.10, N 13.2, N 13.3, N 13.9, N 14.2; record: `research-tree/build/improve/units/T3/report.md` items 3, 5, 6 (the earlier graph network built candidate vectors without the question and drew its score from count features). assumption: what that model lacked was the mark of S_q; it had the vector-pair head that N 9.8 limits.
**Refuted if.** On unseen validation repositories, per repository, it adds nothing over option 1's profile read by the same ranker, on right files with no earlier joint change with S_q.
