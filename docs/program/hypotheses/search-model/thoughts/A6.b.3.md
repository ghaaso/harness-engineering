# A6 option 3: joint descent of the folder tree
Lens: language model first: a large pretrained model of text and code does the main work, the graph enters around or inside it.

**Mechanism.** The repository's tree at t is the hierarchy, so no partition is chosen (N 12.4). At folder d the decoder reads, as one sequence, the question q (with its starting files' paths) and d's listing: per child, its name, the names it defines (D5) and one relation token carrying exact sums over the child's whole subtree: the kernel bank to the starting files (A3.c.1) and typed link counts into it (A4.c.1), relative to the repository. It outputs a softmax over d's children:

p(f | q) = product over folders d on f's path of p(child_d(f) | q, listing(d)).

A beam descends; a file under an unexpanded folder gets its parent's probability split evenly, so every file has a rank. The top N leaves go to the joint reader (A2.b.1). An oversized folder is split into name-ordered blocks.
Training: the loss is minus log p(right file), summed over its levels over levels and right files; each softmax covers all siblings, so nothing is sampled and no right file is a negative.

**Needs from other parts.** A1.b.1 (decoder with soft tokens, adapters tuned on training repositories); A2.b.1 (joint reader for leaves); A3.c.1 (kernels, summed per subtree); A4.c.1 (link counts); A5.b.1 (cut at t, cut-off mark). A7: how the two scores combine. A9: beam width, listing length.

**Can.** M6 by construction: depth is the tree's depth, O(log n) routes (N 11.3), and every step reads content with the question in view, no history needed. M1 by construction: each level is a joint reading, not two vectors. M2 by construction: subtree sums are exact and add up the tree, so a folder holding the joint-change partner carries its count. M3 by construction: no identity. M7 by construction: training cost is one pass per level per right file. A new file that belongs somewhere is a leaf "new file here" under its folder, scored the same way.

**Cannot.** Recover from a wrong turn high up: a right file under a folder the beam drops keeps only a coarse rank. Counterexample: a fix in `vendor/patches/` when the question speaks only of the feature. Rank within a flat folder of 3,000 files beyond its name-ordered blocks. Use a link that crosses the tree except through the subtree sums. Nearest veto W5: not stacked local steps on the link graph but a fixed-depth descent of the given tree. W1: no; every level reads question and listing together.

**Rests on.** N 11.3, N 12.4, N 12.5, N 12.7, N 9.4, N 9.5, N 13.9; record: FACTS-MODELS-SO-FAR.md (no joint change for 30, 66, 21 %). assumption: folder and file names in most repositories describe their content, so a question's words predict the path. count first: per repository, tree depth, largest listing in tokens, and the share of right files whose top-level folder the starting files do not share.

**Refuted if.** On validation repositories, the descent's recall at N, for right files with no history, is no higher than option 1's s1 at equal N; or shuffling child names within each listing leaves it unchanged.
