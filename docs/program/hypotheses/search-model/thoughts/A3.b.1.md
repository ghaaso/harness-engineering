# A3 option 1: exact kernel sums read by LM
Lens: language model first.
**Mechanism.** History is summed exactly outside the language model, then given to it twice.
(1) Kernel sums. For starting set S, candidate c, events e before the asking time (size n_e, age a_e):
C_k(S,c) = sum_{s in S} sum_{e: s,c in e} n_e^(-alpha_k) exp(-a_e / tau_k), K channels with their own (alpha_k, tau_k).
Beside them: the candidate's own decayed change mass A_k(c) (same sum over events containing c), the same for S, the
number of starting files with any joint event, the age of the last joint event. One channel has alpha = 1 and the
baseline's decay: the counting baseline is an input coordinate, exactly. Nothing is sampled; a cap, if ever needed,
weights each kept event by 1/pi_e.
(2) Evidence text. The m events of largest channel weight enter as text: message or pull request title, with size
and age.
Injection: each channel becomes a token v_k = W_k [log(1+C_k), 1(C_k > 0), repository percentile of C_k] in the
cross-encoder's input beside question, candidate and evidence. A linear skip adds
sum_k w_k log(1+C_k) to the score, so the count reaches it without passing through softmax.
**Needs from other parts.** A5: age unit; tau fixed or learned (works either way). A6: a retrieved set small enough
for one cross-encoder pass per candidate. A1: encoder; numbers as tokens. A4: which links make an event. A7: loss.
**Can.** M2 by construction: the count is an input and the skip carries it untouched. M4 by construction: only events
before the asking time (D 9.4, D 6.2). M3 by construction: no identities; logs and percentiles within the repository.
M1 in part: the model reads question, candidate and the reasons for past joint changes together, so equal counts can
score differently. A_k separates "changes with s" from "changes often".
**Cannot.** Learn an aggregate outside the kernel family. Counterexample: c follows s in the next commit, never the
same one; a joint count sees nothing. Read past m passages: a reason in event m+1 is lost. Score every file alive:
cross-encoder cost limits it to a retrieved set. A fixed family is a hand-built projection (D 9.2);
learned alpha, tau only soften it. Nearest veto W4: the passages are a short window, but full-history sums are a
second view. Not W2: sums, no mean or normalised attention over events.
**Rests on.** N 9.5 (sum keeps the multiset); N 12.6, N 13.2 (softmax and degree normalisation act as a mean, hence
the skip); N 14.4; D 3.2; D 9.4; record: `docs/program/hypotheses/search-model/FACTS-MODELS-SO-FAR.md` (decayed
one-over-size counting; count features carried the graph network; the tree ranker on counts leads); record:
`research-tree/build/improve/units/T3/report.md` item 8. assumption: messages often say why files move together.
count first: share of joint events whose message has more than a few words.
**Refuted if.** On validation repositories the full model scores no better than its skip path alone, or real evidence
text scores the same as messages shuffled between events.
