# A3 option 3: question-gated sum over events
Lens: graph first. The model computes on the typed neighbourhood handed over by the data, with the question as a node of it.

**Mechanism.** As option 1 (events as nodes, a sum through them, per starting file), but each event's weight also depends on what the event was and on the question.
- Each event e has a content vector v_e from its message and diff, by A1's encoder; it does not depend on the question, so it is computed once.
- The question node gives q.
- h_{c|s}[k] = sum over joint events e before the asking time of n_e^(-p_k) * exp(-a_e / tau_k) * sigma_k(q, v_e),
  sigma_k(q, v_e) = 2 * sigmoid(b_k + q^T W_k v_e), W_k of low rank.

The gate is bounded and per event, not a softmax over events (N 12.6, W2), so the sum still counts. With W_k = 0 and b_k = 0 the channel is exactly the decayed, size-weighted count. Pooling and activity channels as option 1.

**Needs from other parts.** A1: an encoder with training cut-off before the test cut-off, giving q and v_e in one space. A2: q. A5: ages and the cut. A7: the scorer.

**Can.**
- M2 by construction: the count is the gate's neutral point.
- M1 in part: two candidates with equal joint counts get different history for different questions when their joint events differ in content. Example: s and c changed together in ten logging changes, s and d in ten schema changes; a schema question weighs d's history more.
- This is anisotropic aggregation (N 9.3) on the event, with the fact's own representation in its message (N 13.9).
- M3: only W_k, b_k, p_k, tau_k are trained; no identities.
- M4 by construction, given the loader.

**Cannot.**
- Cost less than option 1: every event touching the starting set needs its stored vector. count first: events per question and the store's size.
- Help where messages say nothing ("fix", empty): the gate stays neutral and this is option 1.
- Weigh order across separate events (option 1's counterexample stands).
- Transfer safely if the gate learns one repository's message habits; the bound of D11 and the bounded gate limit this, not remove it.
- Nearest veto W2; not under it: per-event, unnormalised gates pass counts, only scaled.

**Rests on.** N 9.3, N 9.5, N 12.6, N 13.9, D 6.2 (encoder learned on training data only). assumption: earlier joint changes of similar purpose are better evidence than others, since a task's right files are those its kind of change touched before. count first: the share of commits per repository whose message is more than a few words.

**Refuted if.** With all else as option 1, the gate stays near neutral on validation repositories; or the gated model beats option 1 on training repositories but not on held-out ones.
