# A5 option 2: learned time function, summed messages
Lens: exact relational computation first. This option departs from it: the decay shape is learned inside the model, one exact channel kept.

**Mechanism.** Events (units of work) are nodes with their size and age relative to the question (D14). The neighbourhood is loaded as of t_q (D 9.4), so the computation graph changes with the asking time (N 13.9). A message from event e to candidate c is the event's representation times an embedding of its age, the form of N 13.9:

m(e->c) = psi(x_e, n_e, kind) * phi(a(e)),   h_c(q) = sum over e of m(e->c),

a(e) in the repository's own units (main-line units between e and t_q; wall time over the median gap). phi has fixed channels exp(-a/tau_k) and a learned part, a small network over log(1+a) and periodic terms sin, cos(a/p_j). Aggregation is a sum, never a mean or normalised attention, so how often survives (N 9.5). Order inside a pull request enters as each commit's step index. Where a pair has more events than memory allows, events are drawn with known probabilities and weighted by one over them (D 3.2, D 2.9).

**Needs from other parts.** A1: event and file encoders. A3: the sum form and size inputs. A4: the kind in psi. A9: memory for hub files' events.

**Can.** Learn shapes a bank of exponentials cannot: peaked or periodic coupling (option 1's release-cycle pair); decay that depends on size and kind (a bulk rename forgotten fast, a two-file fix kept long). M2 by construction without sampling: the fixed channel with psi giving 1/n_e is the decayed, size-weighted count; unbiased, not exact, when sampled. M4 by construction through loading as of t_q. M3: ages relative, no identity.

**Cannot.** Extrapolate the learned part to ages outside the training range: a twenty-year history on an unseen repository gives ages no training repository had, and phi there is unconstrained (D 8.1's limit, here for a network). Adapt the shape to one repository except through its inputs. Stay exact under sampling: one draw of a hub pair's events gives a count with variance (N 14.2). Nearest veto W2: the time term weights messages and is not normalised over them, so it is no softmax average. W4: no fixed recent window; sampling is by design, weighted.

**Rests on.** N 13.9, N 9.5, N 12.6, N 14.2; D 9.4, D 3.2, D 2.9, D 8.1; record: `research-tree/build/improve/units/T3/report.md` items 2, 4 (time models reading only 20 to 32 recent events). assumption: the periodic terms matter only if periodic coupling exists; count first: in training repositories, the share of pairs whose joint changes repeat at regular lags.

**Refuted if.** On validation, the learned part of phi converges to a monotone curve the fixed channels already span, and removing it moves no per-repository rank beyond the intervals; or on repositories with histories longer than any in training it scores below option 1.
