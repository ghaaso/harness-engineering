# A8 option 1: one rooted network, question kind as input
Lens: one shared model: a single model with shared weights answers all three questions.

**Mechanism.** Each difference between the questions is an input, never a parameter set of its own:
- the question text (diff, issue, error) goes through A1's one encoder, plus a kind vector k_q, one of three (N 13.1);
- the start relation (in the change, named in the text, in the trace with frame depth) is one relation of the shared basis W_r = sum_b a_rb V_b, so a kind owns only B numbers (N 13.2);
- event sums, relation basis, joint reader phi and read-out are shared.

h_v^0 = sum_k [v in S_k(Q)] a_k + phi(q, x_v) + g(x_v) + U k_q;  s(Q, v) = w . h_v^L.

*Error question.* It shares every weight except a_trace,b and k_error. Its few real examples (D10 tiers b, c, f) fit only those; tier (e) trains, never tests.
*Stages.* One model, two passes. Pass 1 runs with phi masked over A6's candidates; pass 2 with phi on the top set. Phi is masked on a known share of training examples, so the weights are valid in both modes.
*Mix.* Every step mixes all kinds. Each repository has equal weight (D11), split among the kinds it has. Losses are reweighted by one over known draw probabilities (D 3.2). The error share is chosen on validation repositories (D7).

**Needs from other parts.** A1.a.1 (typed nodes, frozen chunks, exact event inputs); A2.a.1 (question-rooted propagation, joint phi); A3.a.3 or A3.c.2 (event sums with the exact count as a channel); A4.a.1 (shared bases, both directions); A5.c.1 (store cut at t, kernel bank). A6 candidates; A7 loss; A9 one run.

**Can.** M1 by construction: root marks and phi are per question, and k_q lets one file score differently by kind. M3 by construction: k_q is a kind, not an identity. M2, M5 as A3.a.3 and A4.a.1. M7 by construction: one run in place of three on three cards for eight hours. The error question gets the trunk the others train (N 5.2: symmetries multiply the data).

**Cannot.** Give a kind a direction outside the bases' span (N 13.2). Counterexample: if deep trace frames matter for errors and nothing in changes or tasks teaches that order, a few error examples cannot fit it. Rule out negative transfer: change questions dominate and can tilt the trunk toward history where task words need content. Pass 1 scores far files without the joint reading; nearest veto W1, not met because the final score comes from pass 2.

**Rests on.** N 5.2, N 13.1, N 13.2, N 1.1, N 8.4; D 3.2, D 7.4 (a rare event with its own model is memorised), D10, D11. Assumption: phased training lets the last kind overwrite the others, hence mixing every step. Count first: real error examples per repository and tier.

**Refuted if.** Per validation repository, a change-only model of this form beats the shared one on change beyond the intervals; or on errors the shared model is no better than the same form trained on errors alone, or than the trace-files baseline.
