# A8 option 2: one shared relational model, kind marks
Lens: linked specialists: a pipeline of parts, each trained for its own job. This option departs from it: one model, all parameters shared by the three questions, trained end to end. A shared class learns a pattern wherever it recurs (N 5.2), and only a conjunction computed inside one model survives (D 9.2).

**Mechanism.** One network over the question-rooted neighbourhood cut at the asking time:
- The question node carries its text vector; starting files carry a mark a_k per kind (in the change, named in the text, in the trace; frame depth as an edge feature). Per-question parameters: the three marks and a kind token in the text input.
- Events are nodes; history is a sum over joint events with a bounded gate read from the question, its neutral point the exact decayed one-over-size count. Relations use shared bases, both directions.
- s(q,c) = w . h_c^L + b . x_exact(q,c).
- Candidates come from an untrained union of exact channels (history kernels, path counts, BM25, named files). Only the ranker is learned.
- *Mixing:* each batch holds all kinds; repositories equal weight (D11); kind k sampled with probability proportional to n_k^(1/2): the change question cannot take every step, small kinds are not memorised.
- *Error:* "in the trace" differs from "in the change" only by a_trace. All else is learned from change and task-words data.

**Needs from other parts.** A1.a.1 (typed nodes, event bank); A2.a.1 (question-marked propagation); A3.a.3 (question-gated event sum) or A3.c.2; A4.a.1 (rooted relational sum, shared bases); A5.c.1 (as-of bank, cut at t). A6 the channels; A7 the loss; A9 neighbour sampling with known probabilities.

**Can.** M1 by construction (marks; gate reads q). M2 by construction (neutral gate, linear count term). M3, M5 by construction (inherited). M4 by construction given the loader. M6 in part. M8: one arm against option 1, differing in one decision (joint against stacked). It can bind evidence: the gate weighs an event by whether its content matches the question; option 1 cannot.

**Cannot.** Keep a large kind from bending shared parameters. Counterexample: task-words questions often have no start set; their gradient pushes the trunk toward content and can weaken the history weights the change question needs. The mix bounds this only. One fault means retraining all. Trace frames through framework hubs get no correction beyond a_trace. M7 open on a count: one propagation per question. Nearest vetoes: W5, avoided since reach comes from the channels, not depth; W6, attention stays within one neighbourhood.

**Rests on.** N 5.2, N 9.5, N 9.10, N 13.2, N 13.9; D 9.2, D 9.4; record: `research-tree/build/improve/units/T3/report.md` items 3, 5 (mean aggregation, no marks, kinds merged). Count first: questions per kind and repository; share of task-words questions with no start set.

**Refuted if.** On validation repositories, a model trained on change questions alone beats the mixed one on the change question beyond the intervals; or fitting a_trace leaves error ranks where the change mark puts them.
