# A8 option 3: every question reduced to weighted seeds
Lens: one shared model. Kept, in a narrower form: the shared part is one scorer that reads a question only as a weighted set of starting files. Each kind owns only the small step that turns its question into that set.

**Mechanism.** Two stages.
1. *Seeding, per kind, small.* Each question becomes a weighted seed set {(s, w_s)}:
   - change: the files in the change, w = 1;
   - error: the files in the trace, w_s = d(depth_s), d a monotone curve with a few parameters, fitted on error examples;
   - task words: files named in the text (w = 1), plus the top m of text search over paths and content, w_s = softmax of their search scores at a fixed temperature.
2. *Scoring, shared.* One scorer computes, from the seeds, everything the change question computes from its files: s(Q, v) = F(sum_s w_s R(s, v), c(q, x_v)). R(s, v) is the exact per-file pair record (kernel bank, typed path counts), linear in the seeds, so a weighted seed set is exact. c is a joint reader shared by all kinds. F is one ranker trained on all kinds pooled, each repository at equal weight (D11).

The error question then needs examples only for d. The rest is trained by the plentiful kinds. The seeding has two to five parameters per kind, against a whole trunk in option 1 (D 7.4: few examples, few free parameters).

**Needs from other parts.** A1.c.1 (exact sums, relative amounts); A2.a.2 (pair record built per start file); A3.c.1 (kernel bank, linear in events); A4.c.1 (path counts); A5.c.1 (as-of bank). A6: reach beyond the seeds' paths. A7: the loss.

**Can.** M2 by construction: the decayed, size-weighted count from each seed is exact, and the weighted sum keeps it exact. M1 by construction: the seeds and c are per question. M3, M4 as the parts it builds on. M8: one decision against option 1, whether the question enters through seeds or through the trunk.

**Cannot.** See a right file tied to no seed and unread by c. Counterexample: an error "connection refused" whose fix is a config file outside the trace, with no history with the trace files and no shared words. For task words, a seed from a wrong search hit pulls in that file's partners. Nearest veto W1: avoided, because c reads q and v jointly. W5: no stacked steps; reach is A6's.

**Rests on.** N 9.10 (a marked start set as relative identity), N 9.5, N 13.9; D 7.4, D 9.2, D10, D11; FACTS: 30, 66 and 21 % of right files have no earlier joint change with the starting file (the limit of seeding); record: `research-tree/build/improve/units/U3/report.md`. Count first: per kind, the share of right files with a non-zero path from any seed.

**Refuted if.** On errors, per validation repository, the learned d gives no better ranks than d constant; or option 1, at equal candidates, beats it on right files that have no path from any seed.
