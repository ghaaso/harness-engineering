# A2 option 1: exact relational profile per question
Lens: exact relational computation first; a learned ranker reads it.
**Mechanism.** At asking time t_q a question becomes a weighted start set S_q (change: files in the change, weight 1; error: files in the trace, weighted by frame depth; task words: files named in the text, plus the top k by lexical search as soft starts weighted by score percentile), its text, and a context (|S_q|, kind of question, repository description). For every candidate c alive at t_q, phi(q,c) is computed exactly from the store cut at t_q:
- per link kind r and direction, paths of length 1 and 2 from S_q to c, as a sum and a maximum over starts: n_r = sum_s w_s A_r[s,c], m_r = max_s A_r[s,c]; length 2 over A_r A_r';
- through events: sum_s w_s sum_{e: s,c in e, t_e < t_q} g(|e|) exp(-(t_q - t_e)/tau), exact form from A3 and A5;
- typed shortest distance from S_q to c (the root marked, N 9.10), capped, with a no-path flag;
- text against c: lexical score over path, defined names and content (word weights from training repositories, D6); identifiers of the text that c defines; one encoder similarity (A1).
Every amount is also given as a percentile within this question's candidates and relative to the repository's scale. The ranker (A7) reads phi(q,c) with the context. The sum keeps the multiset of starts, the maximum the strongest single tie (N 9.5).
**Needs from other parts.** A1 encoder score; A3 event aggregate; A4 kinds and directions; A5 decay and time cut; A6 candidates beyond relations; A7 ranker and loss.
**Can.** M1 by construction: phi depends on S_q and the text, so candidates with the same surroundings differ when their relation to S_q or the text differs; one schema serves all three questions. M2 by construction: counts are computed, not learned. M3 by construction: no identities, relative amounts. M4 by construction: store cut at t_q. M5 in part: one column per kind, direction and path length, bounded. M6 in part: text columns only.
**Cannot.** Learn a relation outside the bank: three hops, or two kinds composed beyond length 2, are invisible (D 9.2). Read meaning beyond scalars: "add retry to the HTTP client" against `net/fetch.ts`, no shared word, rests on one encoder number. Nearest veto W1: that number comes from two independent vectors, but it is one column among relational ones. W10: amounts enter relative.
**Rests on.** N 9.5, N 9.8, N 9.10, N 13.9, D 8.1, D 9.1, D 9.2, D 9.4; record: `research-tree/build/improve/units/T3/report.md` item 1 (tree ranker over pair features leads); `research-tree/build/improve/units/U3/report.md`. count first: share of right files with every relational column zero, per question.
**Refuted if.** On unseen validation repositories, per repository, the ranker over phi does not beat its best single column (decayed one-over-size count; lexical search; trace files); or swapping S_q between questions of one repository leaves scores unchanged.
