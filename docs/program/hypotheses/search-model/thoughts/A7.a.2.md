# A7 option 2: measure-weighted pairwise loss, tree ranker
Lens: graph first; this option departs from it. In the record, a tree ranker over exact pair features led on both questions. The graph part added nothing beyond the count features. N 13.9 calls neighbour aggregation a learnable form of the hand-made features. So the scorer here reads the exact pair record, not node vectors.

**Mechanism.** *Output.* f(Q,v) = sum of trees over R(Q,v). R(Q,v) is the exact record of typed path counts, kernel bank and text scores. Amounts are relative: log, and percentile among the question's candidates. An added file is a slot record per folder (folder features, zero content).
*Loss.* A pairwise logistic loss inside each question. Each pair's gradient is scaled by the change in the reading measure M if the two swap:
lambda_ij = -|Delta M_ij| / (1 + exp(f_i - f_j)), i in P, j not in P.
M is D12's measure: hits in the top ten over min(10, |P|), plus the reciprocal rank of the first right file.
*Negatives.* All A6 stage-one candidates, plus m files drawn from the rest of the alive files with known pi_j, excluding P. A drawn pair is weighted 1/(m pi_j). The rank of a right file among all alive files, which Delta M needs, is estimated the same way: listed negatives above it, plus the sum of 1/(m pi_j) over drawn negatives above it.
*Weights.* omega_Q as D11. The pairs of one question are normalised so that the question's total is omega_Q.

**Needs from other parts.** A1.c.1 (relative amounts, text scores), A2.a.2 (the pair record), A3.c.1 (the kernel bank), A4.c.1 (typed path counts), A5.c.1 (the as-of view). A6: stage one and pi. A8: whether one ranker serves three questions.

**Can.** Put the gradient where the reading is made: pairs that cross the top-ten boundary dominate. Trees learn thresholds and interactions among exact counts with no scaler. M2, M3 (no identities, relative amounts) and M7 by construction: negatives have known probabilities and are never right files; the work runs on processors. M1 through the record (A2.a.2).

**Cannot.** Pass a gradient upstream. Trees cannot train an encoder or the record, so all text meaning must be fixed before training. Move a right file that is far down the list: one ranked 300th has a tiny |Delta M| and is never pulled to 30th. Yet D12 also reads the rank of every right file. Estimated ranks make Delta M noisy for small m. Extrapolate past the training range of an amount (D 8.1). Nearest veto W10: it does not fall under it, since amounts enter relative. W12: the lambda weighting follows from D12's fixed measure, not from a published gain. W1: no, the record is per pair.

**Rests on.** N 13.6, N 13.9; D 3.2, D 8.1, D 9.2, D11, D12; record: `research-tree/build/improve/units/T3/report.md` items 1, 3, 5; record: `research-tree/build/improve/units/U3/report.md`. Count first: the spread of |P| per question and per repository.

**Refuted if.** On validation, read per repository: the same trees with |Delta M| = 1 (plain pairwise) score the same in the top ten. Or option 1 beats this on right files that have no non-zero entry in R.
