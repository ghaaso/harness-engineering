# A3 option 1: exact kernel bank, ranker mixes
Lens: exact relational computation first; whatever can be computed exactly from the store relative to the question is computed, and a learned ranker reads it.

**Mechanism.** For starting file s, candidate c, asking time t: E(s,c,t) are the units of work that reached the main line before t and changed both. Event e has size n_e and two ages: days, and the repository's own clock (main-line commits since e). From the store cut at t:

f_{p,j}(s,c) = sum over e in E(s,c,t) of n_e^(-p) * exp(-age_e / tau_j)

for a few size exponents p (0, 1/2, 1, and an indicator n_e <= k) and a few tau_j on both clocks, tau_j in repository units (quantiles of its own gaps between commits). Beside each sum: f/F_s and f/F_c, F_x being the same sum over all events of x (conditional rates both ways, so direction is kept); the sums restricted to "c changed after s" and "before". Over several starting files: sum, maximum, and the number with f > 0. Two-hop sums through an intermediate file, by one sparse product per kernel. A learned ranker reads the bank. A positive mix of exponentials approximates any completely monotone decay, so the decay shape is learned while every input stays exact.

**Needs from other parts.** A1 relative amounts; A5 the cut and both clocks; A6 candidates and files with no joint event; A7 the loss.

**Can.** M2 by construction: p = 1 with one tau is the decayed one-over-size count, exact, all history. M4 by construction, given the cut at t and the leak tests of D13. M3 by construction (no identities, repository units); open on a test of repository clock against days. M5 in part: direction by the two normalisations and order. M7 by construction: sparse sums once per asking time, on a processor. M1 in part: relative to starting files of a change or trace; task words only where the text names files.

**Cannot.** Weigh an event by what it is. Counterexample: two six-file commits of equal age, a mass rename and a feature, weigh the same in every kernel. Form an aggregate outside the bank (D 9.2). Reach a right file with no joint history (30 to 66 % by repository): A6. Nearest veto W10; avoided because inputs are normalised or in repository units. Not W2 (sums), not W4 (all history).

**Rests on.** N 9.5; N 13.9 and D 9.2 (aggregation as hand-built feature, and its loss); D 7.5; D 8.1; D 6.2, D 9.4 (causal, loaded at t); N 14.4 (exact diffusion once); record: research-tree/build/improve/units/T3/report.md item 1 (tree ranker over counts leads); facts sheet (one-over-size weight carries counting). count first: share of right pairs whose best single kernel lies outside the bank.

**Refuted if.** Per validation repository, the ranker over the bank does no better than the best single kernel; or learned event channels (option 2) add a clear gain, showing event content matters.
