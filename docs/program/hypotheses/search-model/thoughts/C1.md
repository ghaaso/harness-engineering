# C1: Exact reach columns, then question-rooted typed propagation
Starting pairing: A1.a.1 (typed nodes with frozen-text features) with A2.a.1 (question-marked propagation from the question node).
Parents: A1.a.1, A2.a.1, A3.a.3, A4.a.1, A5.c.1, A6.c.1, A7.c.1, A8.c.1

## The design, part by part

**A1, taken from A1.a.1.** Every D14 kind is a node or edge kind with its own input projection (N 13.3). Question text, diff, error text and file content are cut into chunks. One frozen code-and-text encoder embeds each chunk once per content hash (D3). Each chunk is a node with a `part-of` edge. The path is embedded as text. Event nodes carry 1/n_e and the bank (1/n_e)^p exp(-a_e/τ_k). Each amount enters as log(1+x), as its quantile among the repository's values before t, and with a missing flag. Question-free structure per file: random-walk return probabilities k = 1..K (N 10.4) and degree per kind as a quantile. No eigenvectors (W11). No identities (W3). A repository node is linked to the question only.
**Changed to fit.** (1) Ages are A5.c.1's two repository clocks, not raw t - time(e). A1.a.1's own rule makes amounts relative, and N 7.1 and D 8.1 require it. (2) Each event also gets a frozen vector v_e of its message plus the first chunk of its diff, keyed by commit hash. A3.a.3 needs it. (3) A file's chunks are summed into its input at layer 0, so `part-of` costs no propagation hop. The sum is unpooled and keeps the multiset (N 9.5).

**A2, taken from A2.a.1.** The question Q is a node. The starting files S_k(Q) are tied to it by kind (in the change; named in the text; in the trace, with frame depth). Each candidate v in the top-K set gets an edge Q→v carrying the pair reading φ(q, x_v).
h_v^0 = Σ_k [v ∈ S_k(Q)] a_k + φ(q, x_v) + g(x_v) + U x̃(Q,v)
h_v^{l+1} = σ(W_0 h_v^l + Σ_r Σ_{u∈N_r(v,t)} (1/π_u) κ_r(e_uv) ⊙ W_r h_u^l)
The marks a_k are the marked root (N 9.10). The start set is an anchor set drawn afresh by each question (N 10.5). The read-out is fixed and shallow (N 5.4).
**Changed to fit.** (1) φ is a learned late interaction over frozen chunk vectors: the maximum and top-3 mean of the cosines between q's chunks and v's chunks, one bilinear cross-attention from q's chunks to v's chunks, and exact name and path matches, then an MLP. A1.a.1 offers no tuned joint encoder. This is a pair function over many vectors, so it is not W1. (2) Added: U x̃(Q,v), the stage-1 exact columns put into the candidate's start state. It lets the propagation form conjunctions of counts and content, which A8.b.3 and A8.c.2 name as the miss of additive stacking. (3) Added: σ = MLP ∘ slog, with slog(x) = sign(x)·log(1+|x|) applied after each sum. Slog is a pointwise bijection, so the sum stays injective on multisets (N 9.5). It also bounds the scale of hub sums, which A4.a.1 lists as a Cannot. (4) The 1/π_u weights come from A4.a.1's need for sampling (D 2.9).

**A3, taken from A3.a.3.** On an event-to-candidate edge the gate is applied per channel:
κ_k(e) = n_e^(-p_k) exp(-a_e/τ_k) · 2 sigmoid(b_k + qᵀ W_k v_e), with W_k of low rank.
The gate is bounded and works per event, not as a softmax (W2). At W_k = 0, b_k = 0 the channel is exactly the decayed, size-weighted count.
**Changed to fit.** (1) q is the question node's summed chunk projection. (2) The exact, ungated counts live in x (A5, A6), not in the propagation. A7.c.1's offset and A8.c.1's every-file stage need them exact, and stage 2 samples neighbours. (3) The event node's own input projection also reads its relative ages and size. The learned channels can therefore form any function of age, not only a mix of the bank (N 13.9: the time embedding inside the message).

**A4, taken from A4.a.1.** Relations: in the change, named in the text, in the trace, import resolved, name matched but unresolved, use, test by import, test by name, folder to file, file to event. Each is kept forward and reverse. Each layer is a sum within a relation and a sum across relations. There is no 1/|N_r| (N 9.5). W_r = Σ_{b=1..B} a_rb V_b, so the parameters are B d² + R B (N 13.2). Composition, antisymmetry and one-to-many hold as A4.a.1 argues; folder and co-change are symmetric through shared nodes (N 13.8).
**Changed to fit.** (1) Three relation kinds are added, each with its reverse: Q→v (A2.a.1), part-of (A1.a.1) and repository→Q (A1.a.1). R = 28. The shared bases keep the extra cost at B numbers per kind. (2) A4.a.1's scalar edge gate g_r becomes A3.a.3's per-channel vector κ. The scalar is the one-channel case. κ is 1 on non-event relations. (3) L = 3: s→e→c and s→m→c take two hops from a mark, plus one hop for the question side. Longer reach is left to A6, and depth stays small for transfer (N 8.4).

**A5, taken from A5.c.1.** One access path: the view V(t_q) of facts visible before t_q (main-line arrival, D6). Two clocks: a_ord (units since e) and a_wall = (t_q − v_e)/g_R. The columns are C_k(s,c) with w = 1 and w = 1/n_e, M_k(c) (the candidate's own decayed activity), the ages of the last joint change, of c's last change and of c's creation, and the directed order L_k(s→c) with its reverse. Each column is summed over s ∈ S_k(Q).
**Changed to fit.** (1) The lazy pair-state pass is dropped. Per question, C_k is one sparse product over the events touching S, computed on the card from the repository graph masked by t. count first: events touching S per question. (2) "Relative to the repository's distribution at t_q" is read as the quantile among the files alive for this question.

**A6, taken from A6.c.1.** Every file alive gets exact reach columns: the seeds σ_k (for task words also the files that define a name in the text, and BM25); the restarted walk π_{k,g,α} = α Σ_m (1−α)^m σ_k P_g^m over the relation groups (code links, joint change weighted 1/n_e·exp(−a/τ), folder tree, all) and a bank of α; π over the stationary mass (D 2.9); the hop distance to the seed set (N 10.5); the echo E(c) = Σ_u BM25(q, text_u)[c∈u]/n_u; BM25; names and path strings; the maximum chunk cosine. These columns and A5's make up x(Q,c).
**Changed to fit.** (1) A6.c.1's "learned ranker over columns" is A8.c.1's linear stage 1. (2) "The reader of A2 rescores its top K" is the stage-2 propagation, with K set on validation repositories. (3) The A1.c.1 and A4.c.1 features it reads beside its own become the typed one- and two-hop counts from S per relation. These are sparse products, the linear special case of A4.a.1 with W_r fixed.

**A7, taken from A7.c.1.** The candidates are every file alive plus one slot per folder ("a new file belongs here"). The score carries the fixed offset b_k: log(ε + the exact decayed one-over-size count) for a change; log(ε + BM25) plus a constant for named files for task words; trace depth for an error. R(q), the files with any non-zero count or one- or two-hop column, is taken whole. The rest is Poisson-sampled with known π_c. Right files are never negatives.
L1(q) = −(1/|P|) Σ_p log[e^{s_p}/(e^{s_p} + Z)], Z = Σ_{R∖P} e^{s_c} + Σ_sampled e^{s_c}/π_c.
w_q = min(1/n_R, β). Bulk-flagged questions weigh zero.
**Changed to fit.** (1) Added: a second loss L2 of the same form on the top K, with Z exact over the K (no sampling), on logits s1 + s2. A8.c.1 places the top K above the rest, and one loss over all files cannot see that order. (2) Added: folder slots are read by a folder-kind head of stage 2 (post-processing per kind, N 13.3).

**A8, taken from A8.c.1.** One backbone for all three questions:
s_j(q,c) = b_k + (a_0 + d_j)ᵀ x̃_qc + [c ∈ top K] (w_0 + D_j)ᵀ h_c^L.
The top K are ranked by the full score and placed above the rest. d_j and D_j carry λ_j‖·‖² toward zero, with λ_j set on validation. There is one run. Every batch holds all kinds. Each kind's loss is divided by its total weight. Errors train on tier (e) plus the training repositories of the real tiers.
**Changed to fit.** (1) The "joint text reader" of A8.c.1's backbone is φ inside the propagation (A2 above), since no tuned reader is a parent. (2) There is no reader adapter, so the per-question part is d_j and D_j only.

## One question, end to end

**Change.** q = the first commit's diff, S = its files, t = its author time. Computed exactly on the card: the graph masked by t (D 9.4); x̃ for every file alive (A5 bank, A6 walks, echo, BM25, cosine, typed counts); b_k. Learned: stage 1, a linear map (A8), which ranks every file. The top K then get Q→v edges. The neighbourhood of {Q, S, top K} is sampled with known π (A4). Three gated layers run (A2, A3, A4), followed by the read-out. The top K are ordered by s1 + s2 and the rest by s1.
**Task words.** q = the issue title and body, S = the named files, often empty. With S empty the marks are absent, and stage 1 rests on BM25, names, echo and cosine (A6). Inside the top K, φ and the content and folder structure carry the score. The gate still reads q against events touching the named files.
**Error.** q = the error text, S = the trace files, with frame depth on the edge. The offset is trace depth. The rest is as for a change, with D_error.

## What is trained and what it costs

Trained: the input projections per kind; B bases with R·B mixing weights per layer; the W_k gates; φ (an MLP and one bilinear map); U; the linear stage 1; the heads d_j and D_j. All are graph-independent coefficients, of order 10^6 to 10^7 parameters (d ≤ 256, B ≈ 8; width is held down for transfer, N 8.4). Frozen: one code-and-text encoder of the 0.1 to 0.3 B class, trained on code and text, with a cut-off no later than the test cut-off (D7). It must be downloaded, which needs the owner's word (W13).
Computed once: the chunk vectors per content hash, the event vectors per commit and the question-free structure. Argued: a 0.1 B encoder spends about 2×10^8 operations per token. 2×10^10 tokens on three cards at about 2×10^14 effective operations per second is about 2 h. A 0.6 B encoder would take most of the eight hours. The size class therefore follows from the count. count first: distinct content-hash tokens that the examples actually read, and event tokens.
Per question, on the card: the restarted walks are about 20 steps × 12 group-and-α pairs × E edges, which is sparse and cheap. Stage 2 runs on a repository graph of N nodes: B·N·d² for the bases plus E·B·d for the messages per layer. At N = 10^5 and E = 10^6 that is roughly 10^11 operations, memory-bound, on the order of tens of ms with the backward pass. Memory is 1 to 4 GB per question, so one repository's graph stays resident and its questions are batched. At 3×10^5 questions an epoch is under an hour on three cards, which leaves room for several epochs. count first: edges per repository (the largest must fit at 96 GB), questions per kind, and recall at K.
**12 GB form.** The encoder vectors are precomputed on the PC. The same model runs at a smaller d with one question at a time, and only the top-K neighbourhood moves to the card. The repository graph and stage 1 stay in processor memory.

## Against the sheet

- **M1, by construction.** The marks a_k, φ and x̃ make h^0 a function of (Q, v), so one file scores differently under two questions (N 9.4, N 9.8, N 9.10). Every stage-1 column is relative to Q. For task words with S empty it rests on φ and the text columns, which are joint (not W1).
- **M2, by construction.** The decayed one-over-size count is a column of x and the change offset. It is exact over all of history and never sampled. The learned sums are unnormalised, and the gate has the count as its neutral point (N 9.5).
- **M3, by construction for identities and scale; open on a test for the encoder.** There are no identities. Amounts are quantiles or slog-bounded. The marks are relative identities (N 9.10). L = 3 and a small width (N 8.4). Open: whether the frozen encoder recalls public repositories. Test: repositories created after its cut-off (D12).
- **M4, by construction for the data; open on a count for the encoder.** There is one masked view, and D13's cut-against-whole test applies. Open: the validation stretch may precede the encoder's cut-off (A5.b.1's point, not taken here). count: validation questions after the cut-off.
- **M5, by construction; in part for rare kinds.** 28 directed relations on shared bases (N 13.2, N 13.4). No shallow scoring rule (N 13.8). "In the trace" may fall outside the span of the bases.
- **M6, by construction for any file joined to the seeds by a path, a word, a name or an echo; open on two counts.** The walks reach any length, computed rather than learned (N 2.3, N 14.4, N 11.3). Open: the share of right files at zero in every reach column, and recall at K.
- **M7, open on the counts above.** Negatives have known π and are never right files. Weights follow D11. Sampling is by a known design with 1/π (D 2.9, D 3.2). Memory and time are argued above.

Vetoes the design comes nearest to:
- W1: a file outside the top K and reached only by cosine. Stage 1 still reads pair-specific columns, and inside the top K the reading is joint.
- W2: the attention inside φ normalises over content chunks, never over history. History enters only as sums.
- W4: there is no window. Exact counts cover all history, and stage-2 sampling has known π.
- W5: reach is computed by walks, and L = 3.
- W6: φ attends within one pair.
- W9: R(q) excludes P. β, K, λ_j and κ are set on validation.
- W10: there are no trees.
- W11: random-walk return probabilities are used, no eigenvectors.

## Cannot

- Learn a repository's private vocabulary through a frozen encoder: "billing" against `invoice_svc/` (A1.a.1).
- Separate nodes with equal return signatures (mirrored test folders, A1.a.1), or two sibling tests at the same typed path with the same content reading (A2.a.1, A4.a.1). Such pairs tie.
- Rescue a right file that stage 1 ranks below K. It keeps its linear score. If it is reached only by cosine, its score comes from two vectors (A6.c.1).
- Reach a file with no link, word, name or echo: a config key built by joining strings (A6.c.1). Find an error's right file two frames up by a link kind the bases spread thin; no D_j restores it (A8.c.1).
- Keep the order of kinds along a route longer than three hops. The walks mix them (A6.c.1).
- Order patterns longer than one step (A, B, then A) (A5.c.1). The non-monotone decay of A5.c.1 is removed only inside the top K, through the learned age channels.
- Use the gate where messages say nothing ("fix"). It stays neutral there and may carry one repository's habits (A3.a.3).
- Escape A7.c.1's limits. It aims at the whole list, not the top ten. log Z is biased low. A file fixed in the next pull request counts as a negative. It cannot name a new file or place one in a folder not yet made.
- Avoid one propagation per question (A2.a.1). A backbone shared with history-rich change questions may leave task words to φ alone (A8.c.1).

## Refuted if

- Marks (A2.a.1): zeroing every a_k costs nothing, or rankings correlate near 1 across questions asked at the same moment.
- Stage 2 (A2, A4, A8): s2 adds nothing over s1 per unseen repository, among right files with a path of two hops or fewer.
- U x̃ in h^0 (added): removing it leaves stage 2 unchanged among right files that have both content and history signal.
- Gate (A3.a.3): it stays near neutral on validation, or gains on training repositories only.
- Typed relations (A4.a.1): one merged relation with a one-hot kind scores within this design's interval.
- Relative scale (A1.a.1): raw logs match quantiles in the extreme size strata.
- Reach (A6.c.1): among right files with no joint history and no two-hop path, the walk and echo columns do not lift ranks over BM25 and cosine.
- Loss (A7.c.1): uniform uncorrected negatives score the same, or the learned part adds nothing over b_k on unseen repositories.
- Sharing (A8.c.1): a backbone trained on one kind alone matches the shared one on task words and errors.
- Encoder: the lead over the baselines is larger on repositories created before its cut-off than after.
