# A1 option 2: frozen model yields relevance amounts
Lens: language model first; this option departs from it.

**Why it departs.** A tree ranker over pair features leads on both measured questions; the graph network added nothing beyond its count features; retrievers used as they come swing by repository, +23 and -14 points (record: FACTS; `research-tree/build/improve/units/U3/report.md`). A language model is "NOT trained to predict the future" and its "Context size is limited" (N 13.9). A path read as text is a near-identity that tuning on public repositories can memorise.

**Mechanism.** The model is frozen and never sees amounts or links. Text reaches the rest only as relevance amounts between question and candidate, plus one small vector.
- Per content hash: chunk vectors v_c from a frozen code encoder, once (D3). Per question: vectors u_j of its chunks (task text, diff hunks, error frames).
- Per (question, candidate): s_jc = cos(u_j, v_c); kept: the maximum, the mean of the top 3, the number of chunks above R's own 90th percentile at t; the same for the path alone; a word-weight text-search score, weights fitted on training data (D 6.4). Each as [raw, quantile among this question's candidates] (N 7.1).
- A frozen cross-reader (prompt: is this file relevant) gives one log-odds, for a retrieved set only (A6).
- The mean chunk vector, projected small by a map fitted on training repositories: the only dense text input.
- Events, links, amounts and structure as in option 1.

**Needs from other parts.** A2: which chunks are matched (hunks against content, frames against definitions). A6: the retrieved set. A3, A4 as in option 1.

**Can.** Text enters as amounts relative to the question and to R, on the same footing as counts (M3 by construction; W10 avoided). The amounts are per pair, not two separate vectors (M1, in part). Content reach for files with no history (M6, in part). One frozen pass per content hash (M7, open on a count). M4 by construction: no weights tuned on any period.

**Cannot.** Learn what relevance means in this task. Counterexample: for "rename the config key", a frozen encoder scores the documentation page above the loader that reads the key; only the ranker, from structure, can correct it. It loses what the scalars drop (D 9.2). Nearest W1: the vectors are computed apart, but the score uses their pairwise matrix with history and structure.

**Rests on.** N 13.9, N 12.5, N 7.1, N 9.10, N 10.4; D 6.4, D 8.1, D 9.2; record: FACTS (T3 item 1, U3); count first: distinct content hashes per repository.

**Refuted if.** Option 1's tuned reader, on post-cut-off repositories, beats this on right files with no history or code link, both having the same structure inputs.
