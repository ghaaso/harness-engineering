# A3 option 1: sum through event nodes, per start
Lens: graph first. The model computes on the typed neighbourhood handed over by the data, with the question as a node of it.

**Mechanism.** Events (units of work, commits) are nodes (D14), each with size n_e and age a_e from the asking time; only events before it are present (D6). History is two sum steps through event nodes, run once per starting file s, marked as N 9.10 marks the root (no stored identity):
- z_{e|s} = 1 if s changed in e, else 0.
- For candidate c and channel k:
  h_{c|s}[k] = sum over events e containing c of z_{e|s} * n_e^(-p_k) * exp(-a_e / tau_k) * g_k(kind_e, flags_e).
  p_k, tau_k are trainable scalars; g_k is a small gate on the event's kind and flags (bulk, bot, merge), bounded in (0, 2], never normalised over events.
- Activity channels: the same sum with z = 1 for every event of c gives A_c[k]; likewise A_s[k]. The scorer can then separate association from plain frequency.
- Pooling over the starting set S: sum and max over s of rho(h_{c|s}, A_c, A_s), rho a pointwise network applied after the sum. Amounts enter divided by the repository's own scale of the same channel (D14).

Cost: the sum over events touching S of n_e, linear. An event node avoids the n_e^2 pair edges of a bulk change.

**Needs from other parts.** A1: the repository's scale per channel. A4: event kind and flags as typed links. A5: ages and the loader's cut. A7: a scorer reading this vector beside A2's question-relative description.

**Can.**
- M2 by construction: with g_k = 1, channel k is exactly the decayed, size-weighted count summed over S, for any decay and size power. A sum keeps the multiset (N 9.5); nothing divides by a degree (N 13.2).
- The max keeps "one strong partner" apart from "three weak ones", which a sum merges.
- M3 by construction: only scalars and small gates are trained; amounts are relative.
- M4 by construction, given the loader.
- Every joint event enters; no window (W4 avoided).

**Cannot.**
- See order across separate events. Counterexample: c is always changed the day after s, never with it; h_{c|s} = 0.
- Read what an event was about: a rename sweep and a real fix of equal size and age weigh the same, unless a flag separates them.
- Reach a candidate with no joint history (A6's job).
- Nearest veto W2; not under it: a sum with free scalars, not a mean, max or softmax, so counts pass.

**Rests on.** N 9.5, N 13.2, N 13.9 (a message is a fact times a time embedding; aggregation learns hand-built aggregates), N 9.10, D 9.3, D 9.4, D 2.10. record: research-tree/build/improve/units/T3/report.md (mean-aggregated network below counting; window models). assumption: per-start loops are cheap because S is small. count first: the spread of |S| and of events per starting file.

**Refuted if.** With A2 and A7 fixed, the model scores below one-over-n counting on pairs with earlier joint change, on the same examples; or the learned channels collapse to one decay.
