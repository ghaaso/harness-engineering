# First Codex context evaluation results

The adapter preserves working state within its byte limit, including automatic
compaction. **This pilot does not demonstrate a context gain.** On its one completed
work comparison, both arms produced correct artifacts and the adapter used more
reported input.

Only the completed context harness and its Codex adapter were used. All fixtures
were synthetic. No application deployment, real restore or production operation ran.

## Work comparison

The scenario changed a booking policy twice, required an unrelated inventory audit,
then resumed booking work after two manual compactions. The agent maintained its
own initially blank state; the evaluator supplied no correct checkpoint. Hidden
checks graded configuration and output artifacts. Both arms used `gpt-6-astra` at
`ultra` effort, the same 32k trigger and controlled fixture tools. The baseline had
optional ordinary task notes and no adapter.

| Observed measure | Native baseline | Adapter |
| --- | ---: | ---: |
| Artifact score | 100/100 | 100/100 |
| Ordinary reported cumulative input | 300,801 tokens | 331,815 tokens |
| Median reported request input | 12,070 tokens | 13,525 tokens |
| Manual compactions | 2 | 2 |

The adapter used **10.31% more ordinary reported input** in this case. Restored text
measured 2,533 and 3,307 UTF-8 bytes; complete reconstructed envelopes measured 2,655
and 3,436 bytes, below the 4,096-byte cap. Native summary bytes are not exposed;
these are adapter payload sizes, not whole-context byte compression ratios.
Hook execution had a 2,120 ms median and 2,205 ms maximum, showing launch overhead
worth investigating.

One scenario pair cannot establish general quality retention, superiority or a
minimum useful memory budget. The valid native arm was reused after correcting the
adapter verifier; this is a limited pilot comparison, not independent confirmation.
The second scenario pair and budget frontier were not run within this allowance.

## Mechanics and accounting

- Both manual checkpoints were fresh, checksummed and matched state delivered at
  the next work turn, before observable model-generated output.
- A separate pressure probe caused one automatic compaction. Its checkpoint arrived
  before continuation output; its named final response retained the marker,
  corrected retry limit and last log identifier.
- One delegated-worker probe completed correctly. Its 9,931 reported input tokens
  appeared separately from the parent's updates. Parent cumulative increments matched
  its own last-request usage. Concurrent parent/child compaction remains untested.
- Complete UTF-8 output bounds, paged recall, provenance, integrity and session-bound
  cursors are implemented. Unicode survives the actual Windows hook wrapper unchanged.
- Storage stress passed with 1, 4, 8 and 16 spawned processes: 464 events and 464
  snapshots, with exact counts, hashes and session isolation.

Compaction notifications did not increase cumulative input/output totals. Complete
compaction model usage remains unknown, so full-run token or financial savings cannot
be claimed. The [app-server protocol](https://learn.chatgpt.com/docs/app-server)
exposes thread usage notifications; exact request timing and private summary bytes
are not observable here.

## Corrections retained in the evidence

The initial verifier expected restoration before the manual compaction turn ended.
Delivery happens with the next model continuation. The run stopped before submitting
that continuation: an evaluator timing error, not an observed memory failure.
The original report and usage are preserved. The corrected adapter case ran once
on fresh files; both boundaries were audited against its event log. This matches
the documented [compact-start behavior](https://learn.chatgpt.com/docs/hooks).

The automatic probe's first grader concatenated commentary and final JSON, producing
a false formatting failure. An offline audit of the named final message confirmed
its facts. The raw report remains preserved; graders now separate those channels.

A final offline rerun exposed a Windows extended-path alias race in the stress
verifier's size scan. The scanner now uses normalized containment; regression checks
still reject actual escapes. This did not establish lost/corrupt storage records.
Final suite: **136 tests, 134 passed, two symlink checks skipped** on this account.
The full process stress also passed again after the fix.

The live stage consumed 984,984 reported input tokens for stopping and 14,629 output
tokens, including the interrupted verifier and visible worker usage. It stayed within
the planned soft 1M/40k allowance. Unavailable compaction usage is excluded, so this
is not a guaranteed billing ceiling.

## Next decision

Verdict: **revise and continue evaluation; high context gains are unproven**.

Reduce startup/checkpoint overhead and investigate roughly two-second hook launches.
Then use longer, structurally varied work to compare native, a maintained task file,
and the adapter at 2/4/8 KiB memory budgets and matched smaller context settings.
Measure working input and completed work together; keep opaque compaction usage
unknown. Forecast the next stage from observed costs rather than treating this pilot
as evidence for the proposed 50% reduction.
