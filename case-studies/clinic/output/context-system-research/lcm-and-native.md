## What continuity actually does

LCM captures transcripts into project SQLite stores, builds leaf summaries over older raw messages, condenses summaries into a hierarchy with explicit source links, promotes durable findings, and restores recent summaries and project memory. Raw retained messages remain available through search, grep and DAG expansion. The engine uses 20k-token leaf chunks and preserves a recent raw tail. Summary IDs are supplied independently of model-generated summary text. [Architecture](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/docs/architecture.md).

Automatic recovery comprises startup restoration and prompt-time search hints. Default prompt hints select three results, with 200-character snippets and a 2,048-byte injected-memory budget. Deeper recovery uses model-directed `lcm_search`/`lcm_grep` → `lcm_describe` → `lcm_expand`. Summaries are explicitly lossy; their footer advertises omitted detail. Expansion defaults to depth one. Although the retrieval engine supports an optional token cap internally, the shipped daemon/MCP expansion path supplies and exposes none. [Default configuration](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/src/daemon/config.ts), [retrieval tools](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/docs/agent-tools.md).

The current Claude command hooks **do not replace the active Claude message list**. `PreCompact` captures and summarizes into the LCM store, then native Claude compaction continues. The daemon has an opt-in, coverage-checked complete-window response, but that contract does not itself install the window into Claude. The function-hook module's compaction hook runs only when shadow measurement is enabled. This distinction limits the README's broad “automatic compaction” claim. [Hook protocol](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/docs/hook-protocol.md), [function hooks](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/hooks/lcm-hooks.ts).

## Quality and delay evidence

The repository ships an evaluation harness for the production summary engine, measuring format, planted-fact survival, unsupported-detail hints, failures, latency and cost. Its real corpora and result files are gitignored. This is a usable evaluation mechanism, not published evidence that 300–400k active context retains the reasoning quality of 800k on Opus 5.5/Ultracode. [Summarizer bench](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/docs/summarizer-bench.md).

A documented retrieval experiment on 516k messages/1.1GB reports p50 **0.4s**, p95 **0.76s** after a query-plan fix. These measure finding a labelled source session; they do not measure complete evidence recall or downstream reasoning. Prompt-time lexical retrieval and explicit expansion can miss needed detail. Separately, the Claude `PreCompact` command waits up to **115 seconds** for a daemon summarization response, plus lifecycle work within the 120-second hook timeout. [Search measurements](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/docs/search.md), [PreCompact handler](https://github.com/lossless-claude/lcm/blob/0c17dbffda452cf7fae46929af427dff355aeaa3/src/hooks/compact.ts).

The lineage paper reports positive OOLONG results for **Volt**, a fork of OpenCode using Opus 4.6, against Claude Code 2.1.4. Its stronger engine-managed active context and background compaction are not evidence about this Claude plugin. The paper itself distinguishes lossless retrievability from guaranteeing that the agent retrieves the right information. [LCM paper](https://papers.voltropy.com/LCM).

## Native controls as a complementary safeguard

Official Claude docs support Opus 5.5 from **2.1.280**; independent Ultracode toggling from **2.1.284**. Ultracode is workflow orchestration, separate from effort. From **2.1.288**, persistent per-model `autoCompactWindow` is available under `modelSettings`; a project-local settings file avoids changing the user's defaults for other projects. The permitted window is 100k–1M; native retention clears older tool outputs and then summarizes. This governs cumulative residence rather than merely moving state into a new chat. [Model configuration and versions](https://code.claude.com/docs/en/model-config), [settings scopes](https://code.claude.com/docs/en/settings), [aggregate context behavior](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up).

A retention/window mechanism can govern the aggregate without separate caps on every tool. An exact request bound must also account for startup/system content, retrieval injection, recent output and large batches. Native compaction plus LCM offers recoverable history and earlier retirement; source evidence does **not** establish the requested automatic 800k-quality continuation at 300–400k, or absence of delay/degradation. It is a memory component for comparison with a system that owns and rebuilds the complete outgoing request.
