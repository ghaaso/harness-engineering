# Claude Code Infinite and YesMem: primary-source findings

Inspected 9 October 2026. Read-only clones and package metadata; no installation, settings changes, hosted-memory upload or live model trial.

## Claude Code Infinite

Repository [crizCraig/claude-code-infinite](https://github.com/crizCraig/claude-code-infinite), pin `6aaf6d59262bd6806ab73fba6a9ab9e69a5df57d`; published npm `claude-code-infinite@1.0.14` names the same `gitHead`. Requires Node >=20.3. The compression backend is the separately hosted MemTree/PolyChat API; inspecting this wrapper does not establish the backend's complete algorithm or data-retention implementation.

Source surfaces read: README, package.json, src/proxy.ts (selected planning/routing/fallback sections), src/memtree.ts (normalization, history validation, timeout/index interfaces), src/memtree-tools.ts (selected tools/metadata surfaces), src/request-sizing.ts, src/cli-args.ts, src/cli-main.ts (selected setup/env parsing), src/claude-env.ts, and selected test files. This is not a claim of whole-repository review.

The proxy builds a compressed prefix and retains subsequent verbatim messages; recompression applies to both human and tool requests as estimated/reported token usage reaches the trigger. Each session/main/subagent lane owns its route, preventing a background request from replacing another lane's prefix. Request counting is performed against the selected transformed body. This continuously changes what reaches the model, whereas a one-time handoff leaves future request history accumulation unchanged. [Proxy source](https://github.com/crizCraig/claude-code-infinite/blob/6aaf6d59262bd6806ab73fba6a9ab9e69a5df57d/src/proxy.ts).

Original conversation details are exposed through session search, tree-node navigation and exact original lines. Search/list filters include project and time. Indexing normally runs as new batches accumulate; a final idle/exit index handles a remaining tail on a best-effort basis. A later new session has cross-session search tools, but the inspected code does not demonstrate automatic complete restoration of project state on every fresh chat. Recent unindexed tail access and bounded line paging provide recovery paths. [README and tool interface](https://github.com/crizCraig/claude-code-infinite#search-across-sessions).

The reported Opus 5.5 benchmark starts around775k, compresses once around800k to420k, and reports task-score parity to a full-history continuation arm. That arm later hit native compaction near970k. Three rounds/one task family, approximately69/100 score, stated10-point noise and unspecified Ultracode mode limit the claim. No individual source benchmark run artifacts were found in the inspected repository. It is the closest reported test found, not universal equivalence. [Benchmark](https://github.com/crizCraig/claude-code-infinite#long-session-benchmark).

`CCC_COMPACT_TARGET` selects the compressed target; `CCC_BUDGET_TOKENS` changes the repeat trigger and is marked test-only. Default target350k with default trigger800k does not maintain a350k–400k active cycle. Source supports combining target350k and override400k, but that pair is proposed/unmeasured. Compression is a soft trigger: unavailable/slow/unpaid backend may forward the old prefix or original. Ordinary compression timeout15s; missing initial tree can require a longer bounded wait. Prefix reuse and background indexing reduce routine work, not all delay.

Claude's model/authentication are forwarded to Anthropic, while message content is sent separately to PolyChat with its own key. The wrapper disables native automatic compaction and uses an internal first-party-base-URL override to retain native1M behavior through localhost. Those version-sensitive settings and hosted service dependence are part of the practical setup. No nativeWindows OAuth/Ultracode end-to-end trial occurred here.

Historical `thinking`/`redacted_thinking` blocks are removed from the copy sent to MemTree. Successful recompression accepts a single user message with string content and replaces the entire outgoing message history with it. No old typed thinking survives that successful transform; later normal requests append their raw suffix to the installed prefix. This was independently checked in the published npm tarball (SHA-1 `57ab0652eacc3aa09ec88cd992abc8a47358ea54`). Thus a claim that successful recompression demonstrably retains invalid old reasoning is unsupported. Prior internal reasoning is omitted, and raw fallback/resume remains an unresolved compatibility path. The original request is untouched on passthrough paths. [Normalization/validation](https://github.com/crizCraig/claude-code-infinite/blob/6aaf6d59262bd6806ab73fba6a9ab9e69a5df57d/src/memtree.ts), [official rules](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking).

Local focused tests used committed built JS and the bundled Node runtime; no dependencies installed. `node --test` ran memtree-history, route-identity, route-safety, route-cache, request-sizing, proxy-window and proxy-sizing suites:89 tests passed,0 failed/skipped, duration about5.38s. Provider/memory services were mocked; this verifies mechanics, not task quality or live service compatibility.

## YesMem

Repository [carsteneu/yesmem](https://github.com/carsteneu/yesmem), pin `25d8ce444ff570e105afcaded1929404d3ca344d`. Selected surfaces: README, Features, SYSTEM, docs/features/proxy.md, docs/BENCHMARK.md, config.example.yaml, proxy.go/proxy_stub.go selected pipeline/config sections, stubify.go and reexpand.go. Source supports project/session SQLite memory and proxy state, automatic session briefings, extraction of decisions/gotchas/open work, collapse/stubs, frozen-prefix persistence and query-triggered recovery. [Proxy documentation](https://github.com/carsteneu/yesmem/blob/25d8ce444ff570e105afcaded1929404d3ca344d/docs/features/proxy.md).

The transformation replaces older tool results with compact hints, drops older thinking, protects selected decisions/debug pairs/task lists, and collapses older messages into an archive-backed summary. Existing state survives proxy restart. A current-query expansion uses significant-word overlap, selects at most3 stub matches and truncates each recovered content to2000runes, subject to a small expansion budget. Wider detail remains available through search tools. Thus originals are recoverable, but this automatic small keyword pass is not equivalent to considering all800k during the model's next reasoning step. [Recovery source](https://github.com/carsteneu/yesmem/blob/25d8ce444ff570e105afcaded1929404d3ca344d/internal/proxy/reexpand.go).

Its reported LoCoMo evaluation concerns synthetic multi-session conversational recall. The Claude Opus result0.8733 uses a150-question sample; full1540-question gpt5.4 result0.8649 uses agentic retrieval. Retrieval diversity/iterations improve recall, with additional model work. This supports retrieval use, not800k coding-session parity at350k or currentOpus5.5Ultracode behavior. [Method and results](https://github.com/carsteneu/yesmem/blob/25d8ce444ff570e105afcaded1929404d3ca344d/docs/BENCHMARK.md).

The README explicitly requires WSL2 for Windows and says nativeWindows is unavailable. Setup installs a broad MCP/hooks/proxy/services stack, with prompt rewrites and behavioral directives as well as memory. The docs' legacy180k-window/usage-deflation account is not evidence of currentOpus5.5 compatibility. It is a substantial project-continuity option, not the first choice for the least disruptive nativeWindows workflow. No setup or upstream tests ran here.
