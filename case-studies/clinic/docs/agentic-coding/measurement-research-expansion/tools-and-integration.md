# Measurement tooling and integration research expansion

Status: **PROPOSED research**, accessed **2 October 2026**. No measurement system, tool installation, live inference, telemetry change, backend deployment or compatibility trial was performed. This extends the existing 22-source review; it does not change WF03 or implement M00–M06.

Local inputs read: `AGENTS.md`, [measurement research](../measurement-research.md), [source register](../measurement-sources.md), [system design](../measurement-system-design.md) and [implementation plan](../measurement-implementation-plan.md). Their completeness, provenance, missingness, human-effort and artifact-acceptance requirements govern this comparison. The current repository has workflow tools and Git history, but no clinic application or verified application acceptance commands.

## Decision

**Qualify a maintained harness before creating a runner or transcript parser.** Promptfoo already has released Codex SDK and app-server providers, deterministic/custom assertions, trajectory assertions and local exports. Inspect SWE and Harbor also support coding agents. Langfuse and Arize maintain Codex transcript adapters; the former has substantially more documented and source-visible interruption/subagent handling than the latter. “No existing adapter” would now be an unsupported premise.

The smallest proposed first experiment is **one pinned Promptfoo native provider, isolated fixture checkouts, external artifact checks, immutable native results and a small derived accounting module**. Start without an observability server. This recommendation is an inference from documented capabilities and source inspection, not a local product trial. Qualifying the native provider is a prerequisite: if its environment, approvals, event coverage or workflow composition cannot reproduce the intended intervention, do not silently substitute a different agent runtime.

The accounting module has a narrower justified role than the previously proposed general collector: join native evidence to project task/stage/attempt/worker identities, preserve field presence and scope, record explicit human intervals, reconcile duplicates and expected workers, calculate complete/partial totals, and enforce claim gates. It should not duplicate provider execution, grader orchestration, trace storage or visualization that the selected tool already supplies. Neither a dashboard nor a standard token field establishes complete workflow cost, artifact correctness or human productivity.

## Codex compatibility and semantic boundaries

Official documentation establishes non-interactive JSONL execution, app-server lifecycle/item/token notifications and distinct telemetry configuration. It does not establish the ability to attach a measurement client to this already running Desktop conversation. App-server `turn/completed` can represent completed, interrupted or failed turns, and `thread/tokenUsage/updated` is available. Use the schema for the exact installed binary, then verify actual availability; generated fields alone are not observed data. [TI41–TI44]

Current official configuration lists **`otel.exporter` for logs and `otel.trace_exporter` separately**. The trace endpoint's table description still says “for OTEL logs,” so the reference contains inconsistent terminology; do not resolve wire-signal behavior by that label alone. The advanced guide describes log events and metrics, opt-in log export, prompt redaction and asynchronous shutdown flushing. A `/v1/traces` receiver accepting spans is not proof that it ingests `/v1/logs` events. [TI43–TI44]

Promptfoo's released `codex-tracing.ts` explicitly configures `otel.trace_exporter`, propagates OTLP endpoint/protocol, and reserves shutdown grace; this is a real integration implementation rather than just a tutorial claim. Its ordinary item/turn spans and deeper child-process tracing are different observation levels. A protocol turn can contain multiple generations and tools, so counting turn-marker spans cannot determine model-call count or sequential versus batched tool execution. [TI02–TI04]

The inspected execution paths have different meanings:

| Path | What it observes or controls | Required qualification |
| --- | --- | --- |
| Promptfoo SDK | Owns SDK turns; final output and normalized usage/items | Pin optional SDK, fixture home/config, model request, thread policy and permissions. Backend-resolved model/billing route is not automatically supplied. |
| Promptfoo app-server | Owns stdio child app-server, protocol items/turns and token notifications | No existing Desktop attachment. `include_raw_events` is false by default; preserve raw evidence deliberately. Default deterministic declines/empty responses can change interactive workflows. |
| Inspect SWE Codex | Runs CLI inside Inspect sandbox with model requests proxied into Inspect | Pin agent version and image; record bridge behavior and provider/generation differences. Its normal internal-sandbox bypass relies on the external sandbox. |
| Langfuse plugin | Stop hook reads transcript, reconstructs generations/tools/children, sends spans | New hook-enabled sessions, selected runtime, transcript parser compatibility, capture scope, flush/retry and interruptions need a trial. No existing Desktop proof. |
| Arize adapter | Completed-turn notify reads one matching rollout and creates turn/tool spans | Completed-turn-only trigger; failure/interruption/child coverage and selected-task inclusion are not established. |
| Native Codex telemetry | Configured log/trace/metric export | Prove signal type, attributes, scope and coverage before routing into a chosen trace product. |

No advertising phrase such as “Codex integration,” “full observability” or “complete trace” substitutes for these checks.

## Source-visible traps that change the design

### Promptfoo: preserve native presence, replay scope and grading semantics

Source inspection used **released `0.123.1`**, not only `main` documentation. Source/test files exist in that release; selected current `main` blobs differ. Do not treat rolling examples as an exact release contract.

1. **Missing values can become zero.** SDK `buildCodexTokenUsage()` leaves wholly absent usage undefined, but sets absent cached input to `0` (`codex-sdk.ts`, lines 2447–2470). App-server `resolveRawUsage()` chooses `last ?? total ?? raw`, requires numeric input/output, and defaults absent cache/reasoning to zero; its SDK-shaped representation additionally fills cache-write with zero (`codex-app-server.ts`, lines 3435–3488). Preserve source presence and raw `last`/`total` independently. Prove their scope for multi-generation and resumed turns; do not assume a selected `last` field is the complete task total. [TI03]
2. **Replaying output is not a free original run.** `providerOutput` skips execution, but released `evaluator.ts` lines 920–925 creates empty usage and `cost: 0`. This correctly describes the provider bypass in that replay, not the unobserved production of the supplied artifact. A replay reducer must keep originating-run cost unavailable unless linked evidence supplies it. Empty-string behavior also needs a fixture because this branch tests truthiness. [TI05]
3. **“Pass” can mean nothing was checked.** `assertionsResult.ts` lines 215–223 returns pass=true/score=1 with reason `No assertions`; `assertions/index.ts` lines 773–775 selects this for an empty assertion list. Weight-zero assertions force a pass; a zero combined threshold also collects scores without an acceptance gate. Preserve `unchecked` separately from acceptance and require named critical artifact checks. [TI06]
4. **Unknown cost does not silently pass the cost assertion.** `cost.ts` lines 3–19 throws when cost is undefined. `latency.ts` lines 11–14 rejects unavailable cached latency. These are useful safeguards, but an estimated cost still cannot become billed spend just because it passes a threshold. [TI06]
5. **Judging can call another provider.** `llmRubric.ts` calls model grading; `providers/defaults.ts` chooses defaults based on available credentials, including Codex defaults. A precomputed-output test is not necessarily an entirely offline evaluation if it uses model-based assertions. Explicitly select/freeze the grader or use deterministic-only checks; account for judge tokens, runtime and failures. [TI07]
6. **Persistence changes the treatment.** Pooling groups SDK threads by prompt template/config rather than each rendered row. SDK deep tracing disables pooling and ignores explicit thread reuse; app-server deep tracing disables process/pool reuse but still serializes explicit resumes. Fresh baseline and treatment tasks must not inherit another row's conversation or edited workspace unintentionally. [TI01–TI02]
7. **Prices are estimates.** Vendor SDK documentation states the backend's resolved model is absent and uses the requested model for estimates; returned app-server billing metadata does not establish fast-mode spend. Preserve requested/resolved identity and pricing basis separately, or leave exact spend unavailable. Cache-write omission can understate estimates. [TI01–TI03]

Exports include raw outputs, variables and sometimes config; sanitizer coverage is explicitly best-effort. Local results are not automatically safe Git artifacts. Promptfoo usage telemetry and update checks are enabled by default, independently of content tracing. Prospective disabling/configuration must be documented and authorized in an implementation task; this research changed nothing. [TI08–TI09]

### Inspect: unscored and errored cases affect denominators

Inspect's scoring policy distinguishes incorrect outcomes, scorer exceptions and `Score.unscored()`. A failing scorer produces no score, while `Score.unscored()` records `NaN`, excluded from that scorer's metrics. A sample marked with `sample.error` is not necessarily excluded: a successful score retained before another scorer throws still contributes if the run continues; `score_on_error` can grade partial solver state and include that verdict while preserving the error. A scorer returning `None` adds neither a score nor an unscored count. Epoch reduction can hide individual unscored epochs in aggregate counts. Report scheduled/started/completed counts, per-scorer scored/unscored/missing results, per-sample errors, individual epoch outcomes and attempts. Pin failure/retry/partial-scoring policies and count retries in workflow resources. [TI12]

Inspect log readers detect incomplete logs; an option permits partial reads. Error/interrupted logs and rescoring are supported. Use the documented log API/export rather than assuming the on-disk ZIP format is a stable custom-parser interface. [TI11]

Inspect SWE is maintained, but bridges change the evaluated execution: model requests pass through Inspect and some generation configuration is not forwarded by default. Released `0.2.71` source exposes `transparent_proxy=False`; enabling it forwards client generation parameters and supplies the default guardian-model alias (lines 110, 171–185 and 371–387). It still uses the bridge, and this option is absent from the inspected rolling user-guide options table. Pin and test the released implementation rather than assuming the short guide covers every fidelity control. Default agent downloads also introduce drift unless version/image are fixed. These are experimental controls to record, not grounds to call its result a measurement of normal Desktop use. [TI13–TI14]

### Maintained transcript adapters: stronger options, specific limitations

**Langfuse Codex plugin `v0.4.0`, commit `f4be3a47ac2c9c43721223a8f2e5d13f12e676c7`:** Stop-hook integration; parser completion/abort handling. `trace.ts` lines 220–263 validates basic/cache/reasoning counts and preserves missing detail; cache-write is unmapped. Stopped/superseded turns can qualify for export (581–588); hard-crash capture remains unproven. [TI28]

Child indexing scans session-root metadata (99–143); recovered nickname/time attribution (657–671) requires an inferred label. Qualify with an isolated home or adapted allowlist. Child support does not justify scanning the user's unrelated history. [TI28]

`parse.ts` lines 184–189/380–382 closes steps using last usage while retaining cumulative totals. The exporter does not reconcile those totals. Reopened-step duplicate snapshots could repeat usage: a **static inference**, not a reproduced defect. Require that fixture and cumulative reconciliation before accepting span sums. [TI28]

Malformed lines are skipped (34–44), missing children can be omitted (524–530), and conversion errors can leave ERROR spans yet returned upload IDs (546–559/768–769). `index.ts` marks returned IDs after flush (75–84). Successful delivery does not establish completeness; test corruption, omitted children and partial conversion. [TI28]

The sidecar marks delivery after flush; a failed sidecar append risks duplicate upload. Failure is swallowed by default and may be visible only in debug mode. Content collection includes full prompts, system context, outputs, tool details and images. Source `instrumentation.ts` passes all spans and does not configure its documented SDK masking hook. Project credentials/plugin configuration can narrow deployment scope, but the plugin is not automatically a privacy-filtered export. These observations come from code, not an executed upload trial. [TI28–TI30]

**Arize `coding-harness-tracing`, commit `0275668163a266fd25397c1c2e9561a3e4bf2b93`:** `handlers.py` lines 657–681 ignores all notifications except `agent-turn-complete` and locates the matching rollout. It sums observed `last_token_usage` fields after deduplicating repeated cumulative snapshots (lines 225–239), exporting only fields actually observed (lines 340–360). This is a useful maintained parser candidate. It does not establish interrupted/crashed run capture or parent-child completeness. Random span IDs and notify fallback with zero-duration spans need separate duplicate/timing interpretation. [TI37]

There is a concrete **documentation/source contradiction**: its pinned README describes real session/tool/stop hooks and a one-time trust step, while `adapter.py` lines 4–6 says that architecture is gone and `install.py` lines 110–131 writes notify-only configuration. Prefer the reviewed implementation and require a runtime fixture before adoption. Installation changes Codex config, creates credentials/logging/env files and can symlink a skill; these are implementation actions, not harmless reading. Vendor docs' content flags default to true. No task allowlist or child graph was found in the inspected Codex handlers. [TI37]

### Transport and conversion are not the measurement truth

OTel LogRecords have optional trace context; a log with trace/span IDs is still not a span. Current GenAI model and agent convention files inspected at `b31e9e8ea26ac1c086d3313d474e31d7c3f391ae` explicitly have Development status. Pin the mapping and preserve native schema/provenance so a convention change does not rewrite historical measurements. Collector transformations can redact/drop data, but should not fabricate model-call boundaries or turn unknown counts into zero. [TI38–TI40]

Phoenix's maintained ATIF import illustrates why a viewer is a projection: messages are reconstructed, missing duration is represented as event timing, step order does not establish serial tool execution, and root totals stay metadata to avoid double counting. The general upload helper is not idempotent merely because IDs are deterministic. Keep these distinctions in exported evidence. [TI35]

## Recommendation gates before any implementation or adoption

All gates below are **proposed validation**, not completed work. Priorities reflect risk to conclusions.

| Priority | Gate | Evidence required to pass |
| --- | --- | --- |
| P1 | Native harness fit | Frozen fixture checkout/home, agent/provider/runtime versions, configuration digest, permissions and actual command inventory. Demonstrate research → implementation → review stages and multi-worker use or explicitly narrow the study's scope. |
| P1 | Artifact outcome | Seeded fail-before/pass-after checks executed outside the worker-controlled checkout; check final artifact hash, patch application and retained behavior. Native process success, final prose and no-assert score cannot satisfy acceptance. |
| P1 | Complete accounting | Fixtures for missing usage, real zero, `last` versus cumulative totals, resumed turns, duplicate notifications/snapshots after reopened steps, multiple generations, expected-but-missing children, failed/aborted attempts and judge calls. Accept span sums only after cumulative usage and the expected worker graph reconcile. Preserve null + status + provenance. |
| P1 | Scope/privacy | No clinical data or account secrets in synthetic fixtures. Explicit transcript allowlist or isolated home; child expansion bounded to the authorized graph; redaction tested on prompts/config/tools/media before persistence/export. Prove no other chats are inspected. |
| P1 | Delivery/failure | Flush failure, retry, duplicate upload, malformed/truncated records, swallowed partial-conversion errors, missing child rollouts, hard kill and interrupted turn fixtures. A fail-open hook must produce a visible completeness failure in the experiment record; successful delivery cannot substitute for completeness. |
| P2 | Experimental comparability | Identical frozen tasks and artifact starting states; fresh threads by default; explicit intended caching/persistence; no baseline/treatment leakage; stage and child resource totals include every attempt. |
| P2 | Judge calibration | Fixed rubric, grader identity/config/version, independent human-labelled examples and a separate holdout; per-category confusion/disagreement/abstention, blind condition labels and swapped order where relevant. Deterministic checks remain acceptance authority for executable requirements. |
| P2 | Reproducibility/export | Rebuild sanitized tables from native immutable artifacts; raw and derived hashes/versioned mapping; reproduce counts and denominators without a running vendor backend. Native JSONL, result config, artifact/check evidence and judge annotations retained with proper privacy scope. |
| P2 | Human effort | Explicit start/stop intervals for preparation, intervention, review and rework. Record concurrent agent wall time separately from summed resource time. No inference of human activity from file timestamps or elapsed conversation duration. |
| P3 | Backend need | Only after local qualification: demonstrate a query/annotation/trace-debugging need, export/retention/recovery path and incremental infrastructure burden. Do not promise the USD 8 clinic hosting budget can cover a measurement backend without a separate resource/price assessment. |

MLflow offers judge alignment/versioning support, and other candidates offer custom evaluators/annotations. These features can support the calibration gate; none establishes local calibration automatically. Running model scorers or alignment can itself consume inference and send data to a provider. [TI21]

If Promptfoo passes, use its native provider and local results first. If the desired intervention is sandboxed/provider-controlled agent evaluation, choose Inspect SWE or Harbor instead and record that runtime. If passive scoped Codex traces are needed, qualify the Langfuse plugin before custom transcript parsing; the Arize adapter remains a more limited candidate. Select at most one optional backend after the experiment artifacts prove useful. This avoids paying maintenance for several overlapping systems while preserving an upgrade path.
