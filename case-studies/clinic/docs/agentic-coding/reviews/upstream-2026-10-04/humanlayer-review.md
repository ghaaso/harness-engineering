The distinction matters locally. Native instruction files, a command invoked by a person, a subagent prompt, a research note and a task record have different consumers and authority. Current Claude/Codex loading behavior must be verified from the vendor and active session, independently of this historical repository.

The earlier handoff's “one instruction file” should mean **one maintained owner for shared project authority**, not a permanent prohibition on useful directory scope. For this small documentation-focused project, the present root AGENTS.md plus task/context routes is already coherent. Later, a distinct application subtree can justify a short scoped instruction file when it has real local checks or conventions. That file should add those rules, preserve root authority, point to ordinary domain documents, and have its actual loading/scope qualified. Duplicating the root policy everywhere would multiply drift and repeated context. No source evidence warrants adding nested files immediately just to match this repo's file count.

## What the complete authored reading teaches

### Research, planning, implementation and review prompts

The six `.claude/agents` and 27 `.claude/commands` files provide unusually concrete examples of dividing context work. Locator agents find candidate paths; analyzer agents read selected contents and explain present behavior; patterns agents find reusable implementations; thoughts agents locate and analyze historical notes. The current code remains primary, with rejected/superseded proposals distinguished from decisions. Agents are told to act as documentarians unless criticism is requested, which is useful for repository investigation but insufficient by itself for an adversarial correctness review.

The research commands make the main session fully read referenced files before delegating focused questions and ask for paths/lines, metadata and follow-up amendments to the same research artifact. Plan commands add explicit file/code changes, phases, automatic and manual verification, migrations/rollback and unresolved-question treatment. Implementation commands read the plan, stop on material mismatches, run relevant checks and request manual verification when required. Validation compares the actual implementation to the plan rather than treating a checkbox as truth. Resume commands reread the handoff and current files/Git state; this supports the local freshness route.

Useful source anchors are [research_codebase.md](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/research_codebase.md#L1), [create_plan.md](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/create_plan.md#L1), [implement_plan.md](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/implement_plan.md#L1), [validate_plan.md](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/validate_plan.md#L1) and [resume_handoff.md](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/resume_handoff.md#L1).

These are behavioral prompts, not enforcement. Variants differ: some repository research permits web search only when explicitly requested, while generic/founder/Linear loops can search from the writing agent. The web-researcher subagent itself searches inside Claude. Therefore this snapshot does **not** implement the proposed separate Perplexity prior-art stage, frozen approach selection, findings-only Codex review or accepted-findings-only repair boundary. Its “research” frequently means reading the codebase. Its “no open questions in final plan” cannot silently erase the clinic plan's explicitly provisional business questions.

Commit/PR/Linear/worktree commands also carry operational effects and historically contradictory confirmation instructions. Ralph loops and GitHub workflows use automatic ticket discovery, broad permissions, background processes and external writes. Some worktree prompts execute dependency setup; one launch fails to interpolate the discovered plan path; another references `/claude`. These are examples to understand, not ready-made local skills or authority to run them. The disabled Claude review workflow cannot establish an active review gate.

### Thoughts storage and context continuity

The thoughts system stores personal/shared/cross-repository notes in a separate Git repository and maps them into the working project using symlinks. A searchable hard-link tree makes notes visible to tools that do not follow symlinks. Canonical references, explicit profile mapping and separation between code and historical notes are useful ideas. A monorepo can map a thoughts space at its root or by package; that is **notes scoping**, not guidance about multiple AGENTS.md files.

Actual code limits are consequential. Searchable hard links are mutable aliases, despite older “read-only” wording. The index is rebuilt before remote pull/rebase; file replacement can leave a stale alias. Failed cross-filesystem links can be skipped. Sync stages the external thoughts repository broadly, including unrelated notes. Status can fetch and pull/rebase, so it is not a purely observational metadata command. Hook setup assumes the common Git hooks directory and ignores `core.hooksPath`; its post-commit wrapper skips worktrees before an old hook can run. The local project already uses its own verification hook route. Installing this tool would need compatibility work and offers no demonstrated marginal benefit over the current task/plan/review/checkpoint ownership.

### Local daemon, adapters and persistence

hld has real mechanisms worth studying: nullable SQL usage fields; task/run/Claude/parent identities; raw conversation events; file snapshots; local pending/approved/denied records; conditional approval updates; configuration inheritance; orphan-state handling; process interruption/shutdown; and selected isolation helpers. It separates approval requests from decisions. Those are implementation primitives, not a complete coding-workflow evaluation system.

The actual data flow exposes several measurement boundaries:

- Session completion is a runtime status, not acceptance of an artifact. Approval means permission for a tool action, not confirmation that generated behavior satisfies a requirement.
- REST lists default to leaf sessions and hide ancestors; search hides archived/draft/discarded work. Mutable views and deletion cannot serve as the entire denominator for all assigned attempts, retries and costs.
- The event bus and client subscriptions have bounded buffers with dropped-event paths. SSE lacks durable event IDs/replay. UI event delivery cannot be assumed to be complete historical accounting.
- The proxy can change the provider/model and transform messages/tools. When usage is absent, it substitutes fixed 100 input/50 output tokens without a returned provenance flag; present incomplete usage can become zero. Record realized provider/model and actual/estimated/unavailable states before using these numbers for ROI.
- Session-manager token fields intentionally store the latest root assistant message usage, overwrite the earlier values, skip subagent usage, and ignore cumulative result usage to describe context occupancy. They therefore cannot measure full task consumption. Cost is a separate CLI-reported result field, without per-call or invoice reconciliation. API mappings can additionally omit known zero cost/duration, cast currency precision, omit token/model fields from selected list paths, or attach a hardcoded context limit to an alias.
- Continuation preserves configuration/history but does not prove the changed repository was reread. CustomInstructions persists in the store, while `claudecode-go` does not transmit that field in its argument builder. Caller → stored field → command → vendor consumption must be checked separately.
- Raw events/config can contain source content, environment values and credentials. This is not an automatically suitable commit/export format. No tamper-proof ledger, duplicate-import prevention, artifact acceptance record, active human labor or comparative treatment assignment is implemented here.

See [the authored API schema](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/hld/api/openapi.yaml#L1), [root-message token accounting](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/hld/session/manager.go#L955), [proxy transformation](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/hld/api/handlers/proxy_transform.go#L253), [bus](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/hld/bus/events.go#L1) and [SQLite store](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/hld/store/sqlite.go#L1). Generated API/SDK code is classified separately from the authored schema in coverage.

### Desktop consumers: the same boundaries persist in the UI

The full WUI source review includes native/build configuration, state and clients, telemetry, hooks, launchers, editor/mention/search machinery, conversation/tool renderers, SessionDetail, primitives, stories and tests. The interface is a useful view of the daemon; it is not an independent workflow ledger or quality evaluator.

Launch and resume preserve editable prompts, model settings, history and a draft record, with optimistic state, debounced/direct writes and asynchronous event refresh. The draft saved indicator can reflect identifier/content state rather than an acknowledged revision; launch does not wait for every pending draft-setting write. Continuation creates a new child before a later fetch/navigation failure can surface, so a retry is not proven idempotent. Active/fork conversation fetches lack consistent identity/cancellation guards against late responses. These are static integration concerns, not reproduced failures. A current task record, candidate fingerprint and validated resume dependencies remain necessary even when a product provides history.

Approval controls have several consumers. The SessionDetail decision path submits accepted/denied action responses; the inline conversation wrapper can disable denial when its caller supplies no response text. Layout's approval-resolved event temporarily marks Running for either resolution. Automatic editing or permission-bypass flags can approve actions broadly and are separate from accepted review findings. Archiving/discarding/restoring records offers undo but is not process-stop or artifact-acceptance evidence. The UI's permission/expiry indicators also cannot prove that a running vendor process has adopted a changed restriction.

Measurement semantics are narrower than their event names. `SESSION_CREATED` follows a successful launch request. `SUBAGENT_INVOKED` and `SLASH_COMMAND_USED` can fire when a mention/command is inserted, before invocation. `APPROVAL_RECEIVED` is tracked before matching/deduplication; `APPROVAL_RESPONDED.response_time_ms` measures handler-to-HTTP-request latency, not the person's thinking, review or waiting time. The token badge uses a fixed default window and ignores its model prop; tool-result formatting estimates some counts heuristically. Completed statuses, random spinner verbs, TodoWrite payloads and modeled Storybook states are not evidence of accepted correct work. These distinctions prevent event counts or a polished dashboard from being mistaken for ROI.

The retained wrapper explicitly rejects native `/compact`, `/clear`, `/cost`, `/review`, `/agents`, `/permissions`, `/memory` and other commands, citing broken tracking for compaction. It is consequently a product-specific lifecycle, not a transparent way to host the current proposed Perplexity/Claude/Codex loop. QuickLauncher chooses Anthropic/default model and can enable broad bypass without an explicit timeout; realized model/provider and launch configuration need separate capture.

UI documentation and comments also need their actual consumers checked. The Markdown renderer's `sanitize` prop is unused, including the plan-display caller passing false; this does not establish an HTML exploit because raw HTML is not enabled in the reviewed renderer. Proposed edit previews replace the first old-string occurrence and can omit context; they are not final artifact diffs. Fuzzy search/mentions can display partial results without surfacing the daemon's missingness. The telemetry modal's categorical “NEVER collect” language is stronger than its raw Error/hash/log paths and incomplete scrubbing establish. Sensitive-input classes protect selected autocapture fields, not every explicit error/log payload. No runtime exploit, provider request, telemetry transmission or visual trial was performed.

Tests include narrow useful render, keyboard and pure-helper checks, but some hook tests construct expected state without invoking the hook; closed-dropdown tests only establish a container exists; autoscroll helper tests do not run the component's different thresholds. Stories contain fixtures, callbacks and synthetic states, rather than acceptance assertions. No WUI test was run. The relevant source anchors are [SessionDetail decision/continuation consumer](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/humanlayer-wui/src/components/internal/SessionDetail.tsx#L1), [Layout events](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/humanlayer-wui/src/components/Layout.tsx#L438), [unsupported commands](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/humanlayer-wui/src/constants/unsupportedCommands.ts#L7), [route error capture](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/humanlayer-wui/src/components/RouteErrorBoundary.tsx#L10) and [dropdown assertions](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/humanlayer-wui/src/components/ui/dropdown-menu.test.tsx#L61).

### Tests, checks and false reassurance

All authored test files were read; **none were run**. Many provide useful unit-level examples: concrete identities, denial feedback, isolation, parser errors, permission expiry, persistence across a file-backed close/reopen, concurrent event counts, snapshot handling and selective negative cases. The source also illustrates why a named check or green exit cannot establish the intended claim:

| `hld/session/manager_mcp_socket_test.go` | Recreates injection logic inside the test rather than exercising the production launch path |

The useful lesson is to assert **exposure, identity, required outcome, missingness and cleanup**, bind results to the actual candidate, and retain failed/skipped/unrun states separately. That reinforces local RT-01–RT-06 and RT-09 rather than closing them.

## Fit with the existing local documents and next decisions

The [1 October source-adoption audit](../../source-adoption-audit.md) reviewed the distinct `dexhorthy/humanlayer-gensx-example`, not all of this 794-file HumanLayer monorepo. Its scope remains valid. Its A02–A09 lessons—concrete code shape, one current-state owner, fail-before/pass-after when feasible, actual consumer boundaries, command effects and honest evidence—are strengthened here. The audit's original “no Git baseline” statement is historical; its subsequent implementation section and current task records govern status.

The [workflow bridge assessment](../../workflow-bridge-assessment.md) already captures the right overall fit: a candidate Perplexity → Claude → Codex routine around portable task evidence; no orchestrator; proportional prior-art work; a stable review candidate; human disposition; final correction/check leg; and comparisons that include all work. This new source does not make frozen research the only remaining responsibility and does not prove the measurement proposal is ready to implement wholesale.

| Responsibility | Reusable HumanLayer lesson | Local consequence |
| --- | --- | --- |
| Context | Scoped instructions, focused locators/analyzers, canonical note references | Keep root authority and selected routes; add directory scope only when real conventions justify it and loading is verified |
| Design | Concrete files, call paths, phases and manual/automatic criteria | Use the existing plan/template; retain provisional clinic decisions instead of copying a no-open-questions rule |
| Recovery | Persisted state, lineage and handoffs | Keep task.md as current owner; check declared dependency freshness and changed files on resume |
| Control | Explicit permission requests/decisions and interruption | Preserve the selected read-only review/human disposition boundary; permission approval and artifact acceptance remain separate |
| Verification | Specific invariants plus misleading green checks | Repair selected demonstrated local gates; qualify actual cases/results, not command names |
| Measurement | Identities, nullable usage and realized provider data | Freeze one question/route in M00/H00; preserve unknown/estimated states and reconcile event completeness |
| Comparison | No controlled workflow outcome comparison supplied by this snapshot | Compare the actual incumbent with one addition at a time, equal acceptance, all attempts and later change/rework |
| ROI | No local accepted-outcome/human-time comparison | Capture small useful observations now; justify automated collection by repeated decision value and accounting friction |

The smallest useful measurement begins with task/candidate identity, accepted outcome and required check exposure, active human time by research/decision/review/repair, elapsed waiting, known tool spend with unavailable portions explicit, useful/rejected/disputed findings and later defects/change effort. A subscription limit is not a per-task bill. Tokens are neither quality nor human effort. A baseline must retain today's authority/routing/checks, not discard them to exaggerate the treatment. Model changes, extra agents, external research and review should not all change simultaneously if the question is which component helps.

The anonymous healthcare migration article's claimed 40× result is a case account based on an expected alternative schedule and reported savings, without matched tasks/raw baseline/control. The approval diagrams' safety multipliers and future Gen3 cost predictions likewise are conceptual claims. They cannot establish this project's development ROI or clinic facts. The local bridge's incremental benefit must exceed added preparation, review, repair and maintenance; existing source-reading effort is not itself a demonstrated saving.

No new runtime, nested instruction tree, SDK integration or telemetry dashboard is warranted solely by this review. Useful work and narrow observation can proceed, while consequential gate/measurement defects remain explicit. A broader measured-improvement claim requires reliable acceptance and a predeclared comparison; it cannot be obtained by installing this deprecated code. The canonical local task and RT-01–RT-09 remain unchanged.
