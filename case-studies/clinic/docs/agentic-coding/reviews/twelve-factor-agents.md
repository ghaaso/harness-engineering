# Review of humanlayer/12-factor-agents

Reviewed 2026-09-30, pinned to [commit d20c728368bf9c189d6d7aab704744decb6ec0cc](https://github.com/humanlayer/12-factor-agents/tree/d20c728368bf9c189d6d7aab704744decb6ec0cc). This review separates upstream claims, source inspection, and proposed adaptations for the current documentation-only Clinic Workshop repository. No application dependencies were installed and no upstream runtime, BAML, Jest, notebook, or integration tests were executed.

The useful transfer is an engineering discipline: own the instructions and context, make work resumable, keep assignments bounded, and ground decisions in deterministic evidence. Installing HumanLayer, BAML, a new agent runtime, or every upstream instruction file would not itself improve coding performance. This repository offers no evidence establishing a 3× coding productivity gain.

## What the examples actually implement

### TypeScript workshops and agent template

The [2025-05 walkthrough](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/workshops/2025-05/walkthrough.yaml) progresses from a calculator prompt to explicit action unions, tool handlers, prompt assertions, clarification, custom context, HTTP endpoints, persisted thread state, approval, email, and webhook resumption. This is useful instruction in agent runtime construction. Its examples remain deliberately narrow synthetic tasks.

The [2025-05-17 variant](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/workshops/2025-05-17/walkthrough/01-agent.baml) substitutes a Baseten-hosted Qwen3 client, BASETEN_BASE_URL/BASETEN_API_KEY, and /nothink prompt markers. The comment records a provider-specific workaround involving thinking tokens and streaming. This should not become a model-independent coding prompt convention.

The [template agent](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/src/agent.ts), [state store](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/src/state.ts), and [human connector](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/src/a2h.ts) illustrate an event history, filesystem serialization, and yielding for clarification or division approval. They are not repo onboarding tools.

Source-inspection issues matter if someone proposes importing this template:

- [server.ts](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/src/server.ts) assigns store.get and store.create without await although both methods are async; store.update is also invoked without await. This introduces Promise/value inconsistencies and incomplete persistence sequencing.
- [package.json](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/package.json) declares humanlayer while server imports @humanlayer/sdk, and CLI imports chalk without declaring it. BAML is latest while its [generator](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/baml_src/generators.baml) is pinned to 0.88.0.
- [agent.baml](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/baml_src/agent.baml) exposes ProcessRefund, but the agent loop has no corresponding handler or default failure branch. The loop is unbounded.
- The XML-like serializer interpolates raw strings and flattens nested object values into string coercions. A real serializer needs escaping and fidelity. Division by zero is not safely handled.
- JSON-file persistence has no locking, atomic update, version conflict detection, or webhook deduplication mechanism. HTTP payloads use TypeScript casts rather than runtime schema validation, and the shown routes do not implement authentication.
- The [README](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/create-12-factor-agent/template/README.md) is a staged workshop guide referencing walkthrough files absent from this template; its Baseten setup differs from the OpenAI client in the template BAML. Its webhook chapter ends in unfinished instructions. Treat the directory as educational scaffolding, not a verified installable starter.

These are static findings, not observed test failures. They reinforce the need to inspect examples before adopting them.

Chapters covering HTTP, durable runtime state, and human webhook integration are intentionally absent. The [converter](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/workshops/2025-07-16/walkthroughgen_py.py) produces a Colab-style notebook, installs dependencies, fetches BAML, and regenerates/purges client modules to avoid notebook cache issues. Inspection flags:

The documentation describes exploratory work, not a reproducible passing test record.

The saved [main notebook](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/workshops/2025-07-16/workshop_final.ipynb) has 100 cells, 40 code cells, and null execution counts throughout. It is not evidence that those cells ran successfully. Custom serialization logs character lengths rather than measured token cost; the XML efficiency language is not backed by comparative token/quality results.

### Walkthrough generator

[walkthroughgen/src/cli.ts](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/walkthroughgen/src/cli.ts) turns YAML plus canonical stage files into Markdown, section snapshots, and a cumulative final folder. This is a useful documentation-maintenance idea: keep onboarding commands, file changes, and expected observations together.

It only executes commands marked incremental, catches execution errors and continues, and does not verify that displayed expected results equal actual command output. Generated guides therefore do not prove a working environment. Section snapshots are produced before applying that section's steps. Configuration validation and path restrictions are limited; use only trusted YAML.

The [Jest suite](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/walkthroughgen/test/e2e/test-e2e.ts) exercises generation, copying, diffs, command formatting, and state snapshots. It is software-level test coverage for the generator, not an evaluation of coding-agent quality. [package.json](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/packages/walkthroughgen/package.json) has no bin entry or build script matching the advertised global CLI installation; source and example/design commands also differ. Borrow the reproducible walkthrough pattern before relying on this package operationally.

The [A2H draft](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/drafts/a2h-spec.md) describes separate administration and agent scopes, contact/channel discovery, approval, and human responses. It is design material, not an implemented interoperability standard to require here.

Root [CLAUDE.md](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/CLAUDE.md) is a generic instruction scaffold: absent persona-file references, unresolved stack/build/test placeholders, a minimum source-reading quota, deletion preference, and frequent commit rule. These are not evidence-backed performance practices. A minimum line-reading quota can increase irrelevant context; a blanket deletion preference can remove useful behavior. Preserve this project's own authority and safety instructions and replace placeholders with observed repo facts.

## Recommended adoption order for the current repo

The present target is documentation-only and has no application stack or CI. The following is an original adaptation, not a prescription to copy these filenames verbatim.

1. **Establish the verified source map.** Make the canonical documents and their authority relationships easy to discover. State what is decided, proposed, unknown, and superseded. This addresses factors 2, 3, and 13 immediately.
2. **Keep the instruction entry point compact.** Preserve the existing authority rules; link task-specific guidance instead of repeating all documentation in AGENTS.md. Add exact current capabilities and an honest verification section: document checks now, application checks only once an application exists.
3. **Use a proportional task contract.** For substantial work capture objective, acceptance conditions, scope, evidence sources, uncertainties, and verification. Tiny changes need fewer fields and no compulsory research ceremony.
4. **Persist actionable handoffs.** Record current facts with file references, decisions and their reasons, completed edits, commands and outcomes, unresolved concerns, and the next concrete action. Label assumptions. On resume, recheck facts affected by subsequent changes.
5. **Bound research and review assignments.** Give each subagent a clear domain, deliverable, and stop condition. Share a compact relevant context packet. Parent reconciliation and final verification remain necessary.
6. **Record compact failure evidence and change the next attempt.** Distinguish environmental blockage, missing information, incorrect assumption, and actual product defect. Avoid repeated identical attempts; ask a useful question only when independent progress is exhausted.
7. **Add executable bootstrap/verification when there is executable software.** Pin dependencies and make doctor/verify fail clearly. A doctor should disclose observed repo facts; verify should run real checks rather than echo expected success. Avoid inventing an application architecture to justify scripts.
8. **Defer runtime integrations.** HumanLayer, BAML, A2H, webhook storage, email approval, and scheduled channels are relevant if the application itself becomes an agent system. They are unnecessary dependencies for improving an existing coding assistant's ability to work in docs.

A measurable improvement should come from less rediscovery, fewer mistaken edits, faster environment repair, clearer completion criteria, and smaller rework cycles. More instructions, more model calls, or more subagents are not success metrics.

## How to evaluate the 3× target

Upstream [README](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/README.md) motivates its guidance with practitioner experience and interviews. Its framework-success percentages are not a controlled coding-agent benchmark. No reviewed test measures this project's time to accepted code, review rework, or defect rate.

Use 3× as a target hypothesis:

- Choose representative task families and written acceptance rubrics before trials. For this repo, begin with source-grounded document revisions, contradiction resolution, and specification-to-task breakdowns; add coding tasks when code exists.
- Compare baseline and improved setup under the same model, tool permissions, initial files, and acceptance criteria. Use fresh sessions and matched tasks to reduce familiarity effects; repeat rather than drawing a conclusion from one run.
- Count wall-clock completion time, human review/repair time, success rate, rejected or reopened work, unsupported claims, and model/tool cost. Include setup and coordination overhead.
- Define quality-adjusted productivity as accepted comparable tasks per human engineering hour, including active planning, supervision, review and repair. Report elapsed delivery time and agent/tool runtime/cost separately. A speed gain only counts when correctness and safety criteria remain satisfied; the [evaluation plan](../evaluation-plan.md) defines the accounting rules.
- Report uncertainty and task-specific effects. Do not claim a general 3× improvement from a few selected easy examples.
