## Linked artifacts: what they add and what should not be copied

The [research prompt](https://github.com/humanlayer/humanlayer/blob/main/.claude/commands/research_codebase.md) separates source code from historical notes, asks scoped workers to locate/analyze patterns, and returns verifiable paths and metadata. Its direction to describe the repository as it is supports accurate research; it is not a restriction on this user's explicitly requested critical audit.

The [planning prompt](https://github.com/humanlayer/humanlayer/blob/main/.claude/commands/create_plan.md) specifies concrete files, changes and separate automated/manual checks. The [implementation prompt](https://github.com/humanlayer/humanlayer/blob/main/.claude/commands/implement_plan.md) follows a plan while checking results. Their tool names, `thoughts` services, default commands and repeated approval pauses are environment-specific. They should not replace this project's actual commands or already-granted authorization. Blindly trusting completed checkboxes on resume would also weaken the local revalidation rule. The older planning prompt's horizontal layer examples should not override the newer essay's observable vertical slices.

The BAML [research](https://github.com/ai-that-works/ai-that-works/blob/main/2025-08-05-advanced-context-engineering-for-coding-agents/thoughts/shared/research/2025-08-05_05-15-59_baml_test_assertions.md), [research-backed plan](https://github.com/ai-that-works/ai-that-works/blob/main/2025-08-05-advanced-context-engineering-for-coding-agents/thoughts/shared/plans/baml-test-assertion-validation-with-research.md), and [other plan](https://github.com/ai-that-works/ai-that-works/blob/main/2025-08-05-advanced-context-engineering-for-coding-agents/thoughts/shared/plans/fix-assert-syntax-validation-no-research.md) provide a useful concrete contrast: the former uses the semantic validation layer and established fixture conventions, while the latter puts the change in constraint collection and proposes broader ad hoc tests. This illustrates responsibility tracing, not a controlled demonstration that a research phase alone caused better results.

The [SlopCodeBench v1 method](https://arxiv.org/html/2603.24755v1) preserves the agent's workspace but starts fresh conversations as requirements evolve. Its held-out tests, Python-focused measurements and limited runs differ from ordinary development with visible tests and human steering. Its prompt interventions do not establish that adding planning language guarantees better correctness. Transfer the iterative evaluation design, not a numerical quality claim or the entire benchmark harness.

## Quantitative claims

WSFF's two-to-threefold aspiration concerns speed while retaining human-level quality. It is not evidence for three times the quality, and neither the source repository nor its examples establishes five times better context management. A context packet can be five times shorter and still be worse if it omits the decisive invariant. Conversely, reducing repeated search may help even when the final packet is no smaller. The main audit defines measurable alternatives with acceptance and evidence-retention guardrails.

No adoption percentage is assigned. The substantive conclusion is narrower and more useful: the original review learned nearly all of these lessons, while concrete code shape, iterative change evaluation and bug-test integrity lost specificity between the research and the daily workflow.
