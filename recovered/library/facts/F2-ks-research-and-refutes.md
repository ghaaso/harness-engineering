## 2. What the refuters established (bears on E1 to E5)

**KS-C10 recurrence (both lenses NARROWED).**
- 48 fix-prefixed commits on `main` (of 368) [M]. Earlier "almost no explicit repeats" was a subject-line keyword count and is withdrawn.
- Reading commit bodies: repo lens "at least five" same-cause repeats among the 48; ops lens "at least three", plus a fourth pair (expo-audio `stop()`, first fix wrong). Design states "three to five depending on lens" [M]. Pairs: mypy no-implicit-reexport (75b51f9, 981ae08; next day); `NoReferencedTableError` (2f09cec then f29f62f, same day, second was prod login 500); press-race guard ported to sibling (789d522, 0a3b38e); Expo SDK-52 pin drift (b7a5b98, 6928828; CI green both times); expo-audio stop (dbb3661, d440855).
- `git log --all`: 72 fix commits, 24 not on main (squash hides them). Subject regex misses `@ fix` subjects. Main spans 2026-05-31 to 2026-08-03, about 65 days (not 5 months).
- Counting rule adopted (KS-F17): count a repeat only if (a) a lookup-able symptom existed at the second occurrence, (b) earlier knowledge was NOT findable by `git log --all --grep` or grep of CLAUDE.md/HANDOFF, (c) diagnosis was non-trivial (prod incident, burned build, differential vs known-good). Three classes kept apart: exact; same cause different file; shape-level (a checklist serves, not a lookup).
- Strongest repeat was findable without a store: 2f09cec's body had the error token 8 hours before f29f62f, so `git log --grep` would have found it. Every repeat ended with a structural guard (dependabot ignore, bootstrap test, CLAUDE.md trap, library switch). The mypy pair "diagnoses itself from the error message".
- Model tier: of 48 fix commits, trailers show 20 Fable 5, 20 Opus 4.8, 6 Opus 5, 1 Opus 4.7, 1 none, 0 cheap-tier. Every fix was top-tier already. No cost figure recorded anywhere; session re-encounters with no commit are unrecoverable locally. Result: KS-0 yields a prior only; solve cost avoided (S) has no historical prior; KS-9 measures S.
- Design's §9: expected recurrence of vocabulary-miss events E[k] 0.01 to 0.2 per 8-week window [E].

**Incumbents.** Design names two incumbent arms for the pilot: grep over CLAUDE.md/docs (CLAUDE.md counted as already loaded) and `git log --all --grep` over commit bodies. Most seed traps already sit in always-loaded CLAUDE.md (X-05 F21, "about 10 traps in HANDOFF §2, 7 shapes in §6, 4 build traps plus ~12 invariants in CLAUDE.md"). Judges' blind spot: moving narratives out of CLAUDE.md can remove knowledge from sessions that never look up. CI duplicates the Docker test-id gate for ex1, ex5, ex6 (§9). Store's claimed distinct value: traps CI cannot see (ex7, ex8, ex2) and diagnosis paths/negatives. No incumbent comparison has been run; the pilot (KS-5) is unbuilt.

**False alarms (measured by refuters, §12.8 KS-V1).** Under v1.3's diff rule, 48.7% of past commits (103 of 154) would have warned [M, emulated over a synthetic seed]; 27 to 44% with strict handles; `useState` on 31% of commits, `client_id` 22-28%, `job` 58-66%; ex6 handles derived from the fix diff fire on 91%; whole-file precondition fired on 11 of 154 PRs. **Earlier refuters (§12.5):** 30 verdicts: 1 confirmed, 21 narrowed, 8 refuted. **Cost (KS-C9, narrowed both lenses) [M on 2,904 Bash results in local transcripts].** 2,000 characters of output cost about 860 tokens (0.40 per char plus 55 per call), not the 500 first claimed. Each call re-reads the caller's context as cache reads; every subagent starts above 63k prompt tokens. Skill description about 620 tokens, about 0.5% of prompt tokens in a heavy session. Quiet phase: three session turns plus one reviewer call, each `--diff` run 170-220 ms wall, miss line ~70-90 tokens. Recording a solve: about 5-10k Opus author tokens (or a fresh >63k-token subagent start if the solver was Sonnet/main), plus 2-4k reviewer tokens, 10-20 minutes [E]. Lookup output cap: 2,000 chars. Break-even model (X-05 F25) [E]: net saving per encounter = h(S - L_hit) - (1-h)L_miss - W/E; with L about 0.05S and W/E 0.1S, break-even h about 0.15 [G: inputs unknown].

## 3. What the judge panel rejected (§12.2, §12.3, §2)

- Proposal B (separate Postgres container): 222 of 360, unreachable when Docker Desktop is off; second always-on service for hundreds of rows. A scored 292, C 282, D 281.
- LLM extraction at write time (junk, duplicates, per-write cost, poisoning route) [M-01]; LLM-judged contradiction as the invalidation trigger; Mem0 ADD-only side-by-side beliefs; time decay; automatic rewriting of old entries (A-MEM, ACE collapse); LLM judge as retain gate (T-05); LLM re-ranking inside the store (KS-R4, one lead and one candidate shown).
- Embeddings: none in v1; deferred behind D16, a trigger the design itself expects "about never" to fire (E[k] below ~0.2 per window); if ever added, a local pinned model, dense-only hit may reach candidate never lead.
- Pushing content into sessions: rejected; pull-only. No hook in v1; edit-time hook D21 default OFF (blind to Bash/PowerShell edits; lane M-02 rated a lookup hook viable; no-hook rule rests on always-loaded-file evidence, not on a hook measurement).
- Graph/code index: Kùzu, Neo4j, Memgraph etc. rejected; lineage is a join or recursive CTE (0.07 to 95 ms on 300 nodes/3,000 edges); graphify skipped by the harness review (HR §5); "not a code index" (§1.4); `guarded_refs` optional, default off (D22). Search engines, OLAP, Cassandra, vector servers: rejected at hundreds of rows (practitioner thresholds for a second engine about 10^7-10^8 rows vs 10^3-10^4 here [reported]).
- Rejected as a shape: always-loaded storage (CLAUDE.md as the store), per-entry skills, hosted memory (Copilot Memory; hosted-egress), MemTree, claude-mem, Virtual Context, Continuous-Claude, headroom, context-mode.

## 4. What the record lists as unknown or unmeasured

- Whether any lookup beats `git log --grep` and CLAUDE.md on this repository: unproven (§0, §9).
- Whether a Haiku/Sonnet-class agent benefits from a gated hit: "smaller models can fall below baseline with memory" (M-02 open question; no study tests verification-gated lookup by cheap coding agents). The with/without comparison is deferred to the prospective checkpoint KS-9, not the pilot.
- Solve cost avoided S: no historical prior; no source quantifies escalation cost avoided by reuse; every fix is top-tier in history.
- Recurrence rate of hard defects for one developer in a young repo: not measured by any source; only pattern-level population studies.
- Hard-encounter count per phase unknown; 20 encounters could take 7-20 phases (X-05 open). 20 observations can reject a 25% hit rate (P≤1 hit = 2.4%) but not separate 15% from 5% [E].
- Retrieval thresholds (θ_lead 0.5, θ_cand 0.3, μ 0.2): all inferred [E], frozen at KS-4; no literature gives them. 0 false positives in 40 probes bounds the rate at 7.5% (60 gives 5%) [E].
- Pilot recall may not transfer: blind queries are written for entries the corpus already holds.
- Compliance (agents actually looking up): self-reported; no hook.
- Dense retrieval at this scale: no evidence either way; false-candidate rate and cross-host determinism unrun.
- Fix decay after refactors: no study found (M-03). No published repeat-CI-failure rate.
- Writer identity self-declared; native Android compile gated nowhere; Docker off by default so test-id checks often `inconclusive`.
- The store, index, local log, and `tools/ks` do not exist; every refuter replay was emulated on a synthetic seed.
- Pilot go criteria [T]: recall at shown ≥ 60%, zero acted false positives over ≥ 40 probes, win over both incumbents at equal precision, diff arm catches every planted diff with false-fire ceiling one in ten. Kill: fewer than 3 verified hits, any acted false positive that reached a merged change, or an incumbent matching the store. Checkpoint at 20 encounters or 8 weeks.
- The owner-side "no measurable gain" record of the clinic project is not in the repository (X-05 F23, though the C-01 lane later found WF-01/WF-02 and HR §4 wording).

## 5. Other projects, portability, sharing

The record is nearly silent. The store is scoped to this repository: home `C:\Users\User\.fixflow-ks\`, outside every worktree; one state owner for FixFlow diagnoses (D4); shop-specific seed entries (ex1-ex8 from FixFlow history). No section designs a cross-repository store, shared store, or reuse by other projects. Sync topology covers only two hosts of the same owner (dev box and VPS, via bare git remote; never GitHub). The only cross-project items are inputs: the owner's clinic project is a source of warnings (C-01) and a note that "no prior art invalidates by code dependency" (T-05 F26). Closest relevant fact: the store trusts nothing across contexts, because entries are untrusted until the gate passes and "private memory is not team authority" (C-01). Cross-project transfer of cached reasoning, and use by a team without the top model, are not studied in any lane; the memory-transfer evidence is Ghosh et al. ("transfer follows tool-call structure"; harm grew with executor size) and SWE-Exp (same-repo experiences excluded to prevent leakage).
