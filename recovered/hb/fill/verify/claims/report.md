## Zero-token first test for C13 (token side)
Replay the 69 slice and 155 subagent windows offline. Build the import/caller index (and separately co-change) at each window's start commit. Seed from the paths in the window's brief. Count (a) locate-only calls whose answer the index holds (now 1,246 calls, 225M, 5.2 %), with their context re-read and result carry; (b) recall of the finally-edited files by the list (<=15 files); (c) reads outside both the edit set and the list. Pre-register: go live only if (a) >= 3 % of tokens and (b) >= 0.8.

## Strongest honest case for the owner's idea
Every lookup step re-reads the whole window: 54.6 % of calls and 43.6 % of context tokens are read/search-only calls, so a layer that answers in one call what took five saves windows, not bytes. Subagents are the target: 40.1 % fetched, 76.5 % of their calls read/search-only, whole-file reads 16.8 % of their tokens, 85 % of their fetched tokens on unedited paths. A cross-window hot set exists (72 paths = half of fetched; implementation-plan.md in 39 windows, operations/kernel.py in 63), which is what a hash-invalidated digest cache targets. Against it: in-window re-reading is 0.5 %, so an in-window cache is worthless, and no substitute for the lines has been shown to suffice.
