## section many
Many runs Most unknowns are guesses, so the model runs many times with random draws. The result is a spread, not one answer. Runs at each tie Seed Run at all three ties Progress not run yet M of the M drawn unknowns are guesses. Tie: how far the library unknowns move together. At the lowest tie, each is drawn on its own. At the highest, they share one level. The tie moves use and entry quality together. So no tied run is a much-used library with poor entries. The tied share of runs better than the ladder has no matching worst case. This spread follows from the ranges and the way they are drawn. It is not a measurement of the library. Press the button. ## wordsList
Tags M: measured on this PC, in the owner's repositories or session records. S: an outside study or the price list. G: a guess. A computed number takes the weakest tag of its inputs. Piece of work One fix-sized task of about ten cheap calls. A result is made and checked. Visible or latent Visible: something signals a problem, such as an error or a failing check. Latent: nothing signals that a choice matters. Entry One stored conclusion in the library. Look-alike A stored entry that looks like a match but has a different cause. Gate Whatever decides a result is right: tests, and sometimes a review by Opus. Ladder What happens after a caught failure: one cheap retry, then Opus, then Fable. Cost Counted in cheap-call equivalents. One cheap-model call costs one. An Opus call costs the Opus price ratio. Wrong rate The share of pieces of work that do not end accepted and right. Ratio The library's figure divided by the other way's figure. Below one, the library's figure is lower. Library unknown An unknown that exists only because of the library. Each has a good end: the end where the design works as intended. Reference settings Three fixed settings; other unknowns stay at best. Best: every unknown at its best value. Favourable: every library unknown at its good end. Unfavourable: every library unknown at its other end. That is a barely used library, so it can do little harm. The ranges also hold worse settings, such as heavy use with poor entries. Weight of a limitation How much it holds the result down. Its library unknowns move to their good end, and the four ratios are measured again. A limitation with no library unknown is not measured. Rank correlation How steadily a result rises or falls as one unknown rises across the runs. One means always; zero means no steady link. Stock and flow A stock piles up over time and is drawn as a box. A flow fills or drains it, drawn as an arrow with a valve. Loop R or B A chain of causes that returns to its start. R feeds itself. B holds itself back. Seed A whole number that fixes the random draws. The same seed always gives the same runs. Knowledge-store design The owner's earlier design for a store of solved defects in FixFlow. It is not the library mapped here. CI The shared test run on GitHub that checks every change. PR A pull request: a proposed change, reviewed before it joins the main branch. Technical names in the cases Case notes keep some names from the records. These are the common ones. pdftoppm A small tool that turns PDF pages into images. Heredoc A way to hand a long block of text to a shell command in one go. ENAMETOOLONG An error that says a command or a name is too long for the system. CSRF token A random value a web form carries, to block forged requests. job_event.seq The running number on each job event in FixFlow's database. It puts all events in one order. EXPO_PUBLIC_SENTRY_DSN The setting that tells the phone app where to send crash reports. Migration A numbered change to the layout of FixFlow's database. Case notes name one by its number.
